# 第 5 章 Trait 与泛型

Trait 和泛型是 Rust 写“可替换组件”的方式：同一份业务代码，测试时接内存存储，上线时接PostgreSQL。Axum 的处理函数、SQLx 的查询、Tower 的中间件，全都建立在本章的知识上。读完本章，RustMall 会有一套仓储（Repository）接口和它的内存实现。

## 5.1 Trait 基础：定义、实现、默认方法

Trait 是一组方法签名，描述“某种类型能做什么”。任何类型只要实现了这些方法，就可以被当作“会做这件事的东西”来使用。它相当于 Java/Go 的接口，但更强：可以有默认实现、关联类型，还能为别人定义的类型实现。

### 5.1.1【入门】定义和实现一个 trait

场景：RustMall 要给用户发通知，现在有短信和邮件两种渠道，以后可能加 App 推送。我们先定义“能发通知”这件事：

```rust
/// 能发送通知的渠道
pub trait Notifier {
    /// 发送一条通知，返回渠道给出的消息编号
    fn send(&self, to: &str, content: &str) -> Result<String, String>;
}
```

逐行解读：

pub trait Notifier ：定义名为 Notifier 的 trait，pub 让其他模块也能用。

方法只有签名、没有函数体，末尾是分号。实现这个 trait 的类型必须提供函数体。

&amp;self ：和第 3 章的方法一样，表示通过借用调用。

为两种渠道分别实现：

```rust
pub struct SmsNotifier {
    // 短信签名，如“【RustMall】”
    pub sign: String,
}
 
pub struct EmailNotifier {
    pub from: String,
}
 
impl Notifier for SmsNotifier {
    fn send(&self, to: &str, content: &str) -> Result<String, String> {
        if to.len() != 11 || !to.bytes().all(|b| b.is_ascii_digit()) {
            return Err(format!("手机号 {to} 格式错误"));
        }
        println!("[短信] 发往 {to}：{}{content}", self.sign);
        Ok(format!("sms-{to}"))
    }
}
 
impl Notifier for EmailNotifier {
    fn send(&self, to: &str, content: &str) -> Result<String, String> {
        println!("[邮件] {} -> {to}：{content}", self.from);
        Ok(format!("mail-{to}"))
    }
}
```

这两个实现仅在终端打印演示，不连接真实短信或邮件服务；手机号示例只检查 11 位 ASCII 数字，完整规则应由业务边界另行定义。

语法是 impl Trait 名 for 类型名 { ... } 。调用时和普通方法一样，但必须先把 trait 引入作用域：

```rust
// 不引入就调用 .send() 会报 E0599
use crate::notify::Notifier;
 
let sms = SmsNotifier { sign: "【RustMall】".into() };
sms.send("13800000000", "您的订单已发货")?;
```

为什么要引入：一个类型可能实现了多个都有 send 方法的 trait，Rust 只在你引入的 trait 里查找方法，避免歧义。

### 5.1.2【入门】默认方法

Trait 里的方法可以带默认实现，实现者可以直接用，也可以覆盖：

```rust
pub trait Notifier {
    fn send(&self, to: &str, content: &str) -> Result<String, String>;
 
    /// 渠道名称，默认是 "unknown"
    fn channel(&self) -> &'static str {
        "unknown"
    }
 
    /// 批量发送：默认实现逐条调用 send，遇到失败就停止
    fn send_batch(&self, to: &[&str], content: &str) -> Result<Vec<String>, String> {
        to.iter().map(|t| self.send(t, content)).collect()
    }
}
 
impl Notifier for EmailNotifier {
    fn send(&self, to: &str, content: &str) -> Result<String, String> { 
        println!("[邮件] {} -> {to}：{content}", self.from);
        Ok(format!("mail-{to}")) }
 
    // 覆盖默认实现
    fn channel(&self) -> &'static str { "email" }
    // send_batch 不写，直接继承默认实现
}
```

默认方法可以调用同一个 trait 里的其他方法（包括没有默认实现的 send ），这叫模板方法模式：trait规定流程，实现者只填关键的一步。send\_batch 里的 collect 用到了 4.2.4 节的技巧。

### 5.1.3【进阶】调用的消歧：完全限定语法

如果一个类型实现了两个 trait，它们都有同名方法，直接 x.name() 会报 E0034（多个候选方法）。这时用完全限定语法指明是哪一个：

```rust
trait Animal { fn name(&self) -> String; }
trait Robot  { fn name(&self) -> String; }
 
struct Mecha;
impl Animal for Mecha { fn name(&self) -> String { "猫".into() } }
impl Robot  for Mecha { fn name(&self) -> String { "R2".into() } }
 
let m = Mecha;
 
// "猫"
let a = Animal::name(&m);
 
// "R2"，最完整的写法
let r = <Mecha as Robot>::name(&m);
```

&lt;类型 as Trait&gt;::方法 在没有 self 的关联函数上可明确消除歧义；上下文足够明确时也可能使用 Type::method 等较短写法，例如 &lt;u32 as Default&gt;::default() 。

### 5.1.4【进阶】父 trait

第 4 章见过 trait Error: Debug + Display 。自己定义时同理：要求实现者必须先实现另一个 trait。

```rust
use std::fmt::Display;
 
/// 能出现在审计日志里的东西：必须能显示，还要提供一个审计编号
pub trait Auditable: Display {
    fn audit_id(&self) -> String;
 
    fn audit_line(&self) -> String {
        // 因为有父 trait Display，这里可以直接用 {self}
        format!("[{}] {self}", self.audit_id())
    }
}
```

### 5.1.5【精通】Trait 的本质与两个常见误区

trait 定义一组能力，可以用于约束，也可以在满足条件时构造 dyn Trait 这样的 trait 对象类型。你不能写 let n: Notifier = ... ，因为编译器不知道它占多少内存。要么在编译期确定具体类型（泛型，5.2/5.3节），要么在运行期通过指针间接使用（dynNotifier ，5.5 节）。这两种方式是本章重点；枚举也能表达有限实现之间的选择，后面的所有内容都是在这两条路上展开。

误区一：把 trait 当成“类”的替代来建继承体系。Rust 没有继承，父 trait 只表示“要求”，不表示“继承字段”。共享数据用组合（结构体里放另一个结构体），共享行为用 trait 默认方法。

误区二：一开始就为每个结构体定义 trait。只有当确实存在两个以上的实现（例如“真实数据库”和“测试用内存版”），或者需要让调用方插入自己的实现时，才值得抽象出 trait。RustMall 的仓储层满足这个条件，所以本章 5.8 节会定义 Repository trait；而商品、订单这些领域模型只有一种实现，就不需要 trait。

常见编译错误与解读

| 诊断 | 常见原因 | 处理 |
| --- | --- | --- |
| E0599 | trait 方法没有进入作用域 | 导入相关 trait，并核对实现 |
| E0046 | 漏了必须实现的方法 | 补齐 trait 要求的方法 |
| E0407 | trait 实现中出现了不属于它的方法 | 修正拼写；固有方法放进固有 impl |
| E0053 | 方法签名与 trait 不一致 | 核对接收者、参数与返回类型 |
| E0034 | 多个 trait 提供同名方法 | 使用 Trait::method 或完全限定语法 |
| E0277 | 父 trait 约束未满足 | 先提供所要求的能力 |

## 5.2 泛型：函数、结构体、枚举与单态化

泛型就是“类型参数”：写代码时先用 T 占位，使用时再填入具体类型。你早就在用它了：Vec&lt;T&gt; 、Option&lt;T&gt; 、Result&lt;T, E&gt; 、HashMap&lt;K, V&gt; 都是泛型。本节学会自己写泛型，并理解它为什么没有运行时开销。

### 5.2.1【入门】泛型函数

不用泛型时，要对每种类型各写一遍：

```rust
fn first_i64(items: &[i64]) -> Option<&i64> { items.first() }
fn first_str(items: &[String]) -> Option<&String> { items.first() }
```

用泛型合成一个：

```rust
fn first<T>(items: &[T]) -> Option<&T> {
    items.first()
}
 
// T = i64
let a = first(&[1_i64, 2, 3]);
 
// T = String
let names = ["键盘".to_string()];
let b = first(&names);
 
// 推断不出时用 ::<> 指定，俗称“涡轮鱼”
let c = first::<u8>(&[]);
```

fn first&lt;T&gt; ：尖括号里声明类型参数 T ，名字随意，惯例用单个大写字母。

调用时编译器根据实参推断 T 。推断不出（比如空切片）时，用 first::&lt;u8&gt;(...) 显式指定。

### 5.2.2【入门】泛型结构体与枚举

后端最典型的泛型结构体是“分页结果”：商品列表、订单列表结构完全一样，只是元素类型不同。

```rust
#[derive(Debug, Clone)]
pub struct Page<T> {
    pub items: Vec<T>,
    pub total: u64,
    pub page: u32,
    pub page_size: u32,
}
 
impl<T> Page<T> {
    /// 总页数，向上取整
    pub fn total_pages(&self) -> u64 {
        if self.page_size == 0 {
            return 0;
        }
        self.total.div_ceil(u64::from(self.page_size))
    }
    /// 把每个元素换成另一种类型，比如把数据库实体转成 API 响应结构
    pub fn map<U>(self, f: impl FnMut(T) -> U) -> Page<U> {
        Page {
            items: self.items.into_iter().map(f).collect(),
            total: self.total,
            page: self.page,
            page_size: self.page_size,
        }
    }
}
```

要点：

impl&lt;T&gt; Page&lt;T&gt; ：impl 后面的 &lt;T&gt; 是“声明”类型参数，Page&lt;T&gt; 里的 T 是“使用”它。两处都要写。

map&lt;U&gt; 是方法自己额外的类型参数，和结构体的 T 无关。impl FnMut(T) -&gt; U 是 5.3 节要讲的写法，这里先理解为“一个把 T 变成 U 的函数”。

也可以只为某个具体类型写方法：impl Page&lt;String&gt; { ... } 里的方法只有 Page&lt;String&gt;能用。

枚举也一样，Option&lt;T&gt; 和 Result&lt;T, E&gt; 的定义就是最好的例子。

### 5.2.3【进阶】单态化：泛型为什么零开销

编译器对泛型的处理叫单态化（monomorphization）：程序里每用到一种具体类型，编译器就为它生成一份专门的代码。上面的 first 被用于 i64 和 String ，编译后相当于你手写了 first\_i64 和first\_string 两个函数。

| 方面 | 单态化的影响 |
| --- | --- |
| 运行时 | 编译器可针对具体类型生成并优化代码，不需要固有的虚表调用 |
| 构建成本 | 较多类型组合可能增加编译工作 |
| 产物体积 | 实例化可能增加代码体积，优化也可能合并或消除实例 |
| 与类型擦除比较 | 不同语言与运行时采用不同实现，不能简单断言另一种泛型总要装箱 |

Axum、Tower 和 SQLx 使用了较多泛型，实例化与宏展开等会影响首次构建成本。日常可用 cargo check 提前发现类型问题；性能仍需在实际发布构建中测量。

### 5.2.4【进阶】PhantomData 与类型标记

有时类型参数只用来在编译期区分类型，结构体里并不真正存放它的值。Rust 要求每个类型参数都必须被“用到”，否则报 E0392。这时用 std::marker::PhantomData ，它不占任何内存：

```rust
use std::marker::PhantomData;
 
/// 带类型标记的 ID：Id<User> 和 Id<Product> 是不同类型，不能混用
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct Id<T> {
    value: u64,
    _marker: PhantomData<T>,
}
 
impl<T> Id<T> {
    pub fn new(value: u64) -> Self {
        Self { value, _marker: PhantomData }
    }
}
 
pub struct User;
pub struct Product;
 
fn load_user(_id: Id<User>) {}
 
let pid: Id<Product> = Id::new(7);
// load_user(pid); // E0308：expected `Id<User>`, found `Id<Product>`
```

这是第 3 章 newtype 思路的泛型版：一个泛型结构体代替一堆 UserId 、ProductId 。RustMall 第 3 章已经用独立 newtype 实现了 ID，两种做法都正确；泛型版的代价是 derive 会给 T 加上不必要的约束（例如要求 User: Clone 才能克隆 Id&lt;User&gt; ），实际项目里常需要手写这些 trait 实现，所以本书保留第 3 章的写法。

### 5.2.5【精通】const 泛型

除了类型，常量值也可以作为泛型参数，最常见的是数组长度：

```rust
/// 固定长度的验证码，长度在类型里
pub struct Code<const N: usize>([u8; N]);
 
impl<const N: usize> Code<N> {
    pub fn as_str(&self) -> &str {
        std::str::from_utf8(&self.0).unwrap_or("")
    }
}
 
let sms: Code<6> = Code(*b"482913");
```

后端代码里 const 泛型用得不多，但在读 \[T; N\] 相关的标准库签名（如 impl&lt;T, const N:usize&gt;From&lt;\[T; N\]&gt; for Vec&lt;T&gt; ）时需要认识它。

常见编译错误与解读

| 诊断 | 常见原因 | 处理 |
| --- | --- | --- |
| E0282 | 空集合等没有足够的类型约束 | 标注类型或使用 ::&lt;T&gt; |
| E0412 | 使用 T 却没有声明 | 例如改成 impl&lt;T&gt; Page&lt;T&gt; |
| E0392 | 类型参数没有用于类型定义 | 按含义加入 PhantomData 或删除参数 |
| E0369 | 在无相关约束的泛型上比较 | 要求适当的 PartialOrd 或 Ord |

| 诊断 | 常见原因 | 处理 |
| --- | --- | --- |
| E0599：没有 clone | T 没有 Clone 约束 | 需要克隆时要求 T: Clone |

## 5.3 Trait bound、where 子句与 impl Trait

泛型 T 默认“什么都不会”：不能比较、不能打印、不能克隆。Trait bound（约束）就是告诉编译器“T 至少实现了这些 trait”，这样函数里才能使用对应的能力。泛型 + trait bound 是 Rust 静态多态的完整形态。

### 5.3.1【入门】给 T 加约束

```rust
use std::fmt::Display;
 
// 要求 T 能比较大小
fn max_of<T: PartialOrd>(a: T, b: T) -> T {
    if a >= b { a } else { b }
}
 
// 要求 T 能显示
fn log_all<T: Display>(items: &[T]) {
    for item in items {
        println!("- {item}");
    }
}
 
// 用 5.1 节自己定义的 trait 做约束：任何通知渠道都能用
fn notify_shipped<N: Notifier>(n: &N, phone: &str) -> Result<String, String> {
    n.send(phone, "您的订单已发货")
}
```

多个约束用 + 连接：T: Display + Clone 。约束写在 &lt;&gt; 里，叫内联约束。

### 5.3.2【入门】where 子句

约束一多，签名就很难读。where 子句把约束挪到签名后面，语义完全相同：

```rust
use std::fmt::{Debug, Display};
use std::hash::Hash;
 
// 内联写法：很挤
fn group_count<K: Eq + Hash + Display + Clone, V: Debug>(items: &[(K, V)]) -> usize {
items.len() }
 
// where 写法：清晰
fn group_count2<K, V>(items: &[(K, V)]) -> usize
where
    K: Eq + Hash + Display + Clone,
    V: Debug,
{
    items.len()
}
```

约定：一两个简单约束用内联，否则用 where 。cargo fmt 会自动把 where 排成上面的格式。

### 5.3.3【入门】impl Trait：参数位置和返回位置

参数位置的 impl Trait 是泛型的简写：

```rust
// 下面两个函数完全等价
fn notify_a<N: Notifier>(n: &N) { let _ = n.send("13800000000", "hi"); }
fn notify_b(n: &impl Notifier)  { let _ = n.send("13800000000", "hi"); }
```

区别只有一个：impl Trait 写法不能用 ::&lt;&gt; 显式指定类型。参数简单时用它更易读。

返回位置的 impl Trait 含义不同：“我返回某个实现了这个 trait 的具体类型，但不告诉你它叫什么”。它最大的用途是返回闭包和迭代器，因为它们的真实类型名又长又写不出来：

```rust
/// 返回一个“只保留上架商品名称”的迭代器
fn on_sale_names<'a>(items: &'a [(String, bool)]) -> impl Iterator<Item = &'a str> + 'a {
    items.iter().filter(|(_, on_sale)| *on_sale).map(|(name, _)| name.as_str())
}
 
/// 返回一个闭包：给价格打折
fn discount(percent: u32) -> impl Fn(u64) -> u64 {
    assert!(percent <= 100, "教学示例的折扣比例须为 0～100");
    // 先提升到 u128，乘积不溢出；比例不超过 100，结果不会超过原 price。
    move |price| (u128::from(price) * u128::from(100 - percent) / 100) as u64
}
 
let ten_off = discount(10);
assert_eq!(ten_off(2000), 1800);
```

注意：同一个返回位置的 impl Trait 在一个实例化中对应一个确定的具体类型。if 的两个分支返回两种不同的闭包会报 E0308，这时需要 5.5 节的 Box&lt;dyn Fn(u64) -&gt; u64&gt; 。

### 5.3.4【进阶】闭包的三个 trait：Fn、FnMut、FnOnce

闭包是后端代码里最常见的泛型参数（Axum 的处理函数、迭代器适配器、tokio::spawn 的参数）。Rust 用三个 trait 描述闭包怎样使用它捕获的变量：

| trait | 接收者语义 | 调用要求 | 示例 |
| --- | --- | --- | --- |
| Fn | 可通过共享借用调用 | 可以重复调用；并发还<br>需 Sync 等约束 | \|x\| x + offset |
| FnMut | 调用可能修改捕获状态 | 通常通过可变借用依次<br>调用 | \|x\| { count += 1; x } |
| FnOnce | 调用可以消耗捕获值 | 调用方最多承诺调用一<br>次 | move \|\| drop(connection) |

所有 Fn 实现都同时实现 FnMut 和 FnOnce，FnMut 也实现 FnOnce。API 只调用一次时通常选择FnOnce；需要多次调用且允许改变捕获状态时选择 FnMut；需要通过共享借用调用时选择 Fn。Fn 本身不保证线程安全，move 捕获也不直接决定闭包属于哪一种调用 trait。

标准库的 Option::map 要求 FnOnce ，Iterator::map 要求 FnMut ，就是这个道理。

move 关键字强制闭包按值捕获，常见于需要 'static 的场合，例如第 2 章提到的 tokio::spawn。

### 5.3.5【进阶】带约束的 impl：条件实现方法

impl 块也可以加约束，方法只对满足约束的类型可用：

```rust
use std::fmt::Display;
 
impl<T: Display> Page<T> {
    /// 只有元素能显示时，才有这个方法
    pub fn summary(&self) -> String {
        let names: Vec<String> = self.items.iter().map(|i| i.to_string()).collect();
        format!("第 {} 页：{}", self.page, names.join("、"))
    }
}
```

Page&lt;String&gt; 能调用 summary() ，而 Page&lt;Vec&lt;u8&gt;&gt; 不能，编译器会报 E0599 并说明是哪个约束不满足。

### 5.3.6【精通】约束放在哪里：结构体定义 vs impl

可以把约束写在结构体定义上：struct Cache&lt;K: Hash + Eq, V&gt; { ... } 。但社区惯例是结构体定义上不加约束，只在需要的 impl 上加。原因：

1. 定义上的约束会“传染”：之后每个 impl 块、每个用到 Cache&lt;K, V&gt; 的函数都必须重复写一遍。

2. 有些方法（比如 len() ）根本不需要这些约束，放在定义上反而限制了用法。

标准库的 HashMap&lt;K, V, S&gt; 就是这么做的：定义上没有 K: Hash ，new() 也不要求，只有 insert、get 所在的 impl 块才要求 K: Eq + Hash 。

例外：当约束是类型含义的一部分时可以写在定义上，例如需要在 Drop 实现中使用该约束时（Drop 的约束必须和定义一致）。

另一个精通点是静态分发的心智模型：带约束的泛型在编译期就确定了调用哪个实现，调用 n.send(...)被编译成对 SmsNotifier::send 的直接调用，可以内联。下一节的 dyn 则是运行期查表调用。两者如何选择，5.5.5 有完整对比表。

常见编译错误与解读

| 诊断 | 常见原因 | 处理 |
| --- | --- | --- |
| E0277：缺少 Display | 泛型中输出 {x} 却没有约束 | 补上适当的 Display 约束 |
| 实参不满足约束 | 例如 Vec&lt;u8&gt; 没有 Display | 换用适当显示方式或本地包装类型 |

| 诊断 | 常见原因 | 处理 |
| --- | --- | --- |
| E0308：返回闭包类型不同 | impl Fn 的不同分支产生不同具体<br>类型 | 统一具体类型，或选择合适的 trait 对象 |
| E0525 | 消耗捕获值的闭包不能满足 Fn | 按调用语义调整约束或捕获方式 |
| E0373 | 闭包可能比所借用局部值活得更久 | 转交拥有型捕获；move 不会延长原有短期引用 |

## 5.4 关联类型与关联常量

关联类型是 trait 里的“类型占位符”，由实现者决定它具体是什么。判断标准只有一条：对于一个实现类型，这个类型只有一种合理取值，就用关联类型；可能有多种，就用泛型参数。5.8 节的 Entity::Id 就是关联类型的典型用法。

### 5.4.1【入门】最熟悉的关联类型：Iterator::Item

标准库 Iterator 的核心形状如下。为避免和后面的标准 Iterator 示例冲突，这份教学摘录命名为IteratorSketch：

```rust
pub trait IteratorSketch {
    // 关联类型：迭代器产出什么
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
    // ……另有七十多个默认方法：map、filter、collect 等
}
```

自己实现一个：按页码依次产出页码，直到总页数。

```rust
pub struct PageNumbers {
    current: u32,
    total: u32,
}
 
impl Iterator for PageNumbers {
    // 实现者决定：产出 u32
    type Item = u32;
 
    fn next(&mut self) -> Option<u32> {
        if self.current >= self.total {
            return None;
        }
        self.current += 1;
        Some(self.current)
    }
}
 
let pages: Vec<u32> = PageNumbers { current: 0, total: 3 }.collect();
assert_eq!(pages, vec![1, 2, 3]);
```

只实现了 next 一个方法，collect 、map 、filter 、sum 等七十多个默认方法就全部可用。这就是5.1.2 默认方法的威力。

### 5.4.2【入门】关联常量

Trait 里还可以声明常量，每个实现者给出自己的值：

```rust
pub trait Entity {
    /// 实体名称，用于错误信息、日志、表名推断
    const NAME: &'static str;
}
 
struct Product;
impl Entity for Product {
    const NAME: &'static str = "商品";
}
 
fn describe<E: Entity>() -> String {
    // 通过类型访问，不需要实例
    format!("实体：{}", E::NAME)
}
```

关联常量和关联函数一样，通过类型名访问：E::NAME 、Product::NAME 。

### 5.4.3【进阶】关联类型 vs 泛型参数

同样是“trait 里有个待定类型”，为什么 Iterator 用关联类型，而 From&lt;T&gt; 用泛型参数？

| 维度 | 关联类型 | trait 泛型参数 |
| --- | --- | --- |
| 由谁决定 | 由给定的 trait 实现决定 | 由所选择的 trait 实例参数决定 |

| 维度 | 关联类型 | trait 泛型参数 |
| --- | --- | --- |
| 一个实现类型的组合 | 同一 trait 实例不能重复给出不同关<br>联类型 | 可为不同参数提供多个不重叠实现 |
| 例子 | Iterator::Item | From&lt;&amp;str&gt;、From&lt;char&gt; |
| 使用约束 | 可写 I::Item: Display | 可写 T: From&lt;u8&gt; |

对关联类型加约束的写法：

```rust
use std::fmt::Display;
 
// 要求迭代器产出的元素能显示
fn print_all<I>(iter: I)
where
    I: Iterator,
    I::Item: Display,
{
    for x in iter {
        println!("{x}");
    }
}
 
// 简写：直接在约束里指定 Item 必须是什么类型
fn sum_cents(iter: impl Iterator<Item = u64>) -> u64 {
    iter.sum()
}
```

### 5.4.4【进阶】关联类型上的约束

定义 trait 时可以要求关联类型本身满足某些 trait。5.8 节就会这样写：

```rust
use std::fmt::Display;
use std::hash::Hash;
 
pub trait Entity {
    /// 主键类型：必须能克隆、比较、排序、显示
    type Id: Clone + Ord + Display;
    const NAME: &'static str;
    fn id(&self) -> Self::Id;
}
```

这样，任何使用 E: Entity 的泛型代码都能直接 id.clone() 、把 id 当 BTreeMap 的键、用{id}打印，不用每次重复写约束。这些约束由实现者负责满足：如果某个实体的 Id 类型不能排序，impl Entity 时就会报错。

### 5.4.5【精通】泛型关联类型（GAT）与后端框架

Rust 1.65 稳定了泛型关联类型（GAT）：关联类型本身也可以带泛型参数或生命周期参数。最典型的需求是“借出迭代器”：

```rust
pub trait Store {
    // 产出的元素借用自 &self，需要一个生命周期参数
    type Iter<'a>: Iterator<Item = &'a str>
    where
        Self: 'a;
 
    fn names<'a>(&'a self) -> Self::Iter<'a>;
}
 
struct VecStore(Vec<String>);
 
impl Store for VecStore {
    type Iter<'a> = std::iter::Map<std::slice::Iter<'a, String>, fn(&String) -> &str>;
 
    fn names<'a>(&'a self) -> Self::Iter<'a> {
        self.0.iter().map(String::as_str as fn(&String) -> &str)
    }
}
```

业务代码很少需要自己写 GAT，但你会在 SQLx、Tower 等库的签名里碰到：例如 Tower 的Servicetrait 有 type Response 、type Error 、type Future 三个关联类型，Axum 的每个中间件都要实现它，后面的网关章节会亲手写一个。读懂“关联类型 + 约束”是读懂这些框架文档的前提。

常见编译错误与解读

| 诊断 | 常见原因 | 处理 |
| --- | --- | --- |
| E0191 | trait 对象没有指定必要关联类型 | 如 Box&lt;dyn Iterator&lt;Item = u32&gt;&gt; |
| E0220 | 关联类型名拼错或约束不匹配 | 核对实际 trait |
| E0277 | I::Item 不满足操作要求 | 增加相应关联类型约束 |
| E0119 | 同一类型存在重叠实现 | 使用不同包装类型或重新设计 trait 参数 |

| 诊断 | 常见原因 | 处理 |
| --- | --- | --- |
| E0046 | 实现漏掉没有默认值的关联常量 | 补齐实现，或在 trait 中定义合理默认值 |

## 5.5 Trait 对象与动态分发

dyn Trait 表示“某个实现了 Trait 的类型，具体是谁要到运行时才知道”。它让你把不同类型放进同一个集合，或者在运行时根据配置选择实现。代价是一次间接调用，并且要通过指针（&amp; 、Box 、Arc）使用。

### 5.5.1【入门】为什么需要 dyn

需求：RustMall 根据配置同时启用多个通知渠道，下单成功后逐个发送。用泛型写不出来：Vec&lt;T&gt; 里所有元素必须是同一种类型，而短信和邮件是两种类型。

```text
let channels: Vec<Box<dyn Notifier>> = vec![
    Box::new(SmsNotifier { sign: "【RustMall】".into() }),
    Box::new(EmailNotifier { from: "noreply@rustmall.dev".into() }),
];
 
for ch in &channels {
    if let Err(e) = ch.send("13800000000", "下单成功") {
        eprintln!("{} 渠道发送失败：{e}", ch.channel());
    }
}
```

逐项解读：

dyn Notifier 本身大小不确定（可能是短信结构体，也可能是邮件结构体），所以不能直接放进 Vec，要包在 Box 里。Box&lt;dyn Notifier&gt; 大小固定：两个指针。

Box::new(SmsNotifier { .. }) 的类型本来是 Box&lt;SmsNotifier&gt; ，放进标注了 Vec&lt;Box&lt;dyn Notifier&gt;&gt; 的位置时，编译器自动转换成 Box&lt;dyn Notifier&gt; 。这叫非固定大小强制转换（unsized coercion）。

调用 ch.send(...) 时，程序在运行时查表决定调用 SmsNotifier::send 还是 EmailNotifier::send 。

### 5.5.2【入门】三种常用的 trait 对象指针

| 写法 | 所有权 | 用途 |
| --- | --- | --- |
| &amp;dyn Trait | 借用 | 函数参数 |
| Box&lt;dyn Trait&gt; | 拥有一个动态类型值 | 异构集合、字段与返回值 |
| Arc&lt;dyn Trait + Send +<br>Sync&gt; | 共享所有权，并声明相应线程约束 | 可跨线程共享的服务组件；可变访问仍要单独设<br>计 |

例如后续 Axum 状态可以共享通知组件：

```rust
use std::sync::Arc;
 
#[derive(Clone)]
pub struct AppState {
    pub notifier: Arc<dyn Notifier + Send + Sync>,
}
```

+ Send + Sync 是因为 Axum 会在多个线程上同时处理请求，状态必须能跨线程共享（4.4.6 讲过这两个 trait）。

### 5.5.3【进阶】vtable：动态分发是怎么实现的

&amp;dyn Notifier 是一个胖指针，由两部分组成：

1. 数据指针：指向具体的 SmsNotifier 实例。

2. vtable 指针：指向一张编译期生成的函数表，表里存着 SmsNotifier 对 send 、channel 、send\_batch 的实现地址，以及类型的大小、对齐方式和 drop 函数。

调用 ch.send(...) 被编译成：从 vtable 取出 send 的地址，再间接调用它。和 5.3 节的静态分发相比，多了一次内存读取，而且通常不能直接内联；具体实现可被优化器去虚拟化。

```rust
use std::mem::size_of;
 
// 普通引用：一个指针（64 位系统）
assert_eq!(size_of::<&SmsNotifier>(), 8);
 
// 胖指针：两个指针
assert_eq!(size_of::<&dyn Notifier>(), 16);
assert_eq!(size_of::<Box<dyn Notifier>>(), 16);
```

### 5.5.4【进阶】dyn 兼容规则（原“对象安全”）

不是每个 trait 都能写成 dyn Trait 。只有满足下面规则的 trait 才是 dyn 兼容（dyn-compatible，旧称 object safe）的：

| 检查点 | 常见不兼容情形 | 说明 |
| --- | --- | --- |
| trait 自身 | 要求 Self: Sized | trait 对象是不定大小类型 |
| 关联项 | 有关联常量或泛型关联类型 | 会影响 dyn 兼容性 |
| 可动态调用的方法 | 有类型泛型参数 | 不能为任意类型参数预存所有实例 |
| Self 的使用 | 在接收者以外使用 Self，如返回<br>Self | 动态调用时具体 Self 被隐藏 |
| 接收者与返回类型 | 无可动态分发的接收者，或返回不<br>透明类型 | async fn、返回位置 impl Trait 等需另行设计 |
| 排除部分方法 | 为相应方法加 where Self: Sized | 可让这些方法仅供具体 Sized 实现使用；仍须检<br>查 trait 其他条件 |

对部分不需要动态调用的方法，可以加 where Self: Sized，将其排除在动态调用接口之外。下例演示这种设计，trait 的其他部分仍须满足兼容规则：

```rust
pub trait Notifier {
    fn send(&self, to: &str, content: &str) -> Result<String, String>;
 
    // 泛型方法：加上 where Self: Sized，不影响 dyn Notifier
    fn send_display<T: std::fmt::Display>(&self, to: &str, content: T) -> Result<String, 
       String>
    where
        Self: Sized,
    {
        self.send(to, &content.to_string())
    }
}
```

Clone 就不是 dyn 兼容的（clone 返回 Self ），所以 Box&lt;dyn Notifier&gt; 不能 clone 。需要共享时用 Arc&lt;dyn Notifier&gt; ，克隆 Arc 只是增加引用计数。

### 5.5.5【精通】泛型还是 dyn：决策表

| 维度 | 泛型静态分发 | dyn 动态分发 |
| --- | --- | --- |
| 调用 | 通常能确定实现并进行内联优化 | 语义上经虚表间接调用；优化器有时可以去虚拟<br>化 |
| 编译与体积 | 实例化较多时可能增加成本 | 减少某些调用方的实例化，但不保证产物一定更<br>小 |
| 异构集合 | 可用枚举等统一表示 | 通过指针包装不同实现 |
| 运行时切换 | 可在分支或枚举中选择 | 可替换相同 trait 对象类型的实现 |
| trait 要求 | 满足所用约束 | 还必须 dyn 兼容 |
| 签名 | 类型参数可能向上层传播 | 隐藏具体实现类型 |

1. 热路径和小型可组合操作可优先考虑泛型，再按测量结果判断收益。

2. 依赖注入用 Arc&lt;dyn Trait&gt; ：仓储、通知、支付网关等“组件”。这些调用本身涉及网络 IO，耗时以毫秒计，vtable 的几纳秒开销可以忽略，而签名简单、编译快的好处很实在。

3. 实现数量固定且已知时考虑 enum：例如只会有“短信”和“邮件”两种渠道，enum Channel{Sms(..), Email(..) } 加 match 既是静态分发，又支持放进同一个集合。

还有一个和后面章节相关的精通点：trait 里的 async fn 。Rust 1.75 起 trait 可以直接写 async fn，但这样的 trait 不是 dyn 兼容的（返回的 Future 类型各不相同）。需要 Arc&lt;dyn Repository&gt; 时，常见做法是使用 async-trait crate，或手动返回 Pin&lt;Box&lt;dyn Future + Send&gt;&gt; 。后面的数据库章节会把 5.8 节的同步仓储改造成异步版，届时详细讲解这两种方案。

常见编译错误与解读

| 诊断 | 常见原因 | 处理 |
| --- | --- | --- |
| E0038 | trait 不符合 dyn 兼容条件 | 按规则排除具体方法或重新设计 |
| E0277：大小未知 | 试图直接保存 dyn Trait 值 | 使用 &amp;、Box、Arc 等适当指针 |
| Send / Sync 不满足 | 跨线程使用了不满足要求的对象 | 接口和实际实现都须满足相应线程约束 |
| Box&lt;dyn Trait&gt; 不能 clone | 没有定义动态克隆协议 | 可设计 boxed\_clone；只需共享时考虑 Arc |
| 省略 dyn | 旧式裸 trait 对象语法 | 本书 Edition 2024 使用显式 dyn |

## 5.6 孤儿规则、一揽子实现与扩展 trait

本节回答三个实际问题：能不能为别人的类型实现别人的 trait（不能，这是孤儿规则）；怎样为“所有满足某条件的类型”一次性实现 trait（一揽子实现）；怎样给标准库类型“加方法”（扩展 trait）。

### 5.6.1【入门】孤儿规则

规则：impl Trait for Type 时，Trait 和 Type 至少有一个是在当前 crate 里定义的。

| 实现示例 | 是否允许 | 原因 |
| --- | --- | --- |
| impl Notifier for String | 允许 | Notifier 是本 crate 的 trait |
| impl Display for Product | 允许 | Product 是本 crate 的类型 |
| impl Display for<br>Vec&lt;Product&gt; | 通常不允许 | Display 与 Vec 都是外部定义，Vec 不是使内部<br>类型本地化的基础包装 |
| impl serde::Serialize for<br>chrono::DateTime&lt;Utc&gt; | 不允许由第三方 crate 任意添加 | trait 与实现类型都在其他 crate |

这些规则帮助保持实现的一致性（coherence），防止依赖组合引入无法选择的重复实现。

### 5.6.2【入门】绕过孤儿规则：newtype

第 3 章学的 newtype 正好用在这里：把外部类型包一层，新类型就是你的了。

```rust
use std::fmt;
 
/// 商品名称列表，用于日志打印
pub struct NameList(pub Vec<String>);
 
impl fmt::Display for NameList {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "[{}]", self.0.join(", "))
    }
}
 
let names = NameList(vec!["键盘".into(), "鼠标".into()]);
assert_eq!(names.to_string(), "[键盘, 鼠标]");
```

newtype 的代价是失去原类型的方法，names.len() 不能直接用。如果需要，可以实现 5.7 节的 Deref，但要谨慎，见 5.7.5。

### 5.6.3【进阶】一揽子实现（blanket impl）

可以为“所有满足某个约束的类型”一次性实现 trait：

```rust
use std::fmt::Display;
 
pub trait Loggable {
    fn log_line(&self) -> String;
}
 
// 所有能 Display 的类型，自动获得 Loggable
impl<T: Display> Loggable for T {
    fn log_line(&self) -> String {
        format!("[rustmall] {self}")
    }
}
 
assert_eq!(42.log_line(), "[rustmall] 42");
assert_eq!("下单".log_line(), "[rustmall] 下单");
```

标准库里到处是一揽子实现：

| 一揽子实现 | 作用 |
| --- | --- |
| Display → ToString | 可对实现 Display 的值调用 to\_string |
| From&lt;T&gt; → Into&lt;U&gt; | 实现合适的 From 后自动获得对应 Into |
| From&lt;T&gt; for T | 同类型转换有标准库支持 |

| 一揽子实现 | 作用 |
| --- | --- |
| Iterator → IntoIterator | 迭代器自身可以进入 for 循环 |
| 符合约束的 Error →<br>anyhow::Error | 应用边界可汇总 Error + Send + Sync + 'static 的具体错误 |

?Sized 用于放宽泛型参数通常隐含的 Sized 约束，使 str、dyn Trait 等不定大小类型能在合适的借用或指针位置参与泛型。

### 5.6.4【进阶】扩展 trait：给外部类型“加方法”

想给标准库的 str 加一个 .masked() 方法，用来在日志里打码手机号。不能直接给 str 加固有方法，但可以定义自己的 trait 并为 str 实现（trait 是自己的，孤儿规则允许）：

```rust
/// 字符串扩展方法
pub trait StrExt {
    /// 只保留前 3 位和后 4 位，中间用 * 替换
    fn masked(&self) -> String;
}
 
impl StrExt for str {
    fn masked(&self) -> String {
        let chars: Vec<char> = self.chars().collect();
        if chars.len() <= 7 {
            return "*".repeat(chars.len());
        }
        let head: String = chars[..3].iter().collect();
        let tail: String = chars[chars.len() - 4..].iter().collect();
        format!("{head}{}{tail}", "*".repeat(chars.len() - 7))
    }
}
 
// 引入 trait 才能调用方法；as _ 表示只引入方法、不占用名字
use StrExt as _;
assert_eq!("13812345678".masked(), "138****5678");
```

生态里大量使用这个模式：anyhow::Context 给 Result 加 .context() 、futures::StreamExt 给流加 .next() 、tower::ServiceExt 给服务加 .oneshot() 。看到 XxxExt 这种名字，就知道它是扩展 trait，用之前要 use 。

### 5.6.5【精通】一致性的细节：重叠与本地类型

一揽子实现有一个重要副作用：它可能和你后续的具体实现冲突。上面写了 impl&lt;T:Display&gt;Loggable for T 之后，如果 Product 实现了 Display ，再写 impl Loggable for Product 就会报 E0119，因为同一个类型有了两个实现。Product 是本地类型，它有没有实现 Display 完全由你的 crate 决定，所以没实现时编译器允许这个具体实现。但对外部类型就不同了：Vec&lt;u8&gt; 现在没有实现 Display ，标准库将来却可能加上，所以 impl Loggable for Vec&lt;u8&gt; 会被拒绝，编译器会提示“upstream crates may add a new impl”。

孤儿规则的完整版本比 5.6.1 的简化说法稍宽：对 impl&lt;T&gt; ForeignTrait&lt;LocalType&gt;forForeignTyp e&lt;T&gt; 这类写法，只要类型参数列表里按顺序出现的第一个本地类型之前没有未覆盖的类型参数，就是允许的。日常开发中记住两条就够了：

1. impl From&lt;MyType&gt; for String 可以：From&lt;MyType&gt; 里有本地类型。这就是第 4 章 implFrom&lt;ParseIntError&gt; for OrderInputError 能写、而反方向 impl From&lt;OrderInputError&gt;for ParseIntError 也能写的原因。

2. impl&lt;T&gt; ForeignTrait for T 在你的 crate 里永远不行：它覆盖了所有外部类型。

标准库还有一个特殊豁免：Box&lt;T&gt; 、Pin&lt;T&gt; 被视为“基础类型”（fundamental），implForeignTrait for Box&lt;MyType&gt; 是允许的。

常见编译错误与解读

| 诊断 | 常见原因 | 处理 |
| --- | --- | --- |
| E0117 | 为外部类型实现外部 trait，不满足<br>本地类型规则 | 考虑 newtype 或本地扩展 trait |
| E0119 | 一揽子实现与具体实现重叠 | 删除重叠或重设实现范围 |
| E0210 | 外部 trait 实现中的类型参数不满足<br>覆盖要求 | 按本地类型与参数顺序规则重新设计 |

| 诊断 | 常见原因 | 处理 |
| --- | --- | --- |
| E0599：没有 masked | 扩展 trait 不在作用域 | 导入相应 StrExt，可按需用 as \_ |

## 5.7 后端常用标准 trait

标准库定义了一批“约定俗成”的 trait，整个生态都按它们协作：实现了 FromStr ，parse()就能用；实现了 From ，? 和 .into() 就能用；实现了 Default ，框架就能自动构造配置。本节逐个讲清每个trait 的用途、实现方法和后端里的典型用法。第 3 章已讲过的 Debug 、Clone 、PartialEq 、Hash 等可派生 trait 不再重复。

### 5.7.1【入门】From 与 Into：无损转换

```rust
pub struct Cents(pub i64);
 
impl From<u32> for Cents {
    fn from(yuan: u32) -> Self {
        Cents(i64::from(yuan) * 100)
    }
}
 
// 调用 From
let a = Cents::from(12);
 
// Into 由 5.6.3 的一揽子实现自动获得，需要标注目标类型
let b: Cents = 12_u32.into();
```

规则：

1. 只实现 From ，不要实现 Into 。Into 会通过一揽子实现自动得到。

2. From 必须是不会失败、不丢信息的转换。可能失败的用 TryFrom 。

3. 函数参数想“什么都能收”时用 impl Into&lt;String&gt; ：fn new(name: impl Into&lt;String&gt;)，调用方传 &amp;str 或 String 都行，内部 name.into() 得到 String 。

### 5.7.2【入门】TryFrom 与 FromStr：可能失败的转换

```rust
use std::str::FromStr;
 
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SortOrder { Asc, Desc }
 
// FromStr：从字符串解析，之后就能用 "asc".parse::<SortOrder>()
impl FromStr for SortOrder {
    // 关联类型：失败时的错误类型
    type Err = String;
 
    fn from_str(s: &str) -> Result<Self, Self::Err> {
        match s.to_ascii_lowercase().as_str() {
            "asc" => Ok(SortOrder::Asc),
            "desc" => Ok(SortOrder::Desc),
            other => Err(format!("未知排序方式 {other:?}")),
        }
    }
}
 
// TryFrom：从其他类型转换
impl TryFrom<i32> for SortOrder {
    type Error = String;
 
    fn try_from(v: i32) -> Result<Self, Self::Error> {
        match v {
            1 => Ok(SortOrder::Asc),
            -1 => Ok(SortOrder::Desc),
            _ => Err(format!("排序值只能是 1 或 -1，收到 {v}")),
        }
    }
}
 
let o: SortOrder = "DESC".parse()?;
let p = SortOrder::try_from(1)?;
 
// TryInto 同样自动获得
let q: SortOrder = (-1).try_into()?;
```

第 3 章的 Quantity （“只能通过校验创建”）正适合实现 TryFrom&lt;u32&gt; 。后面的 Axum 章节中，查询参数里的枚举会通过 serde 反序列化，原理相同。

### 5.7.3【入门】Default：默认值

```rust
#[derive(Debug, Clone)]
pub struct ListQuery {
    pub page: u32,
    pub page_size: u32,
    pub keyword: Option<String>,
}
 
impl Default for ListQuery {
    fn default() -> Self {
        Self { page: 1, page_size: 20, keyword: None }
    }
}
 
// 结合第 3 章的结构体更新语法：只改需要的字段
let q = ListQuery { keyword: Some("键盘".into()), ..Default::default() };
```

字段都能取“零值”（0、空字符串、None ）时直接 #\[derive(Default)\] ；有业务默认值（如每页 20条）时手写。枚举也可以派生，用 #\[default\] 标出默认变体。

### 5.7.4【进阶】AsRef 与 Borrow：廉价的引用转换

AsRef&lt;T&gt; 表示“可以廉价地借用为 &amp;T ”。最常见的用法是让函数同时接受多种参数：

```rust
use std::path::Path;
 
// &str、String、PathBuf、&Path 都能传进来
fn load_config(path: impl AsRef<Path>) -> std::io::Result<String> {
    std::fs::read_to_string(path.as_ref())
}
 
load_config("config/dev.toml")?;
load_config(String::from("config/prod.toml"))?;
```

Borrow&lt;T&gt; 长得很像，但多一条语义要求：借出的 &amp;T 的 Hash 、Eq 、Ord 必须和原值一致。HashMap&lt;String, V&gt; 能用 &amp;str 查找，就是因为 String: Borrow&lt;str&gt; 。写自己的函数参数时用 AsRef ；Borrow 主要给集合类型用。

### 5.7.5【进阶】Deref：智能指针的 \* 与自动解引用

Deref 决定 \*x 的结果，以及方法调用时的自动解引用：String 实现了 Deref&lt;Target = str&gt;，所以 String 能直接调用所有 str 的方法；Box&lt;T&gt; 、Arc&lt;T&gt; 实现了 Deref&lt;Target = T&gt; ，所以 arc.method() 能直接调到内部对象。

```rust
use std::ops::Deref;
 
pub struct Sku(String);
 
impl Deref for Sku {
    type Target = str;
    fn deref(&self) -> &str {
        &self.0
    }
}
let s = Sku("KB-001".into());
 
// 自动解引用到 str 的方法
assert!(s.starts_with("KB"));
assert_eq!(s.len(), 6);
```

Deref 会让隐式转换和方法解析成为公共 API 的一部分，适合具有明确指针语义的类型。不可变 Deref本身并不会让调用方修改私有字段，但会扩大可用方法集合；DerefMut 等可变访问还可能绕过不变量保护。对 Quantity 这类受约束的值，通常优先提供明确的 get()；对字符串包装可以按语义提供as\_str()。

### 5.7.6【进阶】Iterator 与 IntoIterator

5.4.1 已经实现过 Iterator 。IntoIterator 决定一个类型能不能用在 for 循环里。为集合类型的三种形态分别实现它是惯例：

| 写法 | IntoIterator 实现对象 | 元素 |
| --- | --- | --- |
| for x in v | Vec&lt;T&gt; | T，消耗该 Vec |
| for x in &amp;v | &amp;Vec&lt;T&gt; | &amp;T |
| for x in &amp;mut v | &amp;mut Vec&lt;T&gt; | &amp;mut T |

为 Page&lt;T&gt; 增加共享借用遍历：

```rust
impl<'a, T> IntoIterator for &'a Page<T> {
    type Item = &'a T;
    type IntoIter = std::slice::Iter<'a, T>;
 
    fn into_iter(self) -> Self::IntoIter {
        self.items.iter()
    }
}
 
// 现在可以直接 for item in &page { ... }
```

### 5.7.7【精通】标准 trait 速查与实现建议

| trait | 作用 | 典型用途 | 通常怎样提供 |
| --- | --- | --- | --- |
| Display | 面向使用者的格式 | 错误、ID、金额 | 手写或由宏辅助生成 |
| From&lt;T&gt; | 约定为不失败且合理保留信<br>息的转换 | 错误包装、值转换 | 实现 From 后复用 Into |
| TryFrom&lt;T&gt; | 可失败转换 | 带校验的值 | 手写或宏辅助 |
| FromStr | 字符串解析 | 枚举、配置值 | 手写或宏辅助 |
| Default | 默认值 | 配置与查询参数 | 可派生，也可手写 |
| AsRef&lt;T&gt; | 廉价借用 | 灵活的参数 | 按 API 语义实现 |
| Deref | 类似指针的借用访问 | 智能指针和适合隐式解<br>引用的包装 | 谨慎手写 |
| IntoIterator | 进入 for 循环 | 集合与包装 | 按所有权形态实现 |

| trait | 作用 | 实现注意 |
| --- | --- | --- |
| PartialOrd / Ord | 部分序或全序比较 | 选择符合业务含义的排序，可派生或手写 |
| Send / Sync | 跨线程转移与共享的约束 | 通常自动推导；手动实现涉及 unsafe 契约，不<br>能随意添加 |

这些 trait 有语义契约：相等与哈希必须一致，排序应满足所声明的关系；如果 Display 的输出设计为可解析，则应验证与 FromStr 的往返关系。From 不应通过 panic 表达可预期的失败。Clippy 只能覆盖部分问题。

常见编译错误与解读

| 诊断 | 常见原因 | 处理 |
| --- | --- | --- |
| E0282 | into 的目标类型不明确 | 添加类型约束 |
| FromStr 约束不满足 | 目标类型没有解析实现 | 实现 FromStr |
| E0119 | 手写 Into 与已有 From 产生的实现<br>冲突 | 通常保留 From，删除重复 Into |
| Default 约束不满足 | 使用默认值却未提供对应实现 | 派生或手写合理默认值 |
| should\_implement\_trait | 固有方法容易与标准 trait 混淆 | 核对是否应实现对应 trait |

文件：rustmall/common/src/error.rs （本节修改后的完整内容）

```rust
//! RustMall 领域层统一错误类型。
//!
//! - [`ValidationError`]：输入校验失败的具体原因。
//! - [`DomainError`]：领域层对外暴露的唯一错误类型，所有领域函数都返回 [`DomainResult`]。
//! - [`ErrorKind`]：与传输协议无关的错误分类，HTTP 层和 gRPC 层据此映射状态码。

use thiserror::Error;

use crate::order::OrderError;

/// 输入校验失败的具体原因。
///
/// 字段名用 `&'static str`：字段名都是代码里写死的字面量，
/// 这样既不分配内存，又满足 `'static` 约束（见 4.4.6）。
#[derive(Debug, Clone, PartialEq, Eq, Error)]
pub enum ValidationError {
    #[error("字段 `{field}` 不能为空")]
    Empty { field: &'static str },

    #[error("字段 `{field}` 长度应为 {min}〜{max} 个字符，实际为 {actual} 个")]
    Length {
        field: &'static str,
        min: usize,
        max: usize,
        actual: usize,
    },
    #[error("字段 `{field}` 的值 {value} 超出范围 {min}〜{max}")]
    OutOfRange {
        field: &'static str,
        value: i64,
        min: i64,
        max: i64,
    },

    #[error("字段 `{field}` 格式不正确：{reason}")]
    Format { field: &'static str, reason: String },
}

/// 与传输协议无关的错误分类。
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum ErrorKind {
    /// 调用方传入的数据不合法。
    InvalidInput,
    /// 要操作的对象不存在。
    NotFound,
    /// 请求本身合法，但与当前业务状态冲突。
    Conflict,
    /// 服务端自身的问题。
    Internal,
}

impl ErrorKind {
    /// 稳定的机器可读错误码，会出现在 API 响应体里，发布后不要修改。
    pub const fn code(self) -> &'static str {
        match self {
            ErrorKind::InvalidInput => "INVALID_INPUT",
            ErrorKind::NotFound => "NOT_FOUND",
            ErrorKind::Conflict => "CONFLICT",
            ErrorKind::Internal => "INTERNAL",
        }
    }
}

/// 领域层统一错误。
#[derive(Debug, Error)]
pub enum DomainError {
    /// 输入校验失败。本层没有新信息，透明转发。
    #[error(transparent)]
    Validation(#[from] ValidationError),

    /// 订单状态机拒绝了某个操作。
    #[error(transparent)]
    Order(#[from] OrderError),

    #[error("{entity} {id} 不存在")]
    NotFound { entity: &'static str, id: String },

    #[error("{entity} {id} 已存在")]
    AlreadyExists { entity: &'static str, id: String },

    #[error("商品 {product_id} 库存不足：需要 {requested}，剩余 {available}")]
    InsufficientStock {
        product_id: String,
        requested: u32,
        available: u32,
    },

    /// 不应该发生、但又不值得 panic 的情况。对外只显示“内部错误”，详情进日志。
    #[error("内部错误：{0}")]
    Internal(String),
}

impl DomainError {
    /// 构造“不存在”错误的便捷函数，`id` 接受任何能显示的类型。
    pub fn not_found(entity: &'static str, id: impl std::fmt::Display) -> Self {
        DomainError::NotFound {
            entity,
            id: id.to_string(),
        }
    }

    /// 返回错误分类，传输层据此决定状态码。
    pub fn kind(&self) -> ErrorKind {
        match self {
            DomainError::Validation(_) => ErrorKind::InvalidInput,
            DomainError::Order(OrderError::InvalidInput(_) | OrderError::AmountOverflow) => {
                ErrorKind::InvalidInput
            }
            DomainError::Order(OrderError::IllegalTransition { .. })
            | DomainError::InsufficientStock { .. } => ErrorKind::Conflict,
            DomainError::AlreadyExists { .. } => ErrorKind::Conflict,
            DomainError::NotFound { .. } => ErrorKind::NotFound,
            DomainError::Internal(_) => ErrorKind::Internal,
        }
    }
}
```

```rust
//! 仓储（Repository）抽象：领域层通过它读写实体，不关心数据存放在哪里。
//!
//! 本章提供同步接口和内存实现，供单元测试和早期开发使用。
//! 接入 PostgreSQL 时，接口会改为异步，并新增数据库实现。

use std::collections::BTreeMap;
use std::collections::btree_map::Entry;
use std::fmt::Display;

use crate::error::{DomainError, DomainResult};

/// 可以被仓储存取的实体。
pub trait Entity: Clone {
    /// 主键类型：要能克隆、排序（作为有序集合的键）、显示（用于错误信息）。
    type Id: Clone + Ord + Display;

    /// 实体的中文名称，用于错误信息和日志。
    const NAME: &'static str;

    /// 返回主键。
    fn id(&self) -> Self::Id;
}

/// 实体仓储。
///
/// 读方法返回拥有所有权的实体（`E` 而不是 `&E`）：
/// 数据库实现无法返回指向自身内部的引用，接口要为所有实现留出余地。
pub trait Repository<E: Entity> {
    /// 新增实体；主键已存在时返回 [`DomainError::AlreadyExists`]。
    fn insert(&mut self, entity: E) -> DomainResult<()>;

    /// 按主键查询；不存在时返回 [`DomainError::NotFound`]。
    fn get(&self, id: &E::Id) -> DomainResult<E>;

    /// 整体替换已有实体；不存在时返回 [`DomainError::NotFound`]。
    fn update(&mut self, entity: E) -> DomainResult<()>;

    /// 删除并返回被删除的实体；不存在时返回 [`DomainError::NotFound`]。
    fn remove(&mut self, id: &E::Id) -> DomainResult<E>;

    /// 按主键升序分页列出实体。`offset` 超出范围时返回空列表。
    fn list(&self, offset: usize, limit: usize) -> Vec<E>;

    /// 实体总数。
    fn count(&self) -> usize;

    /// 主键是否存在。默认实现基于 `get`，具体实现可以覆盖成更高效的版本。
    fn contains(&self, id: &E::Id) -> bool {
        self.get(id).is_ok()
    }
}

/// 基于 `BTreeMap` 的内存仓储，按主键有序存放。
pub struct InMemoryRepository<E: Entity> {
    items: BTreeMap<E::Id, E>,
}
impl<E: Entity> InMemoryRepository<E> {
    /// 创建空仓储。
    pub fn new() -> Self {
        Self {
            items: BTreeMap::new(),
        }
    }
}

impl<E: Entity> Default for InMemoryRepository<E> {
    fn default() -> Self {
        Self::new()
    }
}

impl<E: Entity> Repository<E> for InMemoryRepository<E> {
    fn insert(&mut self, entity: E) -> DomainResult<()> {
        match self.items.entry(entity.id()) {
            Entry::Occupied(slot) => Err(DomainError::AlreadyExists {
                entity: E::NAME,
                id: slot.key().to_string(),
            }),
            Entry::Vacant(slot) => {
                slot.insert(entity);
                Ok(())
            }
        }
    }

    fn get(&self, id: &E::Id) -> DomainResult<E> {
        self.items
            .get(id)
            .cloned()
            .ok_or_else(|| DomainError::not_found(E::NAME, id))
    }

    fn update(&mut self, entity: E) -> DomainResult<()> {
        let id = entity.id();
        match self.items.get_mut(&id) {
            Some(slot) => {
                *slot = entity;
                Ok(())
            }
            None => Err(DomainError::not_found(E::NAME, id)),
        }
    }

    fn remove(&mut self, id: &E::Id) -> DomainResult<E> {
        self.items
            .remove(id)
            .ok_or_else(|| DomainError::not_found(E::NAME, id))
    }

    fn list(&self, offset: usize, limit: usize) -> Vec<E> {
        self.items
            .values()
            .skip(offset)
            .take(limit)
            .cloned()
            .collect()
    }

    fn count(&self) -> usize {
        self.items.len()
    }

    // 覆盖默认实现：直接查键，不必克隆实体
    fn contains(&self, id: &E::Id) -> bool {
        self.items.contains_key(id)
    }
}
```

逐段讲解：

pub trait Entity: Clone ：Clone 是父 trait（5.1.4）。因为读方法要返回拥有所有权的实体，内存实现只能克隆一份给调用方。

type Id: Clone + Ord + Display ：关联类型上的约束（5.4.4）。Ord 让它能作 BTreeMap 的键，Display 让错误信息能写出主键。

pub trait Repository&lt;E: Entity&gt; ：实体类型是泛型参数而不是关联类型。将来一个 PgStore 可以同时 impl Repository&lt;Product&gt; 和 impl Repository&lt;Order&gt; ，这是 5.4.3 表格中“一个类型实现多次”的情形。

contains 的默认实现与覆盖：本阶段内存读取只会遇到存在或不存在，因此可以用布尔值演示默认方法。若实现还可能遇到网络或数据库错误，get(...).is\_ok() 会吞掉故障，不能原样沿用。内存版用contains\_key 覆盖默认实现（5.1.2），避免无谓的克隆。

struct InMemoryRepository&lt;E: Entity&gt; 为什么在定义上写了约束：5.3.6 说过一般不在结构体定义上写约束，但这里字段类型用到了关联类型 E::Id ，不约束 E: Entity 就无法写出 E::Id ，所以这是必要的例外。

手写 Default 而不是派生：#\[derive(Default)\] 会生成 impl&lt;E: Entity + Default&gt; ，要求实体本身也实现 Default ，这是不必要的约束。手写版只要求 E: Entity 。同时满足了 clippy 的 new\_without\_default 规则。

entry API：insert 用 BTreeMap::entry 一次查找同时完成“判断是否存在”和“插入”，比先 contains\_key 再 insert 少一次查找，而且在本例中 &amp;mut self 已提供独占访问；数据库的并发正确性必须由数据库唯一约束、事务和具体写入语句保证，不能从这个内存例子直接推出。

DomainError::not\_found(E::NAME, id) ：id 的类型是 &amp;E::Id 。not\_found 接收 implDisplay ，而标准库为所有 &amp;T （T: Display ）实现了 Display ，所以引用可以直接传。

测试用的 Item ：测试不依赖 Product 的内部字段，这样以后修改商品模型时，仓储的测试不会被牵连。

最后一个测试：同一个仓储先通过泛型函数（静态分发）、再通过 &amp;mut dyn Repository&lt;Item&gt;和 Box&lt;dyn Repository&lt;Item&gt;&gt; （动态分发）使用。能编译通过，就证明了 Repository 是 dyn 兼容的，但这并不自动保证 Send、Sync，也不让 &amp;mut self 方法能通过普通 Arc 并发调用；共享写入与异步接口需要后续明确设计。

```rust
//! 商品领域模型。

use crate::ids::ProductId;
use crate::money;
use crate::quantity::Quantity;

/// 商品。
///
/// 所有字段私有：只能通过 [`Product::try_new`] 创建，只能通过业务方法修改，
/// 因此任何实例都满足以下不变量：
/// - 名称去除首尾空白后为 1〜100 个字符
/// - 价格（分）不为负
/// - 库存不为负
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Product {
    id: ProductId,
    name: String,
    price_cents: i64,
    stock: i32,
}

impl Product {
    /// 商品名最大字符数。
    pub const NAME_MAX_CHARS: usize = 100;

    /// 校验并创建商品。
    pub fn try_new(
        id: ProductId,
        name: &str,
        price_cents: i64,
        stock: i32,
    ) -> Result<Self, String> {
        let name = name.trim();
        let chars = name.chars().count();
        if chars == 0 || chars > Self::NAME_MAX_CHARS {
            return Err(format!("商品名长度需为 1〜{} 个字符", Self::NAME_MAX_CHARS));
        }
        if price_cents < 0 {
            return Err("价格不能为负数".to_string());
        }
        if stock < 0 {
            return Err("库存不能为负数".to_string());
        }
        Ok(Self {
            id,
            name: name.to_string(),
            price_cents,
            stock,
        })
    }

    // ---------- 只读访问（getter） ----------

    pub fn id(&self) -> ProductId {
        self.id
    }

    pub fn name(&self) -> &str {
        &self.name
    }

    pub fn price_cents(&self) -> i64 {
        self.price_cents
    }

    pub fn stock(&self) -> i32 {
        self.stock
    }

    /// 价格的“元”表示，例如 `"199.00"`。
    pub fn price_yuan(&self) -> String {
        money::format_yuan(self.price_cents)
    }
    pub fn in_stock(&self) -> bool {
        self.stock > 0
    }

    pub fn can_buy(&self, qty: Quantity) -> bool {
        self.stock >= qty.get()
    }
    // ---------- 业务操作 ----------

    /// 扣减库存。库存不足时返回错误，且**不修改**库存。
    pub fn deduct_stock(&mut self, qty: Quantity) -> Result<(), String> {
        if !self.can_buy(qty) {
            return Err(format!("库存不足：剩余 {}，需要 {}", self.stock, qty.get()));
        }
        self.stock -= qty.get();
        Ok(())
    }

    /// 补货，数量必须为正。
    pub fn restock(&mut self, qty: i32) -> Result<(), String> {
        if qty <= 0 {
            return Err("补货数量必须大于 0".to_string());
        }
        self.stock = self
            .stock
            .checked_add(qty)
            .ok_or_else(|| "库存数量溢出".to_string())?;
        Ok(())
    }

    /// 调整价格，不能为负。
    pub fn change_price(&mut self, price_cents: i64) -> Result<(), String> {
        if price_cents < 0 {
            return Err("价格不能为负数".to_string());
        }
        self.price_cents = price_cents;
        Ok(())
    }
}

impl crate::repository::Entity for Product {
    type Id = ProductId;
    const NAME: &'static str = "商品";

    fn id(&self) -> ProductId {
        // 调用 Product 的固有方法 id()。固有方法优先于同名的 trait 方法，所以这里不会递归。
        self.id()
    }
}
```

3. 通知系统：结合 5.1 和 5.5，写 struct NotifyHub { channels: Vec&lt;Arc&lt;dyn Notifier+Send+ Sync&gt;&gt; } ，提供 fn broadcast(&amp;self, to: &amp;str, content: &amp;str)-&gt;Vec&lt;Result&lt;String, String&gt;&gt; 。

4. 排序参数：为 5.7.2 的 SortOrder 实现 Display 和 Default （默认降序），并写往返测试。

5. 思考题：Repository::get 返回 DomainResult&lt;E&gt; 而不是 Option&lt;E&gt; 。比较两种设计：调用方想区分“不存在”和“数据库出错”时，哪种更方便？本章内存实现的 contains 可以确定地返回 bool；换成可能失败的数据库查询后，为什么通常应该改为 Result&lt;bool, E&gt;？

下一章预告第 6 章“集合、迭代器与闭包实战”将系统讲解 Vec 、HashMap 、BTreeMap 、VecDeque 等集合的内部结构与复杂度，迭代器适配器的完整清单与惰性求值原理，以及用迭代器重写常见业务逻辑（统计、分组、去重、Top-N）。项目部分会在 common 中实现购物车的金额计算与优惠规则。
