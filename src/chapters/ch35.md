# 第 35 章 实验支付：幂等决定与退款屏障

第34章建立独立用户与持久会话，后续服务可以取得经过验证的Identity。现在订单流程还缺一个参与者：一次付款尝试如何保存决定、抵抗重复调用，并在取消先到时挡住迟到付款？本章在同一commerce包中新增独立payments运行角色、支付数据库与有界HTTP客户端。

我们实现的是确定性支付模拟器：金额为1至500000分时决定paid，超过500000分且不超过100000000分时决定declined。它使用真实PostgreSQL、真实HTTP、事务与故障实验，不连接银行卡或第三方支付渠道，也不转移真实资金。

本章把当前收据与追加审计明细一起保存，区分“已付后退款”与“退款先到形成屏障”。学完应能解释同一业务身份如何重放、未知传输结果怎样恢复，以及为什么一次HTTP成功不能直接说明订单已经完成。

## 35.1 先把金额、身份与决定分开

### 35.1.1 【入门】金额单位一直是分

请求amount使用i64，单位为分。19900表示199元，不能写成199.00再交给服务猜单位。输入范围为1-100000000分，零金额领取和部分退款都不属于当前命令语义。

模拟通过阈值500000分即5000元；它是固定教学规则，不是余额、信用额度或渠道风控结果。相同身份保存第一次决定后，重试不重新判一次。

### 35.1.2 【入门】saga_id标记这次尝试

Charge包含saga_id、actor_id和amount。UUID是本次业务尝试的固定身份，后两项是不可变绑定。重复同一UUID却把19900改成1990，应返回身份冲突，不能认为调用方在修正价格。

actor_id由可信协调者从已认证身份取得，支付服务不信任公网请求自称的用户号。本章管理CLI用于受控实验；后续订单接口会把用户身份和保存的订单金额一起绑定到支付命令。

### 35.1.3 【进阶】网络重复与业务重复不同

一个请求可能提交成功但没有收到回复，也可能因为上游重试同时到达两份。我们允许网络多次交付，同一业务身份仍只建立一次初始决定；退款也只能形成一次状态变化和对应审计记录。

每次重试换新UUID，会变成另一笔合法意图，原收据保护不到它。UUID本身没有自动幂等能力，还需要数据库唯一键、绑定检查和事务。

### 35.1.4 【精通】这个账本记录什么

payments是当前业务收据，payment_effects保留初始决定、退款或屏障事实。它帮助实验核对“发生过哪些操作”，没有建立账户余额、借贷双方、清结算与复式记账规则。

后面接真实渠道时，还需渠道幂等号、签名、受理查询、异步通知与对账。当前本地事务不能代替外部资金系统的决定，客户端超时也不能被擅自记为declined。

## 35.2 先做纯状态实验，再连接数据库

### 35.2.1 【入门】三个业务状态

Paid表示本模拟器已接受付款；Declined表示已稳定拒绝；Refunded表示这次身份已经关闭，不能再进入Paid。Refunded既可能来自已付后退款，也可能来自退款先到的屏障，具体历史由审计明细区分。

传输超时不是第四个完成业务状态。它表达调用方暂时不知道事实，须保持原身份查询或重放，不能把未知改写成一种业务拒绝。

### 35.2.2 【入门】完整转移表

| 既有事实 | 到达动作 | 返回状态 | 本次新审计事实 |
| --- | --- | --- | --- |
| 无收据、金额不超过阈值 | Charge | Paid | paid |
| 无收据、金额超过阈值 | Charge | Declined | declined |
| 无收据 | Refund | Refunded | refund_barrier |
| Paid | Charge | Paid | 无 |
| Paid | Refund | Refunded | refunded |
| Declined | Charge或Refund | Declined | 无 |
| Refunded | Charge或Refund | Refunded | 无 |

所有行都先要求身份参数一致。状态表不是授权表，也不能用来跳过金额校验。

### 35.2.3 【进阶】为什么退款先到要留下事实

取消订单的退款请求先到，若服务因查不到付款而直接返回成功且不保存任何内容，迟到的Charge随后仍可创建Paid。协调者已经以为取消完成，付款却重新发生。

本章Refund先建立Refunded状态的持久屏障，协议字符串为refunded。之后同UUID的Charge只能读回Refunded。不能按“很久以前没有付款”自动删除这一身份，否则迟到重试会重新打开它。

### 35.2.4 【进阶】用两个纯测试核对规则

完整payments.rs中的initial与next只计算状态，不访问数据库。文件加入工程后先运行：
```bash
cargo +1.92.0 test --locked -p commerce --lib payments::tests
```

测试覆盖三个既有状态与两种动作，以及阈值两侧和退款先到。纯测试帮助确认规则，真实并发与持久化效果还要由后面的数据库、HTTP实验检查。

### 35.2.5 【精通】补偿是新的事实

已付款再退款，会保留paid和refunded两条审计事实，而不是把paid历史删除。退款先到则只保存refund_barrier，不能把它写成确实发生过付款再退款。

本章仅支持全额退款，金额须与原意图相同。部分退款需要独立refund_id与累计已退金额约束，不能通过把原amount改小实现。

取消还涉及库存释放和订单状态；单个Refunded响应不足以宣布整个订单已取消。协调者必须继续保存和推进其他参与者的恢复步骤。

## 35.3 创建独立支付库

### 35.3.1 【入门】新增迁移文件

新建services/commerce/migrations/payments/0001_payments.sql，完整内容如下：
```sql
CREATE TABLE payments (
    saga_id UUID PRIMARY KEY CHECK(saga_id <> '00000000-0000-0000-0000-000000000000'),
    actor_id BIGINT NOT NULL CHECK(actor_id > 0),
    amount BIGINT NOT NULL CHECK(amount BETWEEN 1 AND 100000000),
    state TEXT NOT NULL CHECK(state IN ('paid','declined','refunded')),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
-- Teaching audit entries, not a bank's double-entry ledger.
CREATE TABLE payment_effects (
    effect_id UUID PRIMARY KEY,
    saga_id UUID NOT NULL REFERENCES payments(saga_id),
    kind TEXT NOT NULL CHECK(kind IN ('paid','declined','refund_barrier','refunded')),
    amount BIGINT NOT NULL CHECK(amount BETWEEN 1 AND 100000000),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE(saga_id,kind)
);
```

payments以saga_id为主键，约束非nil UUID、正数actor、金额范围和三种状态。payment_effects用effect_id标识审计行，按saga_id引用收据，并限制同一身份同一kind只出现一次。

### 35.3.2 【进阶】唯一键和审计kind分别保护什么

收据主键阻止两个独立初始决定；审计唯一约束阻止同类事实重复追加。应用仍要锁收据、核对参数和按状态表执行，不能只依赖数据库报唯一键冲突来替代业务逻辑。

kind中的paid和declined描述初始决定，refund_barrier描述先到取消，refunded描述已付后的退款。审计中的amount始终保存这次身份绑定的正金额，不是可以直接相加的借贷余额。

### 35.3.3 【精通】审计表不自动防篡改

本章应用按追加方式写payment_effects，但本地实验管理员仍有较高数据库权限。表结构和UUID不能证明任何人都无法修改历史。

完整交付还需运行权限、审计留存、备份与对账。created_at与updated_at采用数据库事务时间，不应被当作跨进程绝对因果顺序；核对先后主要依据受保护的业务转移和事实类型。

### 35.4.2 【入门】新建完整源码

文件services/commerce/src/payments.rs：
```rust
use crate::runtime::*;
use axum::{
    Json, Router,
    extract::{Path, Request, State as ExtractState},
    http::StatusCode,
    middleware::{self, Next},
    response::Response,
    routing::{get, post},
};
use inventory::rpc::{SERVICE_TOKEN_HEADER, ServiceKey};
use serde::{Deserialize, Serialize};
use sqlx::{PgPool, Postgres, Transaction};
use std::time::Duration;
use uuid::Uuid;

#[derive(Debug, Clone, Copy, Serialize, Deserialize, PartialEq, Eq)]
#[serde(rename_all = "snake_case")]
pub enum State {
    Paid,
    Declined,
    Refunded,
}
impl State {
    fn stored(self) -> &'static str {
        match self {
            Self::Paid => "paid",
            Self::Declined => "declined",
            Self::Refunded => "refunded",
        }
    }
}
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Action {
    Charge,
    Refund,
}
#[derive(Debug, Serialize, Deserialize, Clone, PartialEq, Eq)]
#[serde(deny_unknown_fields)]
pub struct Charge {
    pub saga_id: Uuid,
    pub actor_id: i64,
    pub amount: i64,
}
impl Charge {
    pub fn valid(&self) -> bool {
        !self.saga_id.is_nil() && self.actor_id > 0 && (1..=100_000_000).contains(&self.amount)
    }
}
#[derive(Debug, Serialize, Deserialize, Clone, PartialEq, Eq)]
pub struct Payment {
    pub saga_id: Uuid,
    pub actor_id: i64,
    pub amount: i64,
    pub state: State,
}
#[derive(sqlx::FromRow)]
struct Row {
    saga_id: Uuid,
    actor_id: i64,
    amount: i64,
    state: String,
}
impl TryFrom<Row> for Payment {
    type Error = ApiError;
    fn try_from(row: Row) -> ApiResult<Self> {
        let state = match row.state.as_str() {
            "paid" => State::Paid,
            "declined" => State::Declined,
            "refunded" => State::Refunded,
            _ => {
                return Err(ApiError(
                    StatusCode::INTERNAL_SERVER_ERROR,
                    "invalid stored payment",
                ));
            }
        };
        let payment = Self {
            saga_id: row.saga_id,
            actor_id: row.actor_id,
            amount: row.amount,
            state,
        };
        if !(Charge {
            saga_id: payment.saga_id,
            actor_id: payment.actor_id,
            amount: payment.amount,
        })
        .valid()
        {
            return Err(ApiError(
                StatusCode::INTERNAL_SERVER_ERROR,
                "invalid stored payment",
            ));
        }
        Ok(payment)
    }
}
/// A deterministic simulation. This function has no channel or bank side effect.
pub fn initial(amount: i64, action: Action) -> State {
    if action == Action::Refund {
        State::Refunded
    } else if amount > 500_000 {
        State::Declined
    } else {
        State::Paid
    }
}
pub fn next(state: State, action: Action) -> State {
    if state == State::Paid && action == Action::Refund {
        State::Refunded
    } else {
        state
    }
}
async fn effect(tx: &mut Transaction<'_, Postgres>, c: &Charge, kind: &str) -> ApiResult<()> {
    sqlx::query("INSERT INTO payment_effects(effect_id,saga_id,kind,amount) VALUES($1,$2,$3,$4)")
        .bind(Uuid::new_v4())
        .bind(c.saga_id)
        .bind(kind)
        .bind(c.amount)
        .execute(&mut **tx)
        .await?;
    Ok(())
}
async fn inside(pool: &PgPool, c: &Charge, action: Action) -> ApiResult<Payment> {
    let mut tx = pool.begin().await?;
    sqlx::query("SET TRANSACTION ISOLATION LEVEL READ COMMITTED")
        .execute(&mut *tx)
        .await?;
    sqlx::query("SET LOCAL lock_timeout='400ms'")
        .execute(&mut *tx)
        .await?;
    sqlx::query("SET LOCAL statement_timeout='500ms'")
        .execute(&mut *tx)
        .await?;
    let first = initial(c.amount, action);
    let inserted = sqlx::query(
        "INSERT INTO payments(saga_id,actor_id,amount,state)
         VALUES($1,$2,$3,$4) ON CONFLICT DO NOTHING",
    )
    .bind(c.saga_id)
    .bind(c.actor_id)
    .bind(c.amount)
    .bind(first.stored())
    .execute(&mut *tx)
    .await?
    .rows_affected()
        == 1;
    let mut row: Payment = sqlx::query_as::<_, Row>(
        "SELECT saga_id,actor_id,amount,state FROM payments WHERE saga_id=$1 FOR UPDATE",
    )
    .bind(c.saga_id)
    .fetch_one(&mut *tx)
    .await?
    .try_into()?;
    if row.actor_id != c.actor_id || row.amount != c.amount {
        return Err(ApiError(StatusCode::CONFLICT, "payment identity conflict"));
    }
    if inserted {
        effect(
            &mut tx,
            c,
            if action == Action::Refund {
                "refund_barrier"
            } else {
                first.stored()
            },
        )
        .await?;
    }
    let state = next(row.state, action);
    if state != row.state {
        sqlx::query("UPDATE payments SET state=$2,updated_at=now() WHERE saga_id=$1")
            .bind(c.saga_id)
            .bind(state.stored())
            .execute(&mut *tx)
            .await?;
        effect(&mut tx, c, "refunded").await?;
        row.state = state;
    }
    tx.commit().await?;
    Ok(row)
}
pub async fn apply(pool: &PgPool, c: &Charge, action: Action) -> ApiResult<Payment> {
    if !c.valid() {
        return Err(invalid());
    }
    tokio::time::timeout(Duration::from_millis(700), inside(pool, c, action))
        .await
        .map_err(|_| ApiError(StatusCode::GATEWAY_TIMEOUT, "payment result may be unknown"))?
}
pub async fn find(pool: &PgPool, id: Uuid) -> ApiResult<Option<Payment>> {
    if id.is_nil() {
        return Err(invalid());
    }
    let row = tokio::time::timeout(
        Duration::from_millis(700),
        sqlx::query_as::<_, Row>(
            "SELECT saga_id,actor_id,amount,state FROM payments WHERE saga_id=$1",
        )
        .bind(id)
        .fetch_optional(pool),
    )
    .await
    .map_err(|_| {
        ApiError(
            StatusCode::GATEWAY_TIMEOUT,
            "payment query budget exhausted",
        )
    })??;
    row.map(Payment::try_from).transpose()
}

#[derive(Clone)]
pub struct Payments {
    pub pool: PgPool,
    pub key: ServiceKey,
}
async fn authorize(
    ExtractState(mut key): ExtractState<ServiceKey>,
    request: Request,
    next: Next,
) -> ApiResult<Response> {
    let token = bearer(request.headers())?;
    let mut internal = tonic::Request::new(());
    internal.metadata_mut().insert(
        SERVICE_TOKEN_HEADER,
        token.parse().map_err(|_| unauthorized())?,
    );
    tonic::service::Interceptor::call(&mut key, internal).map_err(|_| unauthorized())?;
    Ok(next.run(request).await)
}
pub fn router(s: Payments) -> Router {
    let ready = s.pool.clone();
    let protected = Router::new()
        .route("/internal/payments", post(charge))
        .route("/internal/payments/refund", post(refund))
        .route("/internal/payments/{id}", get(query))
        .route_layer(middleware::from_fn_with_state(s.key.clone(), authorize));
    Router::new()
        .merge(protected)
        .route("/healthz", get(|| async { StatusCode::OK }))
        .route("/readyz", get(move || readiness(ready.clone())))
        .layer(axum::extract::DefaultBodyLimit::max(4096))
        .with_state(s)
}
async fn charge(
    ExtractState(s): ExtractState<Payments>,
    BodyJson(c): BodyJson<Charge>,
) -> ApiResult<Json<Payment>> {
    Ok(Json(apply(&s.pool, &c, Action::Charge).await?))
}
async fn refund(
    ExtractState(s): ExtractState<Payments>,
    BodyJson(c): BodyJson<Charge>,
) -> ApiResult<Json<Payment>> {
    Ok(Json(apply(&s.pool, &c, Action::Refund).await?))
}
async fn query(
    ExtractState(s): ExtractState<Payments>,
    Path(raw): Path<String>,
) -> ApiResult<Json<Payment>> {
    let id = Uuid::parse_str(&raw).map_err(|_| invalid())?;
    Ok(Json(find(&s.pool, id).await?.ok_or(ApiError(
        StatusCode::NOT_FOUND,
        "payment not found",
    ))?))
}

#[derive(Debug, thiserror::Error, PartialEq, Eq)]
pub enum RemoteError {
    #[error("invalid payment input")]
    InvalidInput,
    #[error("payment identity conflict")]
    IdentityConflict,
    #[error("payment service identity rejected")]
    Unauthenticated,
    #[error("payment deadline; result may be unknown")]
    Deadline,
    #[error("payment dependency unavailable; result may be unknown")]
    Unavailable,
    #[error("invalid payment response")]
    Protocol,
}
#[derive(Clone)]
pub struct PaymentRemote {
    client: reqwest::Client,
    base: String,
    key: String,
}
impl PaymentRemote {
    pub fn new(base: &str, key: String) -> anyhow::Result<Self> {
        let url = reqwest::Url::parse(base)?;
        anyhow::ensure!(
            matches!(url.scheme(), "http" | "https")
                && url.host_str().is_some()
                && url.username().is_empty()
                && url.password().is_none()
                && url.path() == "/"
                && url.query().is_none()
                && url.fragment().is_none(),
            "payment endpoint must be an HTTP(S) origin without credentials"
        );
        ServiceKey::parse(&key)?;
        Ok(Self {
            client: client()?,
            base: base.trim_end_matches('/').into(),
            key,
        })
    }
    async fn request(
        &self,
        c: &Charge,
        action: Option<Action>,
    ) -> Result<Option<Payment>, RemoteError> {
        if !c.valid() {
            return Err(RemoteError::InvalidInput);
        }
        let request = match action {
            Some(Action::Charge) => self
                .client
                .post(format!("{}/internal/payments", self.base))
                .json(c),
            Some(Action::Refund) => self
                .client
                .post(format!("{}/internal/payments/refund", self.base))
                .json(c),
            None => self
                .client
                .get(format!("{}/internal/payments/{}", self.base, c.saga_id)),
        }
        .bearer_auth(&self.key);
        let mut response = request.send().await.map_err(|e| {
            if e.is_timeout() {
                RemoteError::Deadline
            } else {
                RemoteError::Unavailable
            }
        })?;
        match response.status().as_u16() {
            200 => {}
            404 if action.is_none() => return Ok(None),
            400 | 422 => return Err(RemoteError::InvalidInput),
            409 => return Err(RemoteError::IdentityConflict),
            401 | 403 => return Err(RemoteError::Unauthenticated),
            504 => return Err(RemoteError::Deadline),
            429 | 500 | 502 | 503 => return Err(RemoteError::Unavailable),
            _ => return Err(RemoteError::Protocol),
        }
        let mut bytes = Vec::new();
        while let Some(chunk) = response.chunk().await.map_err(|e| {
            if e.is_timeout() {
                RemoteError::Deadline
            } else {
                RemoteError::Unavailable
            }
        })? {
            if bytes.len().saturating_add(chunk.len()) > 4096 {
                return Err(RemoteError::Protocol);
            }
            bytes.extend_from_slice(&chunk);
        }
        let row: Payment = serde_json::from_slice(&bytes).map_err(|_| RemoteError::Protocol)?;
        if (row.saga_id, row.actor_id, row.amount) != (c.saga_id, c.actor_id, c.amount) {
            return Err(RemoteError::Protocol);
        }
        Ok(Some(row))
    }
    pub async fn apply(&self, c: &Charge, action: Action) -> Result<Payment, RemoteError> {
        tokio::time::timeout(Duration::from_secs(2), self.request(c, Some(action)))
            .await
            .map_err(|_| RemoteError::Deadline)?
            .and_then(|r| r.ok_or(RemoteError::Protocol))
    }
    pub async fn query(&self, c: &Charge) -> Result<Option<Payment>, RemoteError> {
        tokio::time::timeout(Duration::from_secs(2), self.request(c, None))
            .await
            .map_err(|_| RemoteError::Deadline)?
    }
}

### 35.4.3 【进阶】枚举减少字符串猜测

State只允许Paid、Declined、Refunded，JSON采用paid、declined、refunded。数据库行先读入私有Row，再明确转换为Payment；未知存储状态或坏身份不会被当作成功返回。

Action明确表示Charge或Refund，比传一个含义不清的bool更容易核对。initial只用于已校验输入的首次决定，next只计算既有状态的合法转移。

### 35.4.4 【进阶】完整意图先校验

Charge::valid拒绝nil UUID、非正数actor与超范围金额。HTTP反序列化还拒绝未知请求字段，浮点金额无法偷偷变成整数分。

支付服务不查询用户密码或重新计算商品总价。调用方应在创建持久订单时冻结权威商品金额，再按同一保存参数调用；不能接受客户端随请求修改amount。

## 35.5 用本地事务稳定保存决定

### 35.5.1 【入门】先建立身份，再读取并锁住

INSERT ON CONFLICT DO NOTHING尝试建立收据，rows_affected判断本事务是否首次创建；随后SELECT FOR UPDATE取得同一身份的行。并发重复请求会在唯一键或行锁处等待，不会各自保存一份独立Paid。

取得收据后先比较actor_id和amount，再进行任何状态变化或审计追加。参数不符返回409，原意图与历史不改变。

### 35.5.2 【进阶】Read Committed与后续读取

事务显式选择Read Committed。一个请求等待另一个身份相同的事务完成后，后续SELECT应读取已提交收据，再根据它决定重放或退款。

[PostgreSQL 17隔离级别文档](https://www.postgresql.org/docs/17/transaction-iso.html)说明了语句快照与冲突等待行为；[INSERT文档](https://www.postgresql.org/docs/17/sql-insert.html)定义了ON CONFLICT。这里的保证来自特定唯一键与锁协议，不是任意跨表逻辑都自动正确。

### 35.5.3 【进阶】审计和状态一起提交

首次创建收据时，追加对应初始审计；已有Paid转Refunded时，UPDATE状态并追加refunded。最后统一commit。重复命令没有新状态变化，也不追加新事实。

审计INSERT不使用无条件忽略冲突来掩盖异常。若审计约束或写入失败，整个事务应回滚：新收据不能独自存在，已付收据也不能变成缺少退款事实的Refunded。

### 35.5.4 【精通】为何不在事务里等待真实渠道

当前决定由纯函数在本地完成，所以状态和审计可以共用一个数据库事务。真实渠道受理属于外部系统，持有数据库锁并调用渠道仍不能获得共享原子提交。

接渠道时应先持久保存外部意图与渠道身份，使用查询、回调和对账恢复不确定结果。不能把本章inside中一行阈值判断换成HTTP渠道调用，就宣称获得真正的分布式事务。

### 35.5.5 【精通】预算与提交未知

锁等待400ms、单条语句500ms、完整apply外层700ms；HTTP服务沿用第34章五秒请求预算，客户端为两秒总预算。它们约束不同等待层，先触发哪一层不能靠固定显示文案判断。

提交边界超时或连接断开时，调用方得到的是未知结果。仍使用同UUID、actor和amount查询或重放；不得换身份再扣一次，也不得把错误转换为Declined。

## 35.6 内部HTTP契约与凭据

### 35.6.1 【入门】三个内部路径

| 方法与路径 | 输入 | 成功业务结果 |
| --- | --- | --- |
| POST /internal/payments | 完整Charge | 当前Payment，可能paid、declined或refunded |
| POST /internal/payments/refund | 相同身份与绑定参数 | 当前Payment，不重新开放终态 |
| GET /internal/payments/{id} | UUID | 存在时Payment；未见收据404 |

健康探针为/healthz和/readyz，不需要支付凭据。业务路由使用独立PAYMENT_TOKEN，公共用户JWT不能替代它。

### 35.6.2 【进阶】先鉴别调用方，再解析业务正文

protected路由层先运行authorize，要求恰好一个Bearer头，把值交给已有ServiceKey拦截器比较。无凭据、错误凭据或重复头都401，连格式错误的JSON也不能在未认证时进入业务处理。

正文最多4KiB，错误继续使用第34章JSON信封；查询UUID先作为字符串取得，再在授权后显式解析，避免不合法路径自动切换成框架纯文本错误。

### 35.6.3 【进阶】凭据与用户身份各有作用

PAYMENT_TOKEN证明受控调用方持有本服务凭据，actor_id说明该业务意图属于哪个用户；前者不自动证明后者来自一次真实用户认证。后续订单协调者必须从第34章身份路径取得actor，并保存不可变命令。

启动payments时校验密钥格式；若环境中同时出现商品或库存令牌且与支付令牌相同，直接拒绝。生成器为支付单独生成值；部署时还应核对完整凭据清单与分发权限。

### 35.6.4 【精通】query的404不是取消证明

GET未见收据，只说明查询那个时刻没有读到已提交行。另一个在途请求以后仍可能提交。

若业务决定关闭这次尝试，应使用同身份Refund建立屏障，而不是因一次404就认为迟到Charge永远不会到达。更不能在查询失败503时伪装成404。

## 35.7 有界远程客户端与命令行

### 35.7.1 【入门】类型化错误保留恢复依据

PaymentRemote在完整模块末尾。构造时校验origin与凭据；私有client/base/key防止调用方绕过有界客户端。请求禁止重定向，两秒期限覆盖发出请求、接收头和读取正文，回复最多4096字节。

RemoteError区分非法输入、身份冲突、服务身份拒绝、超时、依赖不可用与协议异常。业务Declined属于正常Payment，不是这些错误中的任一项。

### 35.7.2 【进阶】收到200还要核对回复

客户端解码State枚举，拒绝未知值，再逐一比较saga_id、actor_id与amount。另一个身份的成功回复、金额被改写或无效JSON都不能推进订单。

query也接收完整Charge，以核对原意图。它返回Result&lt;Option&lt;Payment&gt;,RemoteError&gt;：Ok(None)与Err是不同事实，不能统一unwrap_or(None)。

### 35.7.3 【入门】完整可信CLI

use anyhow::{Context, bail};
use commerce::payments::{Action, Charge, PaymentRemote};
use uuid::Uuid;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let args: Vec<String> = std::env::args().skip(1).collect();
    if args.len() != 4 || !matches!(args[0].as_str(), "charge" | "refund" | "query") {
        bail!("usage: payment-command charge/refund/query UUID ACTOR_ID AMOUNT_CENTS");
    }
    let c = Charge {
        saga_id: args[1].parse::<Uuid>().context("invalid payment UUID")?,
        actor_id: args[2].parse().context("invalid actor id")?,
        amount: args[3].parse().context("invalid amount")?,
    };
    let remote = PaymentRemote::new(
        &std::env::var("PAYMENTS_BASE_URL")?,
        std::env::var("PAYMENT_TOKEN")?,
    )?;
    let row = match args[0].as_str() {
        "query" => remote.query(&c).await?,
        action => Some(
            remote
                .apply(
                    &c,
                    if action == "charge" {
                        Action::Charge
                    } else {
                        Action::Refund
                    },
                )
                .await?,
        ),
    };
    match row {
        Some(p) => println!(
            "{} {} {} {}",
            p.saga_id,
            p.actor_id,
            p.amount,
            serde_json::to_value(p.state)?
                .as_str()
                .context("invalid state")?
        ),
        None => println!("not_found"),
    }
    Ok(())
}
```

工具读取PAYMENTS_BASE_URL和PAYMENT_TOKEN，不读取数据库密码。参数顺序固定为动作、UUID、actor、金额分。输出身份参数与状态，便于和第31章库存CLI对照。

### 35.7.4 【精通】不在通用客户端里无界重试

客户端每次调用有界，重试总预算与业务步骤由后续协调者掌握。401、409或协议不匹配不能与暂时503混为一类盲目循环。

重试允许回读原收据，也可能看到状态已从Paid推进到Refunded；“同身份幂等”不要求历史每次都返回最初Paid，而要求不会重复产生付款或重新打开终态。当前查询回答最新受保护的业务状态，追加明细保留历史。

"""Check chapter structure and optional local role configuration; never print values.

Python 3.11+ and Cargo are required. This is not a deployment or privilege audit.
"""
import argparse
import ipaddress
import json
import os
from pathlib import Path
import subprocess
import sys
from urllib.parse import urlsplit

ROOT = Path(__file__).resolve().parents[1]


def local_http(value):
    try:
        url = urlsplit(value)
        if url.scheme != "http" or not url.hostname or url.username or url.password:
            return False
        if url.path not in ("", "/") or url.query or url.fragment:
            return False
        if url.port is None or not 1 <= url.port <= 65535:
            return False
        if url.hostname == "localhost":
            return True
        return ipaddress.ip_address(url.hostname).is_loopback
    except ValueError:
        return False


def postgres(value):
    try:
        url = urlsplit(value)
        return (url.scheme in ("postgres", "postgresql") and bool(url.hostname)
                and bool(url.path.strip("/")) and bool(url.username)
                and (url.port is None or 1 <= url.port <= 65535))
    except ValueError:
        return False


def check_environment(role, spec, environment):
    errors = [f"missing {name}" for name in spec["required"] if not environment.get(name)]
    for name in spec["postgres"]:
        if environment.get(name) and not postgres(environment[name]):
            errors.append(f"invalid PostgreSQL URL in {name}")
    for name in spec["http"]:
        if environment.get(name) and not local_http(environment[name]):
            errors.append(f"{name} must be an explicit loopback HTTP endpoint with port")
    for name in ("RUSTMALL_CATALOG_TOKEN", "RUSTMALL_INVENTORY_TOKEN", "PAYMENT_TOKEN"):
        if name not in spec["required"] or not environment.get(name):
            continue
        value = environment[name]
        if not 32 <= len(value) <= 256 or not all(33 <= ord(c) <= 126 for c in value):
            errors.append(f"invalid service credential format in {name}")
        elif name in ("RUSTMALL_INVENTORY_TOKEN", "PAYMENT_TOKEN") and not all(
                c.isascii() and (c.isalnum() or c in "-_") for c in value):
            errors.append(f"invalid service credential alphabet in {name}")
    for name in spec.get("redis", []):
        try:
            url = urlsplit(environment.get(name, ""))
            host = f"[{url.hostname}]" if url.hostname and ":" in url.hostname else url.hostname
            port = url.port if url.port is not None else 6379
            valid = url.scheme == "redis" and url.hostname and local_http(f"http://{host}:{port}") and url.path in ("", "/0") and not url.query and not url.fragment
        except ValueError:
            valid = False
        if not valid:
            errors.append(f"{name} must be a local Redis database 0 URL")
    for name in spec.get("listen", []):
        if not local_http("http://" + environment.get(name, "")):
            errors.append(f"{name} must be a loopback listen address with port")
    if role == "users" and len(environment.get("JWT_SECRET", "").encode()) < 32:
        errors.append("JWT_SECRET must contain at least 32 bytes")
    if role == "catalog" and environment.get("RUSTMALL_CATALOG_TOKEN") == environment.get("RUSTMALL_INVENTORY_TOKEN"):
        errors.append("catalog and inventory credentials must differ")
    if role in ("payments", "payment-client") and environment.get("PAYMENT_TOKEN"):
        if any(environment.get(name) == environment["PAYMENT_TOKEN"] for name in ("RUSTMALL_CATALOG_TOKEN", "RUSTMALL_INVENTORY_TOKEN")):
            errors.append("payment credential must differ from other service credentials")
    if role == "facade":
        if environment.get("APP_ENV") != "production":
            errors.append("APP_ENV must be production for this checkpoint")
        if len(environment.get("APP_AUTH__JWT_SECRET", "").encode()) < 32:
            errors.append("APP_AUTH__JWT_SECRET must contain at least 32 bytes")
    if role in ("inventory-client", "payment-client") and environment.get("DATABASE_URL"):
        errors.append(f"{role} should not receive DATABASE_URL")
    return errors


def check_structure(ledger, metadata):
    packages = {p["name"]: p for p in metadata["packages"]}
    errors = []
    for role, spec in ledger["roles"].items():
        for package_name, binary in [(spec["package"], spec["binary"])] + (
            [(spec["migration_package"], spec["migration_binary"])] if "migration_binary" in spec else []
        ):
            package = packages.get(package_name)
            if package is None or not any(t["name"] == binary and "bin" in t["kind"] for t in package["targets"]):
                errors.append(f"{role}: missing binary {package_name}/{binary}")
        if "migration_path" in spec and not list((ROOT / spec["migration_path"]).glob("*.sql")):
            errors.append(f"{role}: no SQL migration files")
    return errors


def main():
    ledger = json.loads((ROOT / "docs/runtime-boundaries.json").read_text())
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--role", choices=sorted(ledger["roles"]))
    args = parser.parse_args()

        "--offline", "--no-deps", "--format-version", "1", "--manifest-path", str(ROOT / "Cargo.toml")],
        text=True, capture_output=True)
    if result.returncode:
        print("FAIL cargo metadata; run cargo metadata separately for compiler diagnostics", file=sys.stderr)

    errors = check_structure(ledger, json.loads(result.stdout))
    if args.role:
        errors += check_environment(args.role, ledger["roles"][args.role], os.environ)
    if errors:
        for error in errors:
            print("FAIL " + error, file=sys.stderr)
        return 1
    print(f"PASS chapter {ledger['chapter']} structure" + (f" and local {args.role} configuration" if args.role else ""))
    return 0


if __name__ == "__main__":

### 35.9.3 【进阶】验证全额退款与参数冲突

### 35.9.4 【精通】验证先到退款

另取一个新UUID，先refund后charge，金额和actor保持一致。当前状态Refunded，审计只有refund_barrier，没有paid。

这不是随机调度能否碰巧通过的演示；它明确安排到达顺序，证明关闭身份先保存时，后续请求不能重开。并发两种顺序还要由自动测试与锁协议共同核对。

### 35.10.3 【精通】故意阻止已提交回复

### 35.10.6 【进阶】按事实排错

| 观察 | 已知事实或需收集的证据 | 下一步 |
| --- | --- | --- |
| Paid | 当前身份接受模拟付款 | 协调者继续后续步骤，不直接宣布整个订单完成 |
| Declined | 当前身份稳定拒绝 | 进入库存释放等业务路径，不当作503重试 |
| Refunded | 身份已关闭 | 查审计区分已付后退与先到屏障，不再付款 |
| 401 | 服务凭据或重复Bearer错误 | 修复分发与调用身份，不换用户JWT试探 |
| 409 | 不可变参数发生冲突 | 停止猜测，核对保存的业务意图 |
| 504或连接中断 | 结果可能未知 | 保留原UUID与参数，查询或重放 |
| query为404 | 当前未见提交收据 | 不据此证明没有迟到请求；关闭用同身份Refund |
| 审计写入失败 | 状态与明细应同事务回滚 | 核对两表，修复约束或存储后重试 |
| 锁等待503 | 另一事务持有身份行 | 检查阻塞与预算，不能把错误记为Declined |
| 已退款又出现Paid | UUID、绑定、实际库和写入口 | 检查是否换了身份或绕开事务 |
| 原生重启后丢收据 | 是否换库或重建卷 | 核对真实数据来源，不把空库试验当恢复 |

### 35.10.7 【入门练习】成功HTTP和付款成功

为什么HTTP200仍可能需要取消订单？

参考答案：它只说明支付服务正确完成协议处理，Payment可能为Declined或Refunded。协调者必须检查状态，还要继续处理库存与订单步骤。

### 35.10.8 【操作练习】核对两种Refunded

分别做先付后退、先退后付，查询payment_effects。

评分要点：前者paid与refunded各一条，后者仅refund_barrier；重复请求不增加同类事实，也不使终态重新变Paid。

### 35.10.9 【推理练习】超时后换身份重试

参考答案：新UUID代表新意图，可能和已提交但回复丢失的原付款同时生效。必须保留原身份与参数恢复，不能靠随机UUID规避未知结果。

### 35.10.10 【精通练习】真实渠道应该放在哪里

为真实渠道设计受理、明确拒绝、未知结果和回调流程，不要求本章连接外部账户。

参考要点：先持久保存渠道身份与不可变金额；超时进入查询/对账，回调验签并去重；退款单有独立身份和金额约束；本地审计与渠道事实要能对应。未知不能归为Declined，渠道接受也不能绕过订单持久步骤。
