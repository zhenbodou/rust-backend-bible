# 第 10 章 serde 与 serde_json 详解

后端的大部分工作是“格式转换”：把请求中的 JSON 变成结构体，把结构体变成响应的 JSON，把配置文件变成配置对象，把消息队列里的事件变成枚举。Rust 生态中负责这件事的是 serde（ser ialize +de serialize），它是下载量最高的 crate 之一，Axum、SQLx、config、reqwest、rdkafka 的使用都离不开它。本章从原理到属性全解，项目部分让 RustMall 的领域类型在 JSON 中的样子与第 9 章的 API 文档严格一致，并用“契约测试”保证它不会被无意中改变。

## 10.1 serde 的架构

### 10.1.1 【入门】三方分工

serde 把“数据结构”和“数据格式”彻底解耦：

| 角色 | 提供者 | 作用 |
| --- | --- | --- |
| 数据结构 | 你的类型，通常通过 #[derive(Serialize, Deserialize)] | 描述“我由哪些字段组成” |
| 数据模型 | serde crate 本身 | 定义约 29 种抽象类型：布尔、整数、字符串、序列、映射、结构体、枚举变体…… |
| 数据格式 | serde_json 、toml 、serde_yaml 、rmp- se rde （MessagePack）…… | 把抽象类型写成 / 读成具体的字节 |

类比快递：你的结构体是要寄的东西，serde 数据模型是标准包装箱，各种格式是不同的快递公司。东西只要装进标准箱，任何一家快递都能寄。所以同一个 #[derive(Deserialize)] ，既能从 JSON 读，也能从 TOML 配置文件、环境变量（第 15 章）、数据库的 JSONB 列读。

### 10.1.2 【进阶】核心 trait
```rust
pub trait Serialize {
    fn serialize<S: Serializer>(&self, serializer: S) -> Result<S::Ok, S::Error>;
}

pub trait Deserialize<'de>: Sized {
    fn deserialize<D: Deserializer<'de>>(deserializer: D) -> Result<Self, D::Error>;
}
```

Serialize 把自己“告诉”一个 Serializer（“我是一个有 3 个字段的结构体，第一个字段叫 id，是整数 42……”）。

Deserialize&lt;'de&gt; 中的生命周期 'de 表示“输入数据的生命周期”，它让反序列化出的结构体可以借用输入字符串而不复制（10.6.3 节，和第 2.7 节的零拷贝思路一致）。不借用任何东西的类型实现的是 DeserializeOwned （即 for&lt;'de&gt; Deserialize&lt;'de&gt; ），写泛型代码时常用这个约束。

derive 宏在编译期为你的类型生成这两个 impl，没有运行时反射，性能与手写解析器相当。用cargo expand 可以看到生成的代码（相当长）。

## 10.2 安装与基本用法

### 10.2.1 【入门】声明依赖
```toml
[dependencies]
# derive feature 提供 #[derive(Serialize, Deserialize)]
serde = { version = "1", features = ["derive"] }
serde_json = "1"
```

| crate / feature | 作用 | 说明 |
| --- | --- | --- |
| serde | 核心 trait 与数据模型 | 必需 |
| serde 的 derive | 派生宏 | 几乎总是开启；它会引入 serde_derive 过程宏 crate |
| serde 的 rc | 为 Rc 、Arc 实现序列化 | 默认关闭：反序列化会制造独立副本，可能不是你想要的 |
| serde_json | JSON 格式 | 后端最常用 |
| serde_json 的preserve_orde r | Value 中的对象保持插入顺序 | 默认按键排序（BTreeMap） |
| serde_json 的arbitrary_pre cision | 保留任意精度的数字 | 处理第三方金融数据时可能需要 |

### 10.2.2 【入门】结构体与 JSON 互转
```rust
use serde::{Deserialize, Serialize};

#[derive(Debug, Serialize, Deserialize, PartialEq)]
struct CreateProduct {
    name: String,
    price_cents: i64,
    stock: i32,
    tags: Vec<String>,
    // Option：JSON 中缺失或为 null 时都得到 None
    discount_percent: Option<i64>,
}

fn main() -> Result<(), serde_json::Error> {
    // JSON → 结构体（反序列化）
    let input = r#"{"name":"机械键盘","price_cents":19900,"stock":10,"tags":
["外设"]}"#;
    let p: CreateProduct = serde_json::from_str(input)?;

    // discount_percent: None
    println!("{p:?}");

    // 结构体 → JSON（序列化）
    // 紧凑格式
    println!("{}", serde_json::to_string(&p)?);

    // 带缩进，便于阅读
    println!("{}", serde_json::to_string_pretty(&p)?);
    Ok(())
}
```

r#"..."# 是原始字符串字面量：里面的双引号和反斜杠不需要转义，写 JSON 测试数据时非常方便。

### 10.2.3 【入门】serde_json 的常用函数

| 函数 | 方向 | 输入 / 输出 |
| --- | --- | --- |
| to_string(&amp;v)/ to_string_pretty(&amp;v) | 结构 → JSON | String |
| to_vec(&amp;v) | 结构 → JSON | Vec&lt;u8&gt; （写网络、写 Kafka 时更直接） |
| to_writer(w, &amp;v) | 结构 → JSON | 直接写入文件或缓冲区 |

| from_slice(&amp;bytes) | JSON → 结构 | 输入 &amp;[u8] （请求体通常是字节） |
| from_reader(r) | JSON → 结构 | 从文件等流读取（比先读成字符串慢，大文件时省内存） |
| from_value(v) | Value →结构 |  |
| json!({...}) | 宏 | 用类 JSON 语法构造 Value ，可以插入 Rust 变量 |

## 10.3 属性全解

serde 的强大在于用属性精确控制格式。属性分为三类：容器属性（写在结构体或枚举上）、字段属性（写在字段上）、变体属性（写在枚举变体上）。

### 10.3.1 【入门】重命名
```rust
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize)]
// 容器属性：所有字段改为驼峰命名
#[serde(rename_all = "camelCase")]
struct ThirdPartyOrder {
    // JSON 中为 "orderNo"
    order_no: String,
    // 字段属性：单独指定名称
    #[serde(rename = "amt")]
    amount_cents: i64,
    // 反序列化时也接受这些历史名称
    #[serde(alias = "buyer", alias = "user")]
    user_id: i64,
}
```

rename_all 的可选值：lowercase 、UPPERCASE 、camelCase 、PascalCase 、snake_case 、SCREAMING_SNAKE_CASE 、kebab-case 。还可以分别指定序列化和反序列化的名称：#[serde(rename(serialize = "a", deserialize = "b"))] 。对接第三方支付、物流接口时，对方的命名风格往往与你不同，用这些属性就能保持 Rust 代码的命名规范。

### 10.3.2 【入门】默认值与跳过
```rust
use serde::{Deserialize, Serialize};

fn default_page_size() -> u32 { 20 }
#[derive(Debug, Deserialize)]
struct ListQuery {
    // 缺失时用类型的 Default（u32 为 0）
    #[serde(default)]
    page: u32,
    // 缺失时调用指定函数
    #[serde(default = "default_page_size")]
    page_size: u32,
    keyword: Option<String>,
}

#[derive(Serialize)]
struct UserView {
    id: i64,
    username: String,
    // 永远不序列化（反序列化时用 Default）
    #[serde(skip)]
    password_hash: String,
    // None 时整个字段不出现
    #[serde(skip_serializing_if = "Option::is_none")]
    nickname: Option<String>,
    #[serde(skip_serializing_if = "Vec::is_empty")]
    roles: Vec<String>,
}
```

#[serde(skip)] 是防止敏感字段泄露的最后一道防线，但更好的做法是第 3.6.6 节的“响应 DTO 与内部实体分离”：响应类型里根本没有 password_hash 字段，就不存在“忘记加 skip”的可能。

### 10.3.3 【进阶】flatten：展开嵌套结构
```rust
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize)]
struct Pagination { page: u32, page_size: u32 }

#[derive(Serialize, Deserialize)]
struct OrderQuery {
    status: Option<String>,
    // Pagination 的字段直接出现在外层
    #[serde(flatten)]
    pagination: Pagination,
}
// 对应 JSON / 查询字符串：{"status": "paid", "page": 1, "page_size": 20}
```

flatten 也可以用于 HashMap&lt;String, Value&gt; 字段，收集所有“未声明的字段”。注意：flatten 内部会先把数据缓存成中间结构，比普通字段慢，并且与 deny_unknown_fields 不兼容。

### 10.3.4 【进阶】拒绝未知字段
```rust
#[derive(serde::Deserialize)]
#[serde(deny_unknown_fields)]
struct ChangePassword { old_password: String, new_password: String }
// 输入 {"old_password":"a","new_password":"b","is_admin":true} 会报错 unknown field `is_admin`
```

默认忽略未知字段符合第 9.7.5 节“宽容地读”的原则，适合大多数接口。对安全敏感的接口或配置文件（拼错一个配置项名却被悄悄忽略，是常见的事故来源）可以开启 deny_unknown_fields 。

### 10.3.5 【进阶】属性速查表

| 属性 | 位置 | 作用 |
| --- | --- | --- |
| rename = "x" / rename_all = "..." | 容器 / 字段 /变体 | 改名 |
| alias = "x" | 字段 / 变体 | 反序列化时的备用名称 |
| default / default = "path" | 容器 / 字段 | 缺失时使用默认值 |
| skip / skip_serializing/ skip_deserializi ng | 字段 | 跳过 |
| skip_serializing_if = "path" | 字段 | 条件成立时不输出 |
| flatten | 字段 | 展开嵌套结构 |
| deny_unknown_fields | 容器 | 拒绝未知字段 |
| transparent | 容器 | 单字段结构体按内部字段序列化 |
| try_from = "T" / from = "T" / into = "T" | 容器 | 借助另一个类型序列化、反序列化（10.5.1 节） |
| with = "module" / serialize_with/ deserialize_with | 字段 | 自定义单个字段的格式（10.5.3 节） |
| tag / content / untagged | 容器（枚举） | 枚举的表示方式（10.4 节） |
| bound = "..." | 容器 / 字段 | 手动指定泛型约束 |
| borrow | 字段 | 借用输入数据（Cow&lt;str&gt; 等） |

## 10.4 枚举的四种表示

以这个枚举为例，看它在四种表示下的 JSON：
```rust
enum Promotion {
    FullReduction { threshold_cents: i64, off_cents: i64 },
    Discount { percent: i64 },
}
```

| 属性 | 名称 | Discount { percent: 90 } 的JSON | 适用 |
| --- | --- | --- | --- |
| （默认） | 外部标记 | {"Discount": {"percent": 90}} | Rust 内部使用 |
| #[serde(tag = "type")] | 内部标记 | {"type": "Discount", "percent": 90} | API 与事件最常用 |
| #[serde(tag = "type", content = "data")] | 相邻标记 | {"type": "Discount", "data": {"percent": 90}} | 变体携带非对象数据时 |
| #[serde(untagged)] | 无标记 | {"percent": 90} | 兼容第三方格式；按顺序逐个尝试，很慢且错误信息差 |

再配合 rename_all = "snake_case" ，内部标记就是第 9.10 节 API 文档中的 {"type":"full_reduction", ...} 。无数据的枚举（如 OrderStatus ）在默认表示下就是一个字符串"Paid"，加上 rename_all = "snake_case" 变成 "paid" 。

第 28 章 Kafka 中的订单事件就是一个内部标记的枚举：消费者先看 type 字段就知道是哪种事件。

### 10.4.1 常见错误与解读（第 10.1~10.4 节）

| 错误 | 典型信息 | 原因 | 解决 |
| --- | --- | --- | --- |
| 编译E0277 | the trait Serialize is not implemented for Product | 字段类型或类型本身没有派生 | 给类型及其所有字段类型派生 |
| 编译错误 | cannot find derive macro Serialize | 没有开启 serde 的 derive feature | features =["derive"] |
| 运行时 | missing field price_cents at line 1 column 20 | JSON 缺少非 Option 的字段 | 补字段，或加 #[serde(d efault)] |
| 运行时 | invalid type: string "19900", expected i64 | 类型不匹配 | 修正输入；或用deseria lize_with 兼容 |
| 运行时 | unknown variant Paid , expected one of pending , paid | 枚举名大小写不匹配 | 检查 rename_all 与输入 |
| 运行时 | trailing characters at line 1 | JSON 后面还有多余内容 | 检查输入是否拼接了多个JSON |
| 运行时 | key must be a string | 序列化以复合类型（如元组）为键的 Map | 改为 Vec 或把键转为字符串 |

## 10.5 校验与自定义

### 10.5.1 【进阶】反序列化即校验：try_from

第 3.6.3 节的“解析而非校验”在 serde 中有直接的支持。#[serde(try_from = "i32")] 表示：先把输入反序列化为 i32 ，再调用 TryFrom&lt;i32&gt; 转换；转换失败的错误信息会成为反序列化错误：
```rust
use serde::{Deserialize, Serialize};

#[derive(Debug, Clone, Copy, Serialize, Deserialize)]
#[serde(try_from = "i32", into = "i32")]
pub struct Quantity(i32);

impl TryFrom<i32> for Quantity {
    // 错误类型需要实现 Display
    type Error = String;
    fn try_from(n: i32) -> Result<Self, Self::Error> {
        if (1..=99).contains(&n) { Ok(Self(n)) } else { Err(format!("购买数量需为 1~99 件，当前为 {n}")) }
    }
}
impl From<Quantity> for i32 {
    fn from(q: Quantity) -> i32 { q.0 }
}

#[derive(Debug, Deserialize)]
struct PlaceOrder { product_id: i64, quantity: Quantity }

fn main() {
    let bad = serde_json::from_str::<PlaceOrder>(r#"{"product_id": 1, "quantity": 120}"#);

    // 购买数量需为 1~99 件，当前为 120 at line 1 column 35
    println!("{}", bad.unwrap_err());
}
```

这样，只要请求体成功反序列化成 PlaceOrder ，quantity 就一定合法，handler 中不需要再写任何校验。第 12 章 Axum 的 Json&lt;PlaceOrder&gt; 提取器会把这个错误自动转换为 4xx 响应。

into = "i32" 让序列化时先转换为 i32，要求类型实现 Clone 和 Into&lt;i32&gt; 。只需要反序列化校验、序列化保持默认时，可以只写 try_from 。

### 10.5.2 【进阶】transparent
```rust
#[derive(serde::Serialize, serde::Deserialize)]
#[serde(transparent)]
// JSON 中就是 42，而不是 [42] 或 {"0": 42}
struct ProductId(i64);
```

单字段的元组结构体本来就会被序列化为内部值，但 transparent 把这一点写成明确的意图，并且同样适用于只有一个字段的具名结构体。

### 10.5.3 【进阶】自定义单个字段：with / serialize_with

第 9.8.2 节说过，超过 2⁵³ 的整数要以字符串形式交给前端。可以为这种字段写一对函数：
```rust
mod i64_as_string {
    use serde::{Deserialize, Deserializer, Serializer};

    pub fn serialize<S: Serializer>(v: &i64, s: S) -> Result<S::Ok, S::Error> {
        s.serialize_str(&v.to_string())
    }

    pub fn deserialize<'de, D: Deserializer<'de>>(d: D) -> Result<i64, D::Error> {
        let s = String::deserialize(d)?;

        // 把解析错误转换为 serde 的错误
        s.parse().map_err(serde::de::Error::custom)
    }
}

#[derive(serde::Serialize, serde::Deserialize)]
struct Event {
    // 同时指定序列化与反序列化函数所在的模块
    #[serde(with = "i64_as_string")]
    snowflake_id: i64,
}
// 输出：{"snowflake_id": "1234567890123456789"}
```

serde_with crate 提供了大量现成的转换（DisplayFromStr 、时间格式、空字符串视为 None等），可以免去手写；时间类型的序列化由 chrono / time crate 自带的 serde feature 提供（第 14章）。

### 10.5.4 【精通】区分“缺失”与“null”：PATCH 的难题

部分更新接口中，{"nickname": null} 表示“清空昵称”，而不传 nickname 表示“不修改”。普通的Option&lt;String&gt; 把两者都变成 None，无法区分。解法是 Option&lt;Option&lt;T&gt;&gt; ：
```rust
use serde::{Deserialize, Deserializer};

/// 字段出现时（无论值是否为 null）包装成 Some，配合 #[serde(default)] 处理缺失
fn double_option<'de, T, D>(d: D) -> Result<Option<Option<T>>, D::Error>
where
    T: Deserialize<'de>,
    D: Deserializer<'de>,
{
    Option::<T>::deserialize(d).map(Some)
}

#[derive(Debug, Deserialize)]
struct PatchUser {
    #[serde(default, deserialize_with = "double_option")]
    nickname: Option<Option<String>>,
}

fn main() {
    // None：不修改
    let a: PatchUser = serde_json::from_str(r#"{}"#).unwrap();

    // Some(None)：清空
    let b: PatchUser = serde_json::from_str(r#"{"nickname": null}"#).unwrap();

    // Some(Some("阿锋"))：设置
    let c: PatchUser = serde_json::from_str(r#"{"nickname": "阿锋"}"#).unwrap();
    println!("{a:?} {b:?} {c:?}");
}
```

要点：字段缺失时 serde 不调用 deserialize_with ，而是使用 default （得到 None）；字段存在时调用 double_option ，把内层结果（None 或 Some）包一层 Some。

### 10.5.5 【精通】手写 Serialize / Deserialize

派生无法表达的格式（例如把 Money 序列化为 "199.50" 字符串，反序列化时接受"199.5" 、199.5两种输入）需要手写实现。手写 Serialize 很简单（调用 serializer.serialize_xxx ）；手写Deserialize 需要实现一个 Visitor ，处理各种可能的输入类型，代码较长。大多数情况下，先用try_from / from 借道一个辅助类型，可以避免手写 Visitor。

## 10.6 动态 JSON、借用与性能

### 10.6.1 【进阶】serde_json::Value

结构不固定的 JSON（第三方回调、元数据字段、调试接口）用 Value 处理：
```rust
use serde_json::{json, Value};

fn main() {
    let id = 42;
    let v: Value = json!({ "id": id, "name": "键盘", "tags": ["外设"],
"extra": null });

    // "键盘"（带引号，因为是 Value::String）
    println!("{}", v["name"]);
    // Some("键盘")
    println!("{:?}", v["name"].as_str());

    // Null：索引不存在不会
    println!("{:?}", v["missing"]["deep"]);
panic
    // JSON Pointer 访问嵌套值
    println!("{:?}", v.pointer("/tags/0"));
    if let Some(obj) = v.as_object() {
        for (k, val) in obj { println!("{k} = {val}"); }
    }
}
```

Value 是一个枚举：Null 、Bool 、Number 、String 、Array 、Object 。它方便但没有类型检查，能定义结构体时优先定义结构体；常见折中是结构体中的某个字段用 Value 承载“开放”的部分。

### 10.6.2 【进阶】反序列化错误信息

serde_json::Error 包含行号、列号与原因，err.classify() 能区分语法错误（Syntax ，对应HTTP 400）、数据不符合类型（Data ，对应 422）、输入提前结束（Eof ）。第 12 章会用它把错误映射到不同的状态码与错误码。错误信息中可能包含部分输入内容，返回给客戶端前要评估是否泄露信息。

### 10.6.3 【精通】零拷贝反序列化
```rust
use serde::Deserialize;
use std::borrow::Cow;

#[derive(Deserialize)]
struct LogLine<'a> {
    // 直接借用输入中的字符串，不分配
    level: &'a str,
    #[serde(borrow)]
    // 没有转义字符时借用，有转义（如 \n、\"）时才分配
    message: Cow<'a, str>,
}

fn main() {
    let input = r#"{"level": "info", "message": "订单已创建"}"#;
    let line: LogLine = serde_json::from_str(input).unwrap();
    println!("{} {}", line.level, line.message);
}
```

&amp;'a str 字段要求输入中的字符串不含转义字符，否则反序列化失败（因为需要修改内容才能得到真实的字符串）；Cow&lt;'a, str&gt; 两种情况都能处理。零拷贝适合高吞吐的日志处理、消息转发，普通业务接口使用 String 即可--请求体本身很小，分配开销可以忽略，而借用会带来第 2.5.5 节讲过的生命周期传染。

### 10.6.4 【精通】性能要点

from_slice 比先转为 String 再 from_str 少一次 UTF-8 校验与复制。

from_reader 逐字节读取，没有缓冲时很慢；读取文件应先包一层 BufReader ，或直接读成字节再 from_slice 。

序列化到已有的缓冲区（to_writer(&amp;mut buf, &amp;v) ）可以复用内存。

对极端性能场景，simd-json 、sonic-rs 用 SIMD 指令加速解析，接口与 serde 兼容。

### 10.7.2 【精通】反序列化的安全边界

限制输入大小：攻击者发送 1 GB 的 JSON 会耗尽内存。Axum 默认限制请求体为 2 MB，可通过DefaultBodyLimit 调整（第 12 章）；自己读取数据时也要设上限。

嵌套深度：serde_json 默认限制递归深度为 128 层，防止深度嵌套导致栈溢出。不要关闭这个限制。

类型就是白名单：反序列化到明确的结构体本身就是强校验--多余字段被忽略，类型错误被拒绝；不要把外部输入反序列化为 Value 后再到处取值，那会绕开类型系统。

不要反序列化“权限”字段：例如注册请求结构体中不应该有 role 字段，即使前端不传，攻击者也可以手工构造（批量赋值漏洞，Mass Assignment）。请求 DTO 只包含允许客戶端设置的字段。

### 10.7.3 常见错误与解读（第 10.5~10.7 节）

| 错误 | 典型信息 | 原因 | 解决 |
| --- | --- | --- | --- |
| 编译E0277 | the trait bound Quantity: From&lt;i3 2&gt; is not satisfied | 用了 from = "i32"却只实现了 TryFrom | 可能失败时用 try_from |
| 编译E0277 | Quantity: Clone is not satisfied | into = "..." 要求Clone | 派生 Clone |
| 编译错误 | lifetime may not live long enough（借用反序列化） | 输入字符串比结果先释放 | 让输入活得更久，或改用拥有所有权的字段 |
| 运行时 | invalid type: string with escapes,expected a borrowed string | &amp;str 字段遇到转义字符 | 改用 Cow&lt;str&gt; 并加 #[serde(borrow)] |
| 运行时 | recursion limit exceeded | 嵌套超过 128 层 | 视为恶意输入拒绝 |

```rust
//! 合法的购买数量（解析而非校验）。

use serde::{Deserialize, Serialize};

/// 单笔购买数量，取值 1~[`Quantity::MAX`]。
///
/// 字段私有，只能通过 [`Quantity::try_new`] 或 `TryFrom<i32>` 创建，
/// 因此任何 `Quantity` 实例都一定是合法的。JSON 中表示为数字，
/// 反序列化时同样执行校验。
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord, Serialize, Deserialize)]
#[serde(try_from = "i32", into = "i32")]
pub struct Quantity(i32);
impl Quantity {
    /// 单笔最大购买数量。
    pub const MAX: i32 = 99;

    /// 校验并创建购买数量。
    pub fn try_new(n: i32) -> Result<Self, String> {
        if (1..=Self::MAX).contains(&n) {
            Ok(Self(n))
        } else {
            Err(format!("购买数量需为 1~{} 件，当前为 {n}", Self::MAX))
        }
    }

    pub const fn get(self) -> i32 {
        self.0
    }
}

impl TryFrom<i32> for Quantity {
    type Error = String;
    fn try_from(n: i32) -> Result<Self, Self::Error> {
        Self::try_new(n)
    }
}

impl From<Quantity> for i32 {
    fn from(q: Quantity) -> i32 {
        q.0
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn quantity_bounds() {
        assert!(Quantity::try_new(0).is_err());
        assert!(Quantity::try_new(-3).is_err());
        assert!(Quantity::try_new(100).is_err());
        assert_eq!(Quantity::try_new(1).map(Quantity::get), Ok(1));
        assert_eq!(Quantity::try_new(99).map(Quantity::get), Ok(99));
    }

    #[test]
    fn std_conversions_match_try_new() {
        assert_eq!(Quantity::try_from(5), Quantity::try_new(5));
        assert!(Quantity::try_from(0).is_err());
        assert_eq!(i32::from(Quantity::try_new(7).expect("合法")), 7);
    }
}
```

与第 3 章相比：新增 serde 派生与属性、TryFrom&lt;i32&gt; 、From&lt;Quantity&gt; for i32 和一个测试，try_new 与 get 保持不变，已有调用方无需修改。标准的 TryFrom 实现让 let q: Quantity=5.try_into()?; 这样的写法也能使用。

```rust
use serde::Serialize;

/// 分页响应，JSON 形状见 `docs/api-v1.md` 第 3 节。
#[derive(Debug, Clone, PartialEq, Eq, Serialize)]
pub struct Page<T> {
    pub items: Vec<T>,
    pub page: u32,
    pub page_size: u32,
    pub total: i64,
}

impl<T> Page<T> {
    pub fn new(items: Vec<T>, page: u32, page_size: u32, total: i64) -> Self {
        Self { items, page, page_size, total }
    }

    /// 转换每个元素（例如实体 → 响应 DTO），分页信息保持不变。
    pub fn map<U>(self, f: impl FnMut(T) -> U) -> Page<U> {
        Page {
            items: self.items.into_iter().map(f).collect(),
            page: self.page,
            page_size: self.page_size,
            total: self.total,
        }
    }
}
```

2. 在文件末尾的 mod tests 中追加一个测试：
```rust
#[test]
fn page_map_keeps_metadata() {
    let page = Page::new(vec![1, 2, 3], 2, 3, 9).map(|n| n * 10);
    assert_eq!(page.items, vec![10, 20, 30]);
    assert_eq!((page.page, page.page_size, page.total), (2, 3, 9));
}
```

#[derive(Serialize)] 用在泛型结构体上时，会自动生成 impl&lt;T: Serialize&gt; Serialize forPage&lt;T&gt; ：只要元素能序列化，整页就能序列化。map 体现了第 6 章的迭代器写法：仓储返回Page&lt;Product&gt; ，handler 用 page.map(ProductResponse::from) 转换为响应类型。

### 10.8.12 本章小结

serde 把数据结构与数据格式解耦：派生 Serialize / Deserialize 一次，就能用于 JSON、TOML、环境变量、查询字符串等任何格式；没有运行时反射，性能与手写相当。

属性精确控制格式：rename_all 、alias 、default 、skip_serializing_if 、flatten 、deny_unknown_fields 、transparent 。

枚举有四种表示，API 和事件优先使用内部标记 #[serde(tag = "type")] 。

try_from 让反序列化同时完成校验，“解析而非校验”直达 HTTP 边界；with 自定义单个字段；Option&lt;Option&lt;T&gt;&gt; 区分缺失与 null。

Value 处理动态 JSON，但优先使用结构体；Cow&lt;str&gt; 实现零拷贝反序列化；限制输入大小、保持深度限制、请求 DTO 不包含权限字段。

RustMall 的 ID、数量、订单状态、优惠规则、商品和分页响应都有了与 API 文档一致的 JSON 表示，并有 6 个契约测试守护。
