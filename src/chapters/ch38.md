# 第 38 章 日志、指标、追踪与可操作的告警

第37章已经把真实订单产生的商品变化，经Outbox、Kafka送到两个独立投影。现在提出一个更贴近运行现场的问题：用户说订单一直没有完成，我们怎样判断它卡在认证、库存、支付、数据库，还是仅仅展示数据尚未追平？

本章继续扩展同一份工程，增加共享observability包，给现有HTTP、gRPC和后台步骤加入结构化日志、Prometheus指标与OpenTelemetry追踪。我们保留32个HTTP在途许可、5秒请求预算、库存RPC限制、支付收据、订单租约和事件身份；观测层不重新决定这些业务规则。

学完后，应能从一次HTTP请求找到下游商品RPC；从订单UUID找到独立worker尝试；用直方图解释延迟；区分真实队列积压与采样失效；并亲手停止Collector，确认遥测失败不会使另一笔订单失去提交能力。

## 38.1 先写出需要回答的问题

### 38.1.1 【入门】进程存活不是业务成功

/healthz返回200，只能证明相应进程能回答存活请求。订单可能仍在charging，relay可能一直等broker，投影也可能停在毒消息前。

本章关心五件事：入口是否可用、请求是否成功、延迟是否合理、持久责任是否持续推进、事实是否最终传播。CPU和内存能辅助解释这些问题，却不能单独代替业务结果。

### 38.1.2 【入门】三类信号分工

| 信号 | 适合回答 | 本项目示例 |
| --- | --- | --- |
| 日志 | 某次具体操作发生了什么 | order_id、步骤、错误类别、事件位置 |
| 指标 | 一段时间内整体怎样变化 | 请求错误率、延迟桶、最老订单年龄 |
| 追踪 | 一次调用经过哪些组件 | edge到catalog-http再到Catalog RPC |

日志可以带某笔业务的身份，指标不应为每个身份创建一条时序。追踪也不应把完整HTTP正文、密码、token或数据库URL作为属性。

### 38.1.3 【进阶】以同一条业务主线组织观测

HTTP同步链路使用trace_id连接服务，原请求还有request_id。HTTP返回202后，订单仍可能继续运行；worker为每次步骤尝试建立新的根span，使用order_id关联持久责任。

Outbox和projection也有独立span，使用event_id、商品id和revision关联。当前事件契约没有增加traceparent字段，本章不把商品快照事件伪装成原HTTP span的直接延长。

### 38.1.4 【精通】观测不能成为新的提交依赖

数据库保存订单后，Collector不可用不能让服务回滚远程已经发生的付款，也不能把已提交订单改成“未发生”。SDK采用有界后台批处理，导出失败可能丢失部分span；业务仍按原收据、租约和重试协议运行。

遥测数据不是业务账本。财务、库存和订单恢复仍以业务数据库事实为准，不能因为追踪界面没有出现付款span就执行第二次不同身份的付款。

## 38.2 请求号、业务号与追踪上下文

### 38.2.1 【入门】三个标识有不同寿命

request_id表达一次HTTP处理。客户端重试同一订单创建请求，可以有不同request_id，却通过Idempotency-Key返回同一个order_id。

trace_id表达一次同步或明确传播的执行上下文。order_id跨越多次HTTP请求和worker重启，持续时间可能远长于某个trace。event_id则标识已经提交的商品事实，重投时保持不变。

### 38.2.2 【进阶】不要接受任意字符串当请求号

HTTP中间件只保留唯一、合法且非nil的UUID。缺失、重复或全零时重新生成，写入请求头供下游处理读取，并在响应头返回同一值。

旧实现仅返回生成的响应头，处理器未必看到它。本章同时修正这个位置，并通过测试比较处理器读取值与最终响应值。这个标识用于关联，不授予业务权限。

### 38.2.3 【进阶】只传播W3C追踪字段

共享模块提取traceparent与tracestate，忽略任意baggage。重复、过长或无效上下文不会作为有效远程父节点。追踪传播只注入当前span的上下文，不为建立追踪复制Authorization或业务正文。业务授权所需的Bearer仍由原客户端显式设置并由对应服务验证。

edge原有头白名单继续保留。它先经过服务端span，再由观测模块向上游请求注入当前上下文，避免“原始traceparent加新traceparent”形成重复字段。

上下文与span关系的定义可对照[OpenTelemetry上下文传播说明](https://opentelemetry.io/docs/concepts/context-propagation/)。

### 38.2.4 【精通】采样不是身份验证

远程追踪上下文可能由调用者提供，它只能描述关联关系。本章ParentBased采样会继承有效父上下文的采样决定；生产入口还需按可信边界制定是否接受外部采样标志的策略。

本机实验采样率设为1，便于确定性验收；默认无父trace的采样率为0.1。两者都不代表token校验、请求容量或访问控制可以省略。

### 38.3.3 【进阶】初始化与上下文的完整实现

observability/src/lib.rs：
```rust
//! Shared observability, without taking ownership of business timeouts or retries.
pub mod metrics;
use http::HeaderMap;
use opentelemetry::{
    Context,
    propagation::{Extractor, TextMapPropagator},
    trace::{TraceContextExt, TracerProvider},
};
use opentelemetry_sdk::{
    propagation::TraceContextPropagator,
    trace::{BatchConfigBuilder, BatchSpanProcessor, Sampler, SdkTracerProvider},
};
use std::time::Duration;
use tracing_opentelemetry::OpenTelemetrySpanExt;
use tracing_subscriber::prelude::*;

pub struct Telemetry {
    provider: Option<SdkTracerProvider>,
    metrics: Option<(
        tokio_util::sync::CancellationToken,
        tokio::task::JoinHandle<std::io::Result<()>>,
    )>,
}
impl Telemetry {
    pub async fn shutdown(self) {
        if let Some((stop, mut task)) = self.metrics {
            stop.cancel();
            if !matches!(
                tokio::time::timeout(Duration::from_secs(1), &mut task).await,
                Ok(Ok(Ok(())))
            ) {
                task.abort();
                tracing::warn!(
                    category = "metrics-shutdown",
                    "metrics listener shutdown incomplete"
                );
            }
        }
        if let Some(provider) = self.provider {
            // Telemetry failure must not replace a successful business result.
            match tokio::task::spawn_blocking(move || {
                provider.shutdown_with_timeout(Duration::from_secs(2))
            })
            .await
            {
                Ok(Ok(())) => {}
                _ => tracing::warn!(
                    category = "telemetry-shutdown",
                    "trace export shutdown incomplete"
                ),
            }
        }
    }
}
pub fn init(service: &str) -> anyhow::Result<Telemetry> {
    opentelemetry::global::set_text_map_propagator(TraceContextPropagator::new());
    let provider = if std::env::var_os("OTEL_EXPORTER_OTLP_ENDPOINT").is_some() {
        use opentelemetry_otlp::WithExportConfig;
        let ratio = std::env::var("RUSTMALL_TRACE_SAMPLE_RATIO")
            .unwrap_or_else(|_| "0.1".into())
            .parse::<f64>()?;
        anyhow::ensure!(
            ratio.is_finite() && (0.0..=1.0).contains(&ratio),
            "trace sample ratio must be between 0 and 1"
        );
        let exporter = opentelemetry_otlp::SpanExporter::builder()
            .with_tonic()
            .with_timeout(Duration::from_secs(1))
            .build()?;
        let processor = BatchSpanProcessor::builder(exporter)
            .with_batch_config(
                BatchConfigBuilder::default()
                    .with_max_queue_size(1024)
                    .with_max_export_batch_size(128)
                    .with_scheduled_delay(Duration::from_millis(200))
                    .build(),
            )
            .build();
        Some(
            SdkTracerProvider::builder()
                .with_resource(
                    opentelemetry_sdk::Resource::builder()
                        .with_service_name(service.to_owned())
                        .build(),
                )
                .with_sampler(Sampler::ParentBased(Box::new(Sampler::TraceIdRatioBased(
                    ratio,
                ))))
                .with_span_processor(processor)
                .build(),
        )
    } else {
        None
    };
    let layer = provider
        .as_ref()
        .map(|p| tracing_opentelemetry::layer().with_tracer(p.tracer("rustmall")));
    tracing_subscriber::registry()
        .with(
            tracing_subscriber::EnvFilter::try_from_default_env().unwrap_or_else(|_| "info".into()),
        )
        .with(tracing_subscriber::fmt::layer().json())
        .with(layer)
        .try_init()
        .map_err(|_| anyhow::anyhow!("telemetry subscriber initialization failed"))?;
    let metrics = if let Ok(raw) = std::env::var("METRICS_ADDR") {
        let addr: std::net::SocketAddr = raw.parse()?;
        anyhow::ensure!(
            addr.ip().is_loopback(),
            "dedicated metrics listener must bind loopback in the local profile"
        );
        let listener = std::net::TcpListener::bind(addr)?;
        listener.set_nonblocking(true)?;
        let listener = tokio::net::TcpListener::from_std(listener)?;
        let stop = tokio_util::sync::CancellationToken::new();
        let stopped = stop.clone();
        let router = axum::Router::new().route(
            "/metrics",
            axum::routing::get(|| async {
                (
                    [("content-type", "text/plain; version=0.0.4; charset=utf-8")],
                    metrics::process_metrics(),
                )
            }),
        );
        let task = tokio::spawn(async move {
            axum::serve(listener, router)
                .with_graceful_shutdown(stopped.cancelled_owned())
                .await
        });
        Some((stop, task))
    } else {
        None
    };
    Ok(Telemetry { provider, metrics })
}
struct HttpExtract<'a>(&'a HeaderMap);
impl Extractor for HttpExtract<'_> {
    fn get(&self, key: &str) -> Option<&str> {
        if self.0.get_all(key).iter().count() != 1 {
            return None;
        }
        self.0
            .get(key)
            .and_then(|v| v.to_str().ok())
            .filter(|v| v.len() <= 512)
    }
    fn keys(&self) -> Vec<&str> {
        self.0.keys().map(|k| k.as_str()).collect()
    }
}
struct RpcExtract<'a>(&'a tonic::metadata::MetadataMap);
impl Extractor for RpcExtract<'_> {
    fn get(&self, key: &str) -> Option<&str> {
        if self.0.get_all(key).iter().count() != 1 {
            return None;
        }
        self.0
            .get(key)
            .and_then(|v| v.to_str().ok())
            .filter(|v| v.len() <= 512)
    }
    fn keys(&self) -> Vec<&str> {
        vec!["traceparent", "tracestate"]
    }
}
fn extract(source: &impl Extractor) -> Context {
    // Only W3C trace context, no arbitrary baggage or credentials.
    TraceContextPropagator::new().extract_with_context(&Context::new(), source)
}
pub fn http_span(headers: &HeaderMap, method: &str, route: &str) -> tracing::Span {
    let span = tracing::info_span!(
        "http.server",
        otel.kind = "server",
        http.method = method,
        http.route = route,
        otel.status_code = tracing::field::Empty
    );
    let _ = span.set_parent(extract(&HttpExtract(headers)));
    span
}
pub fn rpc_span<T>(request: &tonic::Request<T>, method: &str) -> tracing::Span {
    let span = tracing::info_span!(
        "rpc.server",
        otel.kind = "server",
        rpc.system = "grpc",
        rpc.method = method,
        otel.status_code = tracing::field::Empty
    );
    let _ = span.set_parent(extract(&RpcExtract(request.metadata())));
    span
}
pub async fn rpc_server<T>(
    span: tracing::Span,
    future: impl std::future::Future<Output = Result<T, tonic::Status>>,
) -> Result<T, tonic::Status> {
    use tracing::Instrument;
    async {
        let start = std::time::Instant::now();
        let result = future.await;
        let rpc_code = result
            .as_ref()
            .err()
            .map_or(tonic::Code::Ok, tonic::Status::code);
        metrics::observe_rpc(start.elapsed(), rpc_code);
        let code = rpc_code as i32;
        if code != 0 {
            tracing::Span::current().record("otel.status_code", "ERROR");
        }
        let (trace_id, span_id) = ids();
        tracing::info!(%trace_id,%span_id,rpc_code=code,"RPC completed");
        result
    }
    .instrument(span)
    .await
}
pub fn ids() -> (String, String) {
    let context = tracing::Span::current().context();
    let span = context.span();
    let c = span.span_context();
    if c.is_valid() {
        (c.trace_id().to_string(), c.span_id().to_string())
    } else {
        (String::new(), String::new())
    }
}
fn carrier() -> std::collections::HashMap<String, String> {
    let mut headers = std::collections::HashMap::new();
    TraceContextPropagator::new().inject_context(&tracing::Span::current().context(), &mut headers);
    headers
}
pub fn http(request: reqwest::RequestBuilder) -> reqwest::RequestBuilder {
    let mut headers = HeaderMap::new();
    for (k, v) in carrier() {
        if let (Ok(k), Ok(v)) = (k.parse::<http::header::HeaderName>(), v.parse()) {
            headers.insert(k, v);
        }
    }
    request.headers(headers)
}
pub fn rpc<T>(request: &mut tonic::Request<T>) {
    for (k, v) in carrier() {
        if let (Ok(k), Ok(v)) = (
            k.parse::<tonic::metadata::MetadataKey<tonic::metadata::Ascii>>(),
            v.parse(),
        ) {
            request.metadata_mut().insert(k, v);
        }
    }
}
```

### 38.3.4 【精通】关闭顺序与业务返回值

业务运行函数返回后，main先关闭观测监听器与provider，再返回原业务结果。遥测关闭失败只记录稳定类别的告警，不替换已经成功的业务结果。

HTTP服务仍先按原20秒预算停止接收并处理在途请求，数据库池按原预算关闭。不能在业务还执行时先关闭provider，也不能为遥测导出无限延长进程退出。

## 38.4 正确记录延迟直方图

### 38.4.1 【入门】计数器和桶保存什么

rustmall_http_requests_total记录已经生成响应的业务请求数，errors_total记录其中5xx，rejected_total记录429，deadlines_total记录504。健康探针与/metrics不计入业务分母。

延迟直方图包含多个累计桶、总数count和总秒数sum。请求耗时7毫秒，会进入10毫秒及所有更大的桶，不进入5毫秒桶。+Inf桶等于count。

### 38.4.2 【进阶】不要先截断成整数毫秒

如果先调用as_millis，5.9毫秒会变成5；再与5毫秒桶比较，就错误地落入小桶。本章直接比较Duration，只在输出单位时使用秒。

同样，sum保存秒数，不能把毫秒sum冠以seconds名称。单位错误可能让仪表盘看似漂亮，却把真实延迟缩小或放大1000倍。

### 38.4.3 【进阶】并发抓取必须得到一致快照

本章用一个短Mutex保护一组计数、累计桶与sum，观测时一次更新，抓取时复制快照后立即释放锁。格式化和网络发送发生在锁外。

若每个字段独立用原子数，抓取时先读取count，再读取后来更新的桶，可能得到有限桶大于count的无效直方图。原子读写本身安全，并不等于多个字段组成的一次观测是一致的。

```rust
#[derive(Clone, Default)]
struct Snapshot {
    completed: u64,
    errors: u64,
    rejected: u64,
    deadlines: u64,
    sum: f64,
    buckets: [u64; 10],
}
#[derive(Default)]
pub struct HttpMetrics(Mutex<Snapshot>);
impl HttpMetrics {
    pub fn observe(&self, duration: Duration, status: u16) {
        self.observe_result(
            duration,
            (500..600).contains(&status),
            status == 429,
            status == 504,
        );
    }
    fn observe_result(&self, duration: Duration, failed: bool, rejected: bool, deadline: bool) {
        let mut m = self.0.lock().unwrap_or_else(|p| p.into_inner());
        if m.completed == u64::MAX {
            return;
        }
        m.completed += 1;
        m.errors += u64::from(failed);
        m.rejected += u64::from(rejected);
        m.deadlines += u64::from(deadline);
        m.sum += duration.as_secs_f64();
        for (bucket, bound) in m.buckets.iter_mut().zip(BOUNDS) {
            if duration <= Duration::from_millis(bound) {
                *bucket += 1;
            }
        }
    }
    pub fn encode(&self) -> String {
        self.encode_as("rustmall_http")
    }
    fn encode_as(&self, prefix: &str) -> String {
        // Never keep the lock while formatting or sending the scrape body.
        let m = self.0.lock().unwrap_or_else(|p| p.into_inner()).clone();
        let mut out = String::new();
        for (name, count) in [
            ("rustmall_http_requests_total", m.completed),
            ("rustmall_http_errors_total", m.errors),
            ("rustmall_http_rejected_total", m.rejected),
            ("rustmall_http_deadlines_total", m.deadlines),
        ] {
            writeln!(out, "# TYPE {name} counter\n{name} {count}").expect("String write");
        }
        out.push_str("# TYPE rustmall_http_request_duration_seconds histogram\n");
        for (bound, count) in BOUNDS.into_iter().zip(m.buckets) {

            .expect("String write");

        out.replace("rustmall_http", prefix)
    }
```

### 38.6.2 【进阶】认证与追踪彼此独立

catalog入口改用与Inventory相同的已验证ServiceKey拦截器，保留不同的catalog与inventory凭据。它拒绝重复服务metadata并使用恒定时间比较，不再仅取第一个值后直接字符串相等。

本章业务server span从拦截器之后开始，认证前被拒绝的gRPC请求不会进入业务处理span。它们不能被解释为成功处理请求；后续治理章节再完善认证失败与传输拒绝的观测。

### 38.6.3 【进阶】一次worker尝试是一段有界执行

订单worker把领取后的步骤、远程调用、advance或defer放在同一个saga.attempt span中，记录order_id、state和attempt。每次重试是一段新执行，数据库步骤仍是唯一恢复依据。
```rust
#[tracing::instrument(name="saga.attempt",skip_all,fields(order_id=%row.id,state=%row.state,attempt=row.attempts))]
async fn attempt(s: &Worker, row: &Order, token: Uuid) -> anyhow::Result<()> {
    let result = tokio::time::timeout(Duration::from_secs(5), step(s, row)).await;
    match result {
        Ok(Ok(Outcome::Advance(next, reason))) => {
            let owned = advance(&s.pool, row, token, next, reason).await?;
            tracing::info!(order_id=%row.id,from=%row.state,to=next,owned,"saga transition attempted");
        }
        Ok(Ok(Outcome::Retry(reason))) => {
            defer(&s.pool, row, token, reason).await?;
        }
        Ok(Err(error)) => {
            tracing::error!(order_id=%row.id,%error,"invalid saga work");
            return Err(error);
        }
        Err(_) => {
            defer(&s.pool, row, token, "step-budget-unknown").await?;
        }
    }
    Ok(())
}
async fn sample_queue(pool: &PgPool) {
    use observability::metrics::{self, Gauge};
    let query = sqlx::query_as::<_, (i64, i64, f64)>(
        "SELECT count(*) FILTER(WHERE state NOT IN ('completed','cancelled','manual')),count(*) FILTER(WHERE state='manual'),GREATEST(COALESCE(EXTRACT(EPOCH FROM clock_timestamp()-min(created_at) FILTER(WHERE state NOT IN ('completed','cancelled','manual'))),0),0)::float8 FROM orders",
    );
    if let Ok(Ok((pending, manual, oldest))) =
        tokio::time::timeout(Duration::from_millis(250), query.fetch_one(pool)).await
    {
        metrics::set_gauges(&[
            (Gauge::OrdersPending, pending as f64),
            (Gauge::OrdersManual, manual as f64),
            (Gauge::OrdersOldestSeconds, oldest),
            (Gauge::OrdersSampleUnix, metrics::unix_seconds()),
        ]);
    }
}
pub async fn run(s: Worker, stop: CancellationToken) -> anyhow::Result<()> {
    let mut sampled = std::time::Instant::now() - Duration::from_secs(5);
    loop {
        if sampled.elapsed() >= Duration::from_secs(5) {
            sample_queue(&s.pool).await;
            sampled = std::time::Instant::now();
        }
        if stop.is_cancelled() {
            return Ok(());
        }
        match claim(&s.pool).await {
            Ok(Some((row, token))) => {
                attempt(&s, &row, token).await?;
            }
            Ok(None) => {
                tokio::select! {_=stop.cancelled()=>return Ok(()),_=tokio::time::sleep(Duration::from_millis(200))=>{}}
            }
            Err(error) => {
                tracing::error!(%error,"order claim failed");
                tokio::select! {_=stop.cancelled()=>return Ok(()),_=tokio::time::sleep(Duration::from_secs(1))=>{}}
            }
        }
    }
}
```

队列采样每5秒一次，最多等待250毫秒。成功时同时更新待推进数量、manual数量、最老待推进订单年龄和采样时间；失败时不清零，采样时间保持原值。

### 38.6.4 【精通】采样本身也要有成本边界

本章实验库很小，聚合查询足以解释责任。业务量增长后，持续全表聚合可能昂贵，需要利用部分索引、分段统计或专门聚合读模型；第41章继续分析执行计划与并发影响。

250毫秒预算避免采样无限拖住worker，但采样失败会使数据过期。告警必须同时检查采样时间，不能拿昨天的队列数判断此刻是否安全。

## 38.7 消息链路怎样保持可诊断性

### 38.7.1 【入门】relay span以事件为中心

outbox.delivery记录event_id、product_id、revision和attempt，覆盖发送与交付回写。它不改变Envelope，不生成新的事件身份，也不因为导出失败重新执行商品事务。

relay新增Outbox待交付数、最老事件年龄、待交付最大尝试次数与采样时间。角色自身使用catalog数据库连接采样，Prometheus只抓HTTP指标，不获得catalog管理员凭据。

更新messaging/src/bin/outbox-relay.rs，完整入口如下。采样失败不把原值清零，span覆盖一次交付尝试；业务租约和确认条件仍由store负责：
```rust
use anyhow::Context;
use messaging::{kafka, store};
use std::time::Duration;
#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let telemetry = observability::init("rustmall-relay")?;
    let result = run().await;
    telemetry.shutdown().await;
    result
}
async fn sample_outbox(pool: &sqlx::PgPool) {
    use observability::metrics::{self, Gauge};
    let query = sqlx::query_as::<_, (i64, f64, i32)>(
        "SELECT count(*),GREATEST(COALESCE(EXTRACT(EPOCH FROM clock_timestamp()-min(occurred_at)),0),0)::float8,COALESCE(max(attempts),0) FROM product_outbox WHERE delivered_at IS NULL",
    );
    if let Ok(Ok((pending, oldest, attempts))) =
        tokio::time::timeout(Duration::from_millis(250), query.fetch_one(pool)).await
    {
        metrics::set_gauges(&[
            (Gauge::OutboxPending, pending as f64),
            (Gauge::OutboxOldestSeconds, oldest),
            (Gauge::OutboxMaxAttempts, f64::from(attempts)),
            (Gauge::OutboxSampleUnix, metrics::unix_seconds()),
        ]);
    }
}
async fn run() -> anyhow::Result<()> {
    let pool = sqlx::postgres::PgPoolOptions::new()
        .max_connections(4)
        .acquire_timeout(Duration::from_secs(1))
        .connect(&std::env::var("CATALOG_DATABASE_URL")?)
        .await?;
    let producer = kafka::producer(&std::env::var("KAFKA_BROKERS")?)?;
    let topic =
        std::env::var("KAFKA_TOPIC").unwrap_or_else(|_| "rustmall.catalog.snapshots.v1".into());
    let shutdown = messaging::signal();
    tokio::pin!(shutdown);
    let mut sampled = std::time::Instant::now() - Duration::from_secs(5);
    loop {
        if sampled.elapsed() >= Duration::from_secs(5) {
            sample_outbox(&pool).await;
            sampled = std::time::Instant::now();
        }
        tokio::select! {
            ()=&mut shutdown=>break,
            ()=tokio::time::sleep(Duration::from_millis(200))=>{}
        }
        let lease = tokio::time::timeout(Duration::from_secs(3), store::claim_one(&pool)).await??;
        let Some(lease) = lease else { continue };
        anyhow::ensure!(
            lease.event_id == lease.payload.0.event_id,
            "outbox row and payload event IDs differ"
        );
        use tracing::Instrument;
        let span = tracing::info_span!("outbox.delivery",event_id=%lease.event_id,product_id=lease.payload.0.aggregate_id,revision=lease.payload.0.revision,attempt=lease.attempts);
        async {
            match kafka::send(&producer, &topic, &lease.payload.0).await {
                Ok(()) => {
                    let owned = tokio::time::timeout(
                        Duration::from_secs(3),
                        store::delivered(&pool, &lease),
                    )
                    .await??;
                    if !owned {
                        eprintln!(
                            "acknowledged event {}, but lease ownership changed",
                            lease.event_id
                        );
                    }
                }
                Err(error) => {
                    tokio::time::timeout(
                        Duration::from_secs(3),
                        store::failed(&pool, &lease, &error.to_string()),
                    )
                    .await
                    .context("outbox retry-state write timed out")??;
                    eprintln!("event {} retry scheduled: {error}", lease.event_id);
                }
            }
            Ok::<_, anyhow::Error>(())
        }
        .instrument(span)
        .await?;
    }
    tokio::time::timeout(Duration::from_secs(5), pool.close()).await?;
    Ok(())
}
```

### 38.7.2 【进阶】投影记录位置与应用结果

projection.apply记录事件身份、版本和分区位点。Inbox与view提交后，再提交offset；这些顺序完全沿用第37章。完成后更新最近应用时间，日志记录Updated、Duplicate或Stale。

两个独立投影属于同一个程序实现，但Prometheus job和独立端口区分代次。不能把其中一个实例成功，解释为两个读模型都完成了恢复。

更新messaging/src/bin/projection-worker.rs，保留第37章的身份绑定与毒消息停机行为：
```rust
use anyhow::Context;
use messaging::{kafka, projection};
use rdkafka::{Message, consumer::Consumer};
use std::time::Duration;
#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let telemetry = observability::init("rustmall-projection")?;
    let result = run().await;
    telemetry.shutdown().await;
    result
}
async fn run() -> anyhow::Result<()> {
    let pool = sqlx::postgres::PgPoolOptions::new()
        .max_connections(4)
        .acquire_timeout(Duration::from_secs(1))
        .connect(&std::env::var("PROJECTION_DATABASE_URL")?)
        .await?;
    let name = std::env::var("CONSUMER_NAME").unwrap_or_else(|_| "catalog-view-v1".into());
    let topic =
        std::env::var("KAFKA_TOPIC").unwrap_or_else(|_| "rustmall.catalog.snapshots.v1".into());
    tokio::time::timeout(
        Duration::from_secs(5),
        projection::bind_consumer(&pool, &name),
    )
    .await??;
    let consumer = kafka::consumer(&std::env::var("KAFKA_BROKERS")?, &name, &topic)?;
    let shutdown = messaging::signal();
    tokio::pin!(shutdown);
    loop {
        let message = tokio::select! {()=&mut shutdown=>break,message=consumer.recv()=>message?};
        let (topic, partition, offset) = (
            message.topic().to_string(),
            message.partition(),
            message.offset(),
        );
        // Record a reproducible location, never the payload or credentials.
        let location = format!("topic={topic} partition={partition} offset={offset}");
        let event = kafka::decode_message(&message)
            .with_context(|| format!("decode failed: {location}; no offset commit"))?;
        drop(message);
        use tracing::Instrument;
        let span = tracing::info_span!("projection.apply",event_id=%event.event_id,product_id=event.aggregate_id,revision=event.revision,partition,offset);
        async {
            let result = tokio::time::timeout(
                Duration::from_secs(5),
                projection::apply(&pool, &name, &event),
            )
            .await
            .with_context(|| format!("projection deadline: {location}"))?
            .with_context(|| format!("projection rejected: {location}; no offset commit"))?;
            kafka::commit_processed(consumer.clone(), topic, partition, offset)
                .await
                .with_context(|| format!("database committed, offset commit failed: {location}"))?;
            use observability::metrics::{self, Gauge};
            metrics::set_gauges(&[(Gauge::ProjectionAppliedUnix, metrics::unix_seconds())]);
            tracing::info!(event_id=%event.event_id,%location,?result,"projection committed");
            Ok::<_, anyhow::Error>(())
        }
        .instrument(span)
        .await?;
    }
    consumer.unsubscribe();
    tokio::time::timeout(Duration::from_secs(5), pool.close()).await?;
    Ok(())
}
```

### 38.7.3 【精通】最近应用时间不是完整性证明

没有业务新事件时，最近应用时间变旧是正常现象。不能简单配置“十分钟没有应用就报警”而忽略主题是否应有新数据。

判断传播需结合Outbox责任、Kafka消费位置与第37章完整对账。指标帮助发现异常方向，不能取代留存窗口检查或对下架墓碑的比较。

## 38.9 读指标，不猜百分位

### 38.9.1 【入门】整体错误率
```promql
sum by (job) (rate(rustmall_http_errors_total[5m]))
/
clamp_min(sum by (job) (rate(rustmall_http_requests_total[5m])), 0.001)
```

rate处理计数器增长与进程重启。分母保护避免除零，但很低的流量仍应结合请求数判断。一次请求失败不应自动等同于高流量服务持续故障。

### 38.9.2 【进阶】合并桶后再计算p95
```promql
histogram_quantile(0.95,
  sum by (job, le) (
    rate(rustmall_http_request_duration_seconds_bucket[5m])
  )
)
```

多个实例的p95不能相加，也不能简单平均。先合并各实例的同边界桶，再按桶分布估算分位数。估算精度受桶边界限制；平均值sum/count不能反推p95。

直方图的累计桶与分位数聚合规则参见[Prometheus指标类型说明](https://prometheus.io/docs/tutorials/understanding_metric_types/)。

### 38.9.3 【进阶】容量与未知结果分开看

429表示容量拒绝，不属于本章HTTP5xx错误率。504表示服务预算已用尽，远程结果仍可能未知。分别查看rejected_total与deadlines_total，结合订单身份查收据，避免把预算结束等同于业务从未提交。

### 38.9.4 【精通】低基数是运行成本约束

本章不把用户号、订单UUID、商品ID或任意URL作为Prometheus标签。job与instance由固定抓取配置提供，业务身份留在有访问控制的日志与追踪里。

一百万笔订单若各生成几十个指标序列，会直接扩大内存、磁盘与查询负担。不要为了“能查某笔订单”把指标系统当业务明细数据库。

### 38.10.1 【入门】完整规则

### 38.11.1 【入门】依赖暂停时看见什么

### 38.12.3 【进阶】按现象缩小范围

| 现象 | 先检查 | 不能直接推出 |
| --- | --- | --- |
| Prometheus up为0 | 角色是否运行、端口、主机网络 | 订单一定失败 |
| HTTP5xx增加 | 对应job与trace中的依赖 | 所有请求都失败 |
| 429增加 | 容量、处理时间、调用量 | 数据库已经宕机 |
| 没有trace文件 | OTLP地址、采样、Collector、批处理延迟 | 业务从未提交 |
| 同步链路有断点 | 下游服务端提取、客户端注入、真实父ID | 请求没有traceparent |
| 队列指标长期不变 | sample timestamp | 队列稳定正常 |
| 最近应用时间较旧 | 是否有新事件、Outbox、消费位置 | 消费者已经卡死 |
| 导出恢复但缺旧span | 队列与重试边界 | 业务数据也已丢失 |
| 角色启动报告端口占用 | METRICS_ADDR是否复用 | 应删掉原业务数据重试 |

### 38.12.4 【入门练习】平均值能推出p95吗

题目：平均耗时20毫秒，是否表示95%的请求都小于20毫秒？

参考答案：不能。少量极慢请求和大量快请求可以有相同平均值。使用合理边界的直方图，再按桶估算分位数；需要更高分辨率时调整桶或选用适合的直方图类型。

### 38.12.5 【进阶练习】采样失败时应该把队列数设为0吗

参考答案：不应。0表达“当前成功观察到没有待处理责任”，连接失败没有这种证据。保留最近值和最后成功采样时间，让告警明确指出数据过期。

### 38.12.6 【精通练习】怎样关联持续数小时的订单

参考答案：订单UUID保持稳定，每次worker尝试建立新span，日志记录步骤、尝试次数和结果。进一步需要跨异步边界因果关系时，可以保存受控SpanContext并使用span link；不能持续挂住最初HTTP span，也不能把追踪后端当成恢复状态机。

### 38.12.7 【精通练习】为什么追踪采样率1不适合照搬

参考答案：实验需要稳定验证每个span，生产要权衡吞吐、成本、隐私和诊断需要，还要限制不可信调用者影响采样的能力。降低采样后，某笔业务没有可见span是正常可能性，业务收据和审计仍必须完整。
