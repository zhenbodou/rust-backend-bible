# 第 0 章 开发环境搭建

本章做完，你的电脑上将装好 Rust 工具链、VS Code、Git、Docker 和接口调试工具，并建立RustMall 项目仓库。后续章节会在这里建立的环境和项目目录上继续推进。

## 0.1 安装 Rust：rustup

### 0.1.1 【入门】rustup、rustc、cargo 分别是什么

安装 Rust 时你会同时得到三个程序，先分清它们：

| 程序 | 作用 | 怎样配合 |
| --- | --- | --- |
| rustup | 安装、更新和选择工具链，管理组<br>件与编译目标 | 先准备适合项目的工具链 |
| rustc | 将 Rust 源代码编译成目标文件、库<br>或程序 | 通常由 Cargo 调用 |
| cargo | 管理项目、依赖、构建、测试与文<br>档 | 日常开发主要使用它 |

日常开发主要使用 cargo，由它调用 rustc；学习编译选项和排查构建问题时，也会直接查看 rustc 的行为。

Rust 有三个发布渠道：stable（稳定版，每 6 周发布一次，我们只用它）、beta（下一个稳定版的预览）、nightly（每日构建，包含实验特性）。

### 0.1.2 【入门】在 Windows 上安装

1. 先装 C++ 构建工具。Rust 在 Windows 上默认使用微软的链接器，所以需要 Visual Studio 的C++ 生成工具：a. 打开浏览器搜索“Visual Studio Build Tools”，进入微软官网下载 Build Tools 安装器。b. 运行安装器，勾选工作负载“使用 C++ 的桌面开发”（Desktop development with C++）。c. 右侧确认已勾选“MSVC 生成工具”和“Windows 11 SDK”（或 Windows 10 SDK），点击安装，约需 5GB 空间。

2. 下载 rustup：访问 https://rustup.rs ，页面会自动识别系统，下载 rustup-init.exe（64 位系统选x86\_64 版本）。

3. 运行安装器：双击后出现命令行菜单，输入 1 回车选择默认安装（Proceed with standard installation）。

4. 关闭并重新打开终端（PowerShell 或 Windows Terminal），让新的 PATH 环境变量生效。

5. 也可以用 Windows 自带的包管理器一行安装：winget install Rustlang.Rustup 。

安装位置：工具在 %USERPROFILE%\\.cargo\\bin ，工具链在 %USERPROFILE%\\.rustup 。

提示：如果你更习惯 Linux 环境，强烈推荐在 Windows 上安装 WSL2（Ubuntu），然后按下面Linux 的方式安装。后面 Docker、Kafka、Kubernetes 的大量命令在 WSL2 中体验更好。安装 WSL2：以管理员身份打开 PowerShell，执行 wsl --install ，重启电脑即可。

### 0.1.3 【入门】在 macOS 上安装

```bash
# 1. 安装 Xcode 命令行工具（提供链接器 cc 和 git）
xcode-select --install
 
# 2. 安装 rustup（会下载脚本并执行）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
# 出现菜单时输入 1 回车，选择默认安装
 
# 3. 让当前终端加载环境变量（或者直接新开一个终端）
source "$HOME/.cargo/env"
```

命令逐项解释：--proto '=https' 只允许 HTTPS 协议；--tlsv1.2 要求至少 TLS 1.2；-s 静默模式；-S 出错时仍显示错误；-f 服务器返回错误时失败退出。这串参数是为了安全下载脚本。

也可以用 Homebrew：brew install rustup 然后执行 rustup-init 。不要用 brew install rust，那样装的 Rust 无法用 rustup 管理版本。

### 0.1.4 【入门】在 Linux（Ubuntu/Debian）上安装

```bash
# 1. 安装编译依赖：C 编译器与链接器、pkg-config、OpenSSL 头文件
sudo apt update
sudo apt install -y build-essential pkg-config libssl-dev curl git
 
# 2. 安装 rustup
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env"
```

CentOS/Fedora 等系统把第一步换成 sudo dnf groupinstall "Development Tools" &amp;&amp; sudo dnf install openssl-devel pkgconf 。

### 0.1.5 【入门】验证安装

```bash
# 查看实际安装的版本；下面不预设输出日期或版本号
rustc --version
 
# Cargo 也应能正常输出版本号
cargo --version
rustup --version
 
# 显示默认工具链、已安装的目标平台
rustup show
```

能看到版本号就成功了。看到“命令未找到”说明 PATH 没生效：Windows 重开终端；macOS/Linux 执行 source "$HOME/.cargo/env" ，或检查 ~/.bashrc 、~/.zshrc 中是否有加载 .cargo/env 的一行。

### 0.1.6 【进阶】国内网络加速（可选）

如果下载工具链或依赖很慢，可以使用国内镜像。

加速 rustup 本身（在安装前设置环境变量）：

```bash
# macOS / Linux：写入 ~/.bashrc 或 ~/.zshrc
export RUSTUP_DIST_SERVER="https://rsproxy.cn"
export RUSTUP_UPDATE_ROOT="https://rsproxy.cn/rustup"
```

Windows 在“系统属性 → 环境变量”中新建同名用户变量。

加速 crates.io 依赖下载，新建或编辑文件：

文件：~/.cargo/config.toml （Windows 为 %USERPROFILE%\\.cargo\\config.toml ）

```text
[source.crates-io]
replace-with = "rsproxy-sparse"
 
[source.rsproxy-sparse]
registry = "sparse+https://rsproxy.cn/index/"
 
[net]
git-fetch-with-cli = true
```

逐项解释：\[source.crates-io\] 表示把官方源替换掉；replace-with 指定替换成哪个源；sparse+前缀表示使用“稀疏索引”协议，只下载需要的索引文件，速度快很多；git-fetch-with-cli 让 Cargo 调用系统的 git 命令拉取 git 依赖，兼容代理设置。镜像地址可能变化，以镜像站首页说明为准；网络正常的同学不需要这一步。

### 0.1.7 【进阶】rustup 日常管理命令

```bash
# 更新已安装的可跟踪更新通道；固定版本由团队单独评估升级
rustup update
 
# 设置默认工具链
rustup default stable
 
# 列出已安装的工具链
rustup toolchain list
 
# 额外安装 nightly（一般用不到）
rustup toolchain install nightly
 
# 安装常用组件
rustup component add rustfmt clippy rust-src rust-analyzer
# 已安装组件
rustup component list --installed
 
# 添加编译目标（第 20 章做镜像用）
rustup target add x86_64-unknown-linux-musl
 
# 离线打开官方教程《The Rust Programming Language》
rustup doc --book
 
# 离线打开标准库文档
rustup doc --std
 
# 完全卸载
rustup self uninstall
```

组件说明：

rustfmt：代码格式化工具，cargo fmt 调用它。

clippy：静态检查工具，能发现几百种常见错误和不地道写法，cargo clippy 调用它。

rust-src：标准库源码，编辑器跳转到标准库定义时需要。

rust-analyzer：语言服务器，给编辑器提供补全、跳转、类型提示。

### 0.1.8 【精通】用 rust-toolchain.toml 锁定团队工具链

团队协作时，每个人的 Rust 版本不同会导致“我这里能编译、你那里报错”。在项目根目录放一个文件，rustup 进入该目录时会自动切换到指定版本（没有就自动下载）：

文件：rustmall/rust-toolchain.toml

```toml
[toolchain]
# 使用本书核验环境的具体版本；升级时与代码一起提交
channel = "1.92.0"
components = ["rustfmt", "clippy", "rust-src"]
 
# 只装必需组件，CI 中更快
profile = "minimal"
```

stable 表示稳定通道，会随更新前进，不能把它称为固定版本。写明具体版本号才能统一编译器版本；CI 和 Docker 构建也要显式使用相同版本。依赖、系统库和构建参数仍需分别管理。我们在 0.5 节创建同一份配置。

其他【精通】知识：

Edition（版本纪元）：Rust 每三年左右发布一个 Edition（2015、2018、2021、2024），用于引入少量不兼容的语法改进。不同 Edition 的 crate 可以互相依赖。新项目默认使用最新的 2024 Edition，在 Cargo.toml 的 edition = "2024" 中声明。

MSRV（最低支持的 Rust 版本）：库作者在 Cargo.toml 中用 rust-version = "1.85"声明，低于这个版本编译时会给出清晰提示。

目标三元组：如 x86\_64-unknown-linux-gnu 表示“CPU 架构-厂商-系统-ABI”。gnu 动态链接glibc，musl 可以生成完全静态的二进制文件。

## 0.2 Cargo 命令全解与常用扩展工具

### 0.2.1 【入门】创建项目：cargo new 与 cargo init

```bash
# 新建一个“可执行程序”项目（binary crate），生成 hello/ 目录
cargo new hello
 
# 新建一个“库”项目（library crate）
cargo new --lib mylib
 
# 在当前已存在的目录中初始化项目
cargo init
 
# 不自动初始化 git 仓库（默认会执行 git init）
cargo new hello --vcs none
```

cargo new hello 生成的结构：

```text
hello/
├── .git/            # 自动创建的 git 仓库
├── .gitignore       # 内容为 /target，忽略编译产物
├── Cargo.toml       # 项目清单（manifest）
└── src/
    └── main.rs      # 程序入口
```

binary 和 library 的区别：binary 有 src/main.rs 和 fn main() ，编译成可以运行的程序；library 有src/lib.rs ，编译成供别人调用的代码库，不能直接运行。一个包（package）可以同时有一个 lib 和多个 bin。

### 0.2.2 【入门】Cargo.toml 逐行解释

文件：hello/Cargo.toml

```toml
[package]
# 包名，也是默认的可执行文件名；只能用字母、数字、- 和 _
name = "hello"
 
# 语义化版本：主版本.次版本.修订号
version = "0.1.0"
 
# 使用的 Rust Edition
edition = "2024"
 
# 运行时依赖，例如：serde = "1"
[dependencies]
# 只在测试、示例、基准测试时使用的依赖
[dev-dependencies]
 
# 只在 build.rs 构建脚本中使用的依赖（第 25 章 gRPC 代码生成会用）
[build-dependencies]
```

依赖版本号的写法（非常重要，新手常误解）：

| 版本要求 | 含义 | 允许的正式版本范围 |
| --- | --- | --- |
| "1.2.3" 或 "^1.2.3" | 默认的兼容更新要求 | &gt;=1.2.3，&lt;2.0.0 |
| "0.8" | 主版本为零时按 Cargo 的兼容规则<br>解析 | &gt;=0.8.0，&lt;0.9.0 |
| "0.0.3" | 首个非零分量是修订号 | &gt;=0.0.3，&lt;0.0.4 |
| "~1.2.3" | 只在指定次版本内更新 | &gt;=1.2.3，&lt;1.3.0 |
| "=1.2.3" | 仅允许该版本 | 1.2.3 |

| 版本要求 | 含义 | 允许的正式版本范围 |
| --- | --- | --- |
| "&gt;=1.2, &lt;1.5" | 同时满足两个比较条件 | &gt;=1.2.0，&lt;1.5.0 |

这里列的是正式版本的常用范围；预发布版本还有单独的匹配规则。依赖的其他写法如下：

```toml
[dependencies]
# 开启可选功能
serde = { version = "1", features = ["derive"] }
 
# 关闭默认功能，只要需要的
tokio = { version = "1", default-features = false, features = ["rt"] }
 
# 本地路径依赖（workspace 中常用）
common = { path = "../common" }
 
# git 依赖
my-lib = { git = "https://github.com/xx/my-lib", tag = "v1.0" }
 
# 可选依赖，由本包的 feature 控制是否启用
openssl = { version = "0.10", optional = true }
```

Cargo.lock 文件：第一次构建时自动生成，记录每个依赖实际解析到的精确版本。它统一依赖解析结果，是可重复构建的一部分；编译器、目标平台、系统库和构建参数不同，产物仍可能不同。CI 中可配合--locked 禁止构建过程悄悄更新锁文件。规则：可执行程序项目要把 Cargo.lock 提交到 Git；纯库项目现在也推荐提交。不要手动编辑它。

### 0.2.3 【入门】构建与运行

```bash
# 调试模式编译，产物在 target/debug/，编译快、运行慢、带调试信息
cargo build
 
# 发布模式编译，产物在 target/release/，开启优化，性能差异取决于程序与测量条件
cargo build --release
 
# 编译并运行
cargo run
cargo run --release
 
# “--” 之后的参数传给你的程序，而不是 cargo
cargo run -- --port 8080
 
# 在 workspace 中指定运行哪个包
cargo run -p order-service
 
# 一个包有多个可执行文件时指定其中一个
cargo run --bin migrate
 
# 只做类型检查不生成可执行文件，比 build 快得多，写代码时最常用
cargo check
 
# 删除 target/ 目录，释放磁盘（target 可能占用几个 GB）
cargo clean
```

牢记：性能测试、压测、上线一律使用 --release 。 不要用未优化构建的测量结果代替发布构建的性能结论；先确认输入、构建方式和测量方法一致。

### 0.2.4 【入门】代码质量三件套

```bash
# 按官方风格自动格式化所有代码
cargo fmt
 
# 只检查不修改，格式不对就返回失败（CI 中使用）
cargo fmt -- --check
 
# 静态检查，给出改进建议
cargo clippy
 
# 把所有警告当错误（CI 中使用）
cargo clippy -- -D warnings
 
# 自动修复能修复的问题
cargo clippy --fix
 
# 运行所有测试（第 17 章详解）
cargo test
 
# 只运行名字包含该片段的测试
cargo test 名字片段
 
# 测试时显示 println! 输出
cargo test -- --nocapture
```

### 0.2.5 【进阶】依赖管理命令

```bash
# 添加依赖并写入 Cargo.toml（会自动选最新兼容版本）
cargo add serde --features derive
 
# -F 是 --features 的简写
cargo add tokio -F full
 
# 添加到 [dev-dependencies]
cargo add --dev mockall
 
# 添加本地路径依赖
cargo add common --path ../common
 
# 删除依赖
cargo remove serde
 
# 在 Cargo.toml 允许的范围内把依赖升级到最新，更新 Cargo.lock
cargo update
 
# 只升级某一个依赖
cargo update -p serde
 
# 以树状显示完整依赖关系
cargo tree
 
# 反查：谁引入了 openssl
cargo tree -i openssl
 
# 找出被引入了多个版本的重复依赖
cargo tree -d
 
# 为你的项目及所有依赖生成文档并在浏览器打开（离线查 API 的神器）
cargo doc --open
```

### 0.2.6 【进阶】发布配置（profile）

在 Cargo.toml 中可以调整编译参数：

```text
[profile.dev]
# 调试模式不优化，编译最快
opt-level = 0
[profile.dev.package."*"]
# 但依赖库开启优化：第一次编译慢一点，之后自己的代码改动编译仍很快，运行快很多
opt-level = 2
 
[profile.release]
# 最高优化
opt-level = 3
 
# 链接时优化，进一步提升性能、减小体积
lto = "thin"
 
# 单个代码生成单元，优化更彻底但编译更慢
codegen-units = 1
 
# 去掉符号表，减小二进制体积
strip = true
# panic 时直接终止而不是展开栈，体积更小（注意：会让 catch_unwind 失效）
panic = "abort"
```

### 0.2.7 【精通】常用 cargo 扩展工具

Cargo 支持第三方子命令：安装名为 cargo-xxx 的工具后，就能用 cargo xxx 调用。安装方式统一为cargo install 名字 --locked （--locked 表示使用该工具发布时锁定的依赖版本，尽量按该工具发布时的依赖解析结果构建；这仍不能保证任意平台或编译器都能安装成功）。

| 工具 | 安装示例 | 用途 |
| --- | --- | --- |
| cargo-watch | cargo install cargo-watch<br>--locked | cargo watch -x run：监听文件变化并重新运行 |
| sqlx-cli | 到数据库章节按 PostgreSQL 与<br>TLS 配置安装 | 数据库迁移与查询元数据准备 |
| cargo-nextest | cargo install cargo-nextest<br>--locked | cargo nextest run：运行测试 |
| cargo-llvm-cov | cargo install cargo-llvm-cov<br>--locked | 收集并报告测试覆盖率 |

| 工具 | 安装或使用说明 | 用途 |
| --- | --- | --- |
| cargo-audit | cargo install cargo-audit<br>--locked | 检查依赖涉及的已知安全公告 |
| cargo-deny | cargo install cargo-deny<br>--locked | 按配置检查许可证、公告、重复版本和依赖来源 |
| cargo-chef | 到 Docker 章节按镜像构建步骤安<br>装 | 准备依赖构建计划，改善缓存复用 |
| cargo-edit | cargo add、cargo remove 已是<br>Cargo 内置命令 | 管理依赖不需要为这两个命令额外安装<br>cargo-edit |
| cargo-expand | cargo install cargo-expand<br>--locked | 查看宏展开后的代码；注意其工具链要求 |

| 工具 | 安装或使用说明 | 用途 |
| --- | --- | --- |
| cargo-udeps | 按工具说明使用 nightly | 辅助检查未使用的依赖，结果仍需人工核对 |
| oha | cargo install oha --locked | 发送 HTTP 压测请求 |
| cargo-binstall | 参照项目官方安装说明 | 尝试安装工具的预编译程序；可用性取决于目标<br>平台和发布资产 |

编译速度优化（精通）：

1. 写代码时优先使用 cargo check，确实需要可执行文件时再 cargo build。

2. 使用更快的链接器：Linux 安装 mold （sudo apt install mold ），在~/.cargo/config.toml 中加入 \[target.x86\_64-unknown-linux-gnu\] 和 linker ="clang" 、rustflags = \["-C", "link-arg=-fuse-ld=mold"\] ；macOS 新版本的系统链接器已经足够快。

3. 使用 sccache 缓存编译结果，多个项目之间共享。

4. 按上节配置 \[profile.dev.package."\*"\] 。

5. 拆分 workspace：改动一个 crate 只重新编译它和依赖它的 crate（RustMall 就是这样组织的）。

## 0.3 编辑器：VS Code + rust-analyzer

### 0.3.1 【入门】安装 VS Code 与插件

1. 访问 https://code.visualstudio.com 下载对应系统的安装包并安装。Windows 安装时勾选“添加到 PATH”和“通过 Code 打开”。

2. 打开 VS Code，按 Ctrl+Shift+X （macOS 为 Cmd+Shift+X ）打开扩展面板，搜索并安装：

| 扩展 | 作用 | 使用时机 |
| --- | --- | --- |
| rust-analyzer（rust-lang.rust-<br>analyzer） | Rust 补全、跳转、类型提示、诊断<br>与重构 | 本章安装 |
| CodeLLDB | 配合 launch.json 进行断点调试 | 需要调试时安装 |
| Even Better TOML | 编辑并校验 Cargo.toml 等 TOML<br>文件 | 本章可安装 |
| Dependi | 辅助查看依赖版本信息 | 按需选择 |
| Error Lens | 在代码附近显示诊断信息 | 按需选择 |
| 容器开发扩展 | 辅助编辑 Dockerfile 和管理容器 | Docker 章节按需选择 |

| 扩展 | 作用 | 使用时机 |
| --- | --- | --- |
| YAML（Red Hat） | 辅助编辑 Compose、Kubernetes、<br>工作流配置 | 使用 YAML 时安装 |

### 0.3.2 【入门】rust-analyzer 的核心功能

悬停查看类型：鼠标停在变量上显示类型与文档。

Inlay Hints（内嵌提示）：在代码中以灰色文字显示推断出的类型，学习阶段非常有用。

### 0.3.3 【进阶】推荐的工作区设置

在项目中新建以下文件，团队成员打开项目时会自动应用：

文件：rustmall/.vscode/settings.json

```text
{
  "editor.formatOnSave": true,
  "[rust]": {
    "editor.defaultFormatter": "rust-lang.rust-analyzer"
  },
  "rust-analyzer.check.command": "clippy",
  "rust-analyzer.cargo.features": [],
  "rust-analyzer.inlayHints.typeHints.enable": true,
  "rust-analyzer.inlayHints.parameterHints.enable": true,
  "rust-analyzer.inlayHints.chainingHints.enable": true,
  "rust-analyzer.lens.enable": true,
  "files.exclude": { "**/target": true }
}
```

逐项解释：

editor.formatOnSave ：保存时自动格式化，再也不用手动 cargo fmt 。

rust-analyzer.check.command: clippy ：保存时用 clippy 代替 check 做检查，能看到更多改进建议。

rust-analyzer.cargo.features: \[\]：先使用项目默认 feature。排查某个可选功能时，把需要的 feature 名称填入列表。"all" 会传递 --all-features；存在互斥功能或系统依赖时，全部开启反而可能失败。

三个 inlayHints ：分别显示变量类型、函数参数名、链式调用每一步的类型。

files.exclude ：在文件树中隐藏 target 目录。

### 0.4.2 【入门】安装 Docker

从第 12 章起，PostgreSQL、Redis、Kafka、Prometheus 等所有中间件都优先用 Docker 运行，便于统一运行方式与镜像版本。容器、镜像和数据卷分别管理；删除容器并不等于删除持久化数据。

Windows：

1. 确认 BIOS 已开启虚拟化（任务管理器 → 性能 → CPU，查看“虚拟化：已启用”）。

2. 安装 WSL2：管理员 PowerShell 执行 wsl --install ，重启。

3. 访问 https://www.docker.com/products/docker-desktop 下载 Docker Desktop，安装时勾选“Use WSL 2 instead of Hyper-V”。

4. 启动 Docker Desktop，等左下角显示绿色“Engine running”。

5. 设置 → Resources → WSL Integration 中打开你的 Ubuntu 发行版，这样在 WSL 里也能用docker 命令。

macOS：从同一网址下载对应芯片的版本（Apple 芯片选 Apple Silicon，Intel 芯片选 Intel）。也可按个人环境选择其他支持所需容器工作流的运行时，并核对它对本书命令和资源配置的支持。

Linux（Ubuntu）：使用官方仓库安装 Docker Engine（服务器上不需要 Desktop）：

```bash
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# 以下是 Bash 多行命令，EOF 必须独占一行
sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 可选：使用 docker 组访问系统 Docker 服务，完成后重新登录
sudo usermod -aG docker "$USER"
```

以上命令用于 Docker 官方支持的 Ubuntu 环境，执行前核对发行版和官方安装文档。docker 组具有较高的系统权限；共享主机应由管理员选择合适的访问方式。

验证：

```bash
docker --version
 
# 注意是 "docker compose"（空格），新版已内置，不再是 docker-compose
docker compose version
# 看到 "Hello from Docker!" 说明一切正常
docker run --rm hello-world
```

资源建议：Docker Desktop 设置 → Resources 中，给 Docker 至少分配 4 核 CPU、8 GB 内存（第25 章之后同时跑 Kafka、PostgreSQL、多个服务和监控组件，内存小了会频繁被杀进程）。

镜像加速（国内网络可选）：Docker Desktop 设置 → Docker Engine，在 JSON 中加入"registry-mirrors": \["你的镜像加速地址"\] ；Linux 编辑 /etc/docker/daemon.json 写入同样内容后执行 sudo systemctl restart docker 。可用的加速地址会变化，请使用你所在云厂商控制台提供的个人加速地址。

## 本章小结

rustup 管理工具链，rustc 是编译器，cargo 是日常使用的构建与包管理工具；使用稳定工具链，并在rust-toolchain.toml 中写明团队核验过的具体版本。

Cargo.toml 中依赖的默认版本写法是“兼容更新”，Cargo.lock 锁定精确版本，可执行程序项目必须提交它。

写代码时用 cargo check ，提交前跑 cargo fmt 、cargo clippy 、cargo test ，性能相关的一切都用--release 。

VS Code + rust-analyzer + CodeLLDB 是推荐的开发组合，团队共享.vscode/settings.json 。

所有中间件都用 Docker 运行，给 Docker 分配足够的内存。

## 本章练习

1. 执行 rustup doc --book ，在离线打开的官方书中找到“Common Programming Concepts”一章，与本书第 1 章对照阅读。

2. 新建练习项目，用 cargo add 添加 rand ，用 cargo tree 查看它引入了哪些间接依赖，再用 cargo remove 删除它。

3. 对同一个计算密集的小程序（例如对 1 亿以内的数求和）分别用 cargo run 和 cargo run --release运行并计时，记录速度差距。

4. 修改 rust-toolchain.toml 中的 channel 为一个旧版本号（如 "1.91.0" ），在项目目录执行 rustup show ，观察 rustup 自动下载并切换版本；完成后改回本章的 "1.92.0"；旧工具链可能无法编译项目，请在独立练习目录操作 。

5. 在 VS Code 中为 1.1 节的练习程序设置一个断点，用 F5 调试并在变量面板中查看变量值。
