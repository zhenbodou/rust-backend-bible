## 6.1 集合总览与选型

### 6.1.1 【入门】标准库的八种集合

HashMap、VecDeque等类型位于std::collections；Vec定义于std::vec，String定义于std::string。Vec和String属于标准预导入，通常不必另写use。先看集合全景，随后逐节展开：

| 集合 | 一句话 | 典型后端用途 |
| --- | --- | --- |
| Vec&lt;T&gt; | 连续存放的动态数组 | 查询结果、批量 ID、响应 DTO；遍历局部性通常较好 |
| VecDeque&lt;T&gt; | 两端都能高效进出的环形队列 | 任务队列、滑动窗口、最近 N 条记录 |
| HashMap&lt;K, V&gt; | 哈希表，按键查值 | 内存缓存、按 ID 建索引、计数统计 |
| BTreeMap&lt;K, V&gt; | 按键有序的映射 | 需要有序输出、按区间查询、稳定分页 |
| HashSet&lt;T&gt; | 不重复元素的哈希集合 | 去重、权限集合、已处理事件 ID |
| BTreeSet&lt;T&gt; | 有序且不重复 | 有序去重、区间查询 |
| BinaryHeap&lt;T&gt; | 二叉堆，总能 O(1) 看到最大值 | 优先级队列、Top-N、延时任务调度 |
| LinkedList&lt;T&gt; | 双向链表 | 普通遍历先评估Vec或VecDeque；需要链表拼接、拆分等操作时再比较 |

### 6.1.2 【入门】按操作选择集合

| 你最常做的操作 | 首选 | 原因 |
| --- | --- | --- |
| 按顺序存放、遍历、按下标访问 | Vec | 连续存储，适合顺序访问；实际性能仍须测量 |
| 队头取、队尾放 | VecDeque | 两端移除 O(1)，插入均摊 O(1) |
| 按键查找，不关心顺序 | HashMap | 平均 O(1) |

| 你最常做的操作 | 首选 | 原因 |
| --- | --- | --- |
| 按键查找，且需要有序或区间查询 | BTreeMap | O(log n)，天然有序 |
| 判断“是否出现过” | HashSet | 平均 O(1) |
| 反复取当前最大（或最小）值 | BinaryHeap | 取最大 O(1)，插入与弹出 O(log n) |

### 6.1.3 【进阶】时间复杂度速查

| 操作 | Vec | VecDeque | HashMap/HashSet | BTreeMap/BTreeSet | BinaryHeap |
| --- | --- | --- | --- | --- | --- |
| 按下标访问 | O(1) | O(1) | - | - | - |
| 末尾插入 | 均摊 O(1) | 均摊 O(1) | - | - | - |
| 头部插入 | O(n) | 均摊 O(1) | - | - | - |
| 中间插入/删除 | O(n) | O(n) | - | - | - |
| 按键/值查找 | O(n)（有序时二分O(log n)） | O(n) | 平均 O(1) | O(log n) | O(n) |
| 按键插入/删除 | - | - | 平均 O(1) | O(log n) | O(log n) |
| 取最大值 | O(n) | O(n) | O(n) | O(log n) | O(1) |
| 有序遍历 | 需先排序 | 需先排序 | 不保证顺序 | 天然有序 | 不保证顺序 |

### 6.1.4 【精通】复杂度之外：常数因子与缓存

复杂度描述的是数据规模增长时的趋势，不能直接换算成实际耗时。连续内存通常有利于缓存和预取；具体收益取决于元素大小、访问模式、硬件与编译优化，应当通过测量判断。

元素很少时，线性扫描 Vec 可能比 HashMap 更快，因为它不计算哈希，访问也较连续。不能只根据元素个数下结论，还应测量键的比较成本与实际工作负载。

BTreeMap 的节点存放多个键，某些访问模式可以减少指针跳转。实际性能还取决于键大小、比较成本、缓存和访问分布，应以具体负载测量。

链表节点分别分配，普通遍历通常缺少连续存储的局部性。只有需要特定结构操作时再评估它，不把经验性的性能倾向当作所有场景的定理。

原则：先按语义选集合，写清楚意图；性能问题出现后，用压测和 profiler 的数据说话，而不是凭感觉提前优化。

## 6.2 Vec 与切片深入

第 1.4 节已经讲过 Vec 的创建、增删、遍历和扩容。本节补齐后端开发中常用、但第 1 章没有展开的部分。

### 6.2.1 【入门】批量操作
```rust
fn main() {
    let mut ids: Vec<i64> = Vec::with_capacity(8);

    // 从切片复制追加（要求 T: Clone）
    ids.extend_from_slice(&[3, 1, 2]);

    // 从任意可迭代对象追加
    ids.extend([5, 4]);

    // 把另一个 Vec 的元素全部移过来，对方变空
    ids.append(&mut vec![9, 9]);

    // 取出前两个元素，原 Vec 中删除
    let drained: Vec<i64> = ids.drain(..2).collect();

    // [3, 1] [2, 5, 4, 9, 9]
    println!("{drained:?} {ids:?}");

    // 从下标 3 处一分为二：ids 留前半，tail 拿后半
    let tail = ids.split_off(3);

    // [2, 5, 4] [9, 9]
    println!("{ids:?} {tail:?}");

    // 只保留前 1 个
    ids.truncate(1);

    // 长度调整为 4，不足用 0 补齐：[2, 0, 0, 0]
    ids.resize(4, 0);

    // 全部置为 7
    ids.fill(7);
    println!("{ids:?}");
}
```

drain 在后端中很常见：例如从“待发送事件”缓冲区一次取出一批交给消息队列，同时清空缓冲区，不需要 clone。

### 6.2.2 【入门】删除元素的四种方式

| 方法 | 作用 | 复杂度 | 是否保持顺序 |
| --- | --- | --- | --- |
| pop() | 删除并返回最后一个 | O(1) | 是 |
| remove(i) | 删除下标 i，后面的元素前移 | O(n) | 是 |

| 方法 | 作用 | 复杂度 | 是否保持顺序 |
| --- | --- | --- | --- |
| swap_remove(i) | 用最后一个元素填补下标 i | O(1) | 否 |
| retain(\|x\| 条件) | 只保留满足条件的元素 | O(n) | 是 |

需要删除很多元素时，用一次 retain 代替循环中反复 remove ：后者每次都要移动后面的元素，总复杂度 O(n²)。retain_mut 允许在判断的同时修改元素。

### 6.2.3 【进阶】排序与去重
```rust
#[derive(Debug, Clone)]
struct Item { name: String, price_cents: i64, sold: u32 }

fn main() {
    let mut items = vec![
        Item { name: "鼠标".into(), price_cents: 9_900, sold: 120 },
        Item { name: "键盘".into(), price_cents: 19_900, sold: 80 },
        Item { name: "耳机".into(), price_cents: 9_900, sold: 200 },
    ];

    // 1. 按单个字段
    items.sort_by_key(|i| i.price_cents);

    // 2. 多字段：价格升序，价格相同则销量降序
    items.sort_by(|a, b| a.price_cents.cmp(&b.price_cents).then(b.sold.cmp(&a.sold)));

    // 3. 键需要计算且代价较大时：每个元素只计算一次键
    items.sort_by_cached_key(|i| i.name.to_lowercase());

    // 4. 不关心相等元素的先后顺序时，用 unstable 版本，更快且不额外分配内存
    let mut prices: Vec<i64> = items.iter().map(|i| i.price_cents).collect();
    prices.sort_unstable();

    // 去掉相邻重复
    prices.dedup();

    // [9900, 19900]
    println!("{prices:?}");
    // 5. 按字段去重（相邻）
    items.sort_by_key(|i| i.price_cents);

    // 每个价格只保留第一个
    items.dedup_by_key(|i| i.price_cents);

    // 2
    println!("{}", items.len());
}
```

sort、sort_by、sort_by_key 是稳定排序：比较结果相等的元素保持输入中的相对顺序。sort_unstable 系列不提供这一保证。稳定排序本身不能保证跨请求分页稳定；数据库或输入集合还可能变化。分页至少应增加唯一 ID 作为最终排序键，并根据业务选择游标与一致性快照。

then 与 Ordering ：比较函数返回 std::cmp::Ordering （Less、Equal、Greater）。a.cmp(&amp;b).then(c.cmp(&amp;d)) 表示“先比 a、b，相等时再比 c、d”；把参数顺序反过来（b.cmp(&amp;a)）就是降序。也可以用 .reverse() 或 std::cmp::Reverse 包装键。

### 6.2.4 【进阶】查找
```rust
fn main() {
    let sorted_ids = vec![3_i64, 8, 15, 21, 40];
    match sorted_ids.binary_search(&21) {
        Ok(i) => println!("在下标 {i}"),
        // 返回值同时给出插入位置
        Err(i) => println!("不存在，应插入到下标 {i}"),
    }
    // 把新元素插入到有序 Vec 中并保持有序
    let mut v = sorted_ids.clone();
    let pos = v.binary_search(&10).unwrap_or_else(|i| i);
    v.insert(pos, 10);

    // 按条件二分：第一个大于等于 20 的位置（要求 Vec 已按该条件有序）
    let idx = v.partition_point(|&x| x < 20);

    // [3, 8, 10, 15, 21, 40] 4
    println!("{v:?} {idx}");
}
```

binary_search 只能用于已排序的数据，否则结果没有意义。partition_point 在“按时间戳找某个时间点之后的第一条记录”这类场景很好用。

### 6.2.5 【进阶】切片的窗口与分块
```rust
fn main() {
    let daily_sales = [120, 90, 150, 200, 80, 60, 170];

    // windows：重叠的滑动窗口，计算 3 日移动平均
    let moving_avg: Vec<i32> = daily_sales.windows(3).map(|w| w.iter().sum::<i32>() / 
        3).collect();
    println!("{moving_avg:?}");

    // chunks：不重叠的分块，最后一块可能不满
    for batch in daily_sales.chunks(3) {
        println!("批量写入 {batch:?}");
    }

    // chunks_exact：只给出完整的块，余数单独取
    let exact = daily_sales.chunks_exact(3);
    println!("余数 {:?}", exact.remainder());

    // split_first / split_last：拆出首（尾）元素与其余部分
    if let Some((first, rest)) = daily_sales.split_first() {
        println!("首日 {first}，其余 {} 天", rest.len());
    }

    // 按条件切分
    let csv_line = ["a", "", "b", "c", "", "d"];
    for part in csv_line.split(|s| s.is_empty()) {
        println!("{part:?}");
    }
    // 按相邻元素关系分组：连续相同的值为一组
    let statuses = ["paid", "paid", "shipped", "paid"];
    for group in statuses.chunk_by(|a, b| a == b) {
        println!("{} x {}", group[0], group.len());
    }
}
```

chunks 在后端中极常用：PostgreSQL 单条语句的绑定参数个数有上限（65535 个），批量插入一万行、每行 8 个字段时必须分批写，第 14 章批量导入商品时会用到。

### 6.2.6 【精通】Vec 的内存细节

Vec::new() 不会为元素分配堆内存。对非零大小的元素，第一次需要容量的 push 才可能分配；with_capacity(n) 在 n 大于零时预留容量。零大小类型不需要为元素分配内存。

Vec 保证尾部 push 的均摊常数时间，但不承诺固定的扩容倍数。已知规模时可用 with_capacity 或 reserve 减少重复扩容；不要把某一版标准库的增长策略当成 API 契约。

clear 和 truncate 不主动缩减容量，适合复用缓冲区。shrink_to_fit 会请求缩减容量，但分配器可能保留额外空间，不能保证容量恰好等于长度。

Vec&lt;T&gt; 的元素必须大小相同。需要存放“不同类型但实现同一 trait”的值时用 Vec&lt;Box&lt;dyn Trait&gt;&gt; （第 5.5 节）。

大量小 Vec（例如每个订单一个 Vec&lt;Item&gt; ，平均只有 1~2 个元素）会带来大量小块堆分配。高性能场景可以考虑 smallvec ：元素少时放在栈上，超过阈值才分配堆内存。

返回 Vec&lt;T&gt; 还是 impl Iterator&lt;Item = T&gt; ：调用方需要多次遍历、按下标访问或知道长度时返回 Vec；只需遍历一次且数据量大时返回迭代器，避免一次性占用内存（6.5 节）。

## 6.3 映射与集合深入

### 6.3.1 【入门】HashMap 的 entry API 全解

第 1.4.6 节用过 entry(k).or_insert(v) 。entry API 的完整能力是：只查找一次，就能完成“存在则修改、不存在则插入”的各种组合：
```rust
use std::collections::HashMap;

fn main() {
    let mut stock: HashMap<&str, i32> = HashMap::new();

    // 不存在插入 0，再加 5
    *stock.entry("键盘").or_insert(0) += 5;

    // 用类型默认值（i32 为 0）
    *stock.entry("鼠标").or_default() += 3;

    // 默认值计算昂贵时用闭包，只在需要时执行
    stock.entry("耳机").or_insert_with(|| 10);
    stock.entry("音箱").or_insert_with_key(|k| k.chars().count() as i32);
// 用键计算默认值

    stock.entry("键盘")
        // 存在：修改
        .and_modify(|n| *n -= 1)
        // 不存在：插入
        .or_insert(0);

    // 需要分别处理两种情况时，直接匹配 Entry
    use std::collections::hash_map::Entry;
    match stock.entry("显示器") {
        Entry::Occupied(mut e) => { *e.get_mut() += 1; }
        Entry::Vacant(e) => { e.insert(1); }
    }
    println!("{stock:?}");
}
```

entry API 把同一个 HashMap 上的查找与修改组织为一次入口操作，调用期间的独占借用阻止其他安全代码同时访问该映射。它不提供跨线程或跨进程的数据库原子性。数据库中的查重与写入应由唯一约束、事务及 INSERT ... ON CONFLICT 等语句保证。

### 6.3.2 【入门】其他常用操作
```rust
use std::collections::HashMap;

fn main() {
    let mut prices: HashMap<String, i64> = HashMap::with_capacity(16);
    prices.extend([("键盘".to_string(), 19_900), ("鼠标".to_string(),
9_900)]);

    // 用 &str 查询 String 键：不需要构造 String
    println!("{:?}", prices.get("键盘"));

    // 同时取出键和值
    if let Some((name, price)) = prices.get_key_value("鼠标") { println!("{name}={price}"); }

    // 删除并返回值
    let removed = prices.remove("鼠标");

    // 按条件保留
    prices.retain(|_, p| *p > 10_000);

    // 只遍历键或值
    let names: Vec<&String> = prices.keys().collect();
    let total: i64 = prices.values().sum();

    // 批量打九折
    for p in prices.values_mut() { *p = *p * 9 / 10; }

    // 消耗整个 map 得到键值对
    let pairs: Vec<(String, i64)> = prices.into_iter().collect();
    println!("{removed:?} {names:?} {total} {pairs:?}");
}
```

注意：这段代码故意留了借用错误。 names 借用了 prices ，并且一直用到最后一行的 println!；而在这之间，values_mut 需要可变借用 prices （E0502），into_iter 需要把 prices 整个移走（E0505）。请亲手运行、阅读报错，然后用 2.4.4 节“调整顺序”的技巧修复：在 let names =... 之后立刻打印 names ，让它的借用在修改之前结束。读到这里能一眼看出问题，说明第 2 章已经真正掌握了。

### 6.3.3 【进阶】键的要求与 Borrow

作为 HashMap 键需要 Eq + Hash ；作为 BTreeMap 键需要 Ord 。

get(&amp;self, k: &amp;Q) where K: Borrow&lt;Q&gt; ：这个签名让 HashMap&lt;String, V&gt; 可以用&amp;str 查询，HashMap&lt;ProductId, V&gt; 用 &amp;ProductId 查询。Borrow 要求借用形式与原类型的 Hash 、Eq 结果一致，String 与 str 满足这一点。

键不要可变：放进 map 后再修改键（通过内部可变性）会让它“迷路”，再也查不到。

复合键用元组或结构体：HashMap&lt;(ProductId, String), i32&gt; （商品 + 颜色 → 库存）。

### 6.3.4 【进阶】BTreeMap：有序与区间查询
```rust
use std::collections::BTreeMap;

fn main() {
    // 时间戳 → 当时的库存快照
    let mut snapshots: BTreeMap<i64, i32> = BTreeMap::new();
    for (ts, stock) in [(1_000, 50), (2_000, 42), (3_000, 30), (4_000, 12)] {
        snapshots.insert(ts, stock);
    }

    // 区间查询：[2000, 4000) 之间的记录
    for (ts, stock) in snapshots.range(2_000..4_000) {
        println!("{ts}: {stock}");
    }

    // 某时刻“之前最近的一次”快照：在 ..=t 区间里取最后一个
    let at = snapshots.range(..=2_500).next_back();

    // Some((2000, 42))
    println!("{at:?}");

    println!("{:?} {:?}", snapshots.first_key_value(), snapshots.last_key_value());

    // 弹出最小键
    let oldest = snapshots.pop_first();

    // 键 >= 3000 的部分拆出去
    let recent = snapshots.split_off(&3_000);
    println!("{oldest:?} {snapshots:?} {recent:?}");
}
```

这些区间操作在后端中用于：时间序列、按价格区间筛选、实现“游标分页”（从上一页最后一个键之后继续取，第 14 章用 SQL 实现同样的思想）、第 5.8 节的内存仓储保证分页结果稳定。

### 6.3.5 【进阶】HashSet 与 BTreeSet：集合运算
```rust
use std::collections::{BTreeSet, HashSet};

fn main() {
    let required: HashSet<&str> = ["order:read", "order:write"].into();
    let granted: HashSet<&str> = ["order:read", "product:read"].into();

    // 差集：需要但没有
    let missing: Vec<_> = required.difference(&granted).collect();

    // 交集
    let common: Vec<_> = required.intersection(&granted).collect();

    // 并集，放进有序集合便于输出
    let all: BTreeSet<_> = required.union(&granted).copied().collect();
    println!("{missing:?} {common:?} {all:?}");

    // false：权限不足
    println!("{}", required.is_subset(&granted));

    // insert 返回 bool：是否为新元素。用于“第一次见到才处理”
    let mut seen = HashSet::new();
    for event_id in ["e1", "e2", "e1"] {
        if seen.insert(event_id) { println!("处理 {event_id}"); } else { println!("跳过重复{event_id}"); }
    }
}
```

第 16 章的权限检查、第 29 章消息消费的幂等去重，都是这里集合运算的直接应用。

### 6.3.6 【进阶】VecDeque 与 BinaryHeap
```rust
use std::cmp::Reverse;
use std::collections::{BinaryHeap, VecDeque};

fn main() {
    // VecDeque：只保留最近 3 条操作日志
    let mut recent: VecDeque<String> = VecDeque::with_capacity(3);
    for i in 1..=5 {
        if recent.len() == 3 { recent.pop_front(); }
        recent.push_back(format!("操作{i}"));
    }

    // ["操作3", "操作4", "操作5"]
    println!("{recent:?}");
    // BinaryHeap 默认是最大堆
    let mut heap = BinaryHeap::from([3, 9, 1, 7]);

    // Some(9) Some(9)
    let top = heap.peek().copied();
    let removed = heap.pop();
    println!("{top:?} {removed:?}");

    // 最小堆：用 Reverse 包装。按“执行时间”调度延时任务时，最早的先出来
    let mut tasks = BinaryHeap::new();
    tasks.push(Reverse((1_700_000_300_i64, "关闭未支付订单 1001")));
    tasks.push(Reverse((1_700_000_100_i64, "发送提醒短信")));
    while let Some(Reverse((at, task))) = tasks.pop() {
        // 按时间从早到晚输出
        println!("{at}: {task}");
    }
}
```

VecDeque 内部是环形缓冲区，元素在内存中可能分成两段；需要当作连续切片使用时调用make_contiguous() 。

BinaryHeap 只保证堆顶是最大值，遍历顺序是乱的；要有序输出用 into_sorted_vec()或反复pop() 。

元组按字段依次比较，所以 (时间, 任务) 会先按时间排序。

### 6.3.7 【精通】HashMap 的内部实现与安全

Rust 的 HashMap 基于 Google 的 SwissTable 设计（hashbrown 库）：开放寻址，并用 SIMD 指令一次比较一组控制字节，查找非常快。

默认哈希算法是 SipHash-1-3，带随机种子，可以抵御“哈希洪水”攻击：攻击者构造大量哈希冲突的键（例如请求参数名）让服务退化成 O(n²)。处理外部输入作为键时，保持默认哈希器。

键完全由内部产生（如自增 ID）且追求极致性能时，可以换用 ahash 、rustc-hash（FxHash）等更快的哈希器：HashMap&lt;K, V, BuildHasherDefault&lt;FxHasher&gt;&gt; 。

迭代顺序是随机的，并且每次进程启动都可能不同；测试中不要断言 HashMap 的遍历顺序，需要确定顺序时先收集再排序，或者直接使用 BTreeMap。

HashMap::capacity() 表示在不重新分配的情况下至少还能容纳到多少个元素，不是底层桶数。当前实现会预留空桶，但不要把“capacity 的 7/8”当成触发扩容的公开规则。需要容纳 n 个键值对时直接使用 with_capacity(n)。

## 6.4 闭包深入

第 5.3.4 节从 trait 约束的角度讲了 Fn 、FnMut 、FnOnce 。本节从“闭包本身”讲起：它到底捕获了什么、怎样存放和返回、后端中常见的用法与陷阱。

### 6.4.1 【入门】闭包是什么

闭包是可以捕获周围变量的匿名函数：
```rust
fn main() {
    // 外部变量
    let vip_discount = 95;

    // 闭包捕获了 vip_discount
    let apply = |cents: i64| cents * vip_discount / 100;

    // 9500
    println!("{}", apply(10_000));

    // 参数和返回值类型通常可以推断；多条语句时用花括号
    let describe = |name: &str, stock: i32| -> String {
        if stock > 0 { format!("{name} 有货") } else { format!("{name} 缺货")
}
    };
    println!("{}", describe("键盘", 3));
}
```

普通函数（fn ）不能捕获外部变量，闭包可以--这是两者最本质的区别。

### 6.4.2 【入门】三种捕获方式

编译器根据闭包内部如何使用变量，自动选择最宽松的捕获方式：

| 闭包内部对变量的使用 | 捕获方式 | 闭包实现的 trait |
| --- | --- | --- |
| 只读 | 通常按不可变借用捕获；move 闭包也可拥有只读环境 | Fn （也实现 FnMut、FnOnce） |
| 修改 | 通常按可变借用捕获；move 闭包也可拥有可变环境 | FnMut （也实现 FnOnce） |
| 把值移走（如 drop 或返回） | 闭包取得所有权，并在调用中移出捕获值 | 只实现 FnOnce |
```rust
fn main() {
    let name = String::from("键盘");
    let mut sold = 0;

    // 借用 name：Fn
    let show = || println!("{name}");

    // 可变借用 sold：FnMut，闭包变量本身也要 mut
    let mut sell = || sold += 1;
    show();
    sell();
    sell();

    // sell 的可变借用已结束，可以读取
    println!("已售 {sold}");

    // 返回 name：所有权被移入闭包再移出，只能调用一次
    let consume = move || name;
    let n = consume();
    // consume();                              // 错误 E0382：FnOnce 闭包已被调用过
    println!("{n}");
}
```

闭包持有借用期间，同样受第 2 章借用规则约束：sell 可变借用 sold 的那段时间里，不能读取sold；最后一次调用 sell() 之后借用结束，才能 println! 。

### 6.4.3 【进阶】move 闭包

move 关键字强制闭包获取所有被捕获变量的所有权（Copy 类型则复制一份），而不是借用：
```rust
use std::thread;

fn main() {
    let order_ids = vec![1001, 1002, 1003];
    // 新线程可能比 main 活得更久，不能借用 main 的局部变量，必须 move
    let handle = thread::spawn(move || {
        println!("后台处理 {order_ids:?}");
        order_ids.len()
    });
    // println!("{order_ids:?}");   // 错误 E0382：order_ids 已被移入闭包
    println!("处理了 {} 个", handle.join().expect("后台线程不应 panic"));
}
```

move 不决定闭包实现哪个 Fn trait：move || println!("{order_ids:?}") 拥有 Vec，但内部只读，所以仍然实现 Fn ，可以调用多次。捕获方式（借用还是拥有）和调用方式（Fn/FnMut/FnOnce）是两个独立的维度。

只移动一部分：想让某些变量 move、某些变量借用时，先在闭包外创建引用或克隆，再 move 进去：
```text
let config = String::from("timeout=3s");
let ids = vec![1, 2];

// 准备好要“借用”的部分
let config_ref = &config;
// config_ref（一个引用）被复制进去，ids 被移动
let task = move || println!("{config_ref} {ids:?}");
task();

// config 仍可用
println!("{config}");
```

第 11 章的 tokio::spawn(async move { ... }) 和第 12 章 Axum 状态的 let state=state.clone(); move || ... 都是这个模式。

### 6.4.4 【进阶】Rust 2021 起的精确捕获

2021 Edition 起，闭包只捕获它实际用到的字段，而不是整个结构体：
```rust
struct Ctx { name: String, hits: u32 }

fn main() {
    let mut ctx = Ctx { name: "商品服务".into(), hits: 0 };

    // 只可变借用 ctx.hits
    let mut hit = || ctx.hits += 1;

    // 同时读取 ctx.name：允许
    println!("{}", ctx.name);
    hit();
}
```

在 2018 Edition 中，这段代码会因为闭包借用了整个 ctx 而报错。

### 6.4.5 【进阶】存放与返回闭包

每个闭包都有一个编译器生成的、独一无二且无法写出名字的类型。因此存放和返回闭包时有三种写法：
```rust
// 1. 泛型参数：静态分发，零开销（最常用于“接收”闭包）
fn apply_all<F: Fn(i64) -> i64>(prices: &[i64], f: F) -> Vec<i64> {
    prices.iter().map(|&p| f(p)).collect()
}
// 2. impl Trait：返回单一类型的闭包，零开销
fn discount(percent: i64) -> impl Fn(i64) -> i64 {
    // 必须 move：percent 是参数，函数返回后就不存在了
    move |cents| cents * percent / 100
}

// 3. Box<dyn Fn>：需要在运行时从多种闭包中选择，或存放到集合中
fn pricing_rule(kind: &str) -> Box<dyn Fn(i64) -> i64> {
    match kind {
        "vip" => Box::new(|c| c * 95 / 100),
        "flash" => Box::new(|c| c / 2),
        _ => Box::new(|c| c),
    }
}
/// 结构体中存放回调
struct RetryPolicy<F: Fn(u32) -> u64> {
    max_attempts: u32,
    // 根据第几次重试计算等待毫秒数
    backoff_ms: F,
}

fn main() {
    println!("{:?}", apply_all(&[10_000, 20_000], discount(90)));
    let rules: Vec<Box<dyn Fn(i64) -> i64>> = vec![pricing_rule("vip"), 
        pricing_rule("flash")];
    let final_price = rules.iter().fold(10_000, |acc, rule| rule(acc));

    // 10000 → 9500 → 4750
    println!("{final_price}");

    let policy = RetryPolicy { max_attempts: 3, backoff_ms: |n| 100 * 2_u64.pow(n) };
    for n in 0..policy.max_attempts { println!("第 {} 次重试前等待 {} 毫秒", n + 1, 
        (policy.backoff_ms)(n)); }
}
```

注意最后一行 (policy.backoff_ms)(n) ：调用存在字段里的闭包要加括号，否则编译器会把policy.backoff_ms(n) 当成调用名为 backoff_ms 的方法。

pricing_rule 的各分支若捕获了不同环境，通常产生不同的闭包类型。Box&lt;dyn Fn&gt; 是统一返回类型的一种方法，也可用枚举或把分支移入同一个闭包。不捕获环境的闭包还可以转换成相同签名的函数指针，并非所有分支闭包都必须装箱。

### 6.4.6 【精通】闭包的实现原理

编译器把每个闭包翻译成一个匿名结构体，捕获的变量就是它的字段，再为它实现对应的 Fn trait：
```rust
// let apply = |cents: i64| cents * vip_discount / 100;  大致等价于：
struct Closure<'a> { vip_discount: &'a i64 }
impl<'a> Closure<'a> {
    fn call(&self, cents: i64) -> i64 { cents * *self.vip_discount / 100 }
}
```

由此可以推出几个重要事实：

闭包的内存布局由编译器决定，捕获字段及其对齐会影响大小。无捕获闭包通常是零大小类型，并且可以强制转换为相同调用签名的普通函数指针。不要把“大小恰好等于捕获内容的简单相加”当成布局保证。

闭包是否实现 Clone 、Copy 、Send 、Sync ，取决于它捕获的字段是否实现。捕获了 Rc的闭包不是 Send，因此不能交给 thread::spawn 或 tokio::spawn --这是第 7、11 章中常见报错的根源。

泛型闭包调用可以被单态化，并可能被内联；是否内联由优化器决定。Box&lt;dyn Fn&gt; 引入间接调用，非零大小环境通常还需要堆分配。实际成本应在 release 构建的真实热路径上测量。

### 6.4.7 【精通】后端中闭包的典型用法

延迟计算默认值：unwrap_or_else(|| ...) 、or_insert_with(|| ...) 、ok_or_else(||...) ，只有在需要时才执行昂贵的构造（例如格式化错误信息）。clippy 的or_fun_call 会提示你把 unwrap_or(expensive()) 改成闭包形式。

排序与分组的键：sort_by_key(|x| ...) 、max_by_key 。

把操作作为闭包传给 with_transaction 一类函数，可集中管理资源的进入与退出。第 7 章的 Shared::read/write 用这一形式控制锁的作用域；异步数据库事务还必须处理 Future、借用与提交失败，不能直接照搬同步闭包签名。

中间件与回调：Axum 的 middleware::from_fn 、Tower 的 service_fn 都接受闭包或函数（第12 章）。

配置化策略：重试退避、限流规则、价格计算规则用闭包或 trait 对象表示，便于替换和测试。

| 错误码 | 典型信息 | 原因 | 解决 |
| --- | --- | --- | --- |
| E0373 | closure may outlive the current function, but it borrows x | 线程或返回的闭包借用了局部变量 | 加 move |

## 6.5 迭代器原理与自定义迭代器

### 6.5.1 【入门】Iterator trait 只有一个必需方法
```rust
pub trait Iterator {
    // 关联类型：每次产出的元素类型（第 5.4 节）
    type Item;

    // 有下一个返回 Some，结束返回 None
    fn next(&mut self) -> Option<Self::Item>;
    // ……此外还有七十多个带默认实现的方法：map、filter、sum、collect……
}
```

只要实现了 next ，就自动获得全部适配器和消费器。手动调用 next 可以看清它的工作方式：
```rust
fn main() {
    let prices = vec![19_900, 9_900];

    // 迭代器需要 mut：next 会推进内部位置
    let mut it = prices.iter();

    // Some(19900)
    println!("{:?}", it.next());

    // Some(9900)
    println!("{:?}", it.next());

    // None
    println!("{:?}", it.next());
}
```

### 6.5.2 【入门】for 循环的真面目
```text
for p in &prices { println!("{p}"); }

// 编译器把它展开为：
let mut iter = IntoIterator::into_iter(&prices);
loop {
    match iter.next() {
        Some(p) => { println!("{p}"); }
        None => break,
    }
}
```

for 接受任何实现了 IntoIterator 的值。标准库为集合实现了三种 IntoIterator，对应第 2.4.7 节的三种遍历：&amp;Vec&lt;T&gt; 产出 &amp;T 、&amp;mut Vec&lt;T&gt; 产出 &amp;mut T 、Vec&lt;T&gt; 产出 T 。自己的集合类型也可以实现 IntoIterator 以支持 for 循环。

### 6.5.3 【入门】惰性：不消费就什么都不做
```rust
fn main() {
    let ids = vec![1, 2, 3];
    let mapped = ids.iter().map(|id| {
        // 不会执行！
        println!("处理 {id}");
        id * 10
    });
    println!("还没有任何输出");

    // 直到这里才逐个执行闭包
    let result: Vec<i32> = mapped.collect();
    println!("{result:?}");
}
```

map 、filter 等适配器只是包装出一个新的迭代器，不做任何计算；只有 collect 、sum 、for 等消费器调用 next 时，数据才一个一个地流过整条链。编译器会对“创建了迭代器却没使用”给出警告unused Map that must be used 。

惰性带来两个好处：一是不产生中间集合-- filter().map().take(10) 只处理到凑够 10 个元素为止；二是可以表示无限序列-- (1..).map(...) 是合法的，只要后面有 take 之类的限制。

### 6.5.4 【进阶】实现自定义迭代器

后端中一个实用的例子：把“总条数”切分成一页一页的 (offset, limit) ，用于分批从数据库导出数据：
```rust
/// 依次产出每一页的 (offset, limit)
struct Pages { total: u64, page_size: u64, offset: u64 }

impl Pages {
    fn new(total: u64, page_size: u64) -> Self {
        Self { total, page_size: page_size.max(1), offset: 0 }
    }
}

impl Iterator for Pages {
    type Item = (u64, u64);

    fn next(&mut self) -> Option<Self::Item> {
        if self.offset >= self.total {
            return None;
        }
        let limit = self.page_size.min(self.total - self.offset);
        let page = (self.offset, limit);
        self.offset += limit;
        Some(page)
    }
}

fn main() {
    for (offset, limit) in Pages::new(45, 20) {
        // 三页：20、20、5
        println!("SELECT ... LIMIT {limit} OFFSET {offset}");
    }
    // 自定义迭代器自动拥有所有适配器
    let rows: u64 = Pages::new(45, 20).map(|(_, limit)| limit).sum();

    // 45
    println!("{rows}");
}
```

### 6.5.5 【进阶】快速构造迭代器的函数

不想定义结构体时，标准库提供了几个构造函数：
```rust
use std::iter;

fn main() {
    // from_fn：用闭包实现 next
    let mut n = 0;
    let evens: Vec<u32> = iter::from_fn(|| { n += 2; (n <= 10).then_some(n) }).collect();

    // successors：由前一个值算出下一个，返回 None 时结束。指数退避的等待时间序列：
    let backoff: Vec<u64> = iter::successors(Some(100_u64), |&ms| (ms < 1_600).then(|| ms * 
        2)).collect();

    // [2, 4, 6, 8, 10] [100, 200, 400, 800, 1600]
    println!("{evens:?} {backoff:?}");

    // repeat / repeat_n / once / empty
    let placeholders: Vec<&str> = iter::repeat_n("?", 3).collect();

    // ?, ?, ?   -- 拼 SQL 的 IN (?, ?, ?) 时常用
    println!("{}", placeholders.join(", "));
    let with_header: Vec<&str> = iter::once("id,name").chain(["1,键盘", "2,鼠标"]).collect();
    println!("{with_header:?}");
}
```

| --- | --- | --- |

### 6.6.3 【进阶】collect 的多种目标
```rust
use std::collections::{BTreeMap, HashMap, HashSet};

fn main() {
    let names = ["键盘", "鼠标", "键盘"];

    let v: Vec<&str> = names.iter().copied().collect();

    // 去重
    let set: HashSet<&str> = names.iter().copied().collect();

    // 拼接成一个字符串
    let joined: String = names.iter().copied().collect();

    // 带分隔符：用 join
    let csv = names.join(",");

    // (k, v) 二元组 → map
    let index: HashMap<usize, &str> = names.iter().copied().enumerate().collect();
    let sorted: BTreeMap<&str, usize> = names.iter().map(|n| (*n, n.len())).collect();

    // Result 的“全有或全无”：任何一个解析失败，整体就是 Err
    let ok: Result<Vec<i64>, _> = ["1", "2", "3"].iter().map(|s| s.parse::<i64> ()).collect();
    let bad: Result<Vec<i64>, _> = ["1", "x", "3"].iter().map(|s| s.parse::<i64> 
        ()).collect();
    println!("{v:?} {} {joined} {csv} {} {sorted:?} {ok:?} {}", set.len(), index.len(), 
        bad.is_err());

    // 只想保留成功的、丢弃失败的：用 filter_map + ok
    let lenient: Vec<i64> = ["1", "x", "3"].iter().filter_map(|s| s.parse().ok()).collect();

    // [1, 3]
    println!("{lenient:?}");
}
```

collect::&lt;Result&lt;Vec&lt;_&gt;, _&gt;&gt;() 是后端最常用的技巧之一：批量校验请求中的一组参数，任何一个不合法就整体返回错误（第 4 章的 ? 可以直接接在后面）。

### 6.6.4 【进阶】fold、try_fold 与 scan
```rust
fn main() {
    // 负数表示退款
    let amounts = [19_900_i64, 9_900, -1_000];

    // fold：同时统计收入和退款
    let (income, refund) = amounts.iter().fold((0, 0), |(inc, rf), &a| {
        if a >= 0 { (inc + a, rf) } else { (inc, rf - a) }
    });

    // try_fold：带溢出检查的求和，任何一步溢出就返回 None
    let checked: Option<i64> = amounts.iter().try_fold(0_i64, |acc, &a| acc.checked_add(a));

    // scan：累计余额序列
    let running: Vec<i64> = amounts.iter().scan(0, |bal, &a| { *bal += a; Some(*bal) 
        }).collect();

    // 29800 1000 Some(28800) [19900, 29800, 28800]
    println!("{income} {refund} {checked:?} {running:?}");
}
```

金额求和应当优先使用 try_fold + checked_add ，这是第 1 章“金额计算必须防溢出”在迭代器中的写法，6.8 节的购物车就是这样实现的。

### 6.6.5 【精通】迭代器的性能

迭代器通常能在 release 构建中被内联并融合成紧凑循环，避免中间集合。但生成代码是否与手写循环完全相同、是否向量化，取决于实际代码与优化器，应通过基准和分析工具验证。

避免不必要的中间 collect：v.iter().map(f).collect::&lt;Vec&lt;_&gt;&gt;().iter().filter(g).count() 分配了一个没有必要的 Vec，直接写成v.iter().map(f).filter(g).count() 。

collect 后立刻 len() ：改用 count() 。

iter().cloned() 放在过滤之后：先 filter 再 cloned ，只克隆需要的元素。

短路消费器（find 、any 、all 、position ）找到结果就停止，比先 filter 再collect 后判断空不空更快。

debug 模式下迭代器链比较慢：大量小函数没有被内联；性能比较一律在 --release 下进行。

### 6.7.4 【进阶】Top-N：三种实现与取舍

“销量最高的 N 个商品”是后台报表的常见需求：
```rust
use std::cmp::Reverse;
use std::collections::{BinaryHeap, HashMap};

// 第一步：按商品汇总销量
let mut sold: HashMap<&str, u32> = HashMap::new();
for l in &lines { *sold.entry(l.product).or_default() += l.qty; }

// 方法一：全量排序后截断。简单，O(m log m)，m 为商品数
let mut ranked: Vec<(&str, u32)> = sold.iter().map(|(p, q)| (*p, *q)).collect();

// 销量降序，同销量按名称升序保证结果稳定
ranked.sort_by(|a, b| b.1.cmp(&a.1).then(a.0.cmp(b.0)));
ranked.truncate(2);

// 方法二：大小为 N 的最小堆。O(m log N)，m 很大、N 很小时内存与时间都更省
let mut heap = BinaryHeap::new();
for (p, q) in &sold {
    heap.push(Reverse((*q, *p)));

    // 弹出当前最小的，堆里始终是最大的 N 个
    if heap.len() > 2 { heap.pop(); }
}
let mut top: Vec<(u32, &str)> = heap.into_iter().map(|Reverse(x)| x).collect();
top.sort_by(|a, b| b.cmp(a));

// 方法三：select_nth_unstable 先做 O(m) 的划分，再只对前 N 个排序
println!("{ranked:?} {top:?}");
```

| 方法 | 时间 | 额外内存 | 适用 |
| --- | --- | --- | --- |
| 全量排序 | O(m log m) | 稳定排序可能分配 O(m) 辅助空间；不稳定排序不分配堆缓冲 | 数据量不大（几万以内），代码最简单--首选 |
| 大小为 N 的堆 | O(m log N) | O(N) | 数据量大或以流的形式到来（边读边算） |
| select_nth_unstable | O(m + N log N) 的选取与结果排序 | 无 | 数据已在内存的大 Vec 中 |

排序必须有确定的次序：只按销量排序时，销量相同的商品先后顺序取决于 HashMap 的随机遍历顺序，测试会时好时坏。加上“同销量按名称升序”作为第二排序键，结果就是确定的。

### 6.7.5 【进阶】两个列表的关联：先建索引，避免 O(n²)
```rust
use std::collections::HashMap;

struct Product { name: &'static str, category: &'static str }
let catalog = vec![
    Product { name: "键盘", category: "外设" },
    Product { name: "鼠标", category: "外设" },
    Product { name: "耳机", category: "音频" },
];

// 错误示范：对每个订单行都在 catalog 里线性查找，O(行数 × 商品数)
// 正确做法：先把 catalog 建成 HashMap 索引，O(行数 + 商品数)
let category_of: HashMap<&str, &str> = catalog.iter().map(|p| (p.name, p.category)).collect();
let mut revenue_by_category: HashMap<&str, i64> = HashMap::new();
for l in &lines {
    let cat = category_of.get(l.product).copied().unwrap_or("未分类");
    *revenue_by_category.entry(cat).or_default() += l.amount_cents;
}
println!("{revenue_by_category:?}");
```

这就是数据库“哈希连接”（hash join）的思想。第 14 章遇到“N+1 查询”问题时，解决方法同样是：先一次查出所有关联数据，在内存中建 HashMap，再逐条关联。

### 6.7.6 【精通】什么时候不用迭代器

循环体内有复杂的提前返回、多个可变状态、需要 ? 处理多种错误时，普通 for 循环往往更清晰。迭代器链超过五六步、闭包里嵌套闭包时，考虑拆成具名函数或改写成循环。

需要在遍历中修改集合本身（增删元素）时，迭代器做不到，先收集要修改的内容，遍历结束后再统一修改。

第三方 crate itertools 提供了 group_by （按相邻分组）、sorted_by 、unique 、join、tuple_windows 等大量便利方法，可以按需引入；本书的项目代码只使用标准库，保持依赖精简。

### 6.8.2 业务规则

1. 购物车的一行由“商品 + 数量”组成，单价取加入购物车时的商品价格快照；再次加入同一商品时合并数量，并把单价更新为最新快照。

2. 合并后的数量仍受 Quantity 的 1~99 限制；超过时拒绝本次加入，购物车保持原样，返回ValidationError::OutOfRange 。

3. 小计 = 各行“单价 × 数量”之和；任何一行或总和溢出、超过单笔上限（第 1 章MAX_ORDER_CENTS）时返回 DomainError::Internal 。

4. 优惠规则有两种：满减、全场折扣。多条规则不叠加，结算时选择优惠金额最大的一条；所有规则都不满足时不使用优惠。

5. 不合法的规则（折扣不在 1~99、满减金额为负）视为不生效，优惠为 0，而不是报错--规则由运营配置，单条配置错误不应导致用户无法结算。满减金额超过小计时，最多减到 0 元。

        &self.name
    }

    pub fn unit_price_cents(&self) -> i64 {
        self.unit_price_cents
    }
    pub fn quantity(&self) -> Quantity {
        self.quantity
    }

    /// 本行小计；溢出或超过单笔上限时返回 `None`。
    pub fn subtotal_cents(&self) -> Option<i64> {
        money::line_total(self.unit_price_cents, i64::from(self.quantity.get()))
    }
}

/// 优惠规则。多条规则之间不叠加，结算时自动选择优惠最多的一条。
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Promotion {
    /// 满 `threshold_cents` 减 `off_cents`。
    FullReduction { threshold_cents: i64, off_cents: i64 },
    /// 全场折扣，`percent` 取 1~99，90 表示九折。
    Discount { percent: i64 },
}

impl Promotion {
    /// 计算本规则对给定小计能优惠多少分。
    ///
    /// 不满足条件或规则本身不合法时返回 0；优惠最多减到 0 元。
    ///
    /// 
```
    /// use common::cart::Promotion;
    /// let rule = Promotion::FullReduction { threshold_cents: 30_000, off_cents: 5_000 };
    /// assert_eq!(rule.discount_for(49_700), 5_000);
    /// assert_eq!(rule.discount_for(29_999), 0);
    /// 
```
    pub fn discount_for(&self, subtotal_cents: i64) -> i64 {
        match *self {
            Promotion::FullReduction { threshold_cents, off_cents } => {
                if threshold_cents >= 0 && subtotal_cents >= threshold_cents {
                    off_cents.clamp(0, subtotal_cents)
                } else {
                    0
                }
            }
            Promotion::Discount { percent } => {
                if !(1..=99).contains(&percent) {
                    return 0;
                }
                money::apply_discount(subtotal_cents, percent).map_or(0, |after| 
                    subtotal_cents - after)
            }
        }
    }
}

/// 结算明细。
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct PriceBreakdown {
    /// 优惠前小计
    pub subtotal_cents: i64,
    /// 优惠金额
    pub discount_cents: i64,
    /// 应付金额
    pub payable_cents: i64,
    /// 实际使用的优惠规则；没有满足条件的规则时为 `None`
    pub applied: Option<Promotion>,
}

/// 购物车。
#[derive(Debug, Clone, Default, PartialEq, Eq)]
pub struct Cart {
    lines: Vec<CartLine>,
}

impl Cart {
    pub fn new() -> Self {
        Self::default()
    }

    pub fn lines(&self) -> &[CartLine] {
        &self.lines
    }

    pub fn is_empty(&self) -> bool {
        self.lines.is_empty()
    }
    /// 商品总件数。
    pub fn item_count(&self) -> i32 {
        self.lines.iter().map(|line| line.quantity.get()).sum()
    }

    /// 加入购物车。
    ///
    /// 同一商品合并数量，单价更新为最新快照；合并后超过上限时拒绝，购物车保持不变。
    pub fn add(&mut self, line: CartLine) -> DomainResult<()> {
        if let Some(existing) = self.lines.iter_mut().find(|l| l.product_id == 
            line.product_id) {
            let total = existing.quantity.get() + line.quantity.get();
            // 先校验、成功后才赋值：`?` 提前返回时 existing 没有被修改
            existing.quantity = Quantity::try_new(total).map_err(|_| 
                ValidationError::OutOfRange {
                field: "quantity",
                value: i64::from(total),
                min: 1,
                max: i64::from(Quantity::MAX),
            })?;
            existing.unit_price_cents = line.unit_price_cents;
            return Ok(());
        }
        self.lines.push(line);
        Ok(())
    }

    /// 移除某个商品，返回是否确实移除了。
    pub fn remove(&mut self, product_id: ProductId) -> bool {
        let before = self.lines.len();
        self.lines.retain(|line| line.product_id != product_id);
        self.lines.len() != before
    }

    /// 所有行的小计之和。
    pub fn subtotal_cents(&self) -> DomainResult<i64> {
        self.lines
            .iter()
            .try_fold(0_i64, |acc, line| acc.checked_add(line.subtotal_cents()?))
            .ok_or_else(|| DomainError::Internal("购物车金额溢出或超过单笔上限".to_string()))
    }
    /// 按给定的优惠规则结算，自动选择优惠金额最大的一条。
    pub fn price(&self, promotions: &[Promotion]) -> DomainResult<PriceBreakdown> {
        let subtotal = self.subtotal_cents()?;
        let best = promotions
            .iter()
            .map(|rule| (rule, rule.discount_for(subtotal)))
            .filter(|&(_, discount)| discount > 0)
            .max_by_key(|&(_, discount)| discount);
        let (applied, discount) = match best {
            Some((rule, discount)) => (Some(rule.clone()), discount),
            None => (None, 0),
        };
        Ok(PriceBreakdown {
            subtotal_cents: subtotal,
            discount_cents: discount,
            payable_cents: subtotal - discount,
            applied,
        })
    }
}

### 6.8.4 代码精讲

add 中的 if let ... return 写法：先在 Vec 中用 iter_mut().find 找同一商品；找到就修改并提前返回，找不到才 push 。没有写成 match find { Some =&gt; ..., None =&gt;self.lines.push(...)} ，是为了让“可变借用 existing”与“可变借用 self.lines 来 push”在代码结构上明显分开，读者不必推敲 NLL 的细节就能确认借用合法。

“先校验、后赋值”：existing.quantity = Quantity::try_new(total).map_err(...)?;中，右侧整个表达式先求值；如果 ? 遇到错误就直接返回，赋值根本不会发生。因此失败时 existing 一点都没被修改--测试 merge_over_limit_is_rejected_and_cart_unchanged 用 assert_eq!(cart, before)整体对比来证明这一点（这也是为什么 Cart 要派生 PartialEq 和 Clone ）。注意单价更新写在数量赋值之后，顺序反过来就会出现“数量没变、价格却变了”的半修改状态。

map_err 把字符串错误变成结构化错误：第 3 章的 Quantity::try_new 返回 Result&lt;Self,String&gt;；这里用 map_err 把它转换为带字段名和取值范围的 ValidationError::OutOfRange ，再由 ? 通过第 4 章的 #[from] 自动转换为 DomainError 。上层（第 12 章的 Axum）据此返回 422和清晰的错误信息。

subtotal_cents 中的两层 ? ：try_fold 的闭包返回 Option&lt;i64&gt; ；闭包里的line.subtotal_cents()? 在某一行溢出时让闭包返回 None，checked_add 在总和溢出时返回None；任何一个 None 都会让 try_fold 立刻停止并返回 None，最后被 ok_or_else 转换为DomainError::Internal 。注意这里的 ? 作用于 Option、所在函数是闭包，与外层函数的DomainResult 无关。

为什么溢出是 Internal 而不是 InvalidInput ：用户提交的每个数量都已经通过了 1~99 的校验，单价来自商品数据，金额超过 100 万元意味着数据或配置有异常，属于服务端需要排查的问题。

price 的迭代器链：map 把每条规则映射为“(规则, 优惠额)”，filter 去掉优惠为 0 的规则，max_by_key 取优惠最大的一条。filter(|&amp;(_, discount)| ...) 中的 &amp;(_, discount)是 3.5节的引用模式：filter 的闭包参数是对元素的引用，用模式直接解构出 Copy 的 discount 。多条规则优惠相同时，max_by_key 返回最后一条--如果业务要求“相同时取排在前面的规则”，可以改用.rev().max_by_key(...) 或在比较键中加入下标。

discount_for 中的 match *self ：对 &amp;self 解引用后匹配，绑定的字段都是 i64（Copy），不会移动任何东西。off_cents.clamp(0, subtotal_cents) 同时处理“满减金额为负”和“满减超过小计”两种情况；能走到这一行时已经保证 subtotal_cents &gt;= threshold_cents &gt;= 0 ，clamp的下限不会大于上限（否则 clamp 会 panic）。

### 6.8.9 本章小结

选择集合先看操作：顺序存取用 Vec，两端进出用 VecDeque，按键查找用 HashMap，需要有序或区间查询用 BTreeMap，去重与集合运算用 HashSet，反复取最大值用 BinaryHeap。

Vec 的批量操作（drain 、retain 、split_off ）、稳定与不稳定排序、binary_search 、windows / chunks / chunk_by 覆盖了绝大多数列表处理需求。

entry API 一次查找完成“有则改、无则插”；BTreeMap 的 range 支持区间查询；默认哈希器能抵御哈希洪水，测试不要依赖 HashMap 的遍历顺序。

闭包按使用方式自动选择借用或获取所有权；move 决定捕获方式，Fn/FnMut/FnOnce 由闭包内部的用法决定；返回闭包用 impl Fn ，在运行时选择或存入集合用 Box&lt;dyn Fn&gt; 。

迭代器是惰性的，适配器组装管道、消费器驱动执行；release 模式下与手写循环一样快。collect可以生成多种集合，collect::&lt;Result&lt;Vec&lt;_&gt;, _&gt;&gt;() 实现“全有或全无”；金额求和用try_fold + checked_add 。

业务统计的套路：分组用 entry().or_default() ，保序去重用 HashSet::insert 的返回值，Top-N 按数据规模选排序或堆，两个列表关联先建 HashMap 索引。
