# 第 36 章 持久化订单与可恢复的 Saga

第35章让支付意图能够重放，并用退款屏障抵挡迟到付款。现在把用户、商品、库存和支付连成同一条订单主线：HTTP建立持久订单，独立worker推进下一步，进程退出后仍能从数据库继续。

本章新增订单库、步骤审计、领取租约和worker，同时建立使用新users身份的商品HTTP适配器与edge入口。前章商品资料编辑、库存覆盖拒绝、创建幂等、会话撤销和有界客户端全部保留。新入口先使用独立实验数据集，不静默把旧身份库的编号搬到新服务。

学完应能解释202与完成的区别，按数据库事实推演五个崩溃窗口，核对租约过期与旧持有者的条件写入，并用七个真实进程做出可恢复的单商品订单。

## 36.1 从一条请求走向持久业务寿命

### 36.1.1 【入门】HTTP只建立可恢复起点

POST /api/v1/orders提交商品编号和数量，服务认证用户、读取权威商品价格、计算金额并保存订单，返回202与订单UUID。它表示意图已接受，不表示支付、库存与订单都已完成。

客户端随后GET /api/v1/orders/{id}。订单可能还在reserving或charging，也可能已进入completed、cancelled或manual；创建请求重放返回同一身份及当前进度，不冻结第一次响应中的状态字段。

### 36.1.2 【入门】为什么不能只写一串await

如果预留、付款、确认都放在一次HTTP调用栈中，浏览器超时或部署重启就会丢失“接下来该做什么”。数据库必须保存业务步骤，独立worker从持久状态继续执行。

一串await仍可作为某次步骤内部的实现，但不能成为唯一恢复记录。网络请求结束与业务责任结束是两件事。

### 36.1.3 【进阶】本章每单一种商品

订单保存product_id、quantity、unit_price和amount，数量1-999，金额为正且不超过100000000分。免费领取和多行购物车需要不同的业务模型。

多行订单要为每行建立稳定预留身份，保存成功与待补偿行，不能循环扣库存后只写一个总状态。前章集合练习继续保留，本章把跨服务失败规则先落实在单商品主线上。

### 36.1.4 【精通】Saga依靠本地提交与恢复

订单库、商品库、支付库没有共享SQL事务。每个参与者保护自己的收据和不变量，协调者保存步骤，重复交付时保持同一身份与输入，必要时执行退款或释放。

本章不采用“本地rollback能撤销远程提交”的假设，也不会因为重试次数很多就自动宣布付款未发生。

## 36.2 两种身份、价格冻结与访问控制

### 36.2.1 【入门】请求键与订单ID分别负责什么

Idempotency-Key须恰好一个、可解析为非nil UUID。唯一范围是actor_id与request_key；同一用户同一键只建立一笔订单，不同用户可以使用相同键。

服务端另生成订单UUID作为库存和支付的saga_id。请求键回答“这次创建请求是否重复”，订单ID回答“后续参与者操作属于哪笔订单”。

### 36.2.2 【进阶】先查原订单，再读取商品

重复请求先读原收据，检查商品与数量绑定，返回原订单。商品后来涨价、下架或暂时离线，不应让已接受请求重新冻结另一个金额。

并发首次请求都读取商品后，数据库唯一约束决定哪笔插入胜出；合法报价的竞争者随后读取胜出订单。同键改变商品或数量返回409，不能顺便修改原订单。

### 36.2.3 【进阶】冻结不等于永久报价承诺

worker的Reserve携带保存的unit_price，库存事务再次核对商品价格、上下架与可售量。当前价格已变化时，预留稳定拒绝，订单走取消路径。

本章没有独立报价有效期或价格锁；若需要承诺报价，应单独保存并验证相应规则，不能一边声称冻结、一边在预留时换成最新价格。

### 36.2.4 【精通】订单UUID难猜也必须检查所有者

查询同时匹配订单ID与已认证actor_id，其他用户访问统一404。客户端提交的actor_id等未知字段由请求契约拒绝，身份始终由UserRemote取得。

订单业务路由先认证，再进入正文和路径处理。伪造角色头、服务头或用户号都不能替代真实会话。

## 36.3 把未完成责任写成状态机

### 36.3.1 【入门】完整自动推进表

| 当前步骤 | 外部动作 | 明确结果 | 下一步 |
| --- | --- | --- | --- |
| reserving | Reserve | Held | charging |
| reserving | Reserve | Rejected或Released | cancelled |
| charging | Charge | Paid | confirming |
| charging | Charge | Declined或Refunded | releasing |
| confirming | Confirm | Confirmed | completed |
| confirming | Confirm | Released或Rejected | refunding |
| refunding | Refund | Refunded或Declined | releasing |
| releasing | Release | Released或Rejected | cancelled |
| 任一自动步骤 | 与当前责任矛盾的参与者事实 | 无法安全解释 | manual |

网络失败保持原步骤并延后执行。具体契约不一致进入manual，服务凭据临时不可用保留重试并要求运维修复，不能都变成取消。

### 36.3.2 【入门】终态表达什么

completed表示当前流程已接受支付并确认库存。cancelled表示本流程已处理必要关闭责任，没有仍应继续释放的Held。manual表示自动协议发现矛盾，需要核查，它不等于成功或取消。

例如releasing却看见库存Confirmed，普通Release不会把已确认库存加回；本章停在manual，不伪造cancelled。真实业务可能需要退货或反向履约模型，不能在此处手改一个数字冒充补偿。

### 36.3.3 【进阶】用纯规则先核对

完整orders.rs中的allowed、inventory_outcome和payment_outcome不访问数据库。文件加入后先执行：
```bash
cargo +1.92.0 test --locked -p commerce --lib orders::tests
```

三个测试检查合法无环转移、矛盾参与者不成为假成功、未知传输结果与契约错误分流。它们帮助理解状态表，持久化和并发正确性还需真实数据库验证。

### 36.3.4 【精通】支付超时为何不能直接释放

Charge超时可能已经Paid。若立即释放库存并取消，便可能形成“钱收了、货退回可售”的错误组合。本章保持charging，以原订单UUID、actor和amount重放支付。

参与者收据提供稳定事实，协调者步骤提供恢复责任。二者都不能被一个通用catch错误分支替代。

## 36.4 订单迁移与步骤审计

### 36.4.1 【入门】新增订单库迁移

文件services/commerce/migrations/orders/0001_orders.sql：
```sql
CREATE TABLE orders (
 id UUID PRIMARY KEY CHECK(id<>'00000000-0000-0000-0000-000000000000'),
 actor_id BIGINT NOT NULL CHECK(actor_id>0),
 request_key UUID NOT NULL CHECK(request_key<>'00000000-0000-0000-0000-000000000000'),
 product_id BIGINT NOT NULL CHECK(product_id>0),
 quantity INTEGER NOT NULL CHECK(quantity BETWEEN 1 AND 999),
 unit_price BIGINT NOT NULL CHECK(unit_price BETWEEN 1 AND 100000000),
 amount BIGINT NOT NULL CHECK(amount BETWEEN 1 AND 100000000),
 state TEXT NOT NULL DEFAULT 'reserving' CHECK(state IN
 ('reserving','charging','confirming','releasing','refunding','completed','cancelled','manual')),
 attempts INTEGER NOT NULL DEFAULT 0 CHECK(attempts BETWEEN 0 AND 1000000),
 next_attempt TIMESTAMPTZ NOT NULL DEFAULT now(),
 lease_token UUID, leased_until TIMESTAMPTZ,
 last_error TEXT CHECK(char_length(last_error)<=64),
 created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 UNIQUE(actor_id,request_key),
 CHECK(amount=unit_price*quantity),
 CHECK((lease_token IS NULL)=(leased_until IS NULL)),
 CHECK(lease_token IS NULL OR lease_token<>'00000000-0000-0000-0000-000000000000'),
 CHECK(state NOT IN ('completed','cancelled','manual') OR lease_token IS NULL)
);
CREATE INDEX orders_work ON orders(next_attempt,id)
 WHERE state NOT IN ('completed','cancelled','manual');
CREATE TABLE order_transitions (
 id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
 order_id UUID NOT NULL REFERENCES orders(id),
 from_state TEXT NOT NULL, to_state TEXT NOT NULL,
 reason TEXT NOT NULL CHECK(char_length(reason) BETWEEN 1 AND 64),
 occurred_at TIMESTAMPTZ NOT NULL DEFAULT now(),
 UNIQUE(order_id,from_state),
 CHECK(
  (from_state='reserving' AND to_state IN ('charging','cancelled','manual')) OR
  (from_state='charging' AND to_state IN ('confirming','releasing','manual')) OR
  (from_state='confirming' AND to_state IN ('completed','refunding','manual')) OR
  (from_state='refunding' AND to_state IN ('releasing','manual')) OR
  (from_state='releasing' AND to_state IN ('cancelled','manual'))
 )
);
```

orders保存请求身份、冻结金额、当前步骤、尝试次数、下一次时间与租约。order_transitions保存步骤变化和稳定原因类别；两表在状态推进时一起提交。

### 36.4.2 【进阶】约束保护哪些形状

UUID不能nil，金额与单价、数量一致，租约token与到期时间同时为空或同时存在；终态不能继续持有租约。尝试次数封顶，避免长期故障后整数溢出使任务再也无法领取。

审计表CHECK限定合法有向边，唯一(order_id,from_state)符合当前无环状态机。将来若允许重新授权或重新预留，需要步骤实例编号，而不是删除唯一约束后继续复用旧步骤身份。

### 36.4.3 【精通】历史与时间列不能替代协议

occurred_at便于诊断，但数据库事务时间不是跨服务的绝对先后。步骤边、参与者收据、订单ID与租约token共同解释执行事实。

当前没有将manual恢复成自动步骤的公网接口。人工核查要保留审计，后续恢复设计也必须考虑步骤唯一约束，不能批量UPDATE状态后声称协议自然恢复。

```rust
fn request_key(h: &HeaderMap) -> ApiResult<Uuid> {
    if h.get_all("idempotency-key").iter().count() != 1 {
        return Err(invalid());
    }
    h.get("idempotency-key")
        .and_then(|s| s.to_str().ok())
        .and_then(|s| Uuid::parse_str(s).ok())
        .filter(|s| !s.is_nil())
        .ok_or_else(invalid)
}
async fn create(
    State(s): State<Orders>,
    Extension(Actor(actor)): Extension<Actor>,
    h: HeaderMap,
    BodyJson(d): BodyJson<Draft>,

        return Err(invalid());

    Ok((
        StatusCode::ACCEPTED,
        Json(insert(&s.pool, actor, key, &d, product.price_cents).await?),
    ))
}

pub async fn claim(pool: &PgPool) -> anyhow::Result<Option<(Order, Uuid)>> {
    let token = Uuid::new_v4();
    let fields = FIELDS
        .split(',')
        .map(|s| format!("o.{s}"))
        .collect::<Vec<_>>()
        .join(",");
    let row=sqlx::query_as::<_,Order>(&format!("WITH picked AS (
        SELECT id FROM orders WHERE state NOT IN ('completed','cancelled','manual')
        AND next_attempt<=clock_timestamp() AND (leased_until IS NULL OR leased_until<=clock_timestamp())
        ORDER BY next_attempt,id FOR UPDATE SKIP LOCKED LIMIT 1)
        UPDATE orders o SET lease_token=$1,leased_until=clock_timestamp()+interval '15 seconds',
        attempts=LEAST(o.attempts::bigint+1,1000000)::integer
        FROM picked p WHERE o.id=p.id RETURNING {fields}"))
        .bind(token).fetch_optional(pool).await?;
    if let Some(row) = &row {
        anyhow::ensure!(row.valid(), "invalid stored order");
    }
    Ok(row.map(|row| (row, token)))
}
pub fn allowed(from: &str, to: &str) -> bool {
    match from {
        "reserving" => matches!(to, "charging" | "cancelled" | "manual"),
        "charging" => matches!(to, "confirming" | "releasing" | "manual"),
        "confirming" => matches!(to, "completed" | "refunding" | "manual"),
        "refunding" => matches!(to, "releasing" | "manual"),
        "releasing" => matches!(to, "cancelled" | "manual"),
        _ => false,
    }
}
pub async fn advance(
    pool: &PgPool,
    row: &Order,
    token: Uuid,
    next: &str,
    reason: &str,
) -> anyhow::Result<bool> {
    anyhow::ensure!(
        row.valid() && allowed(&row.state, next) && !reason.is_empty() && reason.len() <= 64,
        "invalid order transition"
    );
    let mut tx = pool.begin().await?;
    let count=sqlx::query("UPDATE orders SET state=$4,lease_token=NULL,leased_until=NULL,next_attempt=clock_timestamp(),last_error=NULL,updated_at=now()
        WHERE id=$1 AND lease_token=$2 AND state=$3 AND leased_until>clock_timestamp()")
        .bind(row.id).bind(token).bind(&row.state).bind(next).execute(&mut *tx).await?.rows_affected();
    if count == 1 {
        sqlx::query("INSERT INTO order_transitions(order_id,from_state,to_state,reason) VALUES($1,$2,$3,$4)")
        .bind(row.id).bind(&row.state).bind(next).bind(reason).execute(&mut *tx).await?;
    }
    tx.commit().await?;
    Ok(count == 1)
}
pub async fn defer(pool: &PgPool, row: &Order, token: Uuid, reason: &str) -> anyhow::Result<bool> {
    anyhow::ensure!(
        !reason.is_empty() && reason.len() <= 64,
        "invalid retry category"
    );
    let delay = (1_i64 << row.attempts.clamp(0, 5)) + i64::from(row.id.as_bytes()[0] % 5);
    Ok(sqlx::query("UPDATE orders SET lease_token=NULL,leased_until=NULL,next_attempt=clock_timestamp()+$4*interval '1 second',last_error=$5,updated_at=now()
        WHERE id=$1 AND lease_token=$2 AND state=$3 AND leased_until>clock_timestamp()")
        .bind(row.id).bind(token).bind(&row.state).bind(delay).bind(reason).execute(pool).await?.rows_affected()==1)
}
#[derive(Debug, PartialEq, Eq)]
pub enum Outcome {
    Advance(&'static str, &'static str),
    Retry(&'static str),
}
pub fn inventory_outcome(step: &str, state: StockState) -> Outcome {
    use Outcome::Advance;
    match (step, state) {
        ("reserving", StockState::Held) => Advance("charging", "inventory-held"),
        ("reserving", StockState::Rejected | StockState::Released) => {
            Advance("cancelled", "inventory-closed")
        }
        ("confirming", StockState::Confirmed) => Advance("completed", "inventory-confirmed"),
        ("confirming", StockState::Released | StockState::Rejected) => {
            Advance("refunding", "inventory-unconfirmable")
        }
        ("releasing", StockState::Released | StockState::Rejected) => {
            Advance("cancelled", "inventory-released")
        }
        _ => Advance("manual", "inconsistent-inventory"),
    }
}
pub fn payment_outcome(step: &str, state: PayState) -> Outcome {
    use Outcome::Advance;
    match (step, state) {
        ("charging", PayState::Paid) => Advance("confirming", "payment-paid"),
        ("charging", PayState::Declined | PayState::Refunded) => {
            Advance("releasing", "payment-closed")
        }
        ("refunding", PayState::Refunded | PayState::Declined) => {
            Advance("releasing", "payment-refunded")
        }
        _ => Advance("manual", "inconsistent-payment"),
    }
}
fn inventory_error(error: tonic::Status) -> Outcome {
    match error.code() {
        tonic::Code::InvalidArgument | tonic::Code::FailedPrecondition | tonic::Code::DataLoss => {
            Outcome::Advance("manual", "inventory-contract")
        }
        tonic::Code::Unauthenticated | tonic::Code::PermissionDenied => {
            Outcome::Retry("inventory-auth-unavailable")
        }
        _ => Outcome::Retry("inventory-result-unknown"),
    }
}
fn payment_error(error: RemoteError) -> Outcome {
    match error {
        RemoteError::InvalidInput | RemoteError::IdentityConflict | RemoteError::Protocol => {
            Outcome::Advance("manual", "payment-contract")
        }
        RemoteError::Unauthenticated => Outcome::Retry("payment-auth-unavailable"),
        _ => Outcome::Retry("payment-result-unknown"),
    }
}
pub async fn step(s: &Worker, row: &Order) -> anyhow::Result<Outcome> {
    anyhow::ensure!(row.valid(), "invalid stored order");
    match row.state.as_str() {
        "reserving" | "confirming" | "releasing" => {
            let action = match row.state.as_str() {
                "reserving" => Action::Reserve,
                "confirming" => Action::Confirm,
                _ => Action::Release,
            };
            Ok(match s.inventory.apply(&row.reservation(), action).await {
                Ok(state) => inventory_outcome(&row.state, state),
                Err(e) => inventory_error(e),
            })
        }
        "charging" | "refunding" => {
            let action = if row.state == "charging" {
                PayAction::Charge
            } else {
                PayAction::Refund
            };
            Ok(match s.payments.apply(&row.charge(), action).await {
                Ok(p) => payment_outcome(&row.state, p.state),
                Err(e) => payment_error(e),
            })
        }
        _ => anyhow::bail!("no automatic work for terminal state"),
    }
}
pub async fn run(s: Worker, stop: CancellationToken) -> anyhow::Result<()> {
    loop {
        if stop.is_cancelled() {
            return Ok(());
        }
        match claim(&s.pool).await {
            Ok(Some((row, token))) => {
                let result = tokio::time::timeout(Duration::from_secs(5), step(&s, &row)).await;
                match result {
                    Ok(Ok(Outcome::Advance(next, reason))) => {
                        let owned = advance(&s.pool, &row, token, next, reason).await?;
                        tracing::info!(order_id=%row.id,from=%row.state,to=next,owned,"saga transition attempted");
                    }
                    Ok(Ok(Outcome::Retry(reason))) => {
                        defer(&s.pool, &row, token, reason).await?;
                    }
                    Ok(Err(error)) => {
                        tracing::error!(order_id=%row.id,%error,"invalid saga work");
                        return Err(error);
                    }
                    Err(_) => {
                        defer(&s.pool, &row, token, "step-budget-unknown").await?;
                    }
                }
            }
            Ok(None) => {
                tokio::select! {_=stop.cancelled()=>return Ok(()),_=tokio::time::sleep(Duration::from_millis(200))=>{}}
            }
            Err(error) => {
                tracing::error!(%error,"order claim failed");
                tokio::select! {_=stop.cancelled()=>return Ok(()),_=tokio::time::sleep(Duration::from_secs(1))=>{}}
            }
        }
    }
}
```

### 36.5.2 【进阶】创建入口逐段理解

认证中间件取得actor并放入请求扩展，处理器读取单一幂等键。existing命中先same核对绑定，再返回同UUID；首次才读取商品并checked_mul计算金额。

SQL值全部使用bind。FIELDS只是固定列名常量，用于生成查询列清单，不拼接请求输入。数据库以唯一约束解决并发首次插入，最后再读回胜出的收据。

### 36.5.3 【进阶】领取任务是短事务边界

claim用WITH选择一个到期非终态订单，FOR UPDATE SKIP LOCKED避开已被其他领取者锁定的行，同一语句写入随机token、15秒租约与尝试次数，然后返回。

远程调用在领取提交后执行，不持有跨网络的长SQL事务。[PostgreSQL SELECT文档](https://www.postgresql.org/docs/17/sql-select.html)说明SKIP LOCKED适合这类队列消费者场景，也会跳过部分行，不能把它当作一致的全表业务快照。

### 36.5.4 【精通】租约不是互斥锁的延长版

旧worker可能暂停超过15秒，新worker已接手，旧进程又恢复。advance和defer必须同时匹配订单ID、步骤、token与未过期租约；旧持有者不能覆盖新状态或延后新任务。

旧worker仍可能发出迟到RPC，所以租约不足以独自保证副作用安全。库存与支付继续按同一订单UUID和参数去重，并以屏障保护关闭后的身份。

### 36.5.5 【精通】用数据库当前时刻判断到期

领取、到期条件和下一次执行使用clock_timestamp，而不是把长事务起始时间误当当前时间。[PostgreSQL时间函数文档](https://www.postgresql.org/docs/17/functions-datetime.html)区分了这些时间来源。

这仍依赖数据库时钟与运行条件，不是跨机器物理时钟永远不跳的证明。租约时长须覆盖正常步骤预算和保存余量，暂停、网络分区与时钟异常仍要测试和监控。

### 36.5.6 【进阶】推进和审计共同提交

advance先校验合法边，再条件UPDATE清租约、变步骤，若命中一行则插入order_transitions，最后commit。审计失败回滚状态与租约，不留下“状态变了但历史没有”。

返回false代表本次没有有效所有权，不应记录成已经完成一次推进。worker日志保存owned，让排查者看到这项差别。

### 36.5.7 【精通】重试保留步骤，不猜业务结果

defer只释放当前有效租约，保存有限指数退避与稳定扰动、错误类别。当前上限约32秒再加0-4秒扰动，尝试数不因进程重启清零。

未知结果持续恢复，不在第N次错误后自动取消；契约冲突或矛盾事实转manual。真实业务期限需要查询、关闭屏障与补偿共同设计，不能只加一个任务超时字段便宣称安全。

### 36.5.8 【精通】worker退出也是恢复路径

run在空队列或领取失败时可响应停止信号；已开始步骤有五秒外层预算，完成本次条件保存后退出。主入口给停止过程独立等待预算。

保存推进失败可能使worker返回错误退出，租约保留至到期，其他实例仍能重放参与者。部署应有重启与告警，不能把任何进程退出都当作订单已取消。

```rust
    }

impl CatalogRemote {
    pub async fn connect(address: &str, key: ServiceKey) -> anyhow::Result<Self> {
        let endpoint = Endpoint::from_shared(address.to_owned())?
            .connect_timeout(Duration::from_millis(300))
            .timeout(Duration::from_millis(900));
        let channel = tokio::time::timeout(Duration::from_secs(1), endpoint.connect()).await??;

            client: CatalogClient::new(channel.clone())
                .max_decoding_message_size(64 * 1024)
                .max_encoding_message_size(64 * 1024),

        })

        let mut r = tonic::Request::new(value);
        self.key.attach(&mut r);
        r.set_timeout(Duration::from_millis(700));
        r
    }
    pub async fn get(&self, id: i64) -> ApiResult<Product> {
        if id <= 0 {
            return Err(invalid());
        }

            Duration::from_secs(1),
            self.client
                .clone()
                .get_product(self.request(GetProductRequest { id })),

        .map_err(error)?

            return Err(unavailable());

    }

            return Err(invalid());

            Duration::from_secs(1),
            self.client
                .clone()
                .list_products(self.request(ListProductsRequest { limit, offset })),

        .map_err(error)?

            return Err(unavailable());
        }
        for row in &p.items {
            check(row)?;
        }
        Ok(p)
    }

        .map_err(error)?
        .into_inner();
        check(&p)?;

    }
    pub async fn update(&self, value: UpdateProductRequest) -> ApiResult<Product> {
        if value.id <= 0 {
            return Err(invalid());
        }
        let id = value.id;

            Duration::from_secs(1),
            self.client.clone().update_product(self.request(value)),
        )

        .map_err(error)?

        }

                .clone()
                .delist_product(self.request(GetProductRequest { id })),

        .await
        .map_err(|_| unavailable())?
        .map_err(error)?;
        Ok(())
    }

        matches!(tokio::time::timeout(Duration::from_millis(500),self.health.clone().check(tonic::Request::new(HealthCheckRequest{service:"readiness".into()}))).await,
            Ok(Ok(r)) if r.get_ref().status==ServingStatus::Serving as i32)
    }
}
```

```rust
        .route("/api/v1/users/me", any(proxy))
        .route("/api/v1/orders", any(proxy))
        .route("/api/v1/orders/{id}", any(proxy))
        .route("/api/v1/products", any(proxy))
        .route("/api/v1/products/{id}", any(proxy))
        .route("/healthz", get(|| async { StatusCode::OK }))
        .route(
            "/readyz",
            get(move || {
                let s = ready.clone();
                async move {
                    let checks = s.client.get(format!("{}/readyz", s.users)).send();
                    let b = s.client.get(format!("{}/readyz", s.orders)).send();
                    let c = s.client.get(format!("{}/readyz", s.catalog)).send();
                    match tokio::time::timeout(Duration::from_secs(2), async {
                        tokio::join!(checks, b, c)
                    })
                    .await
                    {
                        Ok((Ok(a), Ok(b), Ok(c)))
                            if [a.status(), b.status(), c.status()]
                                .iter()
                                .all(|s| *s == StatusCode::OK) =>
                        {
                            StatusCode::OK
                        }
                        _ => StatusCode::SERVICE_UNAVAILABLE,
                    }
                }
            }),
        )
        .layer(cors)
        .with_state(s)
}
async fn proxy(State(s): State<Edge>, r: Request) -> ApiResult<Response> {
    let _permit = enter(&s.capacity)?;
    let path = r.uri().path_and_query().ok_or_else(invalid)?.as_str();
    let base =
        if r.uri().path().starts_with("/api/v1/auth/") || r.uri().path() == "/api/v1/users/me" {
            &s.users
        } else if r.uri().path().starts_with("/api/v1/orders") {
            &s.orders
        } else {
            &s.catalog
        };
    let mut upstream = s
        .client
        .request(r.method().clone(), format!("{base}{path}"));
    let mut hop = Vec::new();
    for value in r.headers().get_all("connection") {
        let value = value.to_str().map_err(|_| invalid())?;
        for name in value.split(',').map(str::trim) {
            hop.push(axum::http::HeaderName::from_bytes(name.as_bytes()).map_err(|_| invalid())?);
        }
    }
    // Whitelist preserves no client-supplied role, service credential or hop-by-hop headers.
    for name in ["authorization", "content-type", "idempotency-key"] {
        if r.headers().get_all(name).iter().count() > 1 {
            return Err(invalid());
        }
        if hop.iter().any(|h| h.as_str() == name) {
            continue;
        }
        if let Some(value) = r.headers().get(name) {
            upstream = upstream.header(name, value);
        }
    }
    let body = to_bytes(r.into_body(), 64 * 1024)
        .await
        .map_err(|_| ApiError(StatusCode::PAYLOAD_TOO_LARGE, "body too large"))?;
    let mut response = upstream
        .body(body)
        .send()
        .await
        .map_err(|_| unavailable())?;
    let status = response.status();
    let ct = response.headers().get("content-type").cloned();
    let mut bytes = Vec::new();
    while let Some(chunk) = response.chunk().await.map_err(|_| unavailable())? {
        if bytes.len().saturating_add(chunk.len()) > 1024 * 1024 {
            return Err(unavailable());
        }
        bytes.extend_from_slice(&chunk);
    }
    let mut out = Response::new(Body::from(bytes));
    *out.status_mut() = status;
    if let Some(ct) = ct {
        out.headers_mut().insert("content-type", ct);
    }
    out.headers_mut()
        .insert("cache-control", HeaderValue::from_static("no-store"));
    Ok(out)
}
```

上游来自固定配置origin，按已登记路径分发；内部支付路径未注册为公共路径。请求头白名单只传认证、正文类型与幂等键，不传客户端伪造角色或服务凭据，并处理Connection点名的逐跳头。

### 36.7.2 【进阶】浏览器预检也是链路的一部分

CORS只允许配置的前端origin，明确允许GET/POST/PUT/DELETE和authorization、content-type、idempotency-key，并暴露响应x-request-id。不能只用curl证明POST成功，随后让浏览器因缺幂等头预检而无法下单。

本章采用Bearer头，没有开启任意origin加凭据的组合。CORS不能代替认证，来自允许origin的伪造管理员仍应被资源服务拒绝。

### 36.7.3 【进阶】请求与回复都有限制

edge在途数有限，正文64KiB、上游回复1MiB，禁止重定向，客户端三秒预算覆盖响应读取；最外层继续使用第34章bounded。

上游即使没有Content-Length或声称错误长度，也按实际已读字节限制。内部用户、订单和商品正文仍各自限制4KiB；网关限制不替代资源服务保护。

### 36.7.4 【精通】与旧入口的关系

前章services/gateway与过渡monolith作为阶段练习保留。本章新edge先在独立数据集验证完整链路，不把旧身份库的用户7和新users中的用户7自动混认。

真实存量切流需要账号ID、用户名冲突、密码哈希、旧令牌失效和关联业务映射演练；后续交付继续验收。当前实验不是已经迁移历史数据的证明。

```python
"""Load one generated role, remove inherited profile settings, and exec a built binary."""
import argparse
import importlib.util
import json
import os
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]
ROLES = ['catalog', 'users', 'payments', 'orders', 'worker', 'catalog-http', 'edge']
def read(path):
    values = {}
    for line in path.read_text().splitlines():
        if line.strip() and not line.lstrip().startswith('#'):
            key, value = line.split('=', 1)
            if not key or not all(c.isascii() and (c.isalnum() or c == '_') for c in key):
                raise ValueError('invalid profile variable name')
            values[key] = value
    return values

def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument('role', choices=ROLES)
    parser.add_argument('--migrate', action='store_true')
    parser.add_argument('--check', action='store_true')
    parser.add_argument('--profile-dir', type=Path, default=Path('.saga.local'))
    parser.add_argument('--bin-dir', type=Path)
    args = parser.parse_args()
    ledger = json.loads((ROOT/'docs/runtime-boundaries.json').read_text())
    environment = dict(os.environ)
    # Each generated role gets only its own settings, even in a previously loaded shell.
    for path in args.profile_dir.glob('*.env'):
        for name in read(path): environment.pop(name, None)
    environment.update(read(args.profile_dir/(args.role+'.env')))
    spec = importlib.util.spec_from_file_location('checkpoint', ROOT/'scripts/check-checkpoint.py')
    check = importlib.util.module_from_spec(spec); spec.loader.exec_module(check)
    errors = check.check_environment(args.role, ledger['roles'][args.role], environment)
    if errors: raise SystemExit('\n'.join(errors))
    if args.check:
        print('PASS isolated role profile: ' + args.role); return
    binaries = args.bin_dir or Path(environment.get('CARGO_TARGET_DIR', str(ROOT/'target')))/'debug'
    if args.role == 'catalog':
        command = [str((binaries/('catalog-migrate' if args.migrate else 'catalog')).resolve())]
    else:
        if args.migrate and args.role not in ('users', 'payments', 'orders'):
            parser.error('this role does not own a migration')
        command = [str((binaries/'rustmall-service').resolve()),
                   'migrate-'+args.role if args.migrate else args.role]
    if not Path(command[0]).is_file():
        raise SystemExit('Build first: cargo build --locked --workspace --all-features --bins')
    os.chdir(ROOT)
    os.execve(command[0], command, environment)
```

### 36.10.1 【入门】五个崩溃窗口

| 窗口 | 数据库中可能留下的事实 | 恢复依据 |
| --- | --- | --- |
| 订单提交前退出 | 没有原订单 | 同请求键重新建立 |
| 提交后回复丢失 | 原订单已存在 | 同用户/键读回原UUID与冻结参数 |
| 领取后调用前退出 | 租约仍存在 | 到期后新worker接手 |
| 支付提交后步骤未保存 | 仍为charging，支付可能Paid | 同身份重放参与者，再条件推进 |
| 库存确认后保存失败 | 仍为confirming，库存Confirmed | 重复Confirm读回终态，再保存completed |

没有一个窗口要求换新UUID、清收据或凭超时猜未执行。恢复能力来自持久责任和幂等参与者。

## 36.12 分层练习与下一章

### 36.12.1 【入门练习】202和completed

参考答案：202确认请求已接受并有持久身份；completed确认本章所需支付与库存步骤已完成。创建重放可能返回当前已完成订单，但不能靠第一次202猜后续结果。

### 36.12.2 【操作练习】不同用户使用同请求键

创建两个真实用户，以相同UUID请求键下单，并尝试互查订单。

评分要点：两笔订单ID不同；同一用户重放仍同ID；另一用户查询404。请求键作用域与订单所有权都必须成立。

### 36.12.3 【推理练习】只有SKIP LOCKED够不够

参考答案：领取语句提交后行锁释放，还需持久租约供崩溃恢复；旧进程恢复后可能继续执行，还需token和到期条件，以及参与者幂等。三者解决不同问题。

### 36.12.4 【推理练习】把远程调用包进SQL事务

参考答案：本地回滚不会撤销另一个服务已经提交的付款，还会长期持锁和连接。应短事务领取、事务外调用、条件保存，再由稳定收据恢复未知窗口。

### 36.12.5 【精通练习】让manual重新工作

参考要点：先核对支付、库存和订单历史，设计受控修复命令及步骤实例身份，记录授权和审计。当前无环唯一约束不能靠删除历史绕过；manual也不能直接等同cancelled。

### 36.12.6 【衔接】业务闭环之后连接事件与读模型

现在同一工程已有真实身份、商品、订单、库存、实验支付与独立worker，能在指定故障后恢复。第37章继续将商品Outbox、Kafka与投影接到这条运行链路，并验证重复事件、墓碑和读模型重建。
