# 第 3 章 结构体、枚举与模式匹配

结构体和枚举是 Rust 中定义自己的类型的两种方式，模式匹配是使用它们的主要手段。本章学完后，我们将用它们定义 RustMall 的领域模型：强类型的 ID、商品、以及通过业务方法拒绝非法转移的订单状态机。

## 3.1 结构体

### 3.1.1 【入门】定义与实例化

结构体（struct）把多个有名字的相关数据打包成一个新类型。和元组相比，每个字段都有名字，代码自带说明。

```rust
/// 商品
struct Product {
    id: i64,
    name: String,
    price_cents: i64,
    stock: i32,
    on_sale: bool,
}
 
fn main() {
    // 创建实例：必须给每个字段赋值，顺序可以与定义不同
    let keyboard = Product {
        name: String::from("机械键盘"),
        id: 1,
        price_cents: 19_900,
        stock: 10,
        on_sale: true,
    };
 
    // 用 . 访问字段
    println!("{} 售价 {} 分", keyboard.name, keyboard.price_cents);
 
    // 修改字段：整个实例必须是 mut，Rust 不支持只把某个字段标记为可变
    let mut mouse = Product { id: 2, name: "鼠标".into(), price_cents: 9_900, stock: 0, 
       on_sale: false };
    mouse.stock += 50;
    mouse.on_sale = true;
    println!("{} 库存 {}", mouse.name, mouse.stock);
}
```

命名规范：结构体名用 UpperCamelCase ，字段名用 snake\_case 。结构体定义一般写在函数外部（模块顶层）。

### 3.1.2 【入门】字段初始化简写

变量名与字段名相同时，可以只写一次：

```rust
fn new_product(id: i64, name: String, price_cents: i64) -> Product {
    Product {
        // 等价于 id: id
        id,
        // 等价于 name: name
        name,
        price_cents,
        stock: 0,
        on_sale: false,
    }
}
```

这是后端代码中最常见的写法：从请求或数据库取出各个值放进同名变量，再一次性组装成结构体。第0 章的 rustfmt.toml 中 use\_field\_init\_shorthand = true 会自动把 id: id 改写成 id 。

### 3.1.3 【入门】结构体更新语法

基于已有实例创建新实例，只改其中几个字段：

```text
let keyboard_v2 = Product {
    id: 3,
    name: String::from("机械键盘 Pro"),
    // 其余字段从 keyboard 取
    ..keyboard
};
```

注意所有权：..keyboard 会把剩余字段移动过来。上例中剩余字段（price\_cents、stock、on\_sale）都是 Copy 类型，所以 keyboard 仍然完整可用；如果被取走的字段中有 String（例如没有显式指定name），keyboard 就会发生部分移动（2.3.4 节），不能再整体使用。这个语法最常用在“默认值 +少量覆盖”的场景：Config { port: 8080, ..Default::default() }（3.3.7 节）。

### 3.1.4 【入门】元组结构体与单元结构体

元组结构体：有类型名、字段没有名字。

```rust
struct Rgb(u8, u8, u8);
struct Point(i32, i32);
 
let red = Rgb(255, 0, 0);
let origin = Point(0, 0);
println!("{} {}", red.0, origin.1);
 
// 解构
let Rgb(r, g, b) = red;
// let p: Point = red;               // 错误：Rgb 和 Point 是不同类型，即使底层字段类型设计得相同
```

单元结构体：没有任何字段，大小为 0。用于“只需要一个类型、不需要数据”的场景，例如作为 trait的实现载体、作为标记类型（3.6.5 类型状态模式）。

```rust
// 例如一个“永远放行”的鉴权策略
struct AlwaysAllow;
let policy = AlwaysAllow;
```

### 3.1.5 【进阶】newtype 模式：后端最有价值的小技巧

只有一个字段的元组结构体称为 newtype。它在编译期是独立类型，通常不需要额外的数据字段。需要把布局和 ABI 与内部类型保持一致作为保证时，应使用 #\[repr(transparent)\]：

```rust
struct UserId(i64);
struct ProductId(i64);
 
fn get_product(id: ProductId) { println!("查询商品 {}", id.0); }
 
fn main() {
    let user = UserId(7);
    let product = ProductId(42);
 
    // 正确
    get_product(product);
    // get_product(user);             // 编译错误：expected `ProductId`, found `UserId`
    let _ = user;
}
```

如果函数签名是 fn place\_order(user\_id: i64, product\_id: i64, qty: i64) ，调用时把参数顺序写反，编译器毫无察觉，线上就会出现“用户 42 买了商品 7”的数据错乱。用 newtype 后，这类 bug 在编译期就被拦下。RustMall 将为所有 ID 使用 newtype（3.7 节）。newtype 的其他用途：

带约束的值：struct Email(String) ，只能通过校验函数创建，拿到 Email 就意味着格式一定合法（3.6.2 节“解析而非校验”）。

单位区分：struct Cents(i64) 与 struct Yuan(i64) 防止单位混用。

为外部类型实现 trait：孤儿规则不允许为外部类型实现外部 trait，包一层 newtype 就可以（第 5 章）。

### 3.1.6 【精通】内存布局与结构体大小

结构体在内存中的大小等于各字段大小之和，再加上对齐填充。默认 Rust 布局允许编译器调整字段布局，不承诺固定字段顺序或固定大小。与 C 布局交互时可使用 #\[repr(C)\]，同时仍需遵守目标平台 ABI。

size\_of::&lt;Product&gt;() ：i64(8) + String(24) + i64(8) + i32(4) + bool(1) = 45，在常见 64 位目标上可能测得 48 字节；这是该目标的测量结果，不是默认布局的跨平台保证。

单字段 newtype 的默认布局不能作为 ABI 保证；#\[repr(transparent)\] 才提供相应的透明布局约束。本章正式 ID 类型会加上这个属性。

单元结构体和空元组 () 大小为 0（零大小类型 ZST），Vec&lt;()&gt; 甚至不分配堆内存。

结构体本身没有“可见性”之外的访问控制：字段默认私有，只有加 pub 才能在模块外访问（第 8 章）。私有字段 + 公开构造函数，是保证结构体内部约束的基础，3.7 节会用到。

## 3.2 方法与关联函数

### 3.2.1 【入门】impl 块与方法

方法是定义在类型上的函数，写在 impl 类型名 { } 块中，第一个参数是 self 的某种形式，调用时用实例.方法() 。

```rust
struct Product { id: i64, name: String, price_cents: i64, stock: i32 }
impl Product {
    /// 是否有货（只读：&self）
    fn in_stock(&self) -> bool {
        self.stock > 0
    }
 
    /// 补货（修改：&mut self）
    fn restock(&mut self, qty: i32) {
        self.stock += qty;
    }
    /// 下架并返回商品名（消耗：self）
    fn into_name(self) -> String {
        self.name
    }
}
 
fn main() {
    let mut p = Product { id: 1, name: "键盘".into(), price_cents: 19_900, stock: 0 };
 
    // false
    println!("{}", p.in_stock());
 
    // 需要 p 是 mut
    p.restock(5);
 
    // true
    println!("{}", p.in_stock());
 
    // p 被消耗，之后不能再用
    let name = p.into_name();
    println!("{name}");
}
```

### 3.2.2 【入门】self 的三种形式

| 写法 | 完整形式 | 含义与用途 | 调用后 |
| --- | --- | --- | --- |
| &amp;self | self: &amp;Self | 共享借用，用于查询与<br>计算 | 实例仍可使用 |
| &amp;mut self | self: &amp;mut Self | 独占可变借用，用于合<br>法的状态修改 | 实例仍可使用，内容可能改变 |

| 写法 | 完整形式 | 含义与用途 | 调用后 |
| --- | --- | --- | --- |
| self | self: Self | 按值取得实例，常用于<br>转换与构建 | 非 Copy 实例被消耗；Copy 接收<br>者按值复制 |

Self 是当前 impl 类型的别名。只读操作通常用 &amp;self，修改操作通常用 &amp;mut self，取得实例所有权的转换可用 self。标准库中命名为 into\_xxx 的方法都获取 self （如 String::into\_bytes ），as\_xxx 返回借用（如 String::as\_str ），to\_xxx 通常会分配新值（如 str::to\_string ）——这套命名约定请在自己的代码中也遵守。

自动引用：调用 p.in\_stock() 时，编译器会自动把 p 变成 &amp;p ；调用 p.restock(5) 时自动变成&amp;mut p 。所以不需要写 (&amp;p).in\_stock() 。

### 3.2.3 【入门】关联函数与构造函数

impl 块中第一个参数不是 self 的函数叫关联函数，用 类型名::函数名() 调用，最常见的就是构造函数：

```rust
impl Product {
    /// 构造函数：Rust 没有 constructor 关键字，约定俗成叫 new
    pub fn new(id: i64, name: impl Into<String>, price_cents: i64) -> Self {
        Self { id, name: name.into(), price_cents, stock: 0 }
    }
 
    /// 可能失败的构造函数：返回 Result
    pub fn try_new(id: i64, name: &str, price_cents: i64) -> Result<Self, String> {
        let name = name.trim();
        if name.is_empty() { return Err("商品名不能为空".into()); }
        if price_cents < 0 { return Err("价格不能为负数".into()); }
        Ok(Self::new(id, name, price_cents))
    }
}
 
fn main() {
    // &str 也可以传
    let a = Product::new(1, "键盘", 19_900);
 
    // String 直接移动进去
    let b = Product::new(2, String::from("鼠标"), 9_900);
 
    // Err("商品名不能为空")
    let c = Product::try_new(3, "   ", 100);
    println!("{} {} {}", a.name, b.name, c.is_err());
}
```

name: impl Into&lt;String&gt; 表示“任何能转换成 String 的类型”（2.3.6 节提过，第 5 章详解），调用方传 &amp;str 或 String 都可以，后者不会产生额外复制。

构造函数命名惯例：new （最常用、通常不会失败）、try\_new 或 parse （可能失败，返回 Result）、with\_xxx （带某个特定参数，如 Vec::with\_capacity ）、from\_xxx （从另一种表示转换，如from\_row ）、Default::default() （默认值）。

### 3.2.4 【进阶】多个 impl 块与方法链

一个类型可以有多个 impl 块（通常按功能分组）。返回 &amp;mut Self 的方法可以链式调用：

```rust
impl Product {
    pub fn set_price(&mut self, cents: i64) -> &mut Self { self.price_cents = cents; self }
    pub fn add_stock(&mut self, qty: i32) -> &mut Self { self.stock += qty; self }
}
let mut p = Product::new(1, "键盘", 0);
p.set_price(19_900).add_stock(10).add_stock(5);
```

### 3.2.5 【进阶】Builder 模式：字段很多时的构造方式

当结构体有很多可选字段时，new 的参数列表会变得又长又难读（new(1, "键盘", 100,None,None, true, false, ...) ）。Builder 模式用一个独立的构建器逐个设置字段，最后 build() ：

```rust
#[derive(Debug)]
pub struct HttpClientConfig {
    base_url: String,
    timeout_ms: u64,
    retries: u32,
    user_agent: String,
}
 
pub struct HttpClientConfigBuilder {
    base_url: String,
    timeout_ms: u64,
    retries: u32,
    user_agent: Option<String>,
}
 
impl HttpClientConfig {
    pub fn builder(base_url: impl Into<String>) -> HttpClientConfigBuilder {
        HttpClientConfigBuilder { base_url: base_url.into(), timeout_ms: 3_000, retries: 0, 
          user_agent: None }
    }
}
 
impl HttpClientConfigBuilder {
    // 获取 self 并返回 Self
    pub fn timeout_ms(mut self, ms: u64) -> Self { self.timeout_ms = ms; self }
    pub fn retries(mut self, n: u32) -> Self { self.retries = n; self }
    pub fn user_agent(mut self, ua: impl Into<String>) -> Self { self.user_agent = 
       Some(ua.into()); self }
    pub fn build(self) -> Result<HttpClientConfig, String> {
        if !(self.base_url.starts_with("http://") || self.base_url.starts_with("https://")) {
            return Err("base_url 必须以 http:// 或 https:// 开头".into());
        }
        Ok(HttpClientConfig {
            base_url: self.base_url,
            timeout_ms: self.timeout_ms,
            retries: self.retries,
            user_agent: self.user_agent.unwrap_or_else(|| "rustmall/0.1".into()),
        })
    }
}
 
fn main() {
    let cfg = HttpClientConfig::builder("http://product-service:8082")
        .timeout_ms(1_000)
        .retries(3)
        .build();
    println!("{cfg:?}");
}
```

你会在大量 crate 中看到这种风格：reqwest::Client::builder() 、PgPoolOptions::new().max\_connections(20) 、tonic::transport::Channel::from\_shared(...).timeout(...) 、config::Config::builder()。这里的前缀检查只用于展示 Builder 的验证位置，不是完整 URL 解析或服务地址授权。理解 Builder 后，再学习对应库的实际构建与校验行为。需要自动生成 Builder 时可以使用 bon 或 derive\_builder 等 crate。

### 3.2.6 【精通】方法解析与设计细节

方法查找顺序：调用 x.m() 时，编译器依次尝试 T 、&amp;T 、&amp;mut T ，再对 \*x 解引用后重复，直到找到方法。这就是为什么 String 能直接调用 str 的所有方法（Deref，2.4.6 节）。

同名的字段和方法可以共存：p.stock 是字段，p.stock() 是方法。常见做法是字段私有、提供同名的只读方法（getter），保证外部不能随意修改：pub fn stock(&amp;self) -&gt; i32 {self.stock} 。Rust 社区惯例中 getter 不加 get\_ 前缀。

完全限定语法：Product::in\_stock(&amp;p) 与 p.in\_stock() 等价，方法本质上就是第一个参数为 self 的关联函数。当多个 trait 提供同名方法时，需要用 &lt;Type as Trait&gt;::method(&amp;x) 消除歧义（第 5 章）。

self: Box&lt;Self&gt; 、self: Arc&lt;Self&gt; 、self: Pin&lt;&amp;mut Self&gt; ：self 还可以是这些智能指针形式，在第 7、11 章会遇到。

不要过度使用 &amp;mut self 的 setter：业务实体的状态变更应该通过表达业务含义的方法（deduct\_stock 、mark\_paid ）完成，方法内部检查业务规则，而不是暴露一堆 set\_xxx 让外部任意修改——这是 3.6 节“领域模型保护自身约束”的基础。

## 3.3 derive 与常用 trait

### 3.3.1 【入门】derive 是什么

新定义的结构体默认“什么都不会”：不能打印、不能比较、不能复制。#\[derive(...)\] 属性让编译器自动生成常用 trait 的实现（trait 是“一组能力”的定义，第 5 章详解）：

```rust
#[derive(Debug, Clone, PartialEq)]
struct Product { id: i64, name: String, price_cents: i64 }
 
fn main() {
    let a = Product { id: 1, name: "键盘".into(), price_cents: 19_900 };
 
    // Clone
    let b = a.clone();
 
    // Debug：Product { id: 1, name: "键盘", price_cents: 19900 }
    println!("{a:?}");
 
    // PartialEq：true
    println!("{}", a == b);
}
```

用 cargo expand （0.2.7 节）可以看到 derive 生成的代码，它和你手写的实现没有区别。

### 3.3.2 【入门】可派生的标准 trait 一览

| trait | 能力 | 主要派生要求 | 注意事项 |
| --- | --- | --- | --- |
| Debug | 使用 {:?} 调试输出 | 相关字段实现 Debug | 敏感字段可能需要手写遮蔽 |
| Clone | 显式复制或共享句柄 | 字段实现 Clone | 不是一概深复制；Arc 的 Clone 共<br>享内部值 |
| Copy | 按值使用时允许隐式按位复<br>制 | 字段都是 Copy，同时满<br>足 Clone | 不能与自身 Drop 实现并存 |

| trait | 能力 | 主要派生要求 | 用途 |
| --- | --- | --- | --- |
| PartialEq | == 与 != | 字段实现 PartialEq | 比较与测试 |
| Eq | 声明相等满足等价关系 | 满足 PartialEq，字段实<br>现 Eq | HashMap / HashSet 键的约束之<br>一 |
| Hash | 向哈希器写入用于计算哈希<br>的信息 | 字段实现 Hash | 必须与相等关系保持一致 |
| PartialOrd | 可能存在无法比较的值 | 字段实现 PartialOrd | 部分序比较 |

| trait | 能力 | 主要要求 | 用途 |
| --- | --- | --- | --- |
| Ord | 全序比较 | 满足 Eq、PartialOrd，<br>字段实现 Ord | 排序与 BTreeMap / BTreeSet |
| Default | 构造默认值 | 结构体派生时字段实现<br>Default；枚举有专门限<br>制 | 配置、测试与更新语法 |

第三方派生还包括 serde 的 Serialize / Deserialize（第 10 章）、SQLx 的 FromRow（第 14 章）和thiserror::Error（第 4 章）。启用对应依赖与功能后，实体可以组合所需能力：

```rust
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize, sqlx::FromRow)]
pub struct Product { /* ... */ }
```

### 3.3.3 【进阶】Debug 的细节

{:?} 单行，{:#?} 多行美化。

敏感字段不要直接派生 Debug：如果 User 有 password\_hash 字段，派生的 Debug 会把哈希值打进日志。正确做法是手动实现 Debug 隐藏该字段，或者把密码包装成一个 Debug 输出为 "\*\*\*"的 newtype（第 16 章使用 secrecy crate 的 SecretString 实现）：

```rust
use std::fmt;
 
struct User { id: i64, username: String, password_hash: String }
 
impl fmt::Debug for User {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.debug_struct("User")
            .field("id", &self.id)
            .field("username", &self.username)
            // 隐藏敏感信息
            .field("password_hash", &"***")
            .finish()
    }
}
```

debug\_struct 、debug\_tuple 、debug\_list 、debug\_map 等辅助方法能生成与派生版本格式一致的输出。

### 3.3.4 【进阶】相等与哈希

```rust
use std::collections::{HashMap, HashSet};
 
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord)]
struct ProductId(i64);
 
fn main() {
    // 需要 Eq + Hash
    let mut stock: HashMap<ProductId, i32> = HashMap::new();
    stock.insert(ProductId(1), 10);
    let ids: HashSet<ProductId> = [ProductId(1), ProductId(1), ProductId(2)].into();
 
    // Some(10) 2
    println!("{:?} {}", stock.get(&ProductId(1)), ids.len());
}
```

为什么有 PartialEq 和 Eq 两个 trait？ 浮点数的 NaN != NaN ，不满足“任何值都等于自身”（自反性），所以 f64 只实现了 PartialEq。含有浮点字段的结构体因此不能派生 Eq，也不能直接满足标准HashMap 键要求；若确有需要，应明确设计相等与哈希语义。

一致性规则（精通）：如果手动实现了 PartialEq，也必须让 Hash 保持一致—— a == b 时hash(a)==hash(b) 必须成立，否则 HashMap 会出现“插入了却查不到”的诡异 bug。最简单的办法是两者都用 derive。

### 3.3.5 【进阶】排序：PartialOrd 与 Ord

派生的比较按字段声明顺序逐个比较（字典序）：

```rust
#[derive(Debug, PartialEq, Eq, PartialOrd, Ord)]
struct Version { major: u32, minor: u32, patch: u32 }
 
fn main() {
    let mut vs = vec![
        Version { major: 1, minor: 10, patch: 0 },
        Version { major: 1, minor: 2, patch: 5 },
    ];
 
    // 需要 Ord：1.2.5 排在 1.10.0 前面
    vs.sort();
    println!("{vs:?}");
}
```

业务实体一般不应该派生 Ord——“两个商品谁大”没有唯一答案。需要排序时使用 sort\_by\_key(|p|p.price\_cents) 或 sort\_by(|a, b|b.created\_at.cmp(&amp;a.created\_at))按具体字段排序，意图更明确。

### 3.3.6 【进阶】Clone 与 Copy 的选择

只包含 Copy 字段、体积小（建议不超过 16〜32 字节）的值类型：派生 Clone, Copy ，例如IDnewtype、订单状态枚举、(i64, i64) 坐标。

包含 String、Vec 等的类型：只派生 Clone 。

一旦对外发布，给类型加 Copy 容易，去掉 Copy 是破坏性变更（调用方依赖隐式复制的代码会全部报错），设计公共 API 时要慎重。

### 3.3.7 【进阶】Default：默认值

```rust
#[derive(Debug, Default)]
struct ListQuery {
    // u32 的默认值是 0
    page: u32,
    page_size: u32,
    // Option 的默认值是 None
    keyword: Option<String>,
    // bool 的默认值是 false
    only_on_sale: bool,
}
 
// 派生的默认值不合业务时，手动实现
struct ServerConfig { host: String, port: u16, max_body_kb: usize }
 
impl Default for ServerConfig {
    fn default() -> Self {
        Self { host: "0.0.0.0".into(), port: 8080, max_body_kb: 256 }
    }
}
 
fn main() {
    // 更新语法 + 默认值
    let q = ListQuery { keyword: Some("键盘".into()), ..Default::default() };
    let cfg = ServerConfig { port: 3000, ..Default::default() };
    println!("{q:?} {}:{} {}", cfg.host, cfg.port, cfg.max_body_kb);
}
```

枚举也可以派生 Default，用 #\[default\] 标记默认变体（3.4 节）。

### 3.3.8 【精通】derive 的边界

derive 对泛型类型会自动添加约束：#\[derive(Clone)\] struct Wrapper&lt;T&gt;(T) 生成 impl&lt;T:Clone&gt; Clone for Wrapper&lt;T&gt; 。有时这个约束过于严格（例如 Wrapper&lt;Arc&lt;T&gt;&gt; 本可以无条件 Clone），这时需要手写实现。

派生宏属于过程宏（procedural macro），它们在编译期运行，读取类型定义的语法树并生成代码。第 10 章 serde 的 #\[serde(rename = ...)\] 这类“辅助属性”就是传给派生宏的参数。

编译时间：大量派生（尤其是 serde、sqlx）会增加编译时间，这是 Rust 后端项目编译慢的原因之一，也是第 7 章要把项目拆成多个 crate 的动机之一。

### 3.3.9 常见编译错误与解读

| 诊断 | 原因 | 处理 |
| --- | --- | --- |
| 未实现 Debug | 调试输出或断言要求该能力 | 按需要派生或手写 Debug |
| E0369 | 类型不能使用 == | 实现符合语义的 PartialEq |
| Hash / Eq 约束不满足 | 映射或集合的键缺少能力 | 按需要实现 PartialEq、Eq、Hash |
| f64 未实现 Eq | 类型包含不可直接派生 Eq 的字段 | 按业务选择比较语义，不为消除报错伪造等价关<br>系 |
| E0204 | 字段不能 Copy | 仅实现合适的 Clone |
| 未实现 Ord | 直接 sort 要求全序 | 明确按哪些字段排序 |

## 3.4 枚举

### 3.4.1 【入门】定义与使用

结构体表示“这个和那个”（一个商品同时有名称、价格、库存），枚举（enum）表示“这个或那个”（一个订单的状态是待支付、已支付、已取消之一）。

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
enum PayMethod {
    Alipay,
    WechatPay,
    BankCard,
}
 
// 手续费，单位：千分之几
fn fee_rate_per_mille(m: PayMethod) -> i64 {
    match m {
        PayMethod::Alipay => 6,
        PayMethod::WechatPay => 6,
        PayMethod::BankCard => 3,
    }
}
 
fn main() {
    // 用 类型名::变体名 创建
    let m = PayMethod::WechatPay;
    println!("{m:?} 手续费 {}‰", fee_rate_per_mille(m));
}
```

每个可能的值叫一个变体（variant）。与 C/Java 的枚举只能是常量不同，Rust 的枚举变体可以携带数据，这让它成为建模工具中最强大的一个。

### 3.4.2 【入门】携带数据的变体

每个变体可以携带不同类型、不同数量的数据，三种写法：

```rust
#[derive(Debug)]
enum OrderEvent {
    // 结构体式变体：字段有名字
    Created { order_id: i64, user_id: i64, total_cents: i64 },
    Paid { order_id: i64, method: PayMethod },
 
    // 元组式变体：订单 ID、快递单号
    Shipped(i64, String),
    Cancelled { order_id: i64, reason: String },
 
    // 单元式变体：不带数据
    Heartbeat,
}
 
fn describe(e: &OrderEvent) -> String {
    match e {
        OrderEvent::Created { order_id, total_cents, .. } => format!("订单 {order_id} 已创建，金额 {total_cents}"),
        OrderEvent::Paid { order_id, method } => format!("订单 {order_id} 已用 {method:?} 支付"),
        OrderEvent::Shipped(id, tracking) => format!("订单 {id} 已发货，单号 {tracking}"),
        OrderEvent::Cancelled { order_id, reason } => format!("订单{order_id} 已取消：{reason}"),
        OrderEvent::Heartbeat => "心跳".to_string(),
    }
}
```

这展示了事件枚举的基本形状；第 28 章 Kafka 使用的实际事件契约还包含版本、标识和持久化要求， 不能直接把本节示例当成已完成的消息协议。用一个枚举表示“所有可能的事件”，配合 match 的穷尽

检查，新增一种事件后，编译器会指出所有忘记处理它的地方——这是枚举相比字符串常量 " order\_created" 的巨大优势。

### 3.4.3 【入门】枚举的方法

枚举和结构体一样可以有 impl 块：

```rust
impl OrderEvent {
    pub fn order_id(&self) -> Option<i64> {
        match self {
            Self::Created { order_id, .. }
            | Self::Paid { order_id, .. }
            | Self::Cancelled { order_id, .. } => Some(*order_id),
            Self::Shipped(id, _) => Some(*id),
            Self::Heartbeat => None,
        }
    }
 
    pub fn kind(&self) -> &'static str {
        match self {
            Self::Created { .. } => "order.created",
            Self::Paid { .. } => "order.paid",
            Self::Shipped(..) => "order.shipped",
            Self::Cancelled { .. } => "order.cancelled",
            Self::Heartbeat => "heartbeat",
        }
    }
}
```

在 impl 内部可以用 Self::变体 代替 OrderEvent::变体。| 把多个模式合并成一个分支，前提是它们绑定的变量名和类型一致。

### 3.4.4 【入门】Option：Rust 没有 null

Rust 没有 null。“可能没有值”用标准库中的枚举 Option&lt;T&gt; 表示：

```rust
// 标准库中的定义（已自动导入，直接用 Some/None 即可）
enum Option<T> {
    None,
    Some(T),
}
```

```rust
fn find_product_name(id: i64) -> Option<String> {
    if id == 1 { Some("机械键盘".to_string()) } else { None }
}
fn main() {
    let name = find_product_name(2);
    // println!("{}", name.len());      // 编译错误：Option<String> 上没有 len 方法——你必须先处理“没有”的情况
    match name {
        Some(n) => println!("找到 {n}"),
        None => println!("商品不存在"),
    }
}
```

这就是 Rust 通过类型明确表达可选值的方式：可能为空的值和一定有值的值是不同的类型。String 一定有值；Option&lt;String&gt; 可能没有，编译器强制你在使用前处理 None。这避免把未处理的 None 当作 String 使用，但 unwrap(None) 仍会 panic，不能因此声称程序不会失败。

后端中 Option 无处不在：按 ID 查询可能查不到（fetch\_optional 返回 Option&lt;Row&gt; ）、请求中的可选参数（page: Option&lt;u32&gt; ）、可空的数据库字段（NULL 对应 None ）、可选配置项。

### 3.4.5 【进阶】Option 的常用方法

直接用 match 处理 Option 很啰嗦，标准库提供了大量组合方法（第 4、5 章会继续使用）：

| Option 方法 | 作用 | 示例 |
| --- | --- | --- |
| is\_some / is\_none | 判断有无 | keyword.is\_some() |
| unwrap\_or | 缺失时用给定值；该值提前求值 | page.unwrap\_or(1) |
| unwrap\_or\_default | 缺失时取 T::default() | tags.unwrap\_or\_default() |
| unwrap\_or\_else | 缺失时才调用闭包 | name.unwrap\_or\_else(make\_name) |
| map | 变换 Some 内的值 | name.map(\|n\| n.len()) |
| and\_then | 串联返回 Option 的操作 | raw.and\_then(\|s\| s.parse::&lt;u32&gt;().ok()) |

| Option 方法 | 作用 | 示例或约束 |
| --- | --- | --- |
| filter | 不满足条件时返回 None | token.filter(\|t\| !t.is\_empty()) |
| ok\_or / ok\_or\_else | 把缺失转换为错误 | 转成 Result |
| as\_ref / as\_deref | 借用内部值 | Option&lt;String&gt; 可借用为 Option&lt;&amp;String&gt;<br>/ Option&lt;&amp;str&gt; |
| take | 取出值，原位置留下 None | 需要可变访问原 Option |
| copied / cloned | 从借用获得 Copy 值或 Clone 结果 | Option&lt;&amp;T&gt; → Option&lt;T&gt; |
| zip | 两者都有值才组合 | start.zip(end) |

| Option 方法 | 作用 | 示例或约束 |
| --- | --- | --- |
| ? | 为 None 时提前传播缺失 | 所在函数等需能承接 Option 的传播 |
| unwrap / expect | 取值；为 None 时 panic | 必须有可说明的前提，不用于可预期的缺失 |

```rust
struct User { nickname: Option<String>, username: String }

impl User {
    /// 显示名：有昵称且非空用昵称，否则用用户名
    fn display_name(&self) -> &str {
        self.nickname
            // Option<String> → Option<&str>，不移动所有权
            .as_deref()
            .filter(|n| !n.trim().is_empty())
            .unwrap_or(&self.username)
    }
}
```

这一行链式调用替代了七八行 match，并且每一步都有清晰的含义。

### 3.4.6 【进阶】带显式值的枚举与 Default

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
// 指定底层整数类型
#[repr(i16)]
enum MemberLevel {
    // 派生 Default 时的默认变体
    #[default]
    Normal = 0,
    Silver = 10,
    Gold = 20,
}
 
fn main() {
    let lv = MemberLevel::Gold;
 
    // 20：无字段枚举可以 as 转成整数
    println!("{}", lv as i16);
 
    // Normal
    println!("{:?}", MemberLevel::default());
}
```

反过来“整数 → 枚举”没有自动实现，因为整数可能不在合法范围内，需要手动实现 TryFrom&lt;i16&gt;（第 5 章）。数据库中存枚举时，RustMall 选择存字符串（如 "pending" ）而不是数字，可读性更好、增删变体不易出错，3.7 节会实现字符串与枚举的相互转换。

### 3.4.7 【精通】枚举的内存布局

枚举通常需要容纳当前变体的数据及区分变体的信息，但大小不能一概用“最大变体 + tag”算出，编译器还可能利用未使用的表示进行优化。OrderEvent 中最大的变体决定了它的大小，即使当前值只是Heartbeat 。

如果某个变体特别大（例如携带一个上 KB 的结构体），会拖累所有值的大小，clippy 的large\_enum\_variant 会提示把大字段放进 Box 。

空指针优化：在标准库所保证的适用条件下，例如 T 为 Sized，Option&lt;&amp;T&gt;、Option&lt;Box&lt;T&gt;&gt;，以及 Option&lt;NonZeroU64&gt; 可与内部类型大小相同——因为引用永远非空，编译器用“全零”表示 None，不需要额外的 tag。所以 Option&lt;&amp;T&gt; 是零

成本的。

无数据的枚举本质是一个小整数；#\[repr(u8)\] 等可以固定其类型。

#\[non\_exhaustive\] ：标在公共枚举上，表示“将来可能增加变体”，外部 crate 的 match 必须写\_ 分支。库作者常用，业务代码内部一般不需要。

### 3.4.8 常见编译错误与解读

| 诊断 | 原因 | 处理 |
| --- | --- | --- |
| E0004 | match 漏了枚举变体 | 补齐需要处理的分支 |
| Option 上没有内部方法 | 把 Option&lt;String&gt; 直接当 String | 先明确处理 Some 和 None |
| E0308 | 应返回 Option 却返回裸值 | 按语义使用 Some(value) |
| E0533 | 把带命名字段的变体当作单元变体 | 按 Variant { .. } 的形状匹配 |

| 诊断 | 原因 | 处理 |
| --- | --- | --- |
| E0605 | 试图把带数据的枚举直接 as 成整数 | 显式匹配并定义转换；不能据此跳过合法性检查 |
| E0408 | 或模式各分支的变量绑定不一致 | 让各子模式按相同名称和兼容类型绑定 |

## 3.5 模式匹配全解

模式（pattern）是描述“值的形状”的语法。它不止出现在 match 中，let 、函数参数、if let、while let 、for 循环都在使用模式。本节系统地讲完所有模式语法。

### 3.5.1 【入门】match 的规则

```text
match 被匹配的值 {
    模式1 => 表达式1,
    // 带守卫
    模式2 if 条件 => 表达式2,
    模式3 => { 多条语句; 表达式3 }
    _ => 默认表达式,
}
```

三条规则：

1. 从上到下逐个尝试，第一个匹配的分支被执行，其余忽略。

2. 必须穷尽：所有可能的值都要被某个分支覆盖，否则编译错误 E0004。

3. match 是表达式，所有分支的类型必须一致。

### 3.5.2 【入门】字面量、范围、多选与通配

```rust
fn http_category(status: u16) -> &'static str {
    match status {
        // | 多选
        200 | 201 | 204 => "成功",
        // 闭区间范围
        300..=399 => "重定向",
        401 | 403 => "鉴权失败",
        // 顺序很重要：401/403 已在上面被匹配
        400..=499 => "客户端错误",
        500..=599 => "服务端错误",
        // _ 匹配任何值且不绑定
        _ => "未知",
    }
}
 
fn grade(c: char) -> &'static str {
    match c {
        'a'..='z' | 'A'..='Z' => "字母",
        '0'..='9' => "数字",
        _ => "其他",
    }
}
```

如果把 400..=499 放到 401 | 403 前面，编译器会警告后者是“不可达模式”（unreachablepattern）。

### 3.5.3 【入门】绑定变量

模式中的名字会绑定匹配到的值：

```text
let point = (3, -2);
match point {
    (0, 0) => println!("原点"),
    (x, 0) => println!("在 x 轴上，x = {x}"),
    (0, y) => println!("在 y 轴上，y = {y}"),
    (x, y) => println!("({x}, {y})"),
}
```

用 @ 在检查范围的同时绑定值：

```rust
fn qty_message(qty: i32) -> String {
    match qty {
        n @ 1..=99 => format!("购买 {n} 件"),
        // 100.. 是无上界范围，包含 100
        n @ 100.. => format!("{n} 件属于批发，请联系客服"),
        _ => "数量必须为正数".to_string(),
    }
}
```

### 3.5.4 【入门】守卫（match guard）

在模式后加 if 条件，模式匹配且条件为真时才进入该分支：

```rust
fn shipping_fee(total_cents: i64, is_vip: bool) -> i64 {
    match total_cents {
        _ if is_vip => 0,
        t if t >= 9_900 => 0,
        _ => 1_000,
    }
}
```

注意：编译器检查穷尽性时不考虑守卫条件，所以带守卫的分支之后通常需要一个无守卫的兜底分支。

### 3.5.5 【进阶】解构结构体、枚举、元组与嵌套

```rust
struct Product { id: i64, name: String, stock: i32 }
enum Command { Restock { id: i64, qty: i32 }, Rename(i64, String), Delist(i64) }
 
fn main() {
    let p = Product { id: 1, name: "键盘".into(), stock: 0 };
 
    // 1. 解构结构体：字段名: 模式；同名时可以简写；.. 忽略其余字段
    let Product { id, stock: s, .. } = &p;
    println!("{id} {s}");
 
    // 2. 在 match 中按字段的值匹配
    match &p {
        Product { stock: 0, name, .. } => println!("{name} 已售罄"),
        Product { stock: 1..=5, name, .. } => println!("{name} 库存紧张"),
        Product { .. } => println!("有货"),
    }
 
    // 3. 嵌套解构：元组里的枚举里的数据
    let batch = ("admin", Command::Restock { id: 7, qty: 20 });
    match batch {
        ("admin", Command::Restock { id, qty }) if qty > 0 => println!("管理员给 {id} 补货{qty}"),
        (_, Command::Rename(id, new_name)) => println!("{id} 改名为 {new_name}"),
        (_, Command::Delist(id)) => println!("下架 {id}"),
        (who, _) => println!("{who} 无权限或参数非法"),
    }
}
```

### 3.5.6 【进阶】匹配引用：绑定模式（binding modes）

2.3.4 节提到，按值匹配会移动数据。实际开发中我们几乎总是匹配引用 &amp;value ，这时 Rust 的“默认绑定模式”会自动让绑定的变量也变成引用：

```rust
enum Payload { Text(String), Number(i64) }
 
fn show(p: &Payload) {
    // p 是 &Payload
    match p {
        // s 自动是 &String，不会移动
        Payload::Text(s) => println!("{}", s.len()),
        // n 是 &i64，算术运算会自动解引用
        Payload::Number(n) => println!("{}", n + 1),
    }
}
 
fn main() {
    let p = Payload::Text("hi".into());
    show(&p);
 
    // 匹配 &p，p 不被移动
    match &p { Payload::Text(s) => println!("{s}"), _ => {} }
    // match p { Payload::Text(s) => ..., _ => {} }             // 匹配 p 本身：s 拿走String，p 被部分移动
}
```

规则记忆：match &amp;x 或者 x 本身就是引用时，绑定的变量都是引用；match x 且 x 是值时，绑定会移动（Copy 类型则复制）。旧代码中可能见到 ref 关键字（Payload::Text(ref s) ），作用是显式按引用绑定，在默认绑定模式出现后已很少需要。ref mut 用于按可变引用绑定。

fn describe_path(segments: &[&str]) -> String {

### 3.5.8 【进阶】if let、while let、let-else 与 matches!

```rust
fn main() {
    let cache: Option<i32> = Some(42);
 
    // if let：只关心一种情况
    if let Some(v) = cache {
        println!("命中缓存 {v}");
    }
 
    // if let ... else if let ... else
    let input = "12";
    if let Ok(n) = input.parse::<i32>() {
        println!("数字 {n}");
    } else if input.is_empty() {
        println!("空");
    } else {
        println!("不是数字");
    }
 
    // if let 链（需要 2024 Edition 且 Rust 1.88 及以上）：在一个 if 中用 && 组合多个 let
    let page: Option<&str> = Some("3");
    if let Some(raw) = page && let Ok(n) = raw.parse::<u32>() && n > 0 {
        println!("第 {n} 页");
    }
 
    // while let：只要匹配就继续循环（消费队列、栈）
    let mut stack = vec!["任务A", "任务B"];
    while let Some(task) = stack.pop() {
        println!("处理 {task}");
    }
    // let-else：不匹配就必须发散（return/break/continue/panic）
    let Some(v) = cache else {
        println!("缓存未命中");
        return;
    };
    println!("{v}");
 
    // matches!：返回 bool，适合简单判断
    let status = 404_u16;
    let is_client_error = matches!(status, 400..=499);
    println!("{is_client_error}");
}
```

选择建议：多个分支都要处理用 match ；只关心一个分支用 if let ；不匹配就要提前退出用 let-else（后端 handler 中最常用，能让主逻辑不缩进）；只需要布尔结果用 matches! 。

### 3.5.9 【进阶】可反驳与不可反驳模式

不可反驳模式（irrefutable）：一定能匹配成功，例如 let (a, b) = (1, 2); 、let Product{id, .. } = p; 、函数参数 fn f((x, y): (i32, i32)) 。let 和函数参数只能使用不可反驳模式。

可反驳模式（refutable）：可能失败，例如 Some(x) 。只能用在 match 、if let 、whilelet、let-else中。

```text
// let Some(x) = maybe;        // 错误 E0005：refutable pattern in local binding
// 正确：let-else 允许可反驳模式
let Some(x) = maybe else { return; };
```

### 3.5.10 【精通】模式匹配的原理与技巧

编译结果：match 会被编译成跳转表或二分比较，性能与手写 if-else 相当甚至更好，不必担心“匹配很多分支会慢”。

穷尽检查是重构的安全网：给枚举新增变体时，所有没处理它的 match 都会报错。因此对业务枚举尽量不要写 \_ =&gt; 兜底分支，否则新增变体时编译器不会提醒你。

@ 绑定子模式：msg @ Message::Hello { id: 3..=7 } 同时检查结构并保留整体。

常量模式：可以在模式中使用 const 常量（但不能用普通变量，变量名在模式中会被当成新的绑定，这是一个经典陷阱）：

```text
const ADMIN_ID: i64 = 1;
let max_id = 100;
match 50_i64 {
    // 正确：匹配常量 1
    ADMIN_ID => println!("管理员"),
    // max_id => ...                    // 陷阱！这不是比较，而是绑定一个叫 max_id 的新变量，匹配一切
    n if n == max_id => println!("最大"),// 正确：用守卫与变量比较
    _ => println!("普通"),
}
```

Box 内部无法直接匹配：需要先 match \*boxed 或 match boxed.as\_ref() 。

## 3.6 后端建模：让非法状态无法表示

本节是本章的思想核心。前五节教会你语法，这一节教你用类型系统表达业务规则，其中一些非法组合可以在编译期被排除，另一些仍需构造函数和业务方法校验。类型建模的收益取决于是否准确表达了业务约束。

### 3.6.1 【进阶】反面教材：布尔与可选字段的组合爆炸

很多系统的订单表是这样建模的：

```rust
struct OrderBad {
    id: i64,
    is_paid: bool,
    is_cancelled: bool,
    is_shipped: bool,
    paid_at: Option<i64>,
    cancel_reason: Option<String>,
    tracking_no: Option<String>,
}
```

三个布尔值有 8 种组合，再乘上三个 Option 的有无，共 64 种组合，但业务上合法的只有 4〜5 种。“已取消但已发货”“已支付但 paid\_at 为空”“未发货却有快递单号”这些非法状态全都可以被构造出来，只能靠每段代码小心翼翼地检查——总有一处会漏掉。

### 3.6.2 【进阶】原则一：用枚举表达“互斥的状态”，把数据放进对应的变体

```rust
enum OrderState {
    // 待支付：没有任何附加数据
    Pending,
    // 已支付：一定有支付时间
    Paid { paid_at: i64 },
 
    // 已发货：一定有快递单号
    Shipped { paid_at: i64, tracking_no: String },
 
    // 已取消：一定有原因
    Cancelled { reason: String },
}
```

现在“已取消且已发货”根本写不出来；“已发货”的订单一定有快递单号，读取它时不需要判断None。枚举保证所选变体具有对应字段；字段是否为空、时间是否合理、支付是否真实完成、并发是否正确，仍需运行时校验与系统设计。

### 3.6.3 【进阶】原则二：解析而非校验（Parse, don't validate）

“校验”是检查一下数据、通过后继续使用原来的类型，后面的代码无从得知它是否被检查过；“解析”是把未经检查的输入转换成一个新类型，只要拿到这个类型，就证明数据合法：

```rust
/// 合法的购买数量：1〜99。只能通过 try_new 创建。
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
// 字段私有：模块外无法直接 Quantity(1000)
pub struct Quantity(i32);
 
impl Quantity {
    pub const MAX: i32 = 99;
 
    pub fn try_new(n: i32) -> Result<Self, String> {
        if (1..=Self::MAX).contains(&n) { Ok(Self(n)) } else { Err(format!("购买数量需为 1〜{}", 
          Self::MAX)) }
    }
 
    pub fn get(self) -> i32 { self.0 }
}
 
// 下游函数直接要求 Quantity，不再需要任何检查
fn reserve_stock(product_id: i64, qty: Quantity) { println!("为商品 {product_id} 预留 {} 件", 
   qty.get()); }
```

关键在于字段私有：Quantity(i32) 中的 i32 没有 pub ，所以在定义它的模块之外，唯一的创建方式就是 try\_new 。校验逻辑只写一次，全系统处处受益。邮箱、手机号、金额、分页参数都适用这个模式。第 10 章会让 serde 在反序列化请求时自动调用这类构造函数。

### 3.6.4 【进阶】原则三：所有 ID 都用 newtype

3.1.5 节已经说明了原因。实践中为每个 ID 定义 newtype 并派生 Debug, Clone, Copy,PartialEq,Eq,Hash, PartialOrd, Ord ，后续再加上 serde 和 sqlx 的支持（第 10、14 章），让它在 JSON 和数据库中透明地表现为普通整数。

### 3.6.5 【精通】状态机的两种实现：运行时枚举 vs 编译期类型状态

方式一：枚举状态机（运行时检查）。状态存在一个枚举字段中，状态转移方法检查当前状态，非法转移返回错误。适合状态需要存入数据库、从数据库读出的场景——数据库读出来时你无法在编译期知道它处于什么状态。RustMall 的订单使用这种方式（3.7 节）。

方式二：类型状态模式（typestate，编译期检查）。每个状态是一个不同的类型，状态转移方法获取self 并返回新状态的类型，非法转移根本没有对应的方法：

```rust
// 单元结构体作为“状态标记”
struct Draft;
struct Submitted;
 
struct Order<S> { id: i64, items: Vec<String>, _state: std::marker::PhantomData<S> }
 
impl Order<Draft> {
    fn new(id: i64) -> Self { Order { id, items: vec![], _state: std::marker::PhantomData } }
    fn add_item(mut self, item: &str) -> Self { self.items.push(item.into()); self }
 
    // Draft → Submitted
    fn submit(self) -> Order<Submitted> {
        Order { id: self.id, items: self.items, _state: std::marker::PhantomData }
    }
}
 
impl Order<Submitted> {
    fn id(&self) -> i64 { self.id }
}
fn main() {
    let order = Order::new(1).add_item("键盘").submit();
    println!("{}", order.id());
    // order.add_item("鼠标");    // 编译错误：Order<Submitted> 没有 add_item 方法
}
```

PhantomData&lt;S&gt; 是零大小的标记，告诉编译器“这个类型在逻辑上与 S 有关”。类型状态模式适合一次流程中在内存里完成的状态转换，例如 Builder（必须先设置 URL 才能 build）、连接建立流程、多步骤表单。很多 crate 内部使用它保证 API 不被误用。

| 维度 | 枚举状态机 | 类型状态模式 |
| --- | --- | --- |
| 非法转移 | 业务方法在运行时检查并返回错误 | 缺少相应方法的调用可在编译时拒绝 |
| 数据库恢复 | 按标签与数据校验并重建 | 通常先解析动态状态，再转换到具体类型 |
| 不同状态放进同一集合 | 同一 Order 类型可以直接混放 | 通常需要枚举等统一包装 |
| 典型用途 | 持久化的订单、支付单等 | Builder、协议阶段等进程内 API |

### 3.6.6 【精通】领域模型的其他设计要点

业务方法代替 setter：order.pay(now) 而不是 order.set\_state(Paid) ；方法名就是业务语言（领域驱动设计中的“通用语言”）。

构造即合法：实体只能通过校验过的构造函数创建，任何一个存在的实例都满足不变量。

时间通过参数传入：pay(&amp;mut self, paid\_at: i64) 而不是在方法内部读取系统时间，这样测试可以传入固定时间，结果可重现（第 17 章测试时体会它的好处）。

领域模型不依赖框架：领域类型不引用 Axum、SQLx 等框架类型，框架只是“适配器”（第 15 章分层架构）。

用 ID 表示关联：订单中存 ProductId ，不存 Product 的引用（2.6.4 节）。

### 3.7.2 订单状态机设计

| --- | --- | --- |

//!

}

//! 合法的购买数量（解析而非校验）。

/// 单笔购买数量，取值 1〜[`Quantity::MAX`]。
///
/// 字段私有，只能通过 [`Quantity::try_new`] 创建，
/// 因此任何 `Quantity` 实例都一定是合法的。
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub struct Quantity(i32);

impl Quantity {
    /// 单笔最大购买数量。
    pub const MAX: i32 = 99;

    /// 校验并创建购买数量。
    pub fn try_new(n: i32) -> Result<Self, String> {
        if (1..=Self::MAX).contains(&n) {
            Ok(Self(n))
        } else {
            Err(format!("购买数量需为 1〜{} 件，当前为 {n}", Self::MAX))
        }
    }

    pub const fn get(self) -> i32 {
        self.0
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn quantity_bounds() {
        assert!(Quantity::try_new(0).is_err());
        assert!(Quantity::try_new(-3).is_err());
        assert!(Quantity::try_new(100).is_err());
        assert_eq!(Quantity::try_new(1).map(Quantity::get), Ok(1));
        assert_eq!(Quantity::try_new(99).map(Quantity::get), Ok(99));
    }
}

//! 商品领域模型。

use crate::ids::ProductId;
use crate::money;
use crate::quantity::Quantity;

/// 商品。
///
/// 所有字段私有：只能通过 [`Product::try_new`] 创建，只能通过业务方法修改，
/// 因此任何实例都满足以下不变量：
/// - 名称去除首尾空白后为 1〜100 个字符
/// - 价格（分）不为负
/// - 库存不为负
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Product {
    id: ProductId,
    name: String,
    price_cents: i64,
    stock: i32,
}

impl Product {
    /// 商品名最大字符数。
    pub const NAME_MAX_CHARS: usize = 100;

    /// 校验并创建商品。
    pub fn try_new(
        id: ProductId,
        name: &str,
        price_cents: i64,
        stock: i32,
    ) -> Result<Self, String> {
        let name = name.trim();
        let chars = name.chars().count();
        if chars == 0 || chars > Self::NAME_MAX_CHARS {
            return Err(format!("商品名长度需为 1〜{} 个字符", Self::NAME_MAX_CHARS));
        }
        if price_cents < 0 {
            return Err("价格不能为负数".to_string());
        }
        if stock < 0 {
            return Err("库存不能为负数".to_string());
        }
        Ok(Self {
            id,
            name: name.to_string(),
            price_cents,
            stock,
        })
    }

    // ---------- 只读访问（getter） ----------

    pub fn id(&self) -> ProductId {
        self.id
    }

    pub fn name(&self) -> &str {
        &self.name
    }

    pub fn price_cents(&self) -> i64 {
        self.price_cents
    }

    pub fn stock(&self) -> i32 {
        self.stock
    }

    /// 价格的“元”表示，例如 `"199.00"`。
    pub fn price_yuan(&self) -> String {
        money::format_yuan(self.price_cents)
    }
    pub fn in_stock(&self) -> bool {
        self.stock > 0
    }

    pub fn can_buy(&self, qty: Quantity) -> bool {
        self.stock >= qty.get()
    }
    // ---------- 业务操作 ----------

    /// 扣减库存。库存不足时返回错误，且**不修改**库存。
    pub fn deduct_stock(&mut self, qty: Quantity) -> Result<(), String> {
        if !self.can_buy(qty) {
            return Err(format!("库存不足：剩余 {}，需要 {}", self.stock, qty.get()));
        }
        self.stock -= qty.get();
        Ok(())
    }

    /// 补货，数量必须为正。
    pub fn restock(&mut self, qty: i32) -> Result<(), String> {
        if qty <= 0 {
            return Err("补货数量必须大于 0".to_string());
        }
        self.stock = self
            .stock
            .checked_add(qty)
            .ok_or_else(|| "库存数量溢出".to_string())?;
        Ok(())
    }

    /// 调整价格，不能为负。
    pub fn change_price(&mut self, price_cents: i64) -> Result<(), String> {
        if price_cents < 0 {
            return Err("价格不能为负数".to_string());
        }
        self.price_cents = price_cents;
        Ok(())
    }
}

````rust
//! 订单领域模型与订单状态机。

use crate::ids::{OrderId, ProductId, UserId};
use crate::money;
use crate::quantity::Quantity;

/// 订单的简单状态，用于存储到数据库和对外展示。
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum OrderStatus {
    Pending,
    Paid,
    Shipped,
    Completed,
    Cancelled,
}

impl OrderStatus {
    /// 全部状态，便于遍历和测试。
    pub const ALL: [OrderStatus; 5] = [
        OrderStatus::Pending,
        OrderStatus::Paid,
        OrderStatus::Shipped,
        OrderStatus::Completed,
        OrderStatus::Cancelled,
    ];

    /// 数据库中存储的字符串。
    pub fn as_str(self) -> &'static str {
        match self {
            Self::Pending => "pending",
            Self::Paid => "paid",
            Self::Shipped => "shipped",
            Self::Completed => "completed",
            Self::Cancelled => "cancelled",
        }
    }

    /// 从数据库字符串解析；未知值返回 `None`，由调用方决定如何报错。
    pub fn parse(s: &str) -> Option<Self> {
        match s {
            "pending" => Some(Self::Pending),
            "paid" => Some(Self::Paid),
            "shipped" => Some(Self::Shipped),
            "completed" => Some(Self::Completed),
            "cancelled" => Some(Self::Cancelled),
            _ => None,
        }
    }

    /// 是否为终态（不能再发生任何转移）。
    pub fn is_terminal(self) -> bool {
        matches!(self, Self::Completed | Self::Cancelled)
    }
}

/// 订单的完整运行时状态：每个状态携带且只携带它需要的数据。
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum OrderState {
    Pending,
    Paid { paid_at: i64 },
    Shipped { paid_at: i64, tracking_no: String },
    Completed { paid_at: i64, tracking_no: String },
    Cancelled { reason: String },
}
impl OrderState {
    pub fn status(&self) -> OrderStatus {
        match self {
            Self::Pending => OrderStatus::Pending,
            Self::Paid { .. } => OrderStatus::Paid,
            Self::Shipped { .. } => OrderStatus::Shipped,
            Self::Completed { .. } => OrderStatus::Completed,
            Self::Cancelled { .. } => OrderStatus::Cancelled,
        }
    }
}

/// 订单操作可能出现的错误。
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum OrderError {
    /// 输入不合法
    InvalidInput(&'static str),
    /// 金额计算溢出或超过单笔上限
    AmountOverflow,
    /// 当前状态不允许该操作
    IllegalTransition {
        from: OrderStatus,
        action: &'static str,
    },
}

/// 订单。
///
/// ```
/// use common::ids::{OrderId, ProductId, UserId};
/// use common::order::{Order, OrderStatus};
/// use common::quantity::Quantity;
///
/// let qty = Quantity::try_new(2).expect("示例数量应当合法");
/// let mut order = Order::new(OrderId::new(1), UserId::new(7), ProductId::new(42), 19_900,
///     qty).expect("示例订单应当合法");
/// assert_eq!(order.total_cents(), 39_800);
/// order.pay(1_760_000_000).expect("待支付订单应允许支付");
/// assert_eq!(order.status(), OrderStatus::Paid);
/// ```
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Order {
    id: OrderId,
    user_id: UserId,
    product_id: ProductId,
    quantity: Quantity,
    unit_price_cents: i64,
    total_cents: i64,
    state: OrderState,
}

impl Order {
    /// 创建待支付订单，自动计算总价。
    pub fn new(
        id: OrderId,
        user_id: UserId,
        product_id: ProductId,
        unit_price_cents: i64,
        quantity: Quantity,
    ) -> Result<Self, OrderError> {
        if unit_price_cents < 0 {
            return Err(OrderError::InvalidInput("单价不能为负数"));
        }
        let total_cents = money::line_total(unit_price_cents, i64::from(quantity.get()))
            .ok_or(OrderError::AmountOverflow)?;
        Ok(Self {
            id,
            user_id,
            product_id,
            quantity,
            unit_price_cents,
            total_cents,
            state: OrderState::Pending,
        })
    }

    // ---------- 只读访问 ----------

    pub fn id(&self) -> OrderId {
        self.id
    }

    pub fn user_id(&self) -> UserId {
        self.user_id
    }

    pub fn product_id(&self) -> ProductId {
        self.product_id
    }

    pub fn quantity(&self) -> Quantity {
        self.quantity
    }
    pub fn unit_price_cents(&self) -> i64 {
        self.unit_price_cents
    }

    pub fn total_cents(&self) -> i64 {
        self.total_cents
    }

    pub fn state(&self) -> &OrderState {
        &self.state
    }

    pub fn status(&self) -> OrderStatus {
        self.state.status()
    }

    // ---------- 状态转移 ----------

    /// 支付：待支付 → 已支付。
    pub fn pay(&mut self, paid_at: i64) -> Result<(), OrderError> {
        match self.state {
            OrderState::Pending => {
                self.state = OrderState::Paid { paid_at };
                Ok(())
            }
            _ => Err(self.illegal("pay")),
        }
    }

    /// 发货：已支付 → 已发货。
    pub fn ship(&mut self, tracking_no: &str) -> Result<(), OrderError> {
        let tracking_no = tracking_no.trim();
        if tracking_no.is_empty() {
            return Err(OrderError::InvalidInput("快递单号不能为空"));
        }
        match self.state {
            OrderState::Paid { paid_at } => {
                self.state = OrderState::Shipped {
                    paid_at,
                    tracking_no: tracking_no.to_string(),
                };
                Ok(())
            }
            _ => Err(self.illegal("ship")),
        }
    }

    /// 确认收货：已发货 → 已完成。快递单号从旧状态“搬”到新状态，不复制。
    pub fn complete(&mut self) -> Result<(), OrderError> {
        // 先用占位值把旧状态整体取出，拿到其中 String 的所有权
        match std::mem::replace(&mut self.state, OrderState::Pending) {
            OrderState::Shipped {
                paid_at,
                tracking_no,
            } => {
                self.state = OrderState::Completed {
                    paid_at,
                    tracking_no,
                };
                Ok(())
            }
            other => {
                // 不允许转移：把旧状态原样放回
                self.state = other;
                Err(self.illegal("complete"))
            }
        }
    }

    /// 取消：待支付或已支付 → 已取消。
    pub fn cancel(&mut self, reason: &str) -> Result<(), OrderError> {
        let reason = reason.trim();
        if reason.is_empty() {
            return Err(OrderError::InvalidInput("取消原因不能为空"));
        }
        match self.state {
            OrderState::Pending | OrderState::Paid { .. } => {
                self.state = OrderState::Cancelled {
                    reason: reason.to_string(),
                };
                Ok(())
            }
            _ => Err(self.illegal("cancel")),
        }
    }

    fn illegal(&self, action: &'static str) -> OrderError {
        OrderError::IllegalTransition {
            from: self.status(),
            action,
        }
    }
}

mod tests {

### 3.7.7 代码精讲

本章的 pay 只是内存状态转移，不代表调用支付渠道成功；Paid → Cancelled 也不会自动退款或保留完整支付审计。接入真实支付前还需要独立的支付事实、幂等与退款流程。此处先把单个实体的状态规则讲清楚。

为什么有 OrderStatus 和 OrderState 两个枚举：OrderState 是运行时的完整状态，保证数据与状态一致；OrderStatus 是可以 Copy 的轻量标签，用于存储、比较、作为 HashMap 键、出现在错误信息中。数据库表会有一个 status TEXT 列存 as\_str() 的结果，再加 paid\_at 、tracking\_no 等可空列；第 14 章从数据库读出时，会根据 status 和这些列重建 OrderState ——如果 status 是 shipped 但tracking\_no 为空，说明数据损坏，返回错误而不是继续运行，这回答了 3.6.7 练习 4。

match self.state 为什么没有移动：self 是 &amp;mut Order ，直接 match 字段 self.state 时，只要分支中的绑定都是 Copy 类型（paid\_at: i64 ）或者没有绑定（.. 、\_ ），就不会发生移动，所以可以在分支中重新给 self.state 赋值。

complete 中的 mem::replace ：从 Shipped 转到 Completed 需要把 tracking\_no: String 从旧状态拿到新状态。直接 match self.state { Shipped { tracking\_no, .. } =&gt; ... } 会试图从&amp;mut 后面移出 String（E0507）。std::mem::replace(&amp;mut self.state,OrderState::Pending) 先放一个临时占位值、把旧状态的所有权整体拿出来，再在分支中组装新状态；不允许转移时把旧状态原样放回。整个过程没有复制字符串。测试 failed\_complete\_keeps\_state 专门验证了“放回”这一步——这种防御性测试能捕获最隐蔽的状态损坏 bug。

illegal 为什么是私有方法：它没有 pub ，只在本模块内部使用，是实现细节，外部无需知道。

错误类型用枚举：OrderError 让调用方可以用 match 区分不同错误并返回不同的 HTTP 状态码（非法输入 → 422，非法转移 → 409）。第 4 章会为它实现标准的 Error trait，第 12、15 章会把领域错误适配为 HTTP 响应。

### 3.7.12 本章小结

结构体表示“和”，枚举表示“或”；newtype 零开销地创造新类型，用于强类型 ID 和带约束的值。

方法通过 &amp;self 、&amp;mut self 、self 表达只读、修改和消耗；构造函数约定为 new /try\_new，参数多时用 Builder。

derive 自动实现常用 trait；含敏感字段的类型要手动实现 Debug；作为 HashMap 键需要 Eq+Hash 。

Option 取代 null，编译器强制处理“没有值”；它的组合方法让代码简洁。

模式匹配是穷尽的、可嵌套的，并支持守卫、@ 、切片模式；匹配引用时绑定自动为引用；业务枚举尽量不用 \_ 兜底。

建模原则：用枚举让非法状态无法表示；解析而非校验；私有字段 + 校验过的构造函数保证不变量；状态转移用表达业务含义的方法。

RustMall 有了强类型 ID、Quantity 、Product 与订单状态机，共 27 个单元测试。

下一章深入讲错误处理：为 OrderError 实现标准 Error trait，系统掌握 Result 、? 运算符、错误转换，以及“什么时候可以 panic”。
