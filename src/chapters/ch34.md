# 第 34 章 独立用户服务与会话生命周期

第33章整理了契约、角色和配置基线。现在开始把身份判断放进独立users服务：它拥有用户与会话数据库，负责注册、登录、查询身份和退出；后续商品适配器与订单服务通过明确接口取得身份，不相信客户端自己填写的用户编号或管理员请求头。

本章从密码小实验、JWT与会话的区别讲起，再把完整实现加入services/commerce。继续使用前文common、workspace、锁文件和检查工具；默认监听127.0.0.1:8082，避开既有8081网关。新增专用PostgreSQL与Redis本地实验配置，最后通过真实依赖、HTTP和故障窗口验收。

当前是并行引入新身份服务的阶段：旧gateway仍指向过渡facade，新users先独立验证。新旧身份库不会自动同步，旧JWT也不是新users令牌。后续统一入口时必须明确切流与账号迁移，不能把两个库中相同的i64编号认作同一个人。

## 34.1 先理解身份服务替谁作决定

### 34.1.1 【入门】认证与授权回答不同问题

认证回答“这个请求当前属于哪个用户”；授权回答“这个用户能否执行这项动作”。users验证会话后返回Identity，包含id和当前role；商品创建和订单查询仍要根据自己的业务规则决定是否允许。

前端发x-user-id=7或x-user-role=admin，不能形成可信身份。网关转发请求也不意味着其他内部端口从此安全，资源服务必须有清楚的身份验证路径。

### 34.1.2 【入门】密码不应成为跨服务参数

用户只向users提交密码。后续服务收到Bearer令牌，再通过UserRemote调用users查询经过验证的身份；它们不读取password_hash，也不持有JWT签名密钥。

同仓库、同Rust语言、同一台本机，都不能成为共享密码表的理由。跨服务身份契约应比数据库行更小、更稳定。

### 34.1.3 【进阶】本章的实际边界

| 单元 | 本章责任 | 不应获得的能力 |
| --- | --- | --- |
| users进程 | 密码验证、JWT签发、会话和撤销 | 不直接改商品、库存或订单 |
| users数据库 | 用户与会话权威事实 | 不复制整个商品库 |
| users专用Redis | 登录计数与撤销标记 | 不保存明文密码或完整JWT |
| UserRemote调用方 | 有界查询身份、处理401与503 | 不靠伪造头或自带actor_id授权 |
| 过渡facade | 继续前章公共路径，等待后续统一切流 | 不把新旧签发者的编号混用 |

### 34.1.4 【精通】集中校验的取舍

本章沿用HS256，只有users持有签名密钥。其他服务每次访问/me，能同时检查数据库会话和当前角色，也会受到users、PostgreSQL与Redis可用性的影响。

后面可研究非对称签名、公钥缓存和JWKS，但本地验签只能证明签名与声明，不能自然提供及时撤销。改变认证方式时，要一起设计会话撤销、角色变化、密钥轮换和依赖故障语义。

## 34.2 从一个密码哈希小实验开始

### 34.2.1 【入门】加密和密码哈希不是同一个目标

服务登录时不需要还原原密码，只需判断用户这次提供的密码是否与原来一致。数据库保存Argon2id的PHC编码串，其中含算法、版本、参数、随机盐和计算结果。

随机盐使两个相同密码通常产生不同保存串；验证函数读取保存串并重新计算。不要自己改成“先SHA256再保存”，也不要把数据库中的串当作可以直接拿来登录的凭据。

### 34.2.2 【入门】复用官方库的哈希与验证接口

在当前工作区旁增加独立概念实验password-lab，先理解底层机制。新建password-lab/Cargo.toml，其中空workspace声明让它拥有自己的实验锁文件：
```toml
[package]
name = "password-lab"
version = "0.1.0"
edition = "2024"
rust-version = "1.92"
[workspace]
[dependencies]
argon2 = "=0.5.3"
rand_core = { version = "0.6.4", features = ["getrandom"] }
[profile.dev.package."*"]
opt-level = 2
```

新建password-lab/src/main.rs：
```rust
use argon2::{
    Argon2, PasswordHasher, PasswordVerifier,
    password_hash::{PasswordHash, SaltString},
};
use rand_core::OsRng;

fn main() {
    // A fixed teaching fixture, never a real account credential.
    let password = b"password-only-for-this-lab";
    let algorithm = Argon2::default();
    let first = algorithm
        .hash_password(password, &SaltString::generate(&mut OsRng))
        .expect("lab hashing succeeds")
        .to_string();
    let second = algorithm
        .hash_password(password, &SaltString::generate(&mut OsRng))
        .expect("lab hashing succeeds")
        .to_string();
    assert_ne!(first, second);
    let saved = PasswordHash::new(&first).expect("generated PHC parses");
    assert!(algorithm.verify_password(password, &saved).is_ok());
    assert!(algorithm.verify_password(b"incorrect", &saved).is_err());
    println!("PASS independent salts, saved PHC verification, wrong password rejection");
}
```

在当前RustMall根目录运行：
```bash
cargo +1.92.0 run --manifest-path password-lab/Cargo.toml
cargo +1.92.0 run --locked --manifest-path password-lab/Cargo.toml
```

第一次为这个小实验建立Cargo.lock，第二次验证锁定依赖也能执行。观察相同密码配独立盐得到不同PHC串，保存串可以验证正确密码，错误密码被拒绝。输出只显示断言摘要。

OsRng需要rand_core的getrandom特性，清单中必须明确开启。大型workspace可能由别的依赖间接开启特性，独立小实验则会暴露缺失声明；不能据此认为同一段代码可以不声明它使用的能力。

小实验用expect标明受控夹具的失败点，后面的HTTP服务改为返回明确错误。它在普通main中顺序计算，服务端则须把同样的昂贵工作放进spawn_blocking并限制容量。

[Argon2库文档](https://docs.rs/argon2/0.5.3/argon2/)给出了PHC保存与验证模式。验证使用保存串内的参数，因此本章服务另检查存储参数上界，避免异常历史串让一次验证申请过量资源。

### 34.2.3 【进阶】昂贵计算放到spawn_blocking

密码计算消耗CPU与内存，直接在异步执行器线程上运行，会阻塞其他请求。spawn_blocking把它交给专用阻塞线程池；仍需单独信号量限制并发，不能把线程池误当成无限资源。

本章users状态共享四个哈希许可。注册和登录在启动计算前尝试取许可，满载立即429；许可移入阻塞闭包，计算真正结束才释放。HTTP请求取消后，已经开始的阻塞任务不会因此自动停止，所以不能在请求future被丢弃时提前归还名额。

### 34.2.4 【进阶】新注册策略与旧密码验证分开

新注册要求密码为12-128字节，按UTF-8字节而非中文字符计数。登录允许非空、最多256字节的输入，以兼容前章较短的有效旧密码；它并不把旧用户重新注册一遍。

用户名继续调用common::text::normalize_username：去首尾空白、转小写、按Unicode标量值计数3-20，并限制为字母数字或下划线。该规则不是完整Unicode用户名安全策略，也没有把视觉相似字符全部合并。

### 34.2.5 【精通】无此用户也执行验证

登录查不到用户时使用启动阶段生成的dummy哈希，仍执行一次同类验证，最后因id无效返回401。错误密码与未知用户使用相同响应。

它减少明显的时间差，不能保证网络、数据库和CPU路径完全等时；注册重复名仍会返回409。本章不把这一做法描述成不可枚举用户系统。

## 34.3 JWT与持久会话分别保存什么

### 34.3.1 【入门】令牌载荷不是保密容器

JWT带签名而不提供本章意义上的载荷加密。持有人可以读取声明，因此只放sub、jti、exp、iss和aud，不放密码、数据库地址、私密业务信息或完整用户对象。

sub使用字符串表示用户编号，解析成正数i64后才进入数据库判断；jti是本次令牌的UUID；iss为rustmall-users，aud为rustmall-api。令牌只由users签发，后续服务通过查询取得Identity。

### 34.3.2 【进阶】明确约束验证器

解码固定HS256，要求正确issuer和audience，leeway设置为零，再拒绝无效用户编号与nil jti。Claims中的字段都是必需字段，缺失不能默默补成有效身份。

[jsonwebtoken 9的Validation文档](https://docs.rs/jsonwebtoken/9.3.1/jsonwebtoken/struct.Validation.html)列出了算法、声明与时钟容忍设置。默认值不等于业务策略；升级库时也要重新验证这些配置。

### 34.3.3 【入门】签名有效不代表会话存在

登录先保存sessions行，再返回签名令牌。/me除验签外，还要求jti与user_id匹配、未撤销、数据库过期时间仍有效。一个用测试密钥签名但从未签发落库的令牌，应返回401。

本章会话过期与JWT过期都要满足。登录在保存会话后、返回令牌前失败，可能留下没有客户端使用的会话，后续按保留策略清理；不能为了避免这种残留而先返回令牌再异步保存。

### 34.3.4 【进阶】角色取当前数据库事实

JWT不保存可长期陈旧的管理员role。/me在会话通过后查询当前用户角色；降权后，后续身份查询看到user，不能继续仅凭旧令牌内某个admin字符串获得权限。

已在降权或退出之前完成身份检查的在途请求，不会被本章自动撤回。需要更强的操作边界时，应在具体高风险业务动作处再设计版本或权限检查。

### 34.3.5 【精通】会话策略的当前范围

本章提供一小时访问令牌和持久撤销，没有刷新令牌、找回密码、多因素认证、密码重置后的全会话撤销或设备管理。不能把前章接口设计草案中的refresh路径当成本章已实现路由。

这些产品能力要围绕已存在的会话模型扩展，并明确身份恢复与审计规则。

## 34.4 Redis：计数、撤销与故障语义

### 34.4.1 【入门】登录计数需要同时设TTL

脚本在一个Redis执行单元中INCR用户名计数，首次计数时EXPIRE 60秒，返回次数。大于10后返回429。若分成独立INCR与EXPIRE，中间进程失败可能留下没有到期时间的键。

[Redis脚本文档](https://redis.io/docs/latest/develop/programmability/eval-intro/)说明脚本执行期间不会与其他命令交错。本章脚本很短；这不是任意错误下的SQL式回滚保证，不能在脚本里安排长时间业务流程。

### 34.4.2 【进阶】用户名限速不是完整入口防护

键为users:v1:login:规范化用户名，正确与错误密码都计数。固定窗口、按用户限速容易影响共享账号，也可能被攻击者用于锁定他人的短期登录。

公网还需可信来源限速、代理链处理、告警与恢复流程。不要把客户端自报IP头当作可信源，也不要用这一层取代哈希并发限制。

### 34.4.3 【入门】撤销标记只保存身份索引

退出在Redis写users:v1:revoked:jti，TTL为剩余令牌寿命，至少一秒。Redis不保存令牌正文，键存在说明该jti不应接受。

更关键的是PostgreSQL中的revoked_at：Redis重启丢失键后，/me仍会查持久会话并拒绝已撤销令牌。Redis是快速拒绝和限速依赖，持久会话维持撤销事实。

### 34.4.4 【精通】先持久撤销，再更新Redis

logout先验签并核对会话身份，执行UPDATE，使用COALESCE保留第一次撤销时间，然后写Redis。若数据库提交成功、Redis写失败，对外返回503，但令牌已经被持久撤销。

调用方此时应把结果当作可能已完成的退出，重试同一个令牌。logout不要求它仍是活跃会话，因而重试可完成Redis标记并稳定返回204；不能先调用“必须活跃”的/me逻辑，否则第一次已完成而回复丢失时，重试会变成401。

### 34.4.5 【进阶】依赖故障如何回答

合法令牌的认证需要Redis和数据库，任一不可用返回503，不把查询失败当“没有撤销”。/readyz同时检查两者；/healthz只表示进程仍可响应。

注册主要依赖数据库和哈希资源，Redis中断时它仍可能成功；readiness变红表示当前服务整体不具备完整认证能力，不代表每条路由都必然失败。非法令牌也可能在访问依赖之前就被401拒绝。

### 34.4.6 【精通】专用Redis的策略

本地Redis使用noeviction，防止内存压力静默驱逐仍应存在的身份键；写入失败必须显式处理。它与可降级的商品缓存不同，不能把第18章“缓存失败按miss”直接应用到登录限速或身份判断。

本实验故意关闭Redis持久化，用真实重启验证数据库会话屏障；这不意味着生产Redis无需持久化或高可用。恢复后已有撤销仍有效，登录计数则会丢失，这项限制需要明确接受。

### 34.5.2 【入门】新建独立迁移

文件services/commerce/migrations/users/0001_users.sql：
```sql
CREATE TABLE users (
 id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
 username TEXT NOT NULL UNIQUE CHECK(char_length(username) BETWEEN 3 AND 20),
 password_hash TEXT NOT NULL,
 role TEXT NOT NULL DEFAULT 'user' CHECK(role IN ('user','admin')),
 created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE TABLE sessions (
 jti UUID PRIMARY KEY,
 user_id BIGINT NOT NULL REFERENCES users(id),
 expires_at TIMESTAMPTZ NOT NULL,
 revoked_at TIMESTAMPTZ
);
CREATE INDEX sessions_expiry ON sessions(expires_at);
```

users保存规范化用户名、PHC串与当前角色；sessions以jti为主键，引用真实用户。expires_at索引帮助后续按保留策略查找过期会话，不意味着数据库会自动清理。

新库迁移只对users库执行。不要把它与monolith旧迁移、catalog迁移或projection迁移放在同一个DATABASE_URL上依次试，表名相同也不代表迁移可以互换。

### 34.5.3 【进阶】旧身份数据如何处理

本章新建空users库，独立验证新契约；现有旧用户不会自动迁入。真实切流前，要确定规范化用户名冲突、用户ID映射、密码哈希参数、角色、关联业务外键和旧会话失效方案，并在备份副本演练。

本书后续统一入口时继续补验这一边界。本阶段避免把新旧令牌混用，也不让订单服务同时接受两个未经映射的用户编号来源。

### 34.6.1 【入门】库声明与信号处理

### 34.6.2 【进阶】完整runtime实现

文件services/commerce/src/runtime.rs：
```rust
use axum::{
    Json, Router,
    http::{HeaderMap, StatusCode},
    response::{IntoResponse, Response},
};
use serde_json::json;
use sqlx::{PgPool, postgres::PgPoolOptions};
use std::{sync::Arc, time::Duration};
use tokio::sync::Semaphore;
use tokio_util::sync::CancellationToken;

#[derive(Debug)]
pub struct ApiError(pub StatusCode, pub &'static str);
impl IntoResponse for ApiError {
    fn into_response(self) -> Response {
        {
            let code = match self.0.as_u16() {
                400 | 422 => "INVALID_INPUT",
                401 => "UNAUTHORIZED",
                403 => "FORBIDDEN",
                404 => "NOT_FOUND",
                409 => "CONFLICT",
                413 => "PAYLOAD_TOO_LARGE",
                415 => "UNSUPPORTED_MEDIA_TYPE",
                429 => "RESOURCE_EXHAUSTED",
                503 => "UNAVAILABLE",
                504 => "DEADLINE_EXCEEDED",
                _ => "INTERNAL",
            };
            (self.0, Json(json!({"code":code,"message":self.1}))).into_response()
        }
    }
}
impl From<sqlx::Error> for ApiError {
    fn from(error: sqlx::Error) -> Self {
        tracing::error!(%error,"database operation failed");
        Self(StatusCode::SERVICE_UNAVAILABLE, "database unavailable")
    }
}
pub type ApiResult<T> = Result<T, ApiError>;
pub fn invalid() -> ApiError {
    ApiError(StatusCode::BAD_REQUEST, "invalid input")
}
pub fn unauthorized() -> ApiError {
    ApiError(StatusCode::UNAUTHORIZED, "authentication required")
}
pub fn unavailable() -> ApiError {
    ApiError(
        StatusCode::SERVICE_UNAVAILABLE,
        "dependency unavailable; retry with same identity",
    )
}
pub fn bearer(h: &HeaderMap) -> ApiResult<&str> {
    if h.get_all("authorization").iter().count() != 1 {
        return Err(unauthorized());
    }
    h.get("authorization")
        .and_then(|s| s.to_str().ok())
        .and_then(|s| s.split_once(' '))
        .filter(|(scheme, _)| scheme.eq_ignore_ascii_case("Bearer"))
        .map(|(_, s)| s.trim())
        .filter(|s| !s.is_empty() && s.len() < 4096)
        .ok_or_else(unauthorized)
}

    }

/// Preserve the book's JSON error contract for request decoding failures.
pub struct BodyJson<T>(pub T);
impl<T, S> axum::extract::FromRequest<S> for BodyJson<T>
where
    T: serde::de::DeserializeOwned,
    S: Send + Sync,
{
    type Rejection = ApiError;
    async fn from_request(
        request: axum::extract::Request,
        state: &S,
    ) -> Result<Self, Self::Rejection> {
        use axum::extract::rejection::JsonRejection;
        match axum::Json::<T>::from_request(request, state).await {
            Ok(axum::Json(value)) => Ok(Self(value)),
            Err(JsonRejection::JsonDataError(_)) => Err(ApiError(
                StatusCode::UNPROCESSABLE_ENTITY,
                "JSON fields do not match contract",
            )),
            Err(JsonRejection::MissingJsonContentType(_)) => Err(ApiError(
                StatusCode::UNSUPPORTED_MEDIA_TYPE,
                "application/json required",
            )),
            Err(error) if error.status() == StatusCode::PAYLOAD_TOO_LARGE => {
                Err(ApiError(StatusCode::PAYLOAD_TOO_LARGE, "body too large"))
            }
            Err(_) => Err(invalid()),
        }
    }
}

/// Bound application requests; probes retain their own dependency budgets.
pub fn bounded(router: Router) -> Router {
    use axum::{
        extract::Request,
        middleware::{self, Next},
    };
    let capacity = capacity();
    router.layer(middleware::from_fn(move |request: Request, next: Next| {
        let capacity = capacity.clone();
        async move {
            let id = request
                .headers()
                .get("x-request-id")
                .and_then(|v| v.to_str().ok())
                .and_then(|v| uuid::Uuid::parse_str(v).ok())
                .unwrap_or_else(uuid::Uuid::new_v4);
            let probe = matches!(request.uri().path(), "/healthz" | "/readyz");
            let mut response = if probe {
                next.run(request).await
            } else {
                match enter(&capacity) {
                    Err(error) => error.into_response(),
                    Ok(_permit) => {
                        match tokio::time::timeout(Duration::from_secs(5), next.run(request)).await
                        {
                            Ok(response) => response,
                            Err(_) => ApiError(
                                StatusCode::GATEWAY_TIMEOUT,
                                "request budget exhausted; result may be unknown",
                            )
                            .into_response(),
                        }
                    }
                }
            };
            response
                .headers_mut()
                .insert("x-request-id", id.to_string().parse().expect("UUID header"));
            response
                .headers_mut()
                .insert("cache-control", "no-store".parse().expect("static header"));
            response
                .headers_mut()
                .insert("pragma", "no-cache".parse().expect("static header"));
            tracing::info!(request_id=%id,status=response.status().as_u16(),"request completed");
            response
        }
    }))
}
```

ApiError保持JSON的code与message契约，数据库错误记录服务端日志后返回通用依赖错误。BodyJson区分字段错误422、缺Content-Type 415、正文过大413和语法错误400，避免新增服务后突然换成框架默认纯文本错误。

### 34.6.3 【进阶】请求与资源各自有界

请求正文最多4KiB，HTTP业务请求最多32个在途、五秒总期限，哈希任务另限四个。业务请求满载429，超过总期限504；健康探针绕开业务并发许可，readiness自身有500ms依赖预算。

PgPool最多10连接，申请连接500ms，连接建立后设置语句1500ms与锁等待500ms。HTTP、连接池、语句和哈希分别限制不同资源，不能把增加一个超时理解为所有等待都已停止。

### 34.6.4 【精通】停止等待不会停止阻塞计算

五秒HTTP期限会丢弃业务future，但已启动的spawn_blocking仍执行并持有哈希许可。数据库操作也可能处于提交边界；不要把504解释为“注册、登录或退出一定没执行”。

服务停机等待HTTP最多20秒，随后主入口关闭数据库池另有两秒预算。Tokio还可能等待已经启动的阻塞任务，因此存储哈希参数上限也关系到停机可控性；它不是对任意操作系统调度的绝对终止保证。

### 34.6.5 【进阶】日志和响应不保存秘密

中间件只记录请求ID和状态，不记录Authorization、密码或完整JSON正文。响应添加Cache-Control: no-store和Pragma: no-cache；调用方也不应把令牌放进URL、错误报告或终端截图。

```rust
async fn register(
    State(s): State<Users>,
    BodyJson(mut c): BodyJson<Credentials>,

async fn login(
    State(s): State<Users>,
    BodyJson(mut c): BodyJson<Credentials>,
) -> ApiResult<Json<serde_json::Value>> {
    if c.password.is_empty() || c.password.len() > 256 {
        return Err(unauthorized());
    }
    c.username = common::text::normalize_username(&c.username).map_err(|_| unauthorized())?;
    let mut redis = s.redis.clone();
    let count:i64=redis::Script::new("local n=redis.call('INCR',KEYS[1]); if n==1 then redis.call('EXPIRE',KEYS[1],60) end; return n")
  .key(format!("users:v1:login:{}",c.username)).invoke_async(&mut redis).await.map_err(|_|unavailable())?;
    if count > 10 {
        return Err(ApiError(StatusCode::TOO_MANY_REQUESTS, "try again later"));
    }
    let row: Option<(i64, String)> =
        sqlx::query_as("SELECT id,password_hash FROM users WHERE username=$1")
            .bind(c.username)
            .fetch_optional(&s.pool)
            .await?;
    let (id, stored) = row.unwrap_or((0, s.dummy.as_ref().clone()));
    let permit = enter(&s.hashes)?;
    let ok = tokio::task::spawn_blocking(move || {
        let _permit = permit;
        PasswordHash::new(&stored).is_ok_and(|p| {
            let supported = p.algorithm.as_str() == "argon2id"
                && p.version == Some(19)
                && p.params
                    .get_decimal("m")
                    .is_some_and(|m| (8..=65536).contains(&m))
                && p.params
                    .get_decimal("t")
                    .is_some_and(|t| (1..=4).contains(&t))
                && p.params
                    .get_decimal("p")
                    .is_some_and(|p| (1..=4).contains(&p));
            supported
                && Argon2::default()
                    .verify_password(c.password.as_bytes(), &p)
                    .is_ok()
        })
    })
    .await
    .map_err(|_| unavailable())?;
    if !ok || id <= 0 {
        return Err(unauthorized());
    }
    let claims = Claims {
        sub: id.to_string(),
        jti: Uuid::new_v4(),
        exp: now()? + 3600,
        iss: "rustmall-users".into(),
        aud: "rustmall-api".into(),
    };
    sqlx::query("INSERT INTO sessions(jti,user_id,expires_at) VALUES($1,$2,to_timestamp($3))")
        .bind(claims.jti)
        .bind(id)
        .bind(claims.exp as f64)
        .execute(&s.pool)
        .await?;
    let token = jsonwebtoken::encode(
        &Header::new(Algorithm::HS256),
        &claims,
        &EncodingKey::from_secret(s.key.as_bytes()),
    )
    .map_err(|_| unavailable())?;

        serde_json::json!({"access_token":token,"token_type":"Bearer","expires_in":3600}),

fn decode_claims(s: &Users, h: &HeaderMap) -> ApiResult<Claims> {
    let raw = bearer(h)?;
    let mut v = Validation::new(Algorithm::HS256);
    v.set_issuer(&["rustmall-users"]);
    v.set_audience(&["rustmall-api"]);
    v.leeway = 0;
    let c = jsonwebtoken::decode::<Claims>(raw, &DecodingKey::from_secret(s.key.as_bytes()), &v)
        .map_err(|_| unauthorized())?
        .claims;
    c.user_id()?;
    if c.jti.is_nil() {
        return Err(unauthorized());
    }
    Ok(c)
}
async fn claims(s: &Users, h: &HeaderMap) -> ApiResult<Claims> {
    let c = decode_claims(s, h)?;
    let mut redis = s.redis.clone();
    let revoked: bool = redis::cmd("EXISTS")
        .arg(format!("users:v1:revoked:{}", c.jti))
        .query_async(&mut redis)
        .await
        .map_err(|_| unavailable())?;
    if revoked {
        return Err(unauthorized());
    }
    let active:bool=sqlx::query_scalar("SELECT EXISTS(SELECT 1 FROM sessions WHERE jti=$1 AND user_id=$2 AND revoked_at IS NULL AND expires_at>now())")
        .bind(c.jti).bind(c.user_id()?).fetch_one(&s.pool).await?;
    if !active {
        return Err(unauthorized());
    }
    Ok(c)
}
async fn me(State(s): State<Users>, h: HeaderMap) -> ApiResult<Json<Identity>> {

        .bind(id)
        .fetch_optional(&s.pool)
        .await?
        .ok_or_else(unauthorized)?;

}
async fn logout(State(s): State<Users>, h: HeaderMap) -> ApiResult<StatusCode> {
    let c = decode_claims(&s, &h)?;
    let changed = sqlx::query("UPDATE sessions SET revoked_at=COALESCE(revoked_at,now()) WHERE jti=$1 AND user_id=$2 AND expires_at>now()")
        .bind(c.jti).bind(c.user_id()?).execute(&s.pool).await?;
    if changed.rows_affected() != 1 {
        return Err(unauthorized());
    }
    let mut redis = s.redis.clone();
    let _: () = redis::cmd("SET")
        .arg(format!("users:v1:revoked:{}", c.jti))
        .arg(1)
        .arg("EX")
        .arg(c.exp.saturating_sub(now()?).max(1))
        .query_async(&mut redis)
        .await
        .map_err(|_| unavailable())?;
    Ok(StatusCode::NO_CONTENT)
}

}
impl UserRemote {
    pub fn new(base: &str) -> anyhow::Result<Self> {
        let url = reqwest::Url::parse(base)?;
        anyhow::ensure!(
            matches!(url.scheme(), "http" | "https")
                && url.host_str().is_some()
                && url.username().is_empty()
                && url.password().is_none()
                && url.path() == "/"
                && url.query().is_none()
                && url.fragment().is_none(),
            "users endpoint must be an HTTP(S) origin without credentials"
        );
        Ok(Self {
            client: client()?,
            base: base.trim_end_matches('/').to_owned(),
        })
    }

    pub async fn authenticate(&self, h: &HeaderMap) -> ApiResult<i64> {
        Ok(self.identity(h).await?.id)
    }
    pub async fn identity(&self, h: &HeaderMap) -> ApiResult<Identity> {
        tokio::time::timeout(std::time::Duration::from_secs(2), self.lookup(h))
            .await
            .map_err(|_| unavailable())?
    }
    async fn lookup(&self, h: &HeaderMap) -> ApiResult<Identity> {
        let r = self
            .client
            .get(format!("{}/api/v1/auth/me", self.base))
            .bearer_auth(bearer(h)?)
            .send()
            .await
            .map_err(|_| unavailable())?;
        if r.status() == StatusCode::UNAUTHORIZED {
            return Err(unauthorized());
        }
        if !r.status().is_success() {
            return Err(unavailable());
        }
        let mut r = r;
        let mut bytes = Vec::new();
        while let Some(chunk) = r.chunk().await.map_err(|_| unavailable())? {
            if bytes.len().saturating_add(chunk.len()) > 4096 {
                return Err(unavailable());
            }
            bytes.extend_from_slice(&chunk);
        }
        let id: Identity = serde_json::from_slice(&bytes).map_err(|_| unavailable())?;
        if id.id <= 0 || !matches!(id.role.as_str(), "user" | "admin") {
            return Err(unavailable());
        }
        Ok(id)
    }
}

async fn users_readiness(s: Users) -> StatusCode {

        pg.map_err(|_| ())?;

        }
        Ok(())
    })
    .await
    {
        Ok(Ok(())) => StatusCode::OK,
        _ => StatusCode::SERVICE_UNAVAILABLE,
    }
}
```

### 34.7.2 【进阶】注册路径逐步拆解

Credentials使用deny_unknown_fields，客户端加role会被422拒绝。校验和规范化通过后，取哈希许可，移入阻塞闭包，得到PHC串，再用参数绑定INSERT。role由数据库默认user决定。

ON CONFLICT(username) DO NOTHING RETURNING id把并发重复名归为409。它不是请求幂等键：两个同时注册相同用户名的请求，只有一个创建成功，另一个得到冲突，不会凭相同密码冒认前一次注册的身份。

### 34.7.3 【进阶】登录路径逐步拆解

先限制输入与登录窗口，再查用户或dummy哈希，取得哈希许可后验证。存储串须为当前支持的Argon2id版本，内存参数不超过65536KiB、轮数与并行度在支持范围；异常或不支持的哈希不会拿来任意放大计算。

验证成功后建立jti、字符串sub和一小时exp，保存会话，再返回JWT。新签发只使用当前默认参数；允许验证部分旧参数，不等于推荐新注册使用弱参数。

### 34.7.4 【进阶】/me和logout的共同点与差异

两者都要求有效签名、声明与合法身份。/me还要求Redis未标记撤销、数据库会话活跃；logout则允许同一有效令牌重复撤销已有会话。

不能把“提取Claims”与“要求会话仍活跃”写成永远不可分的一步。重复退出的业务语义不同于访问受保护资源，公共辅助函数应保持这个区别。

### 34.7.5 【精通】UserRemote不自己决定用户身份

UserRemote只转发一个Bearer到固定users origin，不转发伪造角色头，不跟随重定向。身份查询有两秒总预算，响应正文最多4096字节，返回的id须为正，role须属于user或admin。

401保留为未认证；其他依赖错误、坏JSON、无效身份与超量回复归为503。网络失败不能退回相信客户端actor_id；资源服务随后仍需要自己的授权判断。

```rust
    let args: Vec<_> = std::env::args().skip(1).collect();
    anyhow::ensure!(
        args.len() == 1 && matches!(args[0].as_str(), "migrate-users" | "users"),
        "usage: rustmall-service migrate-users/users"
    );
    tracing_subscriber::fmt()
        .with_env_filter(tracing_subscriber::EnvFilter::from_default_env())
        .json()
        .try_init()
        .map_err(|_| anyhow::anyhow!("logging initialization failed"))?;
    let p = pool().await?;
    let result: anyhow::Result<()> = async {
        if args[0] == "migrate-users" {
            sqlx::migrate!("./migrations/users").run(&p).await?;
            return Ok(());
        }
        let key = env("JWT_SECRET")?;
        anyhow::ensure!(key.len() >= 32, "JWT key too short");
        let redis = tokio::time::timeout(Duration::from_secs(2), async {
            redis::Client::open(env("REDIS_URL")?)?
                .get_connection_manager_with_config(
                    redis::aio::ConnectionManagerConfig::new()
                        .set_response_timeout(Duration::from_millis(400))
                        .set_connection_timeout(Duration::from_millis(400))
                        .set_number_of_retries(1),
                )
                .await
                .map_err(anyhow::Error::from)
        })
        .await
        .map_err(|_| anyhow::anyhow!("Redis startup budget exhausted"))??;
        let s = Users {
            pool: p.clone(),
            redis,
            key: Arc::new(key),
            hashes: Arc::new(tokio::sync::Semaphore::new(4)),
            dummy: Arc::new(hash("dummy-password-never-accepted".into()).await?),
        };
        serve(
            bounded(commerce::users::router(s)),
            "127.0.0.1:8082",
            CancellationToken::new(),
        )
        .await
    }
    .await;
    tokio::time::timeout(Duration::from_secs(2), p.close())
        .await
        .map_err(|_| anyhow::anyhow!("database close budget exhausted"))?;
    result
}
```

模式仅接受migrate-users或users，先检查参数再连接数据库。迁移模式不要求Redis或JWT；服务模式要求明确JWT密钥，限制Redis连接启动等待，再构造dummy哈希与Users状态。

```python
"""Check chapter structure and optional local role configuration; never print values.

Python 3.11+ and Cargo are required. This is not a deployment or privilege audit.
"""
import argparse
import ipaddress
import json
import os
from pathlib import Path
import subprocess
import sys
from urllib.parse import urlsplit

ROOT = Path(__file__).resolve().parents[1]


def local_http(value):
    try:
        url = urlsplit(value)
        if url.scheme != "http" or not url.hostname or url.username or url.password:
            return False
        if url.path not in ("", "/") or url.query or url.fragment:
            return False
        if url.port is None or not 1 <= url.port <= 65535:
            return False
        if url.hostname == "localhost":
            return True
        return ipaddress.ip_address(url.hostname).is_loopback
    except ValueError:
        return False


def postgres(value):
    try:
        url = urlsplit(value)
        return (url.scheme in ("postgres", "postgresql") and bool(url.hostname)
                and bool(url.path.strip("/")) and bool(url.username)
                and (url.port is None or 1 <= url.port <= 65535))
    except ValueError:
        return False


def check_environment(role, spec, environment):
    errors = [f"missing {name}" for name in spec["required"] if not environment.get(name)]
    for name in spec["postgres"]:
        if environment.get(name) and not postgres(environment[name]):
            errors.append(f"invalid PostgreSQL URL in {name}")
    for name in spec["http"]:
        if environment.get(name) and not local_http(environment[name]):
            errors.append(f"{name} must be an explicit loopback HTTP endpoint with port")
    for name in ("RUSTMALL_CATALOG_TOKEN", "RUSTMALL_INVENTORY_TOKEN"):
        if name not in spec["required"] or not environment.get(name):
            continue
        value = environment[name]
        if not 32 <= len(value) <= 256 or not all(33 <= ord(c) <= 126 for c in value):
            errors.append(f"invalid service credential format in {name}")
        elif name == "RUSTMALL_INVENTORY_TOKEN" and not all(
                c.isascii() and (c.isalnum() or c in "-_") for c in value):
            errors.append(f"invalid inventory credential alphabet in {name}")
    for name in spec.get("redis", []):
        try:
            url = urlsplit(environment.get(name, ""))
            host = f"[{url.hostname}]" if url.hostname and ":" in url.hostname else url.hostname
            port = url.port if url.port is not None else 6379
            valid = url.scheme == "redis" and url.hostname and local_http(f"http://{host}:{port}") and url.path in ("", "/0") and not url.query and not url.fragment
        except ValueError:
            valid = False
        if not valid:
            errors.append(f"{name} must be a local Redis database 0 URL")
    for name in spec.get("listen", []):
        if not local_http("http://" + environment.get(name, "")):
            errors.append(f"{name} must be a loopback listen address with port")
    if role == "users" and len(environment.get("JWT_SECRET", "").encode()) < 32:
        errors.append("JWT_SECRET must contain at least 32 bytes")
    if role == "catalog" and environment.get("RUSTMALL_CATALOG_TOKEN") == environment.get("RUSTMALL_INVENTORY_TOKEN"):
        errors.append("catalog and inventory credentials must differ")
    if role == "facade":
        if environment.get("APP_ENV") != "production":
            errors.append("APP_ENV must be production for this checkpoint")
        if len(environment.get("APP_AUTH__JWT_SECRET", "").encode()) < 32:
            errors.append("APP_AUTH__JWT_SECRET must contain at least 32 bytes")
    if role == "inventory-client" and environment.get("DATABASE_URL"):
        errors.append("inventory-client should not receive DATABASE_URL")
    return errors


def check_structure(ledger, metadata):
    packages = {p["name"]: p for p in metadata["packages"]}
    errors = []
    for role, spec in ledger["roles"].items():
        for package_name, binary in [(spec["package"], spec["binary"])] + (
            [(spec["migration_package"], spec["migration_binary"])] if "migration_binary" in spec else []
        ):
            package = packages.get(package_name)
            if package is None or not any(t["name"] == binary and "bin" in t["kind"] for t in package["targets"]):
                errors.append(f"{role}: missing binary {package_name}/{binary}")
        if "migration_path" in spec and not list((ROOT / spec["migration_path"]).glob("*.sql")):
            errors.append(f"{role}: no SQL migration files")
    return errors


def main():
    ledger = json.loads((ROOT / "docs/runtime-boundaries.json").read_text())
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--role", choices=sorted(ledger["roles"]))
    args = parser.parse_args()
    result = subprocess.run([os.environ.get("CARGO", "cargo"), "metadata", "--locked",
        "--offline", "--no-deps", "--format-version", "1", "--manifest-path", str(ROOT / "Cargo.toml")],
        text=True, capture_output=True)
    if result.returncode:
        print("FAIL cargo metadata; run cargo metadata separately for compiler diagnostics", file=sys.stderr)
        return 1
    errors = check_structure(ledger, json.loads(result.stdout))
    if args.role:
        errors += check_environment(args.role, ledger["roles"][args.role], os.environ)
    if errors:
        for error in errors:
            print("FAIL " + error, file=sys.stderr)
        return 1
    print(f"PASS chapter {ledger['chapter']} structure" + (f" and local {args.role} configuration" if args.role else ""))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

### 34.10.3 【精通】必须复现提交后Redis失败

更强的原生实验先登录，停止Redis，再调用logout。应看见503，同时数据库revoked_at已经保存；重启不持久化的Redis后，原令牌/me仍是401，重试logout返回204。

本轮首次实验还发现Docker自动发布的宿主端口在stop/start后改变，使客户端连接旧地址。故障验证应固定发布端口并核对重启前后地址，避免把实验条件变化误诊为连接管理器不能恢复。上述Compose已经显式指定端口。

这明确验证“持久撤销已完成、外部依赖步骤失败”的窗口。仅在退出成功后手动删除一个键，也能验证部分屏障，但不能代替这次实际故障顺序。

### 34.10.7 【操作练习】同一令牌重复退出

登录后连续退出两次，再访问/me，记录状态码和数据库会话，不记录令牌正文。

### 34.10.8 【推理练习】请求取消后哈希许可可否马上归还

参考答案：已启动的阻塞计算仍在运行。若提前归还，后续请求可不断启动新计算，突破四个任务的实际上限；本章把许可移入闭包，随真正计算结束释放。

### 34.10.9 【推理练习】Redis故障时能否只验JWT继续放行

参考答案：当前契约选择依赖故障503。临时退化为只验签会跳过计数或撤销状态，改变已经承诺的身份语义。若设计另一种可用性策略，需明确安全后果并重新验证，不在故障中临时猜测。

### 34.10.10 【精通练习】新旧用户编号都是7意味着什么

参考答案：它们来自不同身份库和签发者，不自动是同一人。切流需要明确映射或保留ID的迁移与验证，还要处理旧令牌失效和业务关联，不能仅比较整数。
