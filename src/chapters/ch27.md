# 第 27 章 网关、身份与协议边界

上一章的 catalog 可以独立保存商品，但公共 HTTP 接口仍通过旧仓储访问 monolith 数据库。本章把这条链路接起来，并新增一个有明确转发边界的 HTTP 网关。目标是让用户继续使用熟悉的 JSON 接口，同时让商品写入只进入 catalog。

为了保留已经完成的登录、管理员授权、参数验证与统一错误，我们采用渐进结构：客户端 → gateway → monolith 的 HTTP 接口层 → RemoteProductRepo → catalog gRPC → 商品数据库。用户注册和登录仍由 monolith 处理。这里的 monolith 正在成为过渡接口层，名称暂时保留；后面的用户服务章节再迁出相应能力。不要把外层代理误认为已经承接所有业务认证，也不要在学习过程中复制出第二套互不一致的权限判断。

本章结束时，你应能解释请求如何穿过三种边界，能验证伪造身份头无效、普通用户不能写商品、管理员写入确实进入新库，并能在商品服务失效时看到明确故障而非悄悄读回旧数据。

## 27.1 网关首先是一条信任边界

### 27.1.1 【入门】反向代理的角色

反向代理接受客户端请求，再向已配置的上游发送请求。客户端看到的是网关地址，后端服务地址由系统管理者控制。本章 Gateway 保存一个固定 upstream origin，不允许请求参数指定任意目标 URL。

origin 包含协议、主机和端口，例如 http://127.0.0.1:8080。路径与查询来自经过限制的公共请求，账户、密码、片段和额外基础路径不允许混进上游配置。这样有助于把“转发到哪个服务”和“调用服务的哪条接口”分开理解。

### 27.1.2 【入门】网关与业务接口层的分工

外层 gateway 限制路径、大小、并发和等待时间，清理不能跨边界信任的请求头，并生成请求 ID。monolith 接口层保留 JWT 校验、管理员授权、JSON 提取、领域错误与 HTTP 状态转换。

catalog 则只处理商品 gRPC 和商品数据库。它接受服务凭据，不直接理解浏览器登录。这一分工是本阶段的实现选择，不是所有系统必须遵守的固定层数。学习时先保持已有行为，再逐步减少过渡组件的职责。

### 27.1.3 【进阶】请求头中的身份由谁证明

客户端可以任意发送 x-user-role: admin。因此“请求头写着管理员”不是权限证据。本章去掉 x-user-id、x-user-role、x-internal-*、外部传入的服务令牌和转发来源头。

Authorization: Bearer 则保留给原有认证层校验。保留这一字段不表示信任其中内容；是否签名有效、签发者正确、时间有效以及是否具备管理员角色，仍由已有 JWT 与 AdminUser 逻辑决定。

### 27.1.4 【进阶】服务令牌错误不能变成用户登录错误

若 monolith 到 catalog 的服务令牌不匹配，故障在内部配置或凭据生命周期。用户即使重新登录，也不能修复服务之间的错误令牌。因此适配器把这类 RPC 失败转换为服务端错误，而不是向最终用户返回“请重新登录”。

相反，外部请求没有有效 JWT，应在 HTTP 认证层返回 401；身份有效但权限不足返回 403。三者必须分开测试，不能看见 Unauthenticated 就机械映射成 HTTP 401。

### 27.1.5 【精通】网络位置不自动产生信任

把接口放到内部网络，可以减少暴露，但不能取代凭据与授权。内部服务也可能配置错误、被误用，或者持有过大的权限。本章服务凭据授权范围仍较宽，生产环境还要继续细分调用身份与能力。

同时，网关不会自动防止用户绕过它直连接口层。如果部署时希望所有流量都经过网关，应通过监听地址、网络规则与服务暴露方式落实。三个进程都能运行，与部署拓扑已经受控，是两项独立结论。

## 27.2 从已有仓储 trait 接入远程调用

### 27.2.1 【入门】先复习原有接口

ProductService 依赖 ProductRepository，而不是在处理函数里直接执行 SQL。仓储 trait 规定 insert、get、list、update、delist。这让我们可以新增远程实现，同时保留服务层和 HTTP 路由的调用方式。

远程实现不是把数据库连接字符串换成 gRPC 地址。它要把领域参数变成消息、携带身份与预算、解释 Status，再把响应重建成领域对象。这一层通常称为适配器，因为它连接两套不同的接口表示。

### 27.2.2 【入门】完整远程商品仓储

新增 monolith/src/repo/remote.rs：
```rust
use super::ProductRepository;
use common::error::{DomainError, DomainResult, ValidationError};
use common::ids::ProductId;
use common::product::{NewProduct, Product};
use contracts::catalog::{self as wire, catalog_client::CatalogClient};
use std::time::Duration;
use tonic::{
    Code, Request, Status,
    metadata::MetadataValue,
    transport::{Channel, Endpoint},
};

#[derive(Clone)]
pub struct RemoteProductRepo {
    client: CatalogClient<Channel>,
    health: tonic_health::pb::health_client::HealthClient<Channel>,
    key: MetadataValue<tonic::metadata::Ascii>,
}
impl RemoteProductRepo {
    pub async fn connect(endpoint: &str, key: &str) -> anyhow::Result<Self> {
        anyhow::ensure!(
            key.len() >= 32 && key.bytes().all(|byte| byte.is_ascii_graphic()),
            "catalog token must be >=32 visible ASCII bytes"
        );
        let channel = Endpoint::from_shared(endpoint.to_string())?
            .connect_timeout(Duration::from_secs(2))
            .timeout(Duration::from_secs(1))
            .connect()
            .await?;
        Ok(Self {
            client: CatalogClient::new(channel.clone()),
            health: tonic_health::pb::health_client::HealthClient::new(channel),
            key: key.parse()?,
        })
    }
    pub async fn is_ready(&self) -> bool {
        let result = self
            .health
            .clone()
            .check(self.request(tonic_health::pb::HealthCheckRequest {
                service: "readiness".into(),
            }))
            .await;
        matches!(result, Ok(reply) if reply.get_ref().status ==
            tonic_health::pb::health_check_response::ServingStatus::Serving as i32)
    }
    fn request<T>(&self, value: T) -> Request<T> {
        let mut request = Request::new(value);
        request.set_timeout(Duration::from_secs(1));
        request
            .metadata_mut()
            .insert("x-rustmall-service-token", self.key.clone());
        request
    }
}
fn decode(value: wire::Product) -> DomainResult<Product> {
    Product::try_new(
        ProductId::new(value.id),
        &value.name,
        value.price_cents,
        value.stock,
    )
    .map_err(|_| DomainError::Internal("catalog returned invalid product".into()))
}
fn map_status(error: Status, id: Option<ProductId>) -> DomainError {
    match error.code() {
        Code::NotFound => match id {
            Some(id) => DomainError::not_found("商品", id),
            None => DomainError::Internal("unexpected catalog NotFound".into()),
        },
        Code::InvalidArgument => ValidationError::Format {
            field: "product",
            reason: error.message().to_string(),
        }
        .into(),
        Code::AlreadyExists | Code::FailedPrecondition => {
            DomainError::Conflict(error.message().to_string())
        }
        _ => DomainError::Internal(format!("catalog RPC failed: {}", error.code())),
    }
}
impl ProductRepository for RemoteProductRepo {
    async fn insert(&self, draft: &NewProduct) -> DomainResult<Product> {
        let response = self
            .client
            .clone()
            .create_product(self.request(wire::CreateProductRequest {
                name: draft.name().into(),
                price_cents: draft.price_cents(),
                stock: draft.stock(),
            }))
            .await
            .map_err(|e| map_status(e, None))?;
        decode(response.into_inner())
    }
    async fn get(&self, id: ProductId) -> DomainResult<Product> {
        let response = self
            .client
            .clone()
            .get_product(self.request(wire::GetProductRequest { id: id.get() }))
            .await
            .map_err(|e| map_status(e, Some(id)))?;
        decode(response.into_inner())
    }
    async fn list(&self, limit: i64, offset: i64) -> DomainResult<(Vec<Product>, i64)> {
        let page = self
            .client
            .clone()
            .list_products(self.request(wire::ListProductsRequest { limit, offset }))
            .await
            .map_err(|e| map_status(e, None))?
            .into_inner();
        if page.total < 0 {
            return Err(DomainError::Internal("invalid catalog total".into()));
        }
        let items = page
            .items
            .into_iter()
            .map(decode)
            .collect::<DomainResult<_>>()?;
        Ok((items, page.total))
    }
    async fn update(&self, product: &Product) -> DomainResult<Product> {
        let response = self
            .client
            .clone()
            .update_product(self.request(wire::UpdateProductRequest {
                id: product.id().get(),
                name: product.name().into(),
                price_cents: product.price_cents(),
                stock: product.stock(),
            }))
            .await
            .map_err(|e| map_status(e, Some(product.id())))?;
        decode(response.into_inner())
    }
    async fn delist(&self, id: ProductId) -> DomainResult<()> {
        self.client
            .clone()
            .delist_product(self.request(wire::GetProductRequest { id: id.get() }))
            .await
            .map_err(|e| map_status(e, Some(id)))?;
        Ok(())
    }
}
```

### 27.2.3 【进阶】Channel 复用与 client.clone

RemoteProductRepo 在启动时建立 Channel，再保存 CatalogClient。每次调用 clone 客户端句柄，满足生成方法对可变客户端的要求，不为每个请求重新握手。

这种克隆共享底层通道能力，不是把远端服务复制一份，也不是无限并行的保证。服务端并发、HTTP/2 流、连接池与数据库仍有容量限制。不要为了避开一个 &amp;mut 编译错误，把所有请求放在全局互斥锁内串行执行。

### 27.2.4 【进阶】连接预算和每次请求预算

connect_timeout 控制建立连接的等待，Endpoint::timeout 提供本地调用等待限制；request.set_timeout 再携带 grpc-timeout。连接成功只说明存在传输连接，不等于商品表已迁移、身份令牌正确或服务已就绪。

本章每次请求使用一秒预算，catalog 内部 SQL 使用七百毫秒。外层网关有更大的上游预算。数字只是可复现实验值；真实链路应根据端到端目标和各阶段分配调整，不能给每一跳都分配全部总预算。

### 27.2.5 【进阶】响应也需要重建领域对象

decode 不直接把远端对象交给 HTTP 序列化，而是调用 Product::try_new。负金额、负库存或非法名称会成为内部错误。列表的 total 还检查不能小于零。

这是防止损坏协议数据越过边界的一层检查，不意味着对端所有语义都已经验证。比如版本兼容、响应 id 与所请求 id 的对应、列表总量与并发变化，仍有各自契约。后面的整合审核需要持续补足，而不是把“能解码”当作可信证明。

### 27.2.6 【进阶】状态转换保持公共语义

NotFound 使用当前调用的商品 id 重建原有领域错误，避免内部英文文案改变公共错误表示。列表操作没有单个商品 id，意外出现 NotFound 应视为内部契约异常。

InvalidArgument 转为字段校验错误；AlreadyExists 和 FailedPrecondition 转为冲突；其他 RPC 状态转为内部错误。目前这意味着依赖不可用等情况在既有 HTTP 错误模型中返回 500。若以后细分 502、503、504，应修改公共错误模型并增加兼容测试，不在某个处理函数里临时拼一种新响应。

### 27.2.7 【精通】不能在失败后自动切回旧仓储

假设新库已经把商品下架，旧库还保存原状态。catalog 暂时不可达时若自动查询旧库，用户就可能再次看到下架商品；若写操作也回落旧库，两边会进一步分叉。

因此 SelectedProductRepo 是启动时选择的数据路径，Remote 分支失败只返回错误，不调用 Local 分支。这与无损重试不是同一问题：旧数据源不是当前权威数据源的备用副本，除非系统已经建立并验证了复制与恢复协议。

## 27.3 选择实现与切换运行路径

### 27.3.1 【入门】完整选择仓储

新增 monolith/src/repo/selected.rs：
```rust
use super::{
    ProductRepository, cached::CachedProductRepo, products::PgProductRepo,
    remote::RemoteProductRepo,
};
use common::error::DomainResult;
use common::ids::ProductId;
use common::product::{NewProduct, Product};

#[derive(Clone)]
pub enum SelectedProductRepo {
    Local(CachedProductRepo<PgProductRepo>),
    Remote(Box<RemoteProductRepo>),
}
impl ProductRepository for SelectedProductRepo {
    async fn insert(&self, draft: &NewProduct) -> DomainResult<Product> {
        match self {
            Self::Local(r) => r.insert(draft).await,
            Self::Remote(r) => r.insert(draft).await,
        }
    }
    async fn get(&self, id: ProductId) -> DomainResult<Product> {
        match self {
            Self::Local(r) => r.get(id).await,
            Self::Remote(r) => r.get(id).await,
        }
    }
    async fn list(&self, limit: i64, offset: i64) -> DomainResult<(Vec<Product>, i64)> {
        match self {
            Self::Local(r) => r.list(limit, offset).await,
            Self::Remote(r) => r.list(limit, offset).await,
        }
    }
    async fn update(&self, product: &Product) -> DomainResult<Product> {
        match self {
            Self::Local(r) => r.update(product).await,
            Self::Remote(r) => r.update(product).await,
        }
    }
    async fn delist(&self, id: ProductId) -> DomainResult<()> {
        match self {
            Self::Local(r) => r.delist(id).await,
            Self::Remote(r) => r.delist(id).await,
        }
    }
}
```

这是一个枚举，每个方法只分派给已经选择的实现。Remote 使用 Box 保存较大的客户端结构，避免枚举的每个值都按最大分支占用过多空间；它仍拥有这个远程仓储，不改变运行时选择规则。Local 继续使用原来的带缓存 PostgreSQL 仓储，Remote 直接访问 catalog。它不是同时执行两个实现，也不是按请求随机选择。

### 27.3.2 【进阶】为什么远程分支暂时不套旧缓存

旧缓存由原来的 monolith 写入路径负责失效。商品写入改到独立服务以后，如果保留多份各自维护的缓存，就必须重新定义失效事件、版本与延迟容忍。

本章先让远程读取直接抵达权威服务，减少切换变量。monolith 仍构造原有本地缓存对象，Local 模式也继续可用；Remote 模式不把商品结果写进旧缓存。后面 Redis 与事件章节会在明确所有权后重新建立缓存一致性策略。

### 27.3.3 【入门】完整 AppState

替换 monolith/src/state.rs：
```rust
use crate::auth::jwt::JwtKeys;
use crate::cache::ProductCache;
use crate::repo::{cached::CachedProductRepo, products::PgProductRepo, users::PgUserRepo};
use crate::repo::{remote::RemoteProductRepo, selected::SelectedProductRepo};
use crate::service::{auth::AuthService, products::ProductService};
use sqlx::PgPool;

pub type ProductRepo = SelectedProductRepo;
#[derive(Clone)]
pub struct AppState {
    pub pool: PgPool,
    catalog_health: Option<RemoteProductRepo>,
    pub products: ProductService<ProductRepo>,
    pub auth: AuthService<PgUserRepo>,
}
impl AppState {
    pub fn new(pool: PgPool, jwt: JwtKeys, cache: ProductCache) -> Self {
        let repo = CachedProductRepo::new(PgProductRepo::new(pool.clone()), cache);
        Self {
            catalog_health: None,
            products: ProductService::new(SelectedProductRepo::Local(repo)),
            auth: AuthService::new(PgUserRepo::new(pool.clone()), jwt),
            pool,
        }
    }
    pub async fn catalog_is_ready(&self) -> bool {
        match &self.catalog_health {
            Some(repo) => repo.is_ready().await,
            None => true,
        }
    }
    pub async fn use_remote_catalog(&mut self, endpoint: &str, key: &str) -> anyhow::Result<()> {
        let repo = RemoteProductRepo::connect(endpoint, key).await?;
        self.catalog_health = Some(repo.clone());
        self.products = ProductService::new(SelectedProductRepo::Remote(Box::new(repo)));
        Ok(())
    }
}
```

AppState::new 默认保留本地路径，便于历史测试和旧检查点使用。use_remote_catalog 建立远程仓储，再替换 ProductService，同时保存远程健康检查句柄。用户认证仍然使用本地 PgUserRepo，数据库连接池也仍要保留。

### 27.3.4 【进阶】显式启用远程模式

替换 monolith/src/main.rs：
```rust
use anyhow::Context;
use monolith::auth::jwt::JwtKeys;
use monolith::cache::{ProductCache, connect_redis};
use monolith::settings::Settings;
use monolith::state::AppState;
use monolith::{background, db, http, shutdown, telemetry};
use platform::{ShutdownBudget, migration_enabled};
use std::future::IntoFuture;
use std::time::Duration;
use tokio_util::sync::CancellationToken;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    dotenvy::dotenv().ok();
    let settings = Settings::load().context("load settings")?;
    telemetry::init(&settings.log).context("init logging")?;
    let run_migrations =
        migration_enabled(std::env::var("RUSTMALL_RUN_MIGRATIONS").ok().as_deref())?;
    let pool = db::connect(&settings.database)
        .await
        .context("connect database")?;
    if run_migrations {
        db::MIGRATOR.run(&pool).await.context("run migrations")?;
    }
    let jwt = JwtKeys::new(
        &settings.auth.jwt_secret,
        &settings.auth.issuer,
        settings.auth.access_token_ttl_secs,
    );
    let redis = connect_redis(&settings.redis).await;
    let cache = ProductCache::new(
        &settings.cache,
        redis,
        Duration::from_millis(settings.redis.op_timeout_ms),
    );
    let mut state = AppState::new(pool.clone(), jwt, cache);
    // Chapter 27: only enable this after the catalog cutover procedure.
    if let Ok(endpoint) = std::env::var("RUSTMALL_CATALOG_ENDPOINT") {
        let key = std::env::var("RUSTMALL_CATALOG_TOKEN").context("catalog token missing")?;
        state.use_remote_catalog(&endpoint, &key).await?;
    }
    let app = http::routes::router(state, &settings.cors);
    let listener = tokio::net::TcpListener::bind(settings.server.addr()).await?;
    let token = CancellationToken::new();
    tokio::spawn(shutdown::wait_for_signal(token.clone()));
    let mut cleaner = tokio::spawn(background::run_periodic(
        Duration::from_secs(60),
        token.clone(),
        || async { tracing::debug!("cart cleanup tick") },
    ));
    let server = axum::serve(listener, app)
        .with_graceful_shutdown(token.clone().cancelled_owned())
        .into_future();
    tokio::pin!(server);
    let (server_result, budget) = tokio::select! {
        result = &mut server => {
            token.cancel();
            (result.context("HTTP server failed"),
                ShutdownBudget::new(settings.server.shutdown_grace()))
        }
        () = token.cancelled() => {
            let budget = ShutdownBudget::new(settings.server.shutdown_grace());
            let result = budget.wait("HTTP", &mut server).await;
            let result = match result {
                Ok(result) => result.context("HTTP server failed"),
                Err(error) => {
                    cleaner.abort();
                    return Err(error);
                }
            };
            (result, budget)
        }
    };
    token.cancel();
    match budget.wait("background", &mut cleaner).await {
        Ok(result) => {
            result.context("background task failed")?;
        }
        Err(error) => {
            cleaner.abort();
            return Err(error);
        }
    }
    budget.wait("database", pool.close()).await?;
    server_result
}
```

设置 RUSTMALL_CATALOG_ENDPOINT 才进入 Remote 模式；启用后还必须提供服务令牌，连接失败会阻止启动。没有设置该变量仍是旧模式，所以部署清单必须明确写出切换配置，不能依赖运行人员记忆。

这段代码支持过渡演练，不适合让正式环境中的部分副本长期保留 Local、另一部分使用 Remote。负载均衡把用户请求发给不同数据来源，会让故障变成偶发的数据分叉。

### 27.3.5 【精通】切换前后的检查顺序

先完成上一章新库迁移和需要的旧数据搬迁，确认直接 gRPC 操作正常；停止旧商品写入，配置全部接口层实例使用 Remote；最后通过公共地址验证创建与读取，并核对实际落库位置。

旧表仍存在不等于可以继续写。保留它是为了核对和受控恢复，权限收紧与最终移除要在后续演进中落实。切换后已经产生新写入时，回滚也必须处理这些事实，而不是简单删掉 endpoint 变量。

### 27.4.1 【入门】逐跳字段是什么

### 27.5.1 【入门】完整转发实现

```rust
use axum::{
    Router,
    body::{Body, to_bytes},
    extract::{Request, State},
    http::{HeaderMap, HeaderName, HeaderValue, StatusCode},
    response::{IntoResponse, Response},
    routing::get,
};
use reqwest::{Client, Url};
use std::{sync::Arc, time::Duration};
use uuid::Uuid;

const REQUEST_LIMIT: usize = 64 * 1024;
const RESPONSE_LIMIT: usize = 2 * 1024 * 1024;
#[derive(Clone)]
pub struct Gateway {
    client: Client,
    upstream: Url,
    permits: Arc<tokio::sync::Semaphore>,
}
impl Gateway {
    pub fn new(upstream: &str) -> anyhow::Result<Self> {
        let upstream = Url::parse(upstream)?;
        anyhow::ensure!(
            matches!(upstream.scheme(), "http" | "https"),
            "HTTP upstream required"
        );
        anyhow::ensure!(
            upstream.host_str().is_some()
                && upstream.username().is_empty()
                && upstream.password().is_none(),
            "upstream must have a host and no credentials"
        );
        anyhow::ensure!(
            upstream.path() == "/" && upstream.query().is_none() && upstream.fragment().is_none(),
            "upstream must be an origin, without path/query/fragment"
        );
        let client = Client::builder()
            .no_proxy()
            .redirect(reqwest::redirect::Policy::none())
            .connect_timeout(Duration::from_secs(1))
            .timeout(Duration::from_secs(3))
            .build()?;
        Ok(Self {
            client,
            upstream,
            permits: Arc::new(tokio::sync::Semaphore::new(32)),
        })
    }
    pub fn router(self) -> Router {
        Router::new()
            .route("/health/live", get(|| async { StatusCode::OK }))
            .route("/health/ready", get(ready))
            .fallback(forward)
            .with_state(self)
    }
}
pub fn filtered_headers(source: &HeaderMap) -> HeaderMap {
    let mut result = source.clone();
    for value in source.get_all("connection") {
        if let Ok(text) = value.to_str() {
            for token in text.split(',').map(str::trim) {
                if let Ok(name) = HeaderName::from_bytes(token.as_bytes()) {
                    result.remove(name);
                }
            }
        }
    }
    for name in [
        "connection",
        "proxy-connection",
        "keep-alive",
        "transfer-encoding",
        "te",
        "trailer",
        "upgrade",
        "proxy-authenticate",
        "proxy-authorization",
        "host",
        "content-length",
        "forwarded",
        "x-user-id",
        "x-user-role",
        "x-rustmall-service-token",
        "x-request-id",
    ] {
        result.remove(name);
    }
    let untrusted: Vec<_> = result
        .keys()
        .filter(|name| {
            name.as_str().starts_with("x-forwarded-") || name.as_str().starts_with("x-internal-")
        })
        .cloned()
        .collect();
    for name in untrusted {
        result.remove(name);
    }
    result
}
async fn ready(State(state): State<Gateway>) -> StatusCode {
    let mut target = state.upstream.clone();
    target.set_path("/health/ready");
    match state.client.get(target).send().await {
        Ok(response) if response.status() == StatusCode::OK => StatusCode::OK,
        _ => StatusCode::SERVICE_UNAVAILABLE,
    }
}
fn failure(status: StatusCode, id: &str) -> Response {
    let code = match status {
        StatusCode::NOT_FOUND => "NOT_FOUND",
        StatusCode::PAYLOAD_TOO_LARGE => "PAYLOAD_TOO_LARGE",
        StatusCode::REQUEST_TIMEOUT => "REQUEST_TIMEOUT",
        StatusCode::GATEWAY_TIMEOUT => "GATEWAY_TIMEOUT",
        StatusCode::BAD_REQUEST => "BAD_REQUEST",
        StatusCode::SERVICE_UNAVAILABLE => "UNAVAILABLE",
        _ => "BAD_GATEWAY",
    };
    let mut response = (
        status,
        axum::Json(serde_json::json!({"code":code,"message":"网关暂时无法处理请求"})),
    )
        .into_response();
    response.headers_mut().insert(
        "x-request-id",
        HeaderValue::from_str(id).expect("UUID header"),
    );
    response
}
async fn forward(State(state): State<Gateway>, request: Request) -> Response {
    let id = Uuid::new_v4().to_string();
    if !request.uri().path().starts_with("/api/v1/") {
        return failure(StatusCode::NOT_FOUND, &id);
    }
    let _permit = match state.permits.clone().try_acquire_owned() {
        Ok(permit) => permit,
        Err(_) => return failure(StatusCode::SERVICE_UNAVAILABLE, &id),
    };
    let (parts, body) = request.into_parts();
    let body =
        match tokio::time::timeout(Duration::from_secs(5), to_bytes(body, REQUEST_LIMIT)).await {
            Ok(Ok(body)) => body,
            Ok(Err(_)) => return failure(StatusCode::PAYLOAD_TOO_LARGE, &id),
            Err(_) => return failure(StatusCode::REQUEST_TIMEOUT, &id),
        };
    let mut target = state.upstream.clone();
    target.set_path(parts.uri.path());
    target.set_query(parts.uri.query());
    if !target.path().starts_with("/api/v1/") {
        return failure(StatusCode::BAD_REQUEST, &id);
    }
    let mut headers = filtered_headers(&parts.headers);
    headers.insert(
        "x-request-id",
        HeaderValue::from_str(&id).expect("UUID header"),
    );
    let mut upstream = match state
        .client
        .request(parts.method, target)
        .headers(headers)
        .body(body)
        .send()
        .await
    {
        Ok(response) => response,
        Err(error) => {
            return failure(
                if error.is_timeout() {
                    StatusCode::GATEWAY_TIMEOUT
                } else {
                    StatusCode::BAD_GATEWAY
                },
                &id,
            );
        }
    };
    if upstream.status().is_redirection() {
        return failure(StatusCode::BAD_GATEWAY, &id);
    }
    let status = upstream.status();
    let mut headers = filtered_headers(upstream.headers());
    headers.insert(
        "x-request-id",
        HeaderValue::from_str(&id).expect("UUID header"),
    );
    let mut bytes = Vec::new();
    loop {
        match upstream.chunk().await {
            Ok(Some(chunk)) if bytes.len() + chunk.len() <= RESPONSE_LIMIT => {
                bytes.extend_from_slice(&chunk)
            }
            Ok(Some(_)) => return failure(StatusCode::BAD_GATEWAY, &id),
            Ok(None) => break,
            Err(error) => {
                return failure(
                    if error.is_timeout() {
                        StatusCode::GATEWAY_TIMEOUT
                    } else {
                        StatusCode::BAD_GATEWAY
                    },
                    &id,
                );
            }
        }
    }
    let mut response = Response::new(Body::from(bytes));
    *response.status_mut() = status;
    *response.headers_mut() = headers;
    response
}
```

Gateway 的 reqwest::Client 是可复用 HTTP 客户端，保存固定 Url 和共享 Semaphore。Arc 使多个路由状态克隆共享同一个并发计数，不是每个请求都重新得到三十二个许可。

### 27.5.2 【进阶】为什么关闭代理环境与重定向

no_proxy 让这里的固定内部调用不受运行环境代理配置意外影响。redirect::Policy::none 禁止客户端自动跟随上游重定向；代码还显式把上游 3xx 转为网关错误。

否则即使初始 upstream 已固定，上游返回的 Location 也可能让客户端追到另一个地址，并改变认证信息流向。禁止重定向会牺牲某些依赖跳转的接口能力，本章 API 明确不依赖这项能力；它不是可以无条件套用到所有网站的规则。

### 27.5.3 【进阶】路径限制不允许任意目标

只接受 /api/v1/ 开头的公共请求，再在固定 origin 上设置路径和查询。设置后再次检查目标路径前缀，防止 URL 规范化后的路径已经离开允许区域。

查询串要保留编码语义，例如 x=one%20two 不应被变成另一种业务值。测试会观察上游实际收到的 path 与 query，而不是只断言网关返回 200。固定 origin 也不代表任意 API 路径都获得授权，具体操作仍由接口层判断。

### 27.5.4 【进阶】并发许可的生命周期

try_acquire_owned 不排队等待许可，满载时立即返回 503。得到的 OwnedSemaphorePermit 保存到 forward 作用域结束，所以读取请求体、等待上游与缓冲响应都占用同一个许可。

如果读取完请求体就提前 drop 许可，后续上游请求可能无限增长；如果 permit 在错误路径上没有释放，服务则会逐渐失去容量。Rust 的作用域析构使正常返回与早退都释放许可，但不能代替对持有范围的正确设计。

### 27.5.5 【进阶】请求体大小和读取时间

请求体最多 64 KiB，并且读取过程最多等待五秒。Content-Length 只是对端声明，不能作为唯一保护，实际读到的字节也必须受限。

当前 to_bytes 的读取错误统一转换为 413，慢请求超过读取期限返回 408。读取错误的分类仍可细化，但不应假称所有失败都源于声明长度超限。上游连接还未建立前就能拒绝过大的输入，这一点有独立测试。

### 27.5.6 【进阶】响应缓冲的内存上限

网关逐块读取上游响应，累计最多 2 MiB，再构造返回 Body。单个请求不会无界增长；三十二个并发请求仍可能同时持有响应缓冲，加上请求体、连接缓冲和运行时开销，内存预算不能只看 2 MiB。

这是一种适合本书小 JSON API 的缓冲代理，不支持原样传递任意大文件、SSE 或无限流。以后增加这些能力，需要流式背压、断开传播和更细的资源策略，不能只把上限调成无限大。

### 27.5.7 【进阶】重新构造传输字段

过滤器移除 Host、Content-Length、Transfer-Encoding 等字段，让当前 HTTP 客户端与服务器根据实际请求体重新组织传输。保留过期长度可能导致下游对消息边界理解不同。

forwarded、x-forwarded-* 和 x-internal-* 也被去掉。本章没有可信前置代理链的配置，因此不把外部提供的来源声明用于鉴权或限流。若未来要保留真实来源，必须明确哪些代理有权追加这些字段。

### 27.5.8 【精通】请求 ID 提供什么证据

每次进入网关生成新的 UUID，并写给上游及最终响应。外部自带的 x-request-id 不作为网关权威标识，避免不同请求故意使用同一个值混淆日志。monolith 原有中间件保留网关传入的 id，因此这一段 HTTP 链路可用它关联。

目前适配器没有把这个 id 放进 gRPC metadata，也没有创建分布式 trace。因此不要在本章宣称一条 id 已经贯穿数据库、Kafka 与所有服务。后面的可观测性章节会把请求关联扩展为明确的跨进程上下文。

### 27.5.9 【精通】错误由哪一层产生

上游返回正常 HTTP 业务错误时，网关保留其状态与响应体。网关自身无法连接上游返回 502，等待上游超时返回 504，资源许可不足返回 503。它生成的通用错误不暴露上游地址或凭据。

如果 catalog 超时先被接口层转换为既有 Internal，网关收到的是一份正常传输的 HTTP 500，因此仍返回 500。不能只看最外层状态码就猜测超时发生在哪一层，应结合请求 ID、服务日志与各阶段耗时判断。

## 27.6 就绪状态必须跟随实际依赖

### 27.6.1 【入门】拆分以后，旧探针少检查了什么

原来的 /health/ready 只查询 monolith 的 PostgreSQL。商品路径改成 RPC 后，即使 catalog 已停机，旧数据库仍可能正常响应。此时如果探针仍返回 200，负载均衡就会把商品流量继续分配给无法完成请求的实例。

因此 readiness 必须根据已经选择的运行模式检查依赖。Local 模式沿用本地数据库；Remote 模式还要确认 catalog 的 readiness。liveness 继续只反映进程能响应，不能把依赖故障和程序死亡混为一谈。

### 27.6.2 【进阶】完整接口层健康实现

替换 monolith/src/http/health.rs：
```rust
//! 健康检查（第 23 章 Kubernetes 的探针会调用）。

use std::time::Duration;

use axum::Json;
use axum::extract::State;
use axum::http::StatusCode;
use serde_json::{Value, json};

use crate::state::AppState;

/// 就绪检查访问数据库的最长时间。
const READY_TIMEOUT: Duration = Duration::from_secs(1);

/// 存活检查：进程能响应即可，不访问任何依赖。
pub async fn live() -> Json<Value> {
    Json(json!({ "status": "ok" }))
}

/// 就绪检查：总共 1 秒内确认本地数据库和已选择的商品依赖。
pub async fn ready(State(state): State<AppState>) -> (StatusCode, Json<Value>) {
    let ping = async {
        sqlx::query("SELECT 1").execute(&state.pool).await?;
        if !state.catalog_is_ready().await {
            return Err(sqlx::Error::Protocol("catalog is not ready".into()));
        }
        Ok::<_, sqlx::Error>(())
    };
    match tokio::time::timeout(READY_TIMEOUT, ping).await {
        Ok(Ok(_)) => (StatusCode::OK, Json(json!({ "status": "ok" }))),
        // 超时或数据库错误：暂时不要把流量分给本实例
        _ => (
            StatusCode::SERVICE_UNAVAILABLE,
            Json(json!({ "status": "unavailable" })),
        ),
    }
}
```

总等待期限仍为一秒，涵盖本地数据库和商品依赖，而不是每个检查各等一秒。RemoteProductRepo 使用标准 gRPC HealthClient 查询 service="readiness"，只在明确收到 Serving 时认为成功；未知服务、网络错误或超时都不通过。

健康客户端与商品客户端共享建立好的 Channel。is_ready 的匹配条件通过 get_ref 借用响应内容，不在模式守卫中移动 Response；这也体现了 Rust 模式匹配对所有权的限制。

### 27.6.3 【进阶】完整 gateway 启动入口

创建 services/gateway/src/main.rs：
```rust
use platform::ShutdownBudget;
use std::{future::IntoFuture, time::Duration};
async fn signal() {
    #[cfg(unix)]
    {
        let mut term = tokio::signal::unix::signal(tokio::signal::unix::SignalKind::terminate())
            .expect("SIGTERM handler");
        tokio::select! {_=term.recv()=>{},_=tokio::signal::ctrl_c()=>{}}
    }
    #[cfg(not(unix))]
    {
        tokio::signal::ctrl_c().await.expect("ctrl-c handler");
    }
}
#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let upstream =
        std::env::var("GATEWAY_UPSTREAM").unwrap_or_else(|_| "http://127.0.0.1:8080".into());
    let addr = std::env::var("GATEWAY_ADDR").unwrap_or_else(|_| "127.0.0.1:8081".into());
    let listener = tokio::net::TcpListener::bind(addr).await?;
    let (send, receive) = tokio::sync::oneshot::channel::<()>();
    let server = axum::serve(listener, gateway::Gateway::new(&upstream)?.router())
        .with_graceful_shutdown(async {
            let _ = receive.await;
        })
        .into_future();
    tokio::pin!(server);
    tokio::select! {
        result=&mut server=>result?,
        ()=signal()=>{
            let _=send.send(());
            ShutdownBudget::new(Duration::from_secs(20)).wait("gateway HTTP",&mut server).await??;
        }
    }
    Ok(())
}
```

默认网关监听 127.0.0.1:8081，上游为 127.0.0.1:8080。外层 /health/ready 请求上游对应接口，得到 200 才返回 200；其他状态或连接错误统一返回 503。收到正常信号时，oneshot 通知服务器停止接受请求，再用共享关闭预算等待。

### 27.6.4 【精通】跨依赖健康的取舍

这个实验选择：商品服务不可用时，整个公共入口暂不就绪。代价是用户登录等尚能工作的功能也可能被摘流。另一个设计是按功能路由分别管理就绪和降级，但需要更细的部署与路由策略。

本章先落实一种明确策略，不让健康状态偶然取决于旧库是否存活。即便所有 readiness 都成功，也不证明服务令牌、每条业务数据和每个写操作正确；真实业务探测与错误率仍然需要继续观察。

### 27.6.5 【精通】避免依赖故障引发重启风暴

在本章拓扑中，catalog 不可用应传播为 readiness 失败，而 gateway liveness 仍应成功。若把 readiness 配置成 liveness，依赖故障会触发反复重启，既不能修复依赖，还会破坏连接与增加恢复负担。

容器和集群配置要分别指定探针路径，并考虑检查频率、超时和失败阈值。这里已验证原生进程状态传播，不能据此声称 Kubernetes 探针已经部署成功。

### 27.7.7 【进阶】管理员验证必须核对落库位置

在专用实验身份库中，沿用前面管理账号初始化方式授予某个测试用户管理员角色，再重新登录取得包含新角色的 JWT。修改数据库角色不会自动改变已经签发的旧 JWT；旧令牌的角色载荷仍是签发时的值。

以管理员令牌调用创建商品，预期 201，并检查 Location 与 x-request-id。随后分别查询两个数据库：新商品应只出现在 catalog 的 products，身份库旧 products 不应增加。只看 HTTP 成功无法证明数据所有权已经切换。

不要把“临时修改教学用户角色”的操作做成公开注册参数，也不要把管理员 JWT 写进书稿或命令历史。后面的用户服务和会话生命周期章节会进一步处理角色变更与令牌撤销。

### 27.7.8 【精通】故障演练应观察整条链

确认没有其他业务依赖你的实验实例后，正常停止自己启动的 catalog，保持 gateway、接口层与两份 PostgreSQL 运行。此时商品请求应失败，公共 /health/ready 应为 503，/health/live 仍应为 200。

接口层不得回退查询旧 products。重新启动 catalog 后等待其 readiness 恢复，再观察公共就绪恢复和业务请求恢复。自动重连的实际时延受客户端和调度影响，不把一次本机恢复耗时当作系统承诺。

## 27.8 测试分层与真实证据

### 27.8.1 【入门】完整代理集成测试

创建 services/gateway/tests/proxy.rs：
```rust
use axum::{
    Router,
    body::{Body, to_bytes},
    extract::Request,
    http::{HeaderValue, StatusCode},
    response::IntoResponse,
};
use tower::ServiceExt;
async fn upstream() -> (String, tokio::task::JoinHandle<()>) {
    let listener = tokio::net::TcpListener::bind("127.0.0.1:0").await.unwrap();
    let addr = listener.local_addr().unwrap();
    let app = Router::new().fallback(|request: Request| async move {
        if request.uri().path() == "/api/v1/redirect" {
            let mut response = StatusCode::FOUND.into_response();
            response.headers_mut().insert(
                "location",
                HeaderValue::from_static("http://127.0.0.1:1/should-not-follow"),
            );
            return response;
        }
        let value = serde_json::json!({"path":request.uri().path(),"query":request.uri().query(),
            "authorization":request.headers().get("authorization").and_then(|v|v.to_str().ok()),
            "forged_role":request.headers().contains_key("x-user-role"),
            "request_id":request.headers().get("x-request-id").and_then(|v|v.to_str().ok())});
        axum::Json(value).into_response()
    });
    let task = tokio::spawn(async move {
        axum::serve(listener, app).await.unwrap();
    });
    (format!("http://{addr}"), task)
}
#[tokio::test]
async fn forwarding_keeps_api_path_query_and_bearer_but_drops_forged_role() {
    let (url, task) = upstream().await;
    let app = gateway::Gateway::new(&url).unwrap().router();
    let request = axum::http::Request::get("/api/v1/products?x=one%20two")
        .header("authorization", "Bearer test-only")
        .header("x-user-role", "admin")
        .header("x-request-id", "untrusted")
        .body(Body::empty())
        .unwrap();
    let response = app.oneshot(request).await.unwrap();
    assert_eq!(response.status(), StatusCode::OK);
    let id = response.headers()["x-request-id"]
        .to_str()
        .unwrap()
        .to_owned();
    let bytes = to_bytes(response.into_body(), 1024 * 1024).await.unwrap();
    let value: serde_json::Value = serde_json::from_slice(&bytes).unwrap();
    assert_eq!(value["path"], "/api/v1/products");
    assert_eq!(value["query"], "x=one%20two");
    assert_eq!(value["authorization"], "Bearer test-only");
    assert_eq!(value["forged_role"], false);
    assert_eq!(value["request_id"], id);
    assert_ne!(id, "untrusted");
    task.abort();
}
#[tokio::test]
async fn redirects_are_rejected_without_following_the_target() {
    let (url, task) = upstream().await;
    let response = gateway::Gateway::new(&url)
        .unwrap()
        .router()
        .oneshot(
            axum::http::Request::get("/api/v1/redirect")
                .body(Body::empty())
                .unwrap(),
        )
        .await
        .unwrap();
    assert_eq!(response.status(), StatusCode::BAD_GATEWAY);
    task.abort();
}
#[tokio::test]
async fn oversized_request_is_rejected_before_forwarding() {
    let response = gateway::Gateway::new("http://127.0.0.1:1")
        .unwrap()
        .router()
        .oneshot(
            axum::http::Request::post("/api/v1/products")
                .body(Body::from(vec![0; 64 * 1024 + 1]))
                .unwrap(),
        )
        .await
        .unwrap();
    assert_eq!(response.status(), StatusCode::PAYLOAD_TOO_LARGE);
}
```

测试启动真正的本机 HTTP 上游，观察它实际收到的字段与查询。网关自身通过 Router::oneshot 驱动，所以这组测试证明路由与客户端逻辑；它不是三个已部署容器的网络验收。

随后验证 HTTP 查询、更新与下架确实跨过 RPC，商品服务停止后不回退旧库。就绪检查已扩展到商品依赖，故障时应传播为外层 503，同时存活检查保持 200。完整链路的当前结果以配套验收记录为准，不将早期暴露缺陷的结果混为修复后的证据。

### 27.8.5 【精通】尚需覆盖的场景

这些测试没有执行 TLS、真实反向代理前置链、集群流量摘除、超大并发压力、跨版本服务滚动切换和旧生产数据搬迁。它们还没有证明所有请求头组合与 URL 规范化边界都正确。

## 27.9 常见错误与迁移复盘

### 27.9.1 【入门】故障表

| 现象 | 应收集的证据 | 判断与修复 |
| --- | --- | --- |
| 公共列表仍显示旧商品 | 各接口层实例的 endpoint 配置与落库 | 确认全部切换 Remote，不在本地与远程间混用 |
| 启动无法连接 catalog | 监听地址、端口、服务日志 | 先启动商品服务，检查使用了本机还是容器地址 |
| 读取正常但写入 401 | JWT 是否存在及认证层错误码 | 服务令牌不能替代用户登录令牌 |
| 普通用户写入 403 | 令牌角色与 AdminUser 行为 | 属于正确授权拒绝，不移除管理员检查 |

### 27.9.2 【进阶】不要用缓存解释所有差异

看到新旧商品不一致时，先核对数据来源和运行模式，再检查缓存。若某个副本根本没有启用 endpoint，清 Redis 只能短暂改变现象，无法让它开始调用 catalog。

同样，身份库中的空 products 不是服务丢数据，可能正是商品写入只进入新库的正确结果。排查应从请求路径与权威数据源开始，避免凭表名猜测系统状态。

### 27.9.3 【精通】过渡组件应有退出条件

现在 monolith 仍承担用户认证、HTTP 协议与远程商品适配；它还保留 Local 模式和旧迁移。过渡结构可以帮助连续学习，但长期不清理会增加运行模式、权限和部署组合。

退出条件包括：所有公共商品请求使用 catalog、旧写入权限关闭、旧数据迁移已验收、用户能力有独立归属、部署与恢复文档不再依赖临时模式。后面的工程整合章节会核对这些条件，而不是永远把“以后清理”当作完成。

## 27.10 分层练习与下一章

### 27.10.1 【入门练习】画出身份判断的位置

为一条管理员创建商品请求标出 Bearer、AdminUser、服务令牌分别在哪里产生和校验。

参考答案：用户登录取得 Bearer JWT，gateway 只保留并转发；接口层校验 JWT，AdminUser 判断角色；RemoteProductRepo 从进程配置附加服务令牌；catalog 拦截器校验服务身份。任何外部 x-user-role 都不能替代前两个判断。

### 27.10.2 【操作练习】证明没有写旧库

通过公共网关创建一个带唯一名称的商品，记录返回 id，再分别在身份库和商品库查询。随后更新和下架，并在正确数据库确认字段变化。

评分要点：请求经过 8081 公共地址，旧库没有对应新增，商品库保留同一 id 与修改结果，软下架后 HTTP 返回 404 而持久化行仍存在。只验证一次列表出现名称不能证明没有双写。

### 27.10.3 【推理练习】错误身份为何不是 401

用户的管理员 JWT 有效，但接口层到 catalog 的服务令牌失效。用户应否重新登录？公共 401 是否准确？

参考答案：重新登录不能修复服务凭据。内部服务认证失败属于服务端依赖配置故障，当前公共模型返回 500 并在内部诊断。若返回 401，会错误归责给最终用户并可能造成无意义的登录循环。

### 27.10.4 【推理练习】三十二个许可限制什么

假设某请求已经取得许可，正以极慢速度发送请求体；另一个请求已发给上游，正在缓冲响应。它们是否都占用许可？只有三十二个许可是否足以证明内存安全？

参考答案：两者都在 forward 作用域内，都会占用。许可限制并发任务数，单次体积限制约束缓冲，超时限制持有时间，仍需计算连接、头部与运行时开销并通过负载测试验证；一个数字不能代替完整资源预算。

### 27.10.5 【扩展练习】设计一个依赖故障实验

保持接口层数据库可用，只停止商品服务。分别预测产品查询、readiness、liveness 的结果，再实际观察并恢复服务。

参考答案：当前设计下产品请求返回依赖错误，readiness 为 503，liveness 为 200；没有本地商品回退。恢复后应等待依赖健康，再观察业务恢复。评分还应包括只操作自己的实验实例、保存诊断证据和完成清理。

### 27.10.6 【衔接】从同步调用进入异步事件

现在公共商品操作已经有一条明确路径，HTTP 用户权限和内部服务身份各有检查位置，数据也有单一写入归属。同步 RPC 适合需要立即答复的查询和命令，但多个服务之间的业务传播仍会遇到提交与发送之间的失败窗口。

下一章学习 Kafka 的主题、分区、偏移量与消费组，先建立可运行消息实验。再下一章把数据库事务与事件发送连接起来，处理“商品修改成功，但事件没有可靠送达”的问题。不能因为换成消息队列，就默认已经解决跨服务一致性。

本章代理配置与逐跳字段处理可进一步对照 [reqwest 0.12.28 ClientBuilder 文档](https://docs.rs/reqwest/0.12.28/reqwest/struct.ClientBuilder.html) 与 [RFC 9110 的 Connection 规则](https://www.rfc-editor.org/rfc/rfc9110.html#name-connection)，阅读时应结合本章固定上游与缓冲 JSON API 的适用范围。
