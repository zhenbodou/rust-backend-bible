# 第 1 章 Rust 基础语法与类型

本章讲清 Rust 的基本语法：程序结构、变量、所有内置类型、常用集合、函数和控制流。所有权、结构体、错误处理等在第 2〜4 章单独详讲。

## 1.1 第一个程序、程序结构与格式化输出

本章的练习代码都放在一个单独的练习项目里，不污染 RustMall：

```bash
# 回到任意一个练习目录，不要放在 rustmall 里面
cd ~
cargo new rust-basics
cd rust-basics
```

### 1.1.1 【入门】逐行读懂 Hello World

文件：rust-basics/src/main.rs

```rust
fn main() {
    println!("Hello, RustMall!");
}
```

fn ：定义函数的关键字（function）。

main ：程序入口函数，可执行程序从这里开始运行，每个 binary crate 必须有且只有一个。

() ：参数列表，main 没有参数。命令行参数要用 std::env::args() 读取。

{ } ：函数体。Rust 用花括号划分代码块，缩进不影响语义（与 Python 不同），但约定 4 个空格。

println! ：注意末尾的 ! ，它表示这是一个宏（macro）而不是函数。这里的输出宏在编译期解析格式字面量和参数，并生成相应调用；一般 Rust 函数签名不能以相同方式接收任意数量的这种参数。

; ：语句结束。1.5 节会讲到语句、表达式和代码块尾表达式的区别，这是 Rust 的重要特性。

运行 cargo run ，输出：

```text
   Compiling rust-basics v0.1.0 (/home/you/rust-basics)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.52s
     Running `target/debug/rust-basics`
Hello, RustMall!
```

前三行是 cargo 的过程信息，最后一行才是程序输出。

### 1.1.2 【入门】输出宏家族

| 宏 | 作用 | 用途 |
| --- | --- | --- |
| println! | 写入标准输出并换行 | 普通输出 |
| print! | 写入标准输出，不换行 | 进度提示 |
| eprintln! / eprint! | 写入标准错误 | 错误诊断；只重定向标准输出时仍可见 |
| format! | 返回 String，不直接输出 | 构造字符串 |
| write! / writeln! | 写入实现相应 Write trait 的目标 | 写文件、缓冲区或格式化目标 |
| dbg! | 在标准错误中输出表达式及位置，<br>并返回表达式的值 | 临时观察程序 |
| panic! | 触发 panic，后果取决于构建策略<br>与捕获边界 | 不能作为正常业务失败的处理方式 |

正式服务日志使用后续章节的 tracing；学习阶段可先用 println! 和 dbg! 观察程序。

### 1.1.3 【入门】格式化字符串全解

文件：rust-basics/src/main.rs （替换全部内容）

```rust
fn main() {
    let name = "机械键盘";
    let price = 199.5_f64;
    let stock = 42;
 
    // 1. 位置参数：{} 依次对应后面的参数
    println!("{} 售价 {} 元", name, price);
 
    // 2. 内联变量名（Rust 1.58 起支持，与 Edition 选择不是一回事）
    println!("{name} 售价 {price} 元，库存 {stock}");
 
    // 3. 指定序号，可重复使用
    println!("{0} 和 {1}，{1} 和 {0}", "甲", "乙");
 
    // 4. 命名参数
    println!("{item} 还剩 {n} 件", item = name, n = stock);
 
    // 5. 小数位数：.2 表示保留 2 位
    // 价格：199.50
    println!("价格：{price:.2}");
 
    // 6. 宽度与对齐：< 左对齐，> 右对齐，^ 居中，数字是总宽度
    // [机械键盘      ]
    println!("[{name:<10}]");
 
    // [    42]
    println!("[{stock:>6}]");
 
    // [  42  ]
    println!("[{stock:^6}]");
    // 7. 填充字符与补零
    // [***42***]
    println!("[{stock:*^8}]");
 
    // 订单号：00001234
    println!("订单号：{:08}", 1234);
 
    // 8. 进制
    // 11111111 377 ff FF 0xff
    println!("{0:b} {0:o} {0:x} {0:X} {0:#x}", 255);
 
    // 9. 科学计数法
    // 1.2345e3
    println!("{:e}", 1234.5);
 
    // 10. Debug 输出：{:?} 单行，{:#?} 美化多行
    let tags = vec!["数码", "外设"];
 
    // ["数码", "外设"]
    println!("{tags:?}");
    println!("{tags:#?}");
 
    // 11. 输出花括号本身：写两次
    // JSON 示例：{"stock": 42}
    println!("JSON 示例：{{\"stock\": {stock}}}");
 
    // 12. format! 得到字符串
    let msg = format!("{name} x {stock}");
    eprintln!("错误输出示例：{msg}");
 
    // 13. dbg! 调试
    // 输出会包含实际文件名、行号、列号；此处不预设位置
    let total = dbg!(price * 2.0);
    // dbg! 会另外输出表达式的值：399.0
    println!("{total}");
}
```

{} 和 {:?} 的本质区别（进阶）：{} 要求类型实现 Display trait（面向用户的友好显示），{:?}要求类型实现 Debug trait（面向开发者的调试显示）。整数、字符串等基本类型两个都实现了；Vec 、元组等只实现了 Debug ，所以 println!("{}", tags) 会编译报错“ Vec&lt;&amp;str&gt; doesn't implement std::fmt::Display ”。自定义结构体用 #\[derive(Debug)\] 自动获得 Debug（第 3 章），Display 需要手动实现（第 5 章）。

宽度对齐与中文：宽度按“字符个数”计算，一个汉字算 1，但在终端里汉字占两个英文字符宽，所以中英混排的表格可能对不齐，这是正常现象。

### 1.1.4 【入门】注释

````rust
// 单行注释：解释“为什么”这样写，而不是“做了什么”
 
/* 块注释，可以
   跨多行，较少使用 */
 
/// 文档注释：写在函数、结构体等定义的上方，支持 Markdown，
/// 会被 cargo doc 生成到 HTML 文档里。
///
/// # 示例
/// ```
/// assert_eq!(rust_basics::add(1, 2), 3);
/// ```
pub fn add(a: i32, b: i32) -> i32 { a + b }
 
// 另有 //! 内部文档注释：只能写在文件或模块的最开头，描述整个模块或 crate（示例见 1.6.5 节 lib.rs）
````

文档注释中的代码块会被当成测试运行（叫 doctest，cargo test 时执行），这样在实际运行并维护测试时，更容易发现文档示例与接口不一致——这是 Rust 生态文档质量高的原因之一。常用的文档小节标题：# Examples 、# Errors（什么情况下返回错误）、# Panics （什么情况下会崩溃）、# Safety（unsafe 函数的使用前提）。

### 1.1.5 【精通】编译过程与程序产物

cargo build 背后执行的是 rustc --edition 2024 src/main.rs ... ，产物在 target/debug/rust-basics（Windows 为 .exe ）。运行它不需要安装 Rust 编译器，但仍须满足目标架构、操作系统和动态库要求。Linux 上使用 glibc 的构建尤其要核对部署环境的库版本，不能只凭“同系统”判断可运行。

编译分阶段：解析 → 宏展开 → 名称解析 → 类型检查 → 借用检查（Rust 特有，保证内存安全）→ 生成 LLVM IR → LLVM 优化 → 生成机器码 → 链接。编译慢主要慢在宏展开、单态化泛型和 LLVM 优化。

main 也可以返回 Result ：fn main() -&gt; Result&lt;(), Box&lt;dyn std::error::Error&gt;&gt; ，返回 Err 时程序会打印错误并以非零退出码结束。后面的服务启动代码都会这样写。

进程退出码：std::process::exit(1) 立刻退出（不会运行析构函数，慎用）；容器和

Kubernetes 依据退出码判断程序是正常结束还是崩溃。

### 1.1.6 常见编译错误与解读

| 诊断 | 原因 | 修正方向 |
| --- | --- | --- |
| E0277：未实现 Display | 用 {} 显示 Vec 等未实现 Display 的<br>类型 | 使用 {:?}，或实现合适的显示方式 |
| 格式宏：缺少位置参数 | 占位符没有对应参数 | 补齐参数或使用已有变量名 |
| argument never used | 参数没有对应占位符 | 补上占位符或删除多余参数 |
| invalid format string | 花括号不匹配 | 输出字面花括号时使用 {{ 和 }} |
| E0425 | 引用了当前作用域没有的变量 | 核对变量名及作用域 |

| 诊断 | 原因 | 处理 |
| --- | --- | --- |
| 找不到 cc / link.exe | 缺少平台链接工具 | 按第 0 章配置构建工具 |
| E0601：缺少 main | 把完整二进制 crate 的入口漏掉了 | 补回 fn main()；纯库则采用库项目结构 |

## 1.2 变量、可变性、常量、静态变量与隐藏

### 1.2.1 【入门】let 声明变量，默认不可变

```rust
fn main() {
    // 声明变量 stock，值为 10，类型由编译器推断为 i32
    let stock = 10;
    println!("{stock}");
    // stock = 9;            // 编译错误！E0384: cannot assign twice to immutable variable
}
```

Rust 的变量默认不可变（immutable）。这和大多数语言相反，设计理由是：程序里绝大多数值一旦算出就不该再变；不可变是默认值，可变才需要你明确声明，代码读者一眼就能看出“哪些值会变化”。跨线程共享还必须满足类型的线程安全约束。不可变绑定并不等于内部数据永远不变；Cell、RefCell 等内部可变性类型需要另外理解，第 7 章会讲解。

### 1.2.2 【入门】mut 声明可变变量

```rust
fn main() {
    // mut = mutable，可变
    let mut stock = 10;
 
    // 卖出一件
    stock -= 1;
 
    // 补货五件
    stock += 5;
    // 14
    println!("当前库存 {stock}");
}
```

规则：只在确实需要修改时加 mut 。多余的 mut 编译器会警告 “variable does not need to bemutable”。

### 1.2.3 【入门】类型标注与类型推断

```text
// 推断为 i32（整数默认类型）
let a = 5;
 
// 推断为 f64（浮点默认类型）
let b = 2.5;
 
// 显式标注：变量名后加冒号和类型
let c: u64 = 5;
 
// 用后缀标注字面量类型
let d = 5u8;
 
// 下划线只是为了好读，等于 1000000
let e = 1_000_000;
 
// parse 能解析成多种类型，必须标注要哪种
let parsed: i64 = "42".parse().unwrap();
```

Rust 是静态强类型语言：每个变量在编译期就有确定的类型，且不会自动隐式转换（i32 和 i64 不能

直接相加）。编译器的类型推断很强，大部分时候不用写类型；以下情况必须写：函数参数和返回值、const / static 、像 parse() 、collect() 这样“返回什么类型由你决定”的泛型函数。

### 1.2.4 【入门】先声明后赋值

```text
// 只声明，不赋值
let level;
let points = 1500;
if points > 1000 { level = "黄金会员"; } else { level = "普通会员"; }
println!("{level}");
// 在赋值前使用 level 会编译错误：E0381 used binding `level` isn't initialized
```

未赋值的变量不能使用，编译器会检查所有分支都赋了值。这种写法不常用，1.5 节会教你用letlevel=if ... { } else { }; 更简洁地表达。

### 1.2.5 【入门】常量 const

```rust
// 必须标注类型，命名用全大写+下划线
const MAX_ORDER_QUANTITY: i32 = 99;
// 可以是编译期能算出的表达式
const CACHE_TTL_SECONDS: u64 = 10 * 60;
const API_PREFIX: &str = "/api/v1";
 
fn main() {
    let qty = 120;
    if qty > MAX_ORDER_QUANTITY { println!("单笔最多购买 {MAX_ORDER_QUANTITY}件"); }
}
```

常量与不可变变量的区别：

| 对比 | let 绑定 | const 项 |
| --- | --- | --- |
| 值的确定 | 可以在运行时计算，也可能被优化<br>为常量 | 初始化式必须能在常量求值中完成 |
| 类型标注 | 常可推断 | 必须声明 |
| 位置 | 通常位于函数或其他局部作用域 | 可以定义在模块或块中 |
| mut | 可使用 let mut | 不能将常量项声明为 mut |
| 含义 | 将名字绑定到一个值 | 定义一个可在多处使用的常量值；不承诺唯一地<br>址 |

后端常用 const 命名分页上限、缓存时间和 API 前缀，避免相同含义的数字散落在各处。

### 1.2.6 【进阶】静态变量 static

```rust
// 全局唯一的一块内存，整个程序生命周期内都存在
static APP_NAME: &str = "RustMall";
 
use std::sync::atomic::{AtomicU64, Ordering};
 
// 线程安全的全局计数器
static REQUEST_COUNT: AtomicU64 = AtomicU64::new(0);
 
fn handle_request() {
    REQUEST_COUNT.fetch_add(1, Ordering::Relaxed);
}
```

const 定义值，不承诺每次引用都指向同一存储位置；static 对应具有固定存储位置的静态项。staticmut（可变静态变量）读写都需要 unsafe ，并且极易产生数据竞争，后端代码中不要使用——需要全局可变状态时，用原子类型（如上例）、std::sync::OnceLock / LazyLock（第 7 章），或者更好的做法：放进 Axum 的共享状态（第 12 章）。

### 1.2.7 【进阶】隐藏（Shadowing）

用 let 再次声明同名变量，新变量会“隐藏”旧变量：

```rust
fn main() {
    // &str 类型
    let input = "  42  ";
 
    // 仍是 &str，去掉首尾空格
    let input = input.trim();
 
    // 变成 i32！类型都可以变
    let input: i32 = input.parse().unwrap();
 
    // 43
    println!("{}", input + 1);
 
    let price = 100;
    {
        // 只在这个内部代码块中隐藏
        let price = price * 2;
 
        // 200
        println!("内部 {price}");
    }
 
    // 100，外部变量没被修改
    println!("外部 {price}");
}
```

隐藏和 mut 的区别：

mut 是修改同一个变量，类型不能变；隐藏是创建一个新变量，类型可以变。

新的 let 绑定默认仍不可变；是否需要修改，应由当前阶段的用途决定。

典型用途：对同一个“概念”做逐步转换（原始字符串 → 去空格 → 解析成数字），不需要起input\_str 、input\_trimmed 、input\_num 这样一串名字。后端处理请求参数时非常常用。

### 1.2.8 【精通】变量相关的细节与陷阱

未使用的变量会产生警告；有意不使用时以下划线开头（let \_unused = 1; ）。单独的 \_ 是忽略模式，不创建绑定：let \_ = some\_fn(); 中新产生的普通临时返回值通常在该语句结束时销毁；let \_guard =lock(); 则建立绑定，在其销毁作用域结束时释放。若右侧是已有变量，let \_ = value; 并不因此移动并销毁它——在持有锁、计时器这类“靠销毁时机起作用”的对象上，两者效果完全不同，这是很隐蔽的bug 来源。

作用域与销毁：局部值通常在其销毁作用域结束时被销毁；也可以通过 drop 显式提前释放，panic 策略等情况还会影响清理（第 2 章讲 Drop）。Rust 没有垃圾回收，靠作用域精确管理资源（内存、文件句柄、数据库连接都一样）。

常量求值：const 中可以调用 const fn ，例如 const TIMEOUT:Duration=Duration::from\_secs(5); ，Duration::from\_secs 就是 const fn 。

命名规范（clippy 会检查）：变量、函数用 snake\_case ；类型、trait、枚举变体用 UpperCamelCase；常量、静态变量用 SCREAMING\_SNAKE\_CASE ；模块和 crate 名用 snake\_case（Cargo 包名可以用连字符，在代码中引用时连字符变成下划线，如 order-service→order\_service ）。

### 1.2.9 常见编译错误与解读

| 诊断 | 原因 | 处理 |
| --- | --- | --- |
| E0384 | 再次赋值给不可变绑定 | 需要修改时用 mut；转换阶段可用隐藏 |
| E0381 | 变量可能尚未初始化 | 确保使用前所有相关路径都已赋值 |
| E0308 | 不同类型混用 | 统一类型或进行明确转换 |
| E0282 | 缺少足够的类型约束 | 标注目标类型或使用 ::&lt;T&gt; |
| 常量缺少类型 | const 没有标注类型 | 为常量声明类型 |
| E0015 | 常量求值调用了不允许的函数 | 改用支持的 const fn 或运行时初始化 |
| E0133 | 在不满足 unsafe 要求的位置访问<br>可变静态数据 | 优先改用原子类型或同步容器 |
| unused\_mut / unused\_variabl<br>es | 多余的 mut 或未使用的变量 | 删除 mut；确实无需使用的绑定以 \_ 开头 |

## 1.3 标量类型：整数、浮点、布尔、字符

“标量”指单个值。Rust 有四种标量类型。

### 1.3.1 【入门】整数类型

| 位数 | 有符号类型 | 无符号类型 | 范围说明 |
| --- | --- | --- | --- |
| 8 | i8 | u8 | i8：-128～127；u8：0～255 |
| 16 | i16 | u16 | i16：-32768～32767 |
| 32 | i32 | u32 | i32：-2^31～2^31-1 |
| 64 | i64 | u64 | i64：-2^63～2^63-1，约<br>±9.22×10^18 |
| 128 | i128 | u128 | i128：-2^127～2^127-1 |
| 随目标平台指针宽度 | isize | usize | 常见 64 位目标为 64 位；不能假设<br>所有目标相同 |

后端选型规则：

数据库主键 ID：使用 i64，与 PostgreSQL 的 BIGINT 对应。PostgreSQL 的普通整数类型没有与 u64直接对应的无符号 64 位类型；转换必须检查范围。

金额：用“分”为单位的 i64 ，例如 199.50 元存为 19950 。永远不要用浮点数存钱（原因见

1.3.3）。

库存、数量：i32 （对应 PostgreSQL 的 INT ）。

集合长度、下标：usize 。Vec::len() 返回 usize ，数组下标必须是 usize 。

端口号：u16 （0〜65535）。

整数字面量写法：98\_222 （十进制）、0xff （十六进制）、0o77 （八进制）、0b1111\_0000（二进制）、b'A' （字节，u8 类型，值 65）。

### 1.3.2 【入门】整数溢出与四类安全运算

```rust
fn main() {
    let stock: u8 = 255;
    // let x = stock + 1;
    // 若编译器已能确定溢出，可能直接拒绝编译；运行时行为受溢出检查配置影响
    // 默认发布配置通常关闭溢出检查；业务代码不要依赖这个默认值
 
    let a: i32 = i32::MAX;
 
    // None：溢出时返回 None，不溢出返回 Some(结果)
    println!("{:?}", a.checked_add(1));
 
    // -2147483648：显式回绕
    println!("{}", a.wrapping_add(1));
 
    // 2147483647：饱和，卡在最大值
    println!("{}", a.saturating_add(1));
 
    // (-2147483648, true)：结果 + 是否溢出
    println!("{:?}", a.overflowing_add(1));
    // 后端场景：计算订单总价，必须防溢出
    let unit_cents: i64 = 19_900;
    let qty: i64 = 3;
    match unit_cents.checked_mul(qty) {
        Some(total) => println!("总价 {total} 分"),
        None => println!("金额溢出，拒绝下单"),
    }
}
```

为什么 debug 和 release 行为不同：溢出检查有运行时开销，所以 release 默认关闭。对安全敏感的项目可在 Cargo.toml 的 \[profile.release\] 中加 overflow-checks = true 。涉及金额、库存的计算，代码中应显式使用 checked\_\* 系列，不依赖编译模式。

整数除法会截断小数：7 / 2 == 3 ，-7 / 2 == -3 ；取余 7 % 2 == 1 。除以 0 会 panic。

### 1.3.3 【入门】浮点类型与“不能用它算钱”的原因

f32 （单精度）和 f64 （双精度，默认）。

```rust
fn main() {
    let x: f64 = 0.1 + 0.2;
 
    // 0.30000000000000004
    println!("{x}");
 
    // false！
    println!("{}", x == 0.3);
 
    // true：浮点比较要按需要选择误差容限；这里仅演示 EPSILON，不是通用比较公式
    println!("{}", (x - 0.3).abs() < f64::EPSILON);
 
    // 3.3333333333333335
    println!("{}", 10.0_f64 / 3.0);
 
    // false：NaN 不等于任何值，包括它自己
    let nan = f64::NAN;
    println!("{}", nan == x);
    // 判定 NaN 应使用 is_nan
    println!("{}", nan.is_nan());
 
    // inf：浮点除以 0 不会 panic
    println!("{}", 1.0_f64 / 0.0);
 
    // 2.67 或 2.68？二进制无法精确表示 2.675，结果不符合直觉
    println!("{:.2}", 2.675_f64);
}
```

浮点数用二进制表示小数，像 0.1 这样的十进制小数无法精确表示（就像十进制无法精确表示 1/3）。累加成千上万笔订单后误差会被放大，可能造成不符合结算规则的结果。所以：

金额用整数“分”（RustMall 的做法，最简单可靠）。

或者用十进制定点数库 rust\_decimal （需要“分”以下精度、利率计算时使用，PostgreSQL 对应NUMERIC 类型，第 13 章会提到）。

浮点数只用于不要求精确的场景：评分、统计平均值、经纬度、延迟毫秒数。

### 1.3.4 【入门】布尔与字符

```text
let on_sale: bool = true;
 
// 比较运算的结果是 bool
let in_stock = 5 > 0;
 
// 与
let can_buy = on_sale && in_stock;
 
// 非、或；&& 和 || 是短路求值
let show_banner = !on_sale || in_stock;
 
// char 用单引号，字符串用双引号
let c: char = '中';
let emoji = '\u{1F980}'; // Unicode 转义：螃蟹字符
 
// 4：char 固定 4 字节，表示一个 Unicode 标量值
println!("{}", std::mem::size_of::<char>());
 
// true
println!("{}", c.is_alphabetic());
 
// 7
println!("{}", '7'.to_digit(10).unwrap());
```

Rust 的 char 是 4 字节的 Unicode 字符，不是 C 语言中的 1 字节。这和 1.4 节字符串的 UTF-8 存储密切相关。

### 1.3.5 【进阶】类型转换

Rust 不做隐式转换，必须显式写出。三种方式：

```rust
fn main() {
    // 方式一：as —— 简单粗暴，可能截断或丢失精度，不报错
    let big: i64 = 300;
 
    // 44（300 - 256），静默截断！
    let small = big as u8;
 
    // 3，直接截掉小数
    let f = 3.99_f64 as i32;
 
    // 4294967295
    let neg = -1_i32 as u32;
 
    // 常用于把 i32 转成下标
    let idx = 5_i32 as usize;
 
    // 方式二：From / Into —— 只用于“绝不会失败”的转换（小类型 → 大类型）
    let a: i64 = i64::from(42_i32);
 
    // 和上一行等价，目标类型由变量标注决定
    let b: i64 = 42_i32.into();
 
    // 方式三：TryFrom / TryInto —— 可能失败的转换，返回 Result（后端推荐）
    use std::convert::TryFrom;
    let qty_from_request: i64 = 5_000_000_000;
    match i32::try_from(qty_from_request) {
        Ok(q) => println!("数量 {q}"),
        // 走这里
        Err(e) => println!("数量超出范围：{e}"),
    }
 
    // 字符串 → 数字：parse，返回 Result
    let n: i32 = "123".parse().unwrap();
 
    // Err(ParseIntError)
    let bad = "12a".parse::<i32>();
    // 数字 → 字符串
    let s = 123.to_string();
    println!("{small} {f} {neg} {idx} {a} {b} {n} {bad:?} {s}");
}
```

后端规则：处理外部输入（请求参数、数据库值、配置）时，一律用 try\_from / try\_into / parse 并处理错误；as 只用于你能证明不会出问题的场景。clippy 的 cast\_possible\_truncation 等检查项可以帮你找出危险的 as 。

### 1.3.6 【精通】内存布局与零成本

用 std::mem::size\_of::&lt;T&gt;() 查看任何类型占用的字节数：i32 为 4，bool 为 1，char 为 4，()（单元类型，表示“没有值”）为 0。

单元类型 () ：没有返回值的函数实际返回 () 。Result&lt;(), Error&gt; 表示“成功时没有值”，后端中删除、更新操作常这样返回。

永不返回类型 ! ：panic!() 、loop {} （无 break）、std::process::exit() 的类型是!，它可以被当作任何类型，所以 let x: i32 = if ok { 1 } else { panic!("...") }; 能通过编译。

标量类型都实现了 Copy ：赋值时按位复制，原变量仍可用（第 2 章所有权的重要前提）。

数值类型的常用方法：abs() 、pow() 、min()/max() 、clamp(lo, hi) （把分页参数限制在 1〜100 之间就用它：page\_size.clamp(1, 100) ）、f64::round()/floor()/ceil() 。

### 1.3.7 常见编译错误与运行时错误

| 诊断 | 原因 | 处理 |
| --- | --- | --- |
| E0308 | 把 i32 直接用于要求 i64 的位置 | 使用 i64::from(x) 等合适转换 |
| E0277 | 整数与浮点直接混算 | 按业务含义统一数值类型 |
| From&lt;i64&gt; for i32 不存在 | 缩窄转换可能超出范围 | 使用 i32::try\_from(x) 并处理失败 |

| 诊断或行为 | 触发条件 | 处理 |
| --- | --- | --- |
| arithmetic operation will<br>overflow | 编译器能确定算术溢出 | 修正运算或明确选择 checked\_\* 等行为 |
| literal out of range | 字面量超出目标类型 | 更正输入或选择足够大的类型 |
| 整数溢出 panic | 启用了溢出检查且运行时发生溢出 | 业务运算显式使用 checked\_\* 等方法 |
| 整数除零 panic | 除数为零 | 验证除数或使用 checked\_div |
| 解析后的 unwrap panic | parse 返回 Err 后仍调用 unwrap | 使用 match 或适当的错误传播 |

## 1.4 复合类型与常用集合

复合类型把多个值组合成一个值。本节先讲语言内置的元组和数组，再讲标准库中后端开发最常用的四种集合：切片、Vec、String/&amp;str、HashMap。它们贯穿整本书：请求参数是 String ，商品列表是 Vec&lt;Product&gt; ，缓存是 HashMap 。

### 1.4.1 【入门】元组（tuple）

元组把固定数量、类型可以不同的值打包在一起：

```rust
fn main() {
    // (商品ID, 名称, 价格分)
    let item: (i64, &str, i64) = (1, "机械键盘", 19_900);
 
    // 访问方式一：用 .0 .1 .2 按位置访问
    println!("ID={} 名称={} 价格={}", item.0, item.1, item.2);
 
    // 访问方式二：解构（destructuring），一次拆成多个变量
    let (id, name, price) = item;
    println!("{id} {name} {price}");
 
    // 不需要的部分用 _ 忽略
    let (_, only_name, _) = item;
    println!("{only_name}");
 
    // 单元素元组必须带逗号，否则就是普通的括号表达式
    let single = (5,);
 
    // 这只是 i32 类型的 5，编译器会提示多余括号
    let not_tuple = (5);
    println!("{single:?} {not_tuple}");
}
```

元组最常见的用途是让函数返回多个值：

```rust
/// 计算分页的 LIMIT 和 OFFSET
fn page_to_limit_offset(page: u32, page_size: u32) -> (i64, i64) {
    // 页码至少为 1
    let page = page.max(1);
 
    // 每页 1〜100 条
    let size = page_size.clamp(1, 100);
    // 先扩大到 i64 再相乘，避免 u32 中间结果溢出
    (i64::from(size), i64::from(page - 1) * i64::from(size))
}
 
fn main() {
    let (limit, offset) = page_to_limit_offset(3, 20);
 
    // LIMIT 20 OFFSET 40
    println!("LIMIT {limit} OFFSET {offset}");
}
```

项目的 pagination 模块会采用同样的先转换、再计算思路；数据库章节继续使用统一的分页工具。

设计建议：元组字段没有名字，超过 3 个字段或者会在多处使用时，应改用结构体（第 3 章），否则item.2 是什么意思，读代码的人只能去猜。

### 1.4.2 【入门】数组（array）

数组是固定长度、元素类型相同的序列，长度是类型的一部分。数组元素内联存放在数组值中；数组可以位于局部变量、堆分配或静态存储中，不是只能放在栈上：

```rust
fn main() {
    // 类型写法 [元素类型; 长度]
    let levels: [&str; 3] = ["普通", "白银", "黄金"];
    // 12 个 0，常用于按月统计
    let zeros = [0i64; 12];
 
    // 下标从 0 开始
    println!("{}", levels[0]);
 
    // 3
    println!("{}", levels.len());
 
    // 遍历
    for level in levels {
        println!("{level}");
    }
 
    let i = 5;
    // println!("{}", levels[i]);       // 运行时 panic：index out of bounds: the len is 3 but the index is 5
    // None：安全访问，越界返回 None 而不是崩溃
    println!("{:?}", levels.get(i));
    println!("{:?}", zeros);
}
```

Rust 的边界检查：每次用 \[i\] 访问都会检查下标，越界立刻 panic，而不是像 C 语言那样读到一块垃圾内存——这类“缓冲区溢出”是历史上最常见的安全漏洞来源，Rust 从语言层面把它消灭了。对来自用户输入的下标，用 .get(i) 返回 Option ，再按第 4 章的方法处理。

数组在后端中用得不多（长度必须在编译期确定），主要用于固定配置，例如允许的图片格式列表 const ALLOWED: \[&amp;str; 3\] = \["jpg", "png", "webp"\]; 。

### 1.4.3 【入门】Vec：动态数组

Vec&lt;T&gt; （读作 vector）是长度可变、元素类型相同的序列，数据存放在堆上。后端中只要是“一组东西”，几乎都用 Vec：查询结果列表、订单明细、批量 ID。

创建与增删：

```rust
fn main() {
    // 空 Vec，必须标注元素类型或之后 push 让编译器推断
    let mut cart: Vec<i64> = Vec::new();
 
    // vec! 宏：带初始值创建
    let mut ids = vec![101, 102, 103];
 
    // 预分配容量，避免多次扩容
    let mut buf: Vec<u8> = Vec::with_capacity(1024);
 
    // 末尾追加
    cart.push(19_900);
    cart.push(9_900);
 
    // 追加多个
    cart.extend([5_000, 3_000]);
    // 弹出末尾，返回 Option<i64>：Some(3000)
    let last = cart.pop();
 
    // 在下标 0 处插入（后面元素整体后移，O(n)）
    cart.insert(0, 1_000);
 
    // 删除下标 1 处的元素并返回它（O(n)）
    let removed = cart.remove(1);
 
    // 只保留满足条件的元素：删掉 102
    ids.retain(|&id| id != 102);
 
    // 只保留前 1 个
    ids.truncate(1);
 
    // 清空，但保留已分配的容量
    buf.clear();
 
    println!("{cart:?} {last:?} {removed} {ids:?} {}", buf.len());
}
```

读取：

```text
let prices = vec![19_900, 9_900, 5_000];
 
// 直接下标，越界 panic
let first = prices[0];
 
// Option<&i64>，越界为 None
let maybe = prices.get(10);
 
// Option<&i64>
let first_opt = prices.first();
 
// true
let has = prices.contains(&9_900);
 
// Some(2)
let pos = prices.iter().position(|&p| p == 5_000);
 
// false
let empty = prices.is_empty();
```

遍历的三种写法（务必掌握区别，第 2 章会从所有权角度解释原因）：

```text
let mut prices = vec![19_900, 9_900, 5_000];
 
// 只读借用：遍历后 prices 仍可用
for p in &prices { println!("{p}"); }
 
// 可变借用：原地打九折，*p 表示“p 指向的值”
for p in &mut prices { *p = *p * 9 / 10; }
 
// 获取所有权：遍历后 prices 不能再用
for p in prices { println!("{p}"); }
// println!("{:?}", prices);                     // 编译错误 E0382: borrow of moved value
 
let names = vec!["键盘", "鼠标"];
 
// 同时拿到下标
for (i, name) in names.iter().enumerate() {
    println!("{i}: {name}");
}
```

排序、去重、查找：

```text
let mut v = vec![3, 1, 2, 3, 1];
 
// [1, 1, 2, 3, 3]，稳定排序
v.sort();
 
// [1, 2, 3]，去掉**相邻**重复，通常先 sort 再 dedup
v.dedup();
 
// 降序 [3, 2, 1]
v.sort_by(|a, b| b.cmp(a));
 
// 反转
v.reverse();
 
// 有序数组二分查找
let found = v.binary_search(&2);
// 按字段排序（结构体在第 3 章）：products.sort_by_key(|p| p.price_cents);
// 浮点数不能直接 sort（NaN 无法比较），要用 v.sort_by(|a, b| a.total_cmp(b));
```

容量与扩容原理【进阶】：Vec 在内存中由三部分组成——指向堆内存的指针、长度 len （当前元素个数）、容量 capacity （已分配可容纳的元素个数）。push 时若 len == capacity ，Vec 会请求更多容量，可能原地扩展，也可能移动到新的分配区域；增长倍数和分配器行为不是稳定承诺。所以：

均摊下来 push 仍是 O(1)，但一次扩容可能很慢。

已知大致数量时用 Vec::with\_capacity(n) 预分配，例如把 1000 行数据库结果转换成 DTO 时。

shrink\_to\_fit() 请求缩减多余容量，最终容量受分配器影响，不保证恰好等于 len。

### 1.4.4 【入门】切片（slice）：借来的一段连续数据

切片 &amp;\[T\] 是对数组或 Vec 中一段连续元素的借用，它本身不拥有数据，只记录“从哪里开始、有多长”：

```rust
// 参数写 &[i64]，数组和 Vec 都能传进来
fn sum_cents(items: &[i64]) -> i64 {
    items.iter().sum()
}
 
fn main() {
    let v = vec![100, 200, 300, 400, 500];
    let arr = [1, 2, 3];
 
    // &Vec<i64> 会自动转换成 &[i64]
    println!("{}", sum_cents(&v));
    println!("{}", sum_cents(&arr));
 
    // 下标 1、2：200+300 = 500
    println!("{}", sum_cents(&v[1..3]));
 
    // [100, 200]
    let first_two = &v[..2];
 
    // [400, 500]
    let from_three = &v[3..];
 
    // 全部
    let all = &v[..];
 
    // 1、2、3（..= 包含右端点）
    let inclusive = &v[1..=3];
 
    // 实用方法
    // 分批：[100,200] [300,400] [500]
    for chunk in v.chunks(2) {
        // 第 14 章分批写数据库时会用
        println!("批量处理 {chunk:?}");
    }
    let (left, right) = v.split_at(2);
    println!("{first_two:?} {from_three:?} {all:?} {inclusive:?} {left:?} {right:?}");
}
```

函数参数的黄金法则：只需要读取一组数据时，参数类型写 &amp;\[T\] 而不是 &amp;Vec&lt;T&gt; 。&amp;\[T\] 能接受数组、Vec、Vec 的一部分，更通用；clippy 会对 &amp;Vec&lt;T&gt; 参数给出 ptr\_arg 警告。

### 1.4.5 【入门】String 与 &amp;str：新手最大的困惑点

Rust 有两种主要的字符串类型，初学者几乎都会在这里卡住。先给结论：

| 对比 | String | &amp;str |
| --- | --- | --- |
| 所有权 | 拥有字符串存储 | 借用一段合法 UTF-8 数据 |
| 存储 | 可增长的字节缓冲区 | 可指向 String、字面量等不同来源 |
| 修改 | 通过适当的可变借用修改或追加 | 共享字符串切片不能修改其引用的内容 |

| 对比 | String | &amp;str |
| --- | --- | --- |
| 典型来源 | String::from、format!、读取请求<br>或数据库 | 字符串字面量、String 的借用或子串 |
| 类比 | 拥有一本书 | 借阅一本书或其中几页 |

```rust
fn main() {
    // 字符串字面量的类型是 &'static str
    let literal: &str = "RustMall";
    let s1 = String::from("机械键盘");
    let s2 = "鼠标".to_string();
 
    // 拼接最推荐的方式
    let s3 = format!("{s1}-{s2}");
    let empty = String::new();
 
    // ---------- 修改 ----------
    let mut title = String::from("Rust");
 
    // 追加一个 char
    title.push(' ');
 
    // 追加 &str
    title.push_str("后端开发");
 
    // += 也可以追加 &str
    title += "圣经";
    title.insert_str(0, "《");
    title.push('》');
 
    // 《Rust 后端开发圣经》
    println!("{title}");
 
    // ---------- String 与 &str 互相转换 ----------
    // String → &str：借用即可，零成本
    let borrowed: &str = &s1;
    let borrowed2: &str = s1.as_str();
 
    // &str → String：需要复制一份数据
    let owned: String = borrowed.to_string();
    let owned2: String = String::from(borrowed);
    let owned3: String = borrowed.to_owned();
 
    // ---------- 常用方法 ----------
    let input = "  Alice@Example.COM  ";
 
    // 去空格、转小写：注册时规范化邮箱
    let email = input.trim().to_lowercase();
 
    // true
    println!("{}", email.contains('@'));
 
    // true
    println!("{}", email.starts_with("alice"));
 
    // true
    println!("{}", email.ends_with(".com"));
    println!("{}", email.replace("example", "test"));
 
    // Some(5)：字节位置
    println!("{:?}", email.find('@'));
    // Some(("alice", "example.com"))
    println!("{:?}", email.split_once('@'));
 
    // ["a", "b", "", "c"]
    let parts: Vec<&str> = "a,b,,c".split(',').collect();
 
    // ["a", "b", "c"]
    let words: Vec<&str> = " a  b c ".split_whitespace().collect();
    let header = "Bearer abc.def";
 
    // Some("abc.def")：第 16 章解析令牌就用它
    println!("{:?}", header.strip_prefix("Bearer "));
 
    // ababab
    println!("{}", "ab".repeat(3));
 
    // a/b/c
    println!("{}", ["a", "b", "c"].join("/"));
    println!("{literal} {s3} {empty:?} {borrowed2} {owned} {owned2} {owned3} {parts:?} {words:?}");
}
```

UTF-8 与“不能用下标取字符”【进阶】：String 内部是一串 UTF-8 编码的字节。英文字母占 1 字节，汉字通常占 3 字节，单个 emoji 标量通常占 4 字节；一个显示出来的 emoji 也可能由多个标量组合。

```text
let s = String::from("键盘ab");
 
// 8：len() 返回的是字节数，不是字符数！
println!("{}", s.len());
 
// 4：字符数
println!("{}", s.chars().count());
// let c = s[0];                            // 编译错误：String 不能用整数下标索引
// 正确取第一个字符：Some('键')
let first: Option<char> = s.chars().next();
 
// "键"：按字节范围切片可以，但必须落在字符边界上
let sub = &s[0..3];
// let bad = &s[0..2];                       // 运行时 panic：byte index 2 is not a char 
// boundary：上面的字节位置不在字符边界上
for (byte_pos, ch) in s.char_indices() { println!("{byte_pos}:{ch}"); }
```

为什么不允许 s\[0\] ？因为“第 0 个”到底指第 0 个字节、第 0 个字符还是第 0 个字形，在 Unicode 中并不明确，而且按字符定位需要从头扫描（O(n)），Rust 拒绝用看似 O(1) 的语法隐藏 O(n) 的开销。后端中的含义：校验用户名长度时，“最多 20 个字符”要用

name.chars().count() &lt;= 20 ，而不是 name.len() &lt;= 20 ——后者对中文用户名只允许 6 个字。截断字符串要用 chars().take(n).collect::&lt;String&gt;() 。

函数参数的黄金法则：只读字符串参数写 &amp;str （能同时接受 &amp;String 和字面量）；需要把字符串保存起来（放进结构体、返回出去）时用 String 。

```rust
// 收 &str，返回 String
fn greet(name: &str) -> String {
    format!("你好，{name}")
}
fn main() {
    let owned = String::from("Alice");
 
    // &String 自动转为 &str（称为 Deref 强制转换，第 7 章）
    println!("{}", greet(&owned));
    println!("{}", greet("Bob"));
}
```

### 1.4.6 【入门】HashMap：键值对

```rust
// HashMap 不在预导入（prelude）中，需要 use
use std::collections::HashMap;
 
fn main() {
    // 商品ID → 库存
    let mut stock: HashMap<i64, i32> = HashMap::new();
    stock.insert(1, 10);
    stock.insert(2, 0);
 
    // 键已存在时覆盖，并返回旧值 Some(10)
    let old = stock.insert(1, 8);
 
    // 读取
    // get 返回 Option<&V>
    match stock.get(&1) {
        Some(n) => println!("商品1库存 {n}"),
        None => println!("商品不存在"),
    }
 
    // 不存在当作 0
    let n = stock.get(&3).copied().unwrap_or(0);
    println!("{}", stock.contains_key(&2));
 
    // 修改已有值
    if let Some(v) = stock.get_mut(&1) { *v -= 1; }
 
    // entry API：存在就修改，不存在就插入 —— 最常用、最地道的写法
    let mut sales: HashMap<String, i64> = HashMap::new();
    for name in ["键盘", "鼠标", "键盘"] {
        // 统计每种商品卖出次数
        *sales.entry(name.to_string()).or_insert(0) += 1;
    }
 
    // 默认值计算代价大时用 or_insert_with
    sales.entry("耳机".into()).or_insert_with(|| 0);
 
    // 删除与遍历
    stock.remove(&2);
 
    // 注意：遍历顺序是不确定的！
    for (id, qty) in &stock { println!("{id} => {qty}"); }
    println!("{old:?} {n} {sales:?} {}", stock.len());
 
    // 从迭代器构建
    let names: HashMap<i64, &str> = vec![(1, "键盘"), (2, "鼠标")].into_iter().collect();
    println!("{names:?}");
}
```

HashMap 要点【进阶】：

遍历顺序不确定，每次运行都可能不同。需要有序时使用 BTreeMap （按键排序，O(log n)操作）。返回给前端的 JSON 如果依赖顺序，不要用 HashMap。

键类型必须实现 Eq 和 Hash （整数、String、元组都满足；浮点数不满足，不能做键）。

标准库默认哈希器包含随机化等用于抵御碰撞攻击的设计，具体算法可能变化；这并不能代替请求大小、数量和资源限制。追求极致性能且键不可被外部控制时，可以换成 ahash 、rustc-hash 等第三方实现。

HashMap&lt;String, V&gt; 查询时可以直接传 &amp;str ：map.get("键盘") ，不需要先构造

String。

### 1.4.7 【进阶】其他集合一览

| 集合 | 特点 | 典型用途 |
| --- | --- | --- |
| HashSet&lt;T&gt; | 无重复元素；查找平均 O(1) | 去重 ID、权限集合 |
| BTreeMap&lt;K,V&gt; | 按键排序的映射 | 有序输出与范围访问 |
| BTreeSet&lt;T&gt; | 按元素排序的集合 | 有序去重 |
| VecDeque&lt;T&gt; | 两端插入均摊 O(1)，两端弹出<br>O(1) | 队列与滑动窗口 |
| BinaryHeap&lt;T&gt; | 默认按最大值优先取出 | 优先级队列；调度需另外设计时间与唤醒机制 |

```rust
use std::collections::{HashSet, BTreeMap, VecDeque};

fn main() {
let ids: HashSet<i64> = [3, 1, 3, 2].into_iter().collect();
let a: HashSet<i32> = [1, 2, 3].into();
let b: HashSet<i32> = [2, 3, 4].into();
 
// 交集 2、3
let common: Vec<_> = a.intersection(&b).collect();
 
// 月份 → 销售额，按月份有序
let mut monthly: BTreeMap<u32, i64> = BTreeMap::new();
monthly.insert(3, 100); monthly.insert(1, 50);
let mut queue: VecDeque<&str> = VecDeque::new();
queue.push_back("订单A"); queue.push_back("订单B");
 
// Some("订单A")：先进先出
let next = queue.pop_front();
println!("{ids:?} {common:?} {monthly:?} {next:?}");
}
```

### 1.4.8 【精通】集合的选择与性能

时间复杂度速查：Vec 末尾增删 O(1)、中间插删 O(n)、按值查找 O(n)；HashMap 增删查平均 O(1)；BTreeMap O(log n)。数据量在几十以内时，线性扫描 Vec 往往比 HashMap 更快（CPU 缓存友好、无哈希计算），不要过早优化。

内存布局：这些容器值保存指针、长度或其他管理信息，动态元素另行存储。具体大小依目标平台和实现而定，可用 size\_of 测量当前目标；不要把某次测量值当成通用契约。移动容器通常不逐个克隆其堆上元素。

String 就是 Vec&lt;u8&gt; 加上“内容必须是合法 UTF-8”的保证；String::from\_utf8(bytes)会校验并可能返回错误，从网络读取的原始字节要经过这一步。

Box&lt;str&gt; 适合单一所有者持有不再增长的字符串；Arc&lt;str&gt; 通过引用计数提供共享所有权。两者的管理方式不同，第 7 章再比较。

小集合优化：smallvec 、arrayvec 等 crate 在元素较少时把数据放在栈上，避免堆分配，常见于高性能网络库内部。

### 1.5.1 【入门】定义和调用函数

```rust
/// 计算含折扣的价格（单位：分）
/// - unit_cents：单价
/// - qty：数量
/// - discount_percent：折扣百分比，90 表示九折
fn discounted_total(unit_cents: i64, qty: i64, discount_percent: i64) -> i64 {
    unit_cents * qty * discount_percent / 100
}
 
// 没有 -> 表示返回单元类型 ()
fn print_receipt(total: i64) {
    println!("应付：{}.{:02} 元", total / 100, total % 100);
}
 
fn main() {
    let total = discounted_total(19_900, 2, 90);
 
    // 应付：358.20 元
    print_receipt(total);
}
```

语法要点：

参数必须标注类型：name: Type ，多个参数用逗号分隔。这是刻意设计——函数签名是“合同”，编译器只看签名就能检查调用方，不需要读函数体。

返回类型写在 -&gt; 之后。

函数定义的位置无所谓，main 可以调用写在它后面的函数。

命名用 snake\_case 。

参数按值传递：传入整数会复制一份；传入 String 、Vec 会转移所有权（第 2 章详解），所以通常传引用 &amp; 。

金额格式化技巧：{:02} 保证分的部分是两位（5 分显示为 05）。这个小函数暴露了一个问题：负数金额（退款）会显示错误，练习 3 请你修复。

### 1.5.2 【入门】语句与表达式：Rust 的核心语法观

这是 Rust 与 C/Java 差异最大的地方之一，理解它之后代码会简洁很多：

语句（statement）：执行一个动作，不产生值。let x = 5; 是语句；以分号结尾的表达式也变成语句。

表达式（expression）：计算并产生一个值。5 、a + b 、函数调用、if 、match 、{ }代码块都是表达式。

```rust
fn main() {
    // 代码块 { } 是表达式，它的值就是最后一个不带分号的表达式
    let total = {
        let unit = 19_900;
        let qty = 3;
 
        // 没有分号：这是代码块的值
        unit * qty
    };
 
    // 59700
    println!("{total}");
 
    let nothing = {
        let unit = 19_900;
 
        // 有分号：变成语句，代码块的值是 ()
        unit * 3;
    };
 
    // ()
    println!("{nothing:?}");
}
```

函数的返回值就是函数体这个代码块的值，所以最后一行不写分号即可返回：

```rust
fn square(x: i64) -> i64 {
    // 正确：返回 x*x
    x * x
}
 
fn square_wrong(x: i64) -> i64 {
    // 错误！E0308 mismatched types: expected `i64`, found `()`
    x * x;
 
// 编译器会贴心提示：remove this semicolon to return this value
}
```

return 关键字用于提前返回（常见于参数校验）：

```rust
fn validate_qty(qty: i32) -> Result<i32, String> {
    if qty <= 0 {
        // 提前返回
        return Err(String::from("数量必须大于 0"));
    }
    if qty > 99 {
        return Err(format!("单笔最多 99 件，你选择了 {qty} 件"));
    }
 
    // 正常路径：最后一行表达式返回
    Ok(qty)
}
```

这种“先排除异常情况、最后返回正常结果”的写法叫卫语句（guard clause），是后端代码最常见的结构，能避免层层嵌套的 if。

### 1.5.3 【入门】if 表达式

```rust
fn main() {
    let stock = 3;
 
    if stock == 0 {
        println!("已售罄");
    } else if stock < 5 {
        println!("仅剩 {stock} 件");
    } else {
        println!("有货");
    }
 
    // if 是表达式：可以直接给变量赋值（替代其他语言的三元运算符 ?:）
    let label = if stock > 0 { "有货" } else { "缺货" };
 
    // 各分支的类型必须一致
    // let bad = if stock > 0 { 1 } else { "无" };   // E0308: `if` and
    // `else` have incompatible types
    println!("{label}");
}
```

规则：条件必须是 bool 。Rust 不会把整数、空字符串自动当作真假（if stock { } 编译错误），这消灭了 C 语言里 if (x = 0) 一类的经典 bug。条件不需要括号。

### 1.5.4 【入门】loop、while、for 三种循环

loop：无限循环，用 break 退出，break 可以携带返回值

```rust
fn main() {
    let mut attempt = 0;
    let result = loop {
        attempt += 1;
        println!("第 {attempt} 次尝试连接数据库");
        if attempt == 3 {
            // loop 也是表达式，break 的值就是 loop 的值
            break "连接成功";
        }
    };
    println!("{result}");
}
```

这个固定次数的循环仅用于认识 loop；真实重试还需超时、退避和重试条件。服务器主循环与第 28 章的消息消费者也会使用循环。

while：条件为真时循环

```text
let mut stock = 3;
while stock > 0 {
    println!("卖出一件，剩 {}", stock - 1);
    stock -= 1;
}
```

for：遍历任何可迭代对象（最常用）

```text
// 0 1 2 3 4（左闭右开）
for i in 0..5 { print!("{i} "); }
 
// 1 2 3 4 5（..= 包含右端）
for i in 1..=5 { print!("{i} "); }
 
// 3 2 1
for i in (1..=3).rev() { print!("{i} "); }
 
// 0 3 6 9
for i in (0..10).step_by(3) { print!("{i} "); }
 
let orders = vec!["A001", "A002"];
 
// 遍历集合首选 for + 借用
for o in &orders { println!("{o}"); }
```

选择建议：遍历集合一律用 for ，不要用 while i &lt; v.len() { v\[i\] } 的下标写法—— 直接遍历元素无需手写下标；是否更快仍需按实际代码测量。需要条件循环用 while ，需要“一直运行直到某事发生”用 loop 。

### 1.5.5 【进阶】continue、break 与循环标签

```rust
fn main() {
    let warehouses = vec![vec![0, 5, 0], vec![3, 0], vec![0]];
    let mut found = None;
 
    // 标签以单引号开头
    'outer: for (w, shelves) in warehouses.iter().enumerate() {
        for (s, &qty) in shelves.iter().enumerate() {
            if qty == 0 {
                // 跳过本次，进入内层下一轮
                continue;
            }
            found = Some((w, s));
 
            // 直接跳出外层循环
            break 'outer;
        }
    }
    // Some((0, 1))
    println!("第一个有货的位置：{found:?}");
}
```

多层嵌套循环中要从内层直接结束外层时，用标签；不加标签的 break / continue 只作用于最内层循环。

### 1.5.6 【进阶】match 预览与 if let

match 是 Rust 最强大的控制流，第 3 章会用一整节讲。这里先认识它的基本形态，因为后面每一章都会用：

```rust
fn status_text(code: u16) -> &'static str {
    match code {
        200 => "成功",
        201 => "已创建",
        // 多个值
        400 | 422 => "请求参数错误",
        401 => "未登录",
        // 范围
        500..=599 => "服务器错误",
        // 兜底分支：_ 匹配一切
        _ => "其他",
    }
}
 
fn main() {
    let maybe_stock: Option<i32> = Some(3);
    // 只关心一种情况时，if let 比 match 简洁
    if let Some(n) = maybe_stock {
        println!("库存 {n}");
    } else {
        println!("查无此商品");
    }
    // let-else：不匹配就必须提前退出（return/break/continue/panic），后端参数校验极常用
    let Some(n) = maybe_stock else {
        println!("查无此商品");
        return;
    };
    println!("{} {n}", status_text(422));
}
```

### 1.5.7 【进阶】函数的更多形式

```rust
// 1. 函数可以作为值传递（函数指针类型 fn(参数) -> 返回值）
fn apply_discount(cents: i64) -> i64 { cents * 9 / 10 }
fn apply_all(prices: &[i64], f: fn(i64) -> i64) -> Vec<i64> {
    prices.iter().map(|&p| f(p)).collect()
}
 
// 2. 嵌套函数：只在外层函数内部可见
fn outer() -> i64 {
    fn helper(x: i64) -> i64 { x + 1 }
    helper(1)
}
 
// 3. const fn：可以在编译期求值，用于初始化常量
const fn kb(n: usize) -> usize { n * 1024 }
const MAX_BODY: usize = kb(256);
 
// 4. 永不返回的函数
fn fatal(msg: &str) -> ! {
    panic!("致命错误：{msg}");
}
 
fn main() {
    println!("{:?} {} {}", apply_all(&[100, 200], apply_discount), outer(), MAX_BODY);
    if MAX_BODY == 0 { fatal("配置错误"); }
}
```

闭包（匿名函数 |x| x + 1）在第 6 章详细讲解；async fn 在第 11 章讲解。

### 1.5.8 【精通】表达式导向编程与代码风格

尽量让变量一次性初始化：用 let x = if/match/{块} 代替“先声明 mut 再在分支中赋值”，变量可以保持不可变，也不会出现漏赋值。

早返回优于深嵌套：卫语句 + ? 运算符（第 4 章）+ let-else ，让主逻辑保持在最外层缩进。

函数应短小单一：一个函数只做一件事，超过 50 行通常意味着应该拆分。clippy 的too\_many\_arguments （默认超过 7 个参数警告）提示你该把参数打包成结构体。

布尔参数是坏味道：create\_order(true, false) 读不懂，应改为枚举（第 3 章）。

递归：Rust 支持递归但不保证尾调用优化，深度过大会栈溢出（栈大小依平台、链接选项和线程创建配置而定）。处理用户可控深度的数据（如评论树）时用循环 + 显式栈代替递归。

内联：编译器会自动内联小函数；#\[inline\] 是给编译器的提示，不保证一定内联，不要滥用。

### 1.5.9 常见编译错误与解读

| 诊断 | 原因 | 处理 |
| --- | --- | --- |
| E0308：预期数值却得到 () | 末尾多了分号 | 去掉不需要的分号 |
| E0308：分支类型不一致 | if / else 返回不同类型 | 统一各分支的结果类型 |

### 1.6.2 第 1 步：创建 workspace 根清单

什么是 workspace：一组共享同一个 Cargo.lock 和同一个 target/ 编译目录的包。好处是：多个服务的依赖版本保持一致；可复用兼容的构建产物；不同目标、feature 或 profile 仍可能产生多份；cargo test --workspace 一条命令测试全部。

RustMall 最终会有 common、proto、monolith、四个微服务和 gateway 共八九个成员，全部放在这个 workspace 中。

文件：rustmall/Cargo.toml

```toml
[workspace]
resolver = "3"
members = [
    "common",
]
 
[workspace.package]
version = "0.1.0"
edition = "2024"
rust-version = "1.85"
license = "MIT"
 
[workspace.dependencies]
# 后续章节在这里统一声明第三方依赖的版本，各成员用 xxx.workspace = true 引用
 
[workspace.lints.rust]
unsafe_code = "forbid"
 
[workspace.lints.clippy]
unwrap_used = "warn"
 
[profile.dev.package."*"]
opt-level = 2
```

逐行解释：

\[workspace\] ：声明这是一个工作区根。注意根目录没有 \[package\] ，这种叫“虚拟清单（virtual manifest）”，根目录本身不是一个包。

resolver = "3" ：依赖解析器版本。2024 Edition 对应 resolver 3，它在选择依赖版本时会考虑各包声明的 rust-version ，避免选到你的编译器不支持的新版本。虚拟清单必须显式写出 resolver。

members ：成员包的目录列表，也可以用通配符，例如第 26 章会写 "services/\*" 。

\[workspace.package\] ：成员可以继承的公共元数据，避免每个包重复写 edition、version。

rust-version = "1.85" ：最低支持的 Rust 版本，1.85 是首个支持 2024 Edition 的版本。

\[workspace.dependencies\] ：集中管理依赖版本。比如这里写 serde = { version = "1",features = \["derive"\] } ，成员中只需写 serde.workspace = true 。这样各成员可以复用同一依赖要求；传递依赖等原因仍可能引入多个版本，升级只改一处。从后续依赖引入阶段开始使用。

\[workspace.lints.rust\] unsafe\_code = "forbid" ：继承该 lint 的成员禁止直接写 unsafe 代码。它不禁止依赖内部使用 unsafe，也不是整个系统安全性的证明；仍需审核依赖与业务逻辑。

\[workspace.lints.clippy\] unwrap\_used = "warn" ：对 .unwrap() 给出警告，提醒你在业务代码中正确处理错误（第 4 章详解）。测试代码中使用 unwrap 是可以的，后面会配置豁免。

\[profile.dev.package."\*"\] opt-level = 2 ：调试模式下第三方依赖也开启优化（原理见 0.2.6 节）。

//! 金额工具。
//!
//! 全项目统一约定：金额一律使用 `i64` 表示，单位为“分”。
//! 例如 199.50 元表示为 `19950`。禁止使用浮点数表示金额。

/// 每元等于多少分。
pub const CENTS_PER_YUAN: i64 = 100;

/// 单笔订单允许的最大金额：100 万元。
pub const MAX_ORDER_CENTS: i64 = 1_000_000 * CENTS_PER_YUAN;

/// 计算 `单价 × 数量` 的总价，溢出或超过上限时返回 `None`。
///
/// # Examples
///
/// ```
/// use common::money::line_total;
/// assert_eq!(line_total(19_900, 3), Some(59_700));
/// assert_eq!(line_total(i64::MAX, 2), None);
/// ```
pub fn line_total(unit_cents: i64, qty: i64) -> Option<i64> {
    if unit_cents < 0 || qty <= 0 {
        return None;
    }
    let total = unit_cents.checked_mul(qty)?;
    if total > MAX_ORDER_CENTS {
        return None;
    }
    Some(total)
}

/// 按百分比打折，结果向下取整到分。`percent` 取值 1〜100，90 表示九折。
///
/// 金额为负、折扣超出范围或乘法溢出时返回 `None`。
pub fn apply_discount(total_cents: i64, percent: i64) -> Option<i64> {
    if total_cents < 0 || !(1..=100).contains(&percent) {
        return None;
    }
    // 先乘后除，避免先除导致的精度损失：19950 * 90 / 100 = 17955
    Some(total_cents.checked_mul(percent)? / 100)
}

/// 把“分”格式化为“元”的字符串，支持负数（退款）。
///
/// ```
/// use common::money::format_yuan;
/// assert_eq!(format_yuan(19_950), "199.50");
/// assert_eq!(format_yuan(5), "0.05");
/// assert_eq!(format_yuan(-1_050), "-10.50");
/// ```
pub fn format_yuan(cents: i64) -> String {
    let sign = if cents < 0 { "-" } else { "" };
    // unsigned_abs 返回 u64，避免 i64::MIN.abs() 溢出
    let abs = cents.unsigned_abs();
    let per_yuan = CENTS_PER_YUAN.unsigned_abs();
    format!("{sign}{}.{:02}", abs / per_yuan, abs % per_yuan)
}

/// 把用户输入的“元”字符串解析为“分”，最多两位小数。
///
/// 接受 `"199"`、`"199.5"`、`"199.50"`；拒绝负数、三位小数和非数字。
/// 不使用浮点数解析，避免精度问题。
pub fn parse_yuan(input: &str) -> Option<i64> {
    let s = input.trim();
    let (yuan_part, cent_part) = match s.split_once('.') {
        Some((y, c)) => (y, c),
        None => (s, ""),
    };
    if yuan_part.is_empty() || cent_part.len() > 2 {
        return None;
    }
    if !yuan_part.chars().all(|c| c.is_ascii_digit())
        || !cent_part.chars().all(|c| c.is_ascii_digit())
    {
        return None;
    }
    let yuan: i64 = yuan_part.parse().ok()?;
    // "5" 表示 50 分，"05" 表示 5 分，空表示 0 分
    let cents: i64 = match cent_part.len() {
        0 => 0,
        1 => cent_part.parse::<i64>().ok()? * 10,
        _ => cent_part.parse().ok()?,
    };
    yuan.checked_mul(CENTS_PER_YUAN)?.checked_add(cents)
}

代码要点：

checked\_mul(qty)? ：? 作用在 Option 上时，值为 None 就立即让整个函数返回 None ，为Some(x) 就取出 x 继续。这是第 4 章的重点，这里先体会它的简洁。

(1..=100).contains(&amp;percent) ：范围也是一个值，可以调用 contains 判断是否在范围内，比 percent &gt;= 1 &amp;&amp; percent &lt;= 100 更易读，clippy 也推荐这种写法。

unsigned\_abs() ：i64::MIN 的绝对值超出 i64 范围，abs() 会溢出，unsigned\_abs()返回 u64 则永远安全——处理边界值的细节决定了代码的健壮性。

parse\_yuan 刻意没有用 "199.5".parse::&lt;f64&gt;()，原因见 1.3.3 节。当前语法允许小数点后为空，即 "199." 也按 199 元处理；这与“最多两位小数”的约定一致。它只负责解析，订单金额上限由 line\_total 等业务规则另行检查。

#\[cfg(test)\] mod tests ：只在运行 cargo test 时才编译的测试模块；use super::\*;导入上层模块的所有内容；#\[test\] 标记测试函数；assert\_eq!(实际, 期望)不相等时测试失败并显示两边的值。第 17 章完整讲解测试。

//! 分页参数换算。
//!
//! 前端传入“第几页、每页几条”，数据库需要 `LIMIT`（取几条）和 `OFFSET`（跳过几条）。
/// 默认每页条数。
pub const DEFAULT_PAGE_SIZE: u32 = 20;
/// 每页最大条数，防止客户端一次请求过多数据拖垮数据库。
pub const MAX_PAGE_SIZE: u32 = 100;

/// 把可选的页码和每页条数规范化为合法值。
///
/// - 页码缺省或小于 1 时视为 1
/// - 每页条数缺省时为 [`DEFAULT_PAGE_SIZE`]，并限制在 1〜[`MAX_PAGE_SIZE`] 之间
pub fn normalize(page: Option<u32>, page_size: Option<u32>) -> (u32, u32) {
    let page = page.unwrap_or(1).max(1);
    let size = page_size
        .unwrap_or(DEFAULT_PAGE_SIZE)
        .clamp(1, MAX_PAGE_SIZE);
    (page, size)
}

/// 计算 SQL 需要的 `(limit, offset)`，类型为 `i64` 以便直接绑定到 PostgreSQL 的 BIGINT。
///
/// ```
/// use common::pagination::limit_offset;
/// assert_eq!(limit_offset(Some(3), Some(20)), (20, 40));
/// assert_eq!(limit_offset(None, Some(1000)), (100, 0));
/// ```
pub fn limit_offset(page: Option<u32>, page_size: Option<u32>) -> (i64, i64) {
    let (page, size) = normalize(page, page_size);
    let limit = i64::from(size);

    // u32 → i64 用 from，不可能失败
    let offset = i64::from(page - 1) * limit;
    (limit, offset)
}

/// 根据总条数计算总页数。
pub fn total_pages(total_items: i64, page_size: u32) -> i64 {
    // 负数视为 0；转成无符号类型后可以使用标准库的向上取整除法 div_ceil
    let items = u64::try_from(total_items).unwrap_or(0);
    let size = u64::from(page_size.max(1));
    i64::try_from(items.div_ceil(size)).unwrap_or(i64::MAX)
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn normalize_handles_edges() {
        assert_eq!(normalize(None, None), (1, DEFAULT_PAGE_SIZE));
        assert_eq!(normalize(Some(0), Some(0)), (1, 1));
        assert_eq!(normalize(Some(5), Some(500)), (5, MAX_PAGE_SIZE));
    }

    #[test]
    fn total_pages_rounds_up() {
        assert_eq!(total_pages(0, 20), 0);
        assert_eq!(total_pages(1, 20), 1);
        assert_eq!(total_pages(40, 20), 2);
        assert_eq!(total_pages(41, 20), 3);
    }
}
````

要点：total\_pages 需要“向上取整的整数除法”（41 条、每页 20 条应为 3 页）。经典手写法是(n+size - 1) / size ，但标准库已为无符号整数提供了 div\_ceil ，clippy 也会建议使用它（manual\_div\_ceil 规则）。由于有符号整数的 div\_ceil 尚未稳定，代码先用 u64::try\_from 把总数转为无符号类型——负数转换失败时按 0 处理，最后再用 i64::try\_from 安全地转回。这也是 1.3.5 节“外部数据转换一律用 try\_from”的实际应用。

//! 文本规范化与校验。

/// 用户名最少字符数。
pub const USERNAME_MIN_CHARS: usize = 3;
/// 用户名最多字符数（按字符计，不是字节）。
pub const USERNAME_MAX_CHARS: usize = 20;

/// 规范化用户名：去除首尾空白、转为小写，并校验长度与字符。
///
/// 合法字符：字母（含中文等 Unicode 字母）、数字、下划线。
/// 不合法时返回描述原因的 `Err(String)`。
///
/// ```
/// use common::text::normalize_username;
/// assert_eq!(normalize_username("  Alice_01 "), Ok("alice_01".to_string()));
/// assert!(normalize_username("ab").is_err());
/// ```
pub fn normalize_username(input: &str) -> Result<String, String> {
    let name = input.trim().to_lowercase();
    let count = name.chars().count();
    if !(USERNAME_MIN_CHARS..=USERNAME_MAX_CHARS).contains(&count) {
        return Err(format!(
            "用户名长度需为 {USERNAME_MIN_CHARS}〜{USERNAME_MAX_CHARS} 个字符，当前为 {count} 个"
        ));
    }
    if let Some(bad) = name.chars().find(|c| !(c.is_alphanumeric() || *c == '_')) {
        return Err(format!("用户名包含不允许的字符：{bad:?}"));
    }
    Ok(name)
}

/// 按 Unicode 标量值数量截断；上限为 0 时返回空串，省略号也计入上限。
/// 这保证 UTF-8 边界，但不保证组合字形完整。用于简单的日志、列表摘要展示。
pub fn truncate_chars(s: &str, max_chars: usize) -> String {
    if max_chars == 0 {
        return String::new();
    }
    if s.chars().count() <= max_chars {
        return s.to_string();
    }
    let kept: String = s.chars().take(max_chars.saturating_sub(1)).collect();
    format!("{kept}…")
}

/// 本阶段只识别大小写固定的 `Bearer ` 前缀，返回非空令牌。
/// 这是教学用字符串处理函数，不是完整的 HTTP 认证解析与令牌验证。
pub fn bearer_token(header_value: &str) -> Option<&str> {
    header_value
        .strip_prefix("Bearer ")
        .map(str::trim)
        .filter(|t| !t.is_empty())
}

#[cfg(test)]
mod tests {
    use super::*;

        assert!(normalize_username("a b c").is_err());
        assert!(normalize_username(&"a".repeat(21)).is_err());
    }

    #[test]
    fn truncate_keeps_char_boundaries() {
        assert_eq!(truncate_chars("机械键盘青轴", 4), "机械键…");
        assert_eq!(truncate_chars("短", 4), "短");
        assert_eq!(truncate_chars("长文本", 0), "");
        assert_eq!(truncate_chars("长文本", 1), "…");
    }

    #[test]
    fn bearer_token_parsing() {
        assert_eq!(bearer_token("Bearer abc.def"), Some("abc.def"));

### 1.6.12 本章小结

Rust 变量默认不可变，mut 显式声明可变；const 是编译期常量；隐藏可以在转换数据时复用变量名。

后端数值选型：ID 用 i64 、金额用“分”为单位的 i64 、数量用 i32 、长度下标用 usize ；溢出敏感的计算使用 checked\_\* ；外部输入的类型转换使用 try\_from / parse 。

字符串：拥有用 String ，借用用 &amp;str ；len() 是字节数，字符数用 chars().count() ；不能用整数下标访问字符。

集合：列表用 Vec ，参数用切片 &amp;\[T\] ；键值对用 HashMap ，需要有序用 BTreeMap ；去重用 HashSet 。

Rust 是表达式导向的语言：代码块、if 、match 、loop 都有值；函数最后一个不带分号的表达式就是返回值；用卫语句和 let-else 提前返回。

RustMall 建立了 workspace 和 common 库，有了金额、分页、文本三个经过测试的工具模块。

下一章讲 Rust 最核心、也最独特的概念：所有权、借用与生命周期。理解它之后，你会明白本章中 forp in &amp;prices 和 for p in prices 的区别、为什么函数参数要写 &amp;str 、以及为什么 Rust 不需要垃圾回收也能保证内存安全。
