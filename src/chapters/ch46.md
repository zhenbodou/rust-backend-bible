# 第 46 章 SRE、备份恢复、对账与长期维护

第45章把“超时没有告诉我们提交结果”写成协议问题。本章继续追问：如果不是回复丢失，而是订单库被还原到昨天，付款收据仍留在今天，原来成立的前提还剩多少？

一个能启动的数据库不一定保存着需要的业务事实。一个能回答200的网关，也不一定能让积压订单继续完成。我们先定义服务要恢复什么，再沿同一个RustMall建立排查、停写、六库逻辑备份、离线恢复、对账与恢复原部署的实际路径。所有新增工具都保留现有业务身份与服务边界。

## 46.1 从用户承诺定义可靠性

### 46.1.1 【入门】SLI、SLO与SLA各回答什么

SLI是可测量的服务表现，例如一段时间内有效下单请求获得受理结果的比例。SLO是为这项表现设定的目标与窗口。SLA则通常涉及服务双方约定的责任，不能把团队内部目标直接写成对外合同承诺。

本项目一次POST返回202只表示订单已受理，不表示库存确认与付款已经结束。因此至少要分别观察受理体验与订单后续完成情况。只看网关200或202比例，会漏掉一直停在charging的订单。

### 46.1.2 【进阶】先写分子、分母与排除规则

| 指标候选 | 分子 | 分母 | 容易遗漏的边界 |
| --- | --- | --- | --- |
| 下单受理成功率 | 按约定返回可解释受理结果的有效请求 | 全部有效下单尝试 | 不应通过排除所有超时提高数字 |
| 受理延迟 | 规定时间内完成受理的有效尝试 | 全部有效尝试 | 重试是否按尝试还是业务身份计数 |
| 订单推进及时率 | 到期前进入可解释终态的受理订单 | 已到观察截止时间的受理订单 | 不能把刚受理订单当超时，也不能漏掉未结束订单 |
| 商品投影新鲜度 | 约定时间内反映权威版本的商品变化 | 受观察的权威变化 | 无更新时不能用更新时间老推断消费坏了 |

“可解释终态”需要业务定义。付款被正常拒绝可以是已完成处理的一种结果，不能为了提高成交率把它改成系统成功付款；系统错误也不能伪装成用户拒付。重放同一订单身份是一次业务操作的多个尝试，应同时保留尝试指标与订单指标的解释。

### 46.1.3 【精通】目标只是设计输入，不能冒充观测结果

例如团队提议28天窗口内99.9%的有效受理尝试成功，这只是讨论用目标。本章没有运行28天生产观测，也没有给项目新增一条经过业务批准的SLA。

错误预算把允许的失败比例变成变更与处置依据；请求比率和时间比率的分母不同，应先固定再计算。[Google SRE：Implementing SLOs](https://sre.google/workbook/implementing-slos/)

## 46.2 错误预算与告警

### 46.2.1 【入门】把百分比变成可以比较的数量

若某窗口中有1000000次有效尝试，目标为99.9%，预算是1000次失败。已经有400次失败，则消耗40%。这些数字只适用于该请求定义、窗口与当前流量，不表示允许任意一次持续很久的停机。

假设一个观察窗口内错误率是1%，允许错误率为0.1%，燃烧速率就是10。它表示相对于这项预算的消耗速度；不是CPU负载，也不是每秒失败次数。

### 46.2.2 【进阶】短窗口与长窗口分别防什么

短窗口能较快看见突然故障，却容易被低流量波动放大；长窗口能抑制短暂噪声，却可能迟迟无法发现严重问题。双窗口要求持续条件与近期条件一起满足，帮助减少已经恢复却持续告警等情况。[Google SRE：Alerting on SLOs](https://sre.google/workbook/alerting-on-slos/)

当前项目已有worker缺失、订单最老等待、采样过期与manual告警。它们用于定位运行风险，不等于本节四项用户SLI都已经部署。尤其是metrics端点可抓取时，业务数据库采样仍可能过期；不能把旧的积压零值当作最新健康事实。

### 46.2.3 【精通】每一条告警对应一个有界动作

| 信号 | 先确认 | 首个动作 |
| --- | --- | --- |
| worker抓取失败 | 是计划停写还是意外退出 | 查部署事件与进程，不批量改订单 |
| 最老订单等待过久 | 采样是否新鲜、哪些步骤积压 | 查询本章只读诊断SQL |
| manual数量增加 | 是否有绑定冲突或未知状态 | 指定负责人并收集参与者事实 |
| 投影停止推进 | 是否有新权威事件、位点是否越界 | 保留错误与原消费身份，避免跳过消息 |
| TLS入口不可达 | 证书、代理、上游分别是否可用 | 沿第44章探针逐层缩小范围 |

一个告警若只有“重启试试”，会让证据不断消失。动作应明确需要保留什么、何时升级、谁决定停止新写入，以及恢复后检查什么。

## 46.3 从订单积压开始排查

### 46.3.1 【入门】按责任步骤划分调查方向

reserving对应库存预留，charging对应付款，confirming对应库存确认，refunding与releasing对应补偿。步骤只是调查入口；例如charging可能已经付款，只是回复未到，不能因此直接重新创建付款身份。

attempts体现协调尝试，不等于扣款次数。next_attempt表示下一次允许调度时间，leased_until与token表示当前领取关系，last_error是经过约束的错误类别。四者应与转换审计一起阅读。

### 46.3.2 【进阶】只读诊断也需要一致性与预算

下面三个脚本分别在自己数据库内使用只读、可重复读事务，并限定语句时间。它们提供各自库中的观察快照，不构成跨库原子观察。返回最近50条只是定位样本，不能用它证明全量没有异常。

订单库：
```sql
BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ READ ONLY;
SET LOCAL statement_timeout='5s';
SELECT state,count(*) AS orders,
       min(created_at) AS earliest_created,
       max(attempts) AS highest_attempts,
       count(*) FILTER (WHERE next_attempt<=statement_timestamp()) AS due,
       count(*) FILTER (WHERE leased_until>statement_timestamp()) AS active_leases,
       count(*) FILTER (WHERE lease_token IS NOT NULL AND leased_until<=statement_timestamp()) AS expired_leases
FROM orders GROUP BY state ORDER BY state;
SELECT id,state,attempts,last_error,next_attempt,leased_until,
       extract(epoch FROM statement_timestamp()-created_at)::bigint AS age_seconds
FROM orders WHERE state NOT IN ('completed','cancelled')
ORDER BY created_at,id LIMIT 50;
SELECT order_id,from_state,to_state,reason,occurred_at
FROM order_transitions ORDER BY occurred_at DESC,id DESC LIMIT 50;
COMMIT;
```

库存与Outbox所在的Catalog库：
```sql
BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ READ ONLY;
SET LOCAL statement_timeout='5s';
SELECT state,count(*) AS receipts,min(updated_at) AS oldest_update
FROM inventory_reservations GROUP BY state ORDER BY state;
SELECT count(*) FILTER (WHERE delivered_at IS NULL) AS pending,
       min(occurred_at) FILTER (WHERE delivered_at IS NULL) AS oldest_pending,
       max(attempts) FILTER (WHERE delivered_at IS NULL) AS max_attempts
FROM product_outbox;
SELECT event_id,aggregate_id,revision,attempts,last_error,leased_until
FROM product_outbox WHERE delivered_at IS NULL
ORDER BY occurred_at,event_id LIMIT 50;
COMMIT;
```

付款库：
```sql
BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ READ ONLY;
SET LOCAL statement_timeout='5s';
SELECT state,count(*) AS receipts,sum(amount) AS receipt_amount
FROM payments GROUP BY state ORDER BY state;
SELECT kind,count(*) AS effects,sum(amount) AS effect_amount
FROM payment_effects GROUP BY kind ORDER BY kind;
SELECT p.saga_id,p.state,p.amount,
       count(e.effect_id) AS effects,
       bool_and(e.amount=p.amount) AS all_amounts_match
FROM payments p LEFT JOIN payment_effects e USING(saga_id)
GROUP BY p.saga_id,p.state,p.amount
HAVING count(e.effect_id)=0 OR NOT bool_and(e.amount=p.amount);
COMMIT;
```

### 46.3.3 【精通】不要把金额汇总当成复式账本

payments的amount汇总表示收据绑定金额；payment_effects按kind汇总表示实验效果。paid与refunded分别汇总，才能解释先付后退；refund_barrier没有真实先付款事实，不能简单把它当作退款流水相减。

本项目支付是确定性的教学参与者，没有银行渠道、结算周期和完整复式会计账簿。数据库里金额守恒的检查不能证明外部资金到账；接入真实渠道时，需要渠道查询、结算文件与退款责任的独立证据。

## 46.4 事故处理的工作顺序

### 46.4.1 【入门】先限制影响，再解释原因

先确认影响用户和时间范围，指定协调者与记录者，保留部署版本、错误类别和关键身份。若新请求持续扩大未完成责任，可以关闭受影响写入口；仍应保留查询与事故沟通路径。

关闭入口不是停止所有后台写入。worker可能继续付款，relay继续发事件，消费端继续更新投影，用户服务也可能更新会话。后面的停写实验会逐项停止这些客户端。

### 46.4.2 【进阶】把事实、判断与动作分别记录

| 记录项 | 示例内容 |
| --- | --- |
| 事实 | 某订单charging，付款库存在同UUID的paid收据 |
| 判断 | 可能为回复丢失，尚未证明协调者故障原因 |
| 动作 | 保留身份查询付款，核对绑定后允许原协议继续 |
| 结果 | 状态推进至confirming，审计记录与库存确认相符 |
| 未解决 | 是否存在其他受影响订单，是否需要整批复核 |

记录原始身份不意味着把密码、令牌与完整请求体复制进事故文档。当前诊断查询只选择必要字段；恢复导出则另行按敏感备份管理。

### 46.4.3 【精通】回滚应用不能撤销已发生的业务

旧镜像不一定认识新迁移，回滚也不会撤回已发送的Kafka事件或已生效的付款。发布前应知道应用与数据库兼容窗口，保留可运行的旧版本，并区分停止新影响、恢复处理能力和修复历史数据。

如果根因尚不清楚，可以先恢复流量或执行受控降级，但应明确剩余债务：未完成订单、待退款责任、投影缺口以及待复核名单，不能以网关重新返回200作为事故全部结束的条件。

## 46.5 RPO、RTO与恢复范围

### 46.5.1 【入门】先问允许失去多少事实

RPO关注允许丢失的数据时间范围，RTO关注恢复服务所需时间目标。它们是目标，不是定时任务的配置名称。每小时备份一次，在备份失败、文件损坏或保留缺口时，并不能自动得到一小时RPO。

恢复所需时间包括发现、决策、准备资源、取得备份与密钥、导入、配置权限、对账、恢复处理和验证用户体验。下面工具记录的导入秒数只覆盖其中一段。

### 46.5.2 【进阶】列出本项目需要保留的不同事实

| 对象 | 丢失后的风险 | 恢复后检查 |
| --- | --- | --- |
| users与sessions | 身份归属断裂，已撤销令牌可能复活 | 用户ID、撤销事实、签名密钥策略 |
| orders与transitions | 受理身份和未完成责任丢失 | 请求键、步骤、审计、租约 |
| inventory_reservations与products | 旧命令重放、库存失真 | 绑定、收据、可售与预留事实 |
| payments与effects | 原付款结果与屏障丢失 | 一次效果、金额、外部渠道事实 |
| Outbox | 已提交但未传播的变化丢失 | 事件ID、版本、投递责任 |
| Inbox、投影与消费位点 | 跳过旧消息或重复处理 | 逻辑身份、保留范围、位点与版本 |
| 角色、权限与密钥 | 服务启动失败或越权 | 最小权限、凭据来源与轮换 |

Redis中的缓存和会话派生状态不能代替PostgreSQL撤销权威。Kafka副本也不代替全部业务数据库备份；同一故障域上的多份数据仍可能一起丢失。

### 46.5.3 【精通】恢复旧会话库是独立风险

如果sessions被还原到注销以前，即使Redis被清空，持久撤销事实也已经丢失。第42章“Redis丢失不复活已撤销会话”的结论以前提数据库保留撤销为基础；不能把它扩大到数据库任意回退。

实际事故要根据恢复时间切面决定是否集中失效旧会话，必要时轮换签名密钥并重新登录。46.7至46.12的离线恢复阶段不切换应用，也不演示无感会话回退；不把原部署中的旧令牌继续有效冒称为恢复库里的撤销保护已得到验证。

## 46.6 逻辑备份、物理备份与PITR

### 46.6.1 【入门】pg_dump的一致性对象是一座数据库

pg_dump可以在并发使用下获得单库一致备份，但一次调用只覆盖一座数据库；角色等全局对象不包含在普通单库逻辑备份里。先后导出六库，不会自动产生同一个跨库业务切面。[PostgreSQL17：pg_dump](https://www.postgresql.org/docs/17/app-pgdump.html)

第41章已经验证订单单库恢复。本章采用明确的停写实验，再备份Catalog、Users、Payments、Orders、Projection与Rebuild六库，避免把单库成功当作整个项目已恢复。

### 46.6.2 【进阶】恢复到时间点需要另一条证据链

PITR依赖基础备份和连续WAL归档，不能把pg_dump文件与WAL直接拼成物理恢复。本项目这次新增的是逻辑备份演练；没有因此建立完整归档链或多机灾难切换。[PostgreSQL17：Continuous Archiving and PITR](https://www.postgresql.org/docs/17/continuous-archiving.html)

设计PITR还要处理归档失败监测、保留链、恢复目标、时间线、磁盘空间与定期独立恢复。六库若属于同一物理集群，可以在相同集群恢复切面中恢复数据库事实；Redis、Kafka和外部付款仍有自己的恢复边界。

### 46.6.3 【精通】校验和不是可信来源证明

SHA256可以帮助发现文件改变；若文件和预期哈希同时被替换，就不能证明来自可信备份。预期清单哈希应来自受保护的独立记录，备份访问与密钥也要分别控制。

恢复归档会执行其中的数据库定义与代码，因此只接受自己控制且来源可信的备份。不要把下载来的归档直接交给管理员恢复。[PostgreSQL17：pg_restore](https://www.postgresql.org/docs/17/app-pgrestore.html)

## 46.7 停写六库恢复实验的协议

### 46.7.1 【入门】停止的是全部数据库客户端

自动实验先创建独立Compose项目，完成真实注册、下单、付款、库存、投影和权限检查，再停止十个应用角色；若启用TLS，也停止入口代理。数据库、Kafka与Redis暂时保留。

停止worker以后仍可能存在已提交但未观察到的结果，所以不能只靠“进程停止”判定业务干净。实验会分别检查源库对账与恢复库对账，并明确要求这个基线中的订单已完成、投影已收敛。

### 46.7.2 【进阶】停写检查的能力边界

备份前后检查六库没有其他客户端，并比较全量公共表指纹与序列状态。单库导出本身的一致性由pg_dump提供；跨库没有业务变化这一前提来自实验中已停止的全部客户端与隔离网络。

客户端计数检查不会阻止另一个管理员稍后连接，也不能识别一次改后又改回的所有历史。--ack-quiesced-lab表示操作者接受并建立了停写前提，不是自动产生了写入栅栏。生产环境需要正式维护窗口和访问控制，不能把这个实验工具直接当成通用在线一致备份产品。

### 46.7.3 【精通】备份集合的完成标志

工具只创建全新目录，权限0700，单个归档0600；六个导出完成、前后指纹一致以后，才写manifest.json。中途失败可能留下部分归档，但没有成功清单，不能按完整集合使用。

清单记录六个文件名、大小与SHA256、表数据摘要、序列状态、未验证约束数和集合身份。密码哈希与会话记录仍在归档里面，目录权限不能代替加密与异地存储；本书源码包不得包含这些实验归档。

## 46.8 恢复前先完成所有检查

### 46.8.1 【入门】使用独立验证库名称

工具要求目标前缀为rustmall_restore_加限定字符，六个目标名分别追加逻辑库名。所有清单、文件哈希、归档目录和已有目标检查都发生在首次创建数据库以前。

恢复不使用--clean、不删除已有库，也不会把应用连接地址改成新目标。每库使用单事务导入；六库整体不是一个PostgreSQL事务，所以某库失败时，已创建的验证库保留用于诊断，不宣称整体回滚。

### 46.8.2 【进阶】比较的不只是订单数量

恢复后逐表比较行数与排序后的完整JSONB行摘要，包含_sqlx_migrations；逐序列比较last_value与is_called；比较公共schema中未验证约束数。这样同数量但金额改变、迁移账本不同、会话撤销丢失等情况，不会因汇总数量相同而混过去。

当前实现为可读实验限制每表100000行，使用内存处理排序文本；超出上限立即失败。大规模生产恢复需要流式摘要和独立资源预算，不能把小数据集耗时线性放大成容量承诺。

### 46.8.3 【精通】恢复权限仍需独立处理

默认离线实验的导出与导入都使用no-owner/no-acl，验证库由管理员拥有。它证明数据集合可恢复并匹配，未证明九个应用账户已能按原权限连接恢复库。

正式切换还需创建正确角色和数据库归属、恢复授权、提供秘密、运行权限拒绝测试与业务验收。第40章的权限脚本按原库名编写，不能对新前缀盲目执行后假装已经切换完成。

## 46.9 完整恢复与对账工具

### 46.9.1 【进阶】公共执行层与私密输出边界

工具通过Docker容器内psql、pg_dump、pg_restore执行，适用于本机实验的受信管理员。错误只暴露命令类别和退出状态，不把可能包含数据库行值的原始响应直接打印到共享报告。

完整实现如下。注意它没有修改订单、库存或付款的恢复策略；唯一的创建动作是全新的验证数据库。
```python
"""Read-only reconciliation and quiesced six-database logical recovery lab.

Trusted local admin only. Archives can contain executable SQL and private user data.
No live cross-database snapshot, role/ACL restoration, Kafka rewind, or cutover.
"""
import argparse
import hashlib
import json
import os
from pathlib import Path
import re
import subprocess
import sys
import time
import uuid

DATABASES = ('catalog', 'users', 'payments', 'orders', 'projection', 'rebuild')
LIMIT = 100000


def execute(container, command, input=None):
    r = subprocess.run(['docker', 'exec', '-i', container, *command], input=input,
                       stdout=subprocess.PIPE, stderr=subprocess.PIPE, timeout=900)
    if r.returncode:
        raise RuntimeError(f'{command[0]} failed (exit {r.returncode}); private database response suppressed')
    return r.stdout


def sql(container, database, query):
    if not re.fullmatch(r'rustmall_(?:[a-z0-9_]{1,60})', database):
        raise ValueError('invalid database name')
    return execute(container, ['psql', '-X', '-qAt', '-v', 'ON_ERROR_STOP=1', '-U',
                              'postgres', '-d', database],
                   ("SET timezone='UTC'; SET statement_timeout='30s';\n" + query).encode()).decode().strip()


def records(container, database, query):
    return [json.loads(x) for x in sql(container, database,
            'SELECT row_to_json(r) FROM (' + query + ') r;').splitlines()]


def fingerprint(container, database):
    tables = sql(container, database, "SELECT tablename FROM pg_tables WHERE schemaname='public' ORDER BY 1;").splitlines()
    result = {'tables': {}, 'sequences': {}}
    for name in tables:
        if not re.fullmatch(r'[a-z_][a-z0-9_]*', name):
            raise ValueError('unsupported table identifier')
        count = int(sql(container, database, f'SELECT count(*) FROM public.{name};'))
        if count > LIMIT:
            raise ValueError('lab table exceeds bounded fingerprint limit; use a streaming production verifier')
        # JSONB normalizes object key order. Sort complete rows, preserving duplicates.
        rows = sql(container, database, f'SELECT to_jsonb(r)::text FROM public.{name} r ORDER BY to_jsonb(r)::text;')
        result['tables'][name] = {'rows': count, 'sha256': hashlib.sha256(rows.encode()).hexdigest()}
    sequences = sql(container, database, "SELECT sequencename FROM pg_sequences WHERE schemaname='public' ORDER BY 1;").splitlines()
    for name in sequences:
        if not re.fullmatch(r'[a-z_][a-z0-9_]*', name):
            raise ValueError('unsupported sequence identifier')
        result['sequences'][name] = sql(container, database, f'SELECT last_value,is_called FROM public.{name};')
    result['invalid_constraints'] = int(sql(container, database,
        "SELECT count(*) FROM pg_constraint WHERE connamespace='public'::regnamespace AND NOT convalidated;"))
    return result


def snapshot(container, databases):
    if set(databases) != set(DATABASES):
        raise ValueError('all six logical database names required')
    return {name: fingerprint(container, databases[name]) for name in DATABASES}


def quiet(container):
    names = ','.join("'rustmall_" + name + "'" for name in DATABASES)
    count = int(sql(container, 'rustmall_orders',
        f"SELECT count(*) FROM pg_stat_activity WHERE datname IN ({names}) AND backend_type='client backend' AND pid<>pg_backend_pid();"))
    if count:
        raise ValueError('other database clients remain; stop ALL lab roles and migrations before backup')


def file_hash(path):
    with path.open('rb') as stream:
        return hashlib.file_digest(stream, 'sha256').hexdigest()


def backup(container, directory):
    # Operator must first stop every writer, reader and migration; this check is
    # evidence of present clients, not a fence against future privileged clients.
    quiet(container)
    directory.mkdir(mode=0o700)  # New bundle only, never overwrite.
    started = time.monotonic()
    databases = {name: 'rustmall_' + name for name in DATABASES}
    before = snapshot(container, databases)
    archives = {}
    for name, database in databases.items():
        path = directory / (name + '.dump')
        with path.open('xb') as output:
            os.chmod(path, 0o600)
            r = subprocess.run(['docker', 'exec', '-i', container, 'pg_dump', '-U', 'postgres',
                '--format=custom', '--no-owner', '--no-acl', '--dbname', database],
                stdout=output, stderr=subprocess.PIPE, timeout=900)
            if r.returncode:
                raise RuntimeError('pg_dump failed; incomplete bundle retained without manifest')
            output.flush()
            os.fsync(output.fileno())
        archives[name] = {'file': path.name, 'sha256': file_hash(path), 'bytes': path.stat().st_size}
    quiet(container)
    after = snapshot(container, databases)
    if before != after:
        raise ValueError('database contents changed during backup; bundle has NO success manifest')
    manifest = {'format': 1, 'set_id': uuid.uuid4().hex, 'archives': archives,
                'fingerprints': before, 'elapsed_seconds': round(time.monotonic() - started, 3),
                'scope': 'operator-quiesced local six DB logical set; no future-writer fence, roles, ACL, Kafka, external payment or cutover'}
    path = directory / 'manifest.json'
    path.write_text(json.dumps(manifest, indent=2) + '\n')
    os.chmod(path, 0o600)
    return {'manifest_sha256': file_hash(path), 'databases': 6, 'seconds': manifest['elapsed_seconds']}


def restore(container, directory, expected_sha256, prefix, bootstrap_owners=False):
    if not re.fullmatch(r'rustmall_restore_[a-z0-9]{1,20}', prefix):
        raise ValueError('new verification prefix must be rustmall_restore_*')
    path = directory / 'manifest.json'
    if path.is_symlink() or not re.fullmatch('[0-9a-f]{64}', expected_sha256) or file_hash(path) != expected_sha256:
        raise ValueError('manifest checksum mismatch')
    manifest = json.loads(path.read_text())
    if manifest['format'] != 1 or set(manifest['archives']) != set(DATABASES) or set(manifest['fingerprints']) != set(DATABASES):
        raise ValueError('invalid six-database manifest')
    targets = {name: prefix + '_' + name for name in DATABASES}
    for name in DATABASES:
        entry = manifest['archives'][name]
        if entry['file'] != name + '.dump':
            raise ValueError('archive must use fixed local basename')
        archive = directory / entry['file']
        if archive.is_symlink() or file_hash(archive) != entry['sha256'] or archive.stat().st_size != entry['bytes']:
            raise ValueError('archive integrity mismatch')
        with archive.open('rb') as header:
            if header.read(5) != b'PGDMP':
                raise ValueError('custom archive required')
        with archive.open('rb') as stream:
            # Do not buffer a header read before passing this descriptor to Docker.
            r = subprocess.run(['docker', 'exec', '-i', container, 'pg_restore', '--list'],
                stdin=stream, stdout=subprocess.DEVNULL, stderr=subprocess.PIPE, timeout=90)
            if r.returncode:
                raise ValueError('invalid archive index')
        exists = sql(container, 'rustmall_orders', "SELECT count(*) FROM pg_database WHERE datname='" + targets[name] + "';")
        if exists != '0':
            raise ValueError('verification target already exists; no databases were created')
    if bootstrap_owners:
        for name in DATABASES:
            exists = sql(container, 'rustmall_orders', "SELECT count(*) FROM pg_roles WHERE rolname='migrate_" + name + "' AND NOT rolsuper AND NOT rolcreatedb AND NOT rolcreaterole;")
            if exists != '1':
                raise ValueError('expected restricted bootstrap owner missing')
    # All integrity and target checks precede the first mutation. A concurrent
    # creator still causes createdb to fail; never reuse, DROP or --clean a target.
    started = time.monotonic()
    for name in DATABASES:
        target = targets[name]
        owner_args = ['--owner', 'migrate_' + name] if bootstrap_owners else []
        execute(container, ['createdb', '-U', 'postgres', '--template=template0', *owner_args, target])
        with (directory / (name + '.dump')).open('rb') as stream:
            r = subprocess.run(['docker', 'exec', '-i', container, 'pg_restore', '-U', 'postgres',
                '--exit-on-error', '--single-transaction', '--no-owner', '--no-acl',
                *(['--role=migrate_' + name] if bootstrap_owners else []), '--dbname', target],
                stdin=stream, stdout=subprocess.DEVNULL, stderr=subprocess.PIPE, timeout=900)
            if r.returncode:
                raise RuntimeError('restore failed; created verification targets retained for diagnosis')
    actual = snapshot(container, targets)
    if actual != manifest['fingerprints']:
        raise ValueError('restored table/sequence/constraint fingerprints differ; no recovery success')
    return {'databases': targets, 'verified_tables': sum(len(x['tables']) for x in actual.values()),
            'verified_sequences': sum(len(x['sequences']) for x in actual.values()),
            'seconds': round(time.monotonic() - started, 3), 'matches': True,
            'scope': 'new offline verification DBs only; privileges and application cutover not restored'}


def collect(container, databases):
    def rows(name, query):
        return records(container, databases[name], query)
    # Exports intentionally exclude usernames, password hashes, tokens and sessions.
    return {
        'orders': rows('orders', 'SELECT id,actor_id,product_id,quantity,unit_price,amount,state FROM orders'),
        'payments': rows('payments', 'SELECT saga_id,actor_id,amount,state FROM payments'),
        'effects': rows('payments', 'SELECT saga_id,kind,amount FROM payment_effects'),
        'inventory': rows('catalog', 'SELECT saga_id,product_id,quantity,unit_price_cents,state FROM inventory_reservations'),
        'users': rows('users', 'SELECT id FROM users'),
        'products': rows('catalog', 'SELECT id,revision,name,price_cents,stock,(delisted_at IS NULL) AS listed FROM products'),
        'projection': rows('projection', 'SELECT product_id,revision,payload FROM catalog_view'),
        'rebuild': rows('rebuild', 'SELECT product_id,revision,payload FROM catalog_view'),
    }


def reconcile(data):
    """Classify a quiesced cut. Never issues repair commands or rewrites states."""
    findings = []
    def add(code, identity):
        findings.append({'code': code, 'identity': str(identity)})
    orders = {x['id']: x for x in data['orders']}
    payments = {x['saga_id']: x for x in data['payments']}
    inventory = {x['saga_id']: x for x in data['inventory']}
    users = {x['id'] for x in data['users']}
    effects = {}
    for effect in data['effects']:
        effects.setdefault(effect['saga_id'], []).append(effect)
    for identity in sorted(set(payments) | set(inventory)):
        if identity not in orders:
            add('orphan_participant_receipt', identity)
    for identity, order in sorted(orders.items()):
        payment, reservation = payments.get(identity), inventory.get(identity)
        if order['actor_id'] not in users:
            add('order_actor_missing', identity)
        if payment and (payment['actor_id'], payment['amount']) != (order['actor_id'], order['amount']):
            add('payment_binding_mismatch', identity)
        if reservation and (reservation['product_id'], reservation['quantity'], reservation['unit_price_cents']) != (order['product_id'], order['quantity'], order['unit_price']):
            add('inventory_binding_mismatch', identity)
        pstate = payment['state'] if payment else None
        istate = reservation['state'] if reservation else None
        if order['state'] == 'completed':
            if pstate != 'paid' or istate != 'confirmed':
                add('completed_participants_mismatch', identity)
        elif order['state'] == 'cancelled':
            if pstate == 'paid' or istate in ('held', 'confirmed', 'pending'):
                add('cancelled_retains_effect', identity)
        else:
            # Some intermediate cuts are legitimate. Classify for review/resume,
            # not as corruption or proof that an automatic repair is safe.
            add('manual_requires_owner' if order['state'] == 'manual' else 'pending_requires_resume', identity)
    for identity, payment in sorted(payments.items()):
        entries = effects.get(identity, [])
        kinds = [x['kind'] for x in entries]
        if any(x['amount'] != payment['amount'] for x in entries):
            add('effect_amount_mismatch', identity)
        expected = {'paid': {'paid'}, 'declined': {'declined'}}.get(payment['state'])
        if payment['state'] == 'refunded':
            valid = set(kinds) in ({'paid', 'refunded'}, {'refund_barrier'})
        else:
            valid = set(kinds) == expected
        if not valid or len(kinds) != len(set(kinds)):
            add('payment_effects_mismatch', identity)
    for identity in sorted(set(effects) - set(payments)):
        add('orphan_effect', identity)
    products = {x['id']: x for x in data['products']}
    for name in ('projection', 'rebuild'):
        view = {x['product_id']: x for x in data[name]}
        for identity in sorted(set(products) | set(view)):
            product, row = products.get(identity), view.get(identity)
            if not product or not row or row['revision'] != product['revision'] or row['payload'] != {k: product[k] for k in ('id','name','price_cents','stock','listed')}:
                add(name + '_not_converged', identity)
    return {'clean': not findings, 'findings': findings, 'orders': len(orders),
            'scope': 'read-only quiesced lab classification; pending is review, not corruption; no repair or live consistent snapshot'}


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument('operation', choices=['backup', 'restore', 'audit'])
    parser.add_argument('--container', required=True)
    parser.add_argument('--directory', type=Path)
    parser.add_argument('--expected-manifest-sha256')
    parser.add_argument('--prefix')
    parser.add_argument('--ack-quiesced-lab', action='store_true')
    args = parser.parse_args()
    if not re.fullmatch(r'[A-Za-z0-9][A-Za-z0-9_.-]{0,127}', args.container):
        parser.error('invalid container identity')
    if args.operation == 'backup':
        if not args.ack_quiesced_lab or not args.directory or args.prefix or args.expected_manifest_sha256:
            parser.error('backup needs NEW directory and --ack-quiesced-lab after stopping ALL roles')
        report = backup(args.container, args.directory)
    elif args.operation == 'restore':
        if not args.directory or not args.prefix or not args.expected_manifest_sha256:
            parser.error('restore needs directory, new prefix and expected manifest SHA256')
        report = restore(args.container, args.directory, args.expected_manifest_sha256, args.prefix)
    else:
        if not args.ack_quiesced_lab or args.directory or args.expected_manifest_sha256:
            parser.error('audit needs --ack-quiesced-lab; optional restored prefix')
        if args.prefix and not re.fullmatch(r'rustmall_restore_[a-z0-9]{1,20}', args.prefix):
            parser.error('invalid verification prefix')
        if not args.prefix:
            quiet(args.container)
        databases = {x: (args.prefix or 'rustmall') + '_' + x for x in DATABASES}
        report = reconcile(collect(args.container, databases))
    print(json.dumps(report, ensure_ascii=False, indent=2))
    return 2 if report.get('clean') is False else 0


if __name__ == '__main__':
    try:
        sys.exit(main())
    except (OSError, ValueError, KeyError, RuntimeError, subprocess.TimeoutExpired) as error:
        sys.exit('Recovery lab failed: ' + type(error).__name__ + '; no success or application cutover is claimed')
```

### 46.9.2 【精通】指纹前提仍然存在

排序后的JSONB文本用于当前PostgreSQL版本与相同数据定义下的比较，不是跨任意版本的通用业务规范。时间戳统一到UTC，行排序保留重复行；序列状态另行读取，不通过调用nextval生成指纹。

对账查询排除用户名、密码哈希、会话令牌与签名秘密。它依然包含订单与参与者身份，运行报告应控制访问，不应被当作公共指标标签发布。

## 46.10 对账分类与修复责任

### 46.10.1 【入门】先区分稳定终态和处理中

completed要求付款paid且库存confirmed；cancelled不能保留paid、held、confirmed或pending库存责任。manual明确需要负责人，其他中间步骤列为pending_requires_resume。

中间步骤在付款已提交、订单尚未推进时可能完全合法，因此“需要继续处理”不是“数据库已经损坏”。工具以非干净结果提示复核，避免把所有非completed状态强行改成cancelled。

### 46.10.2 【进阶】绑定与效果分别核对

付款收据必须与订单的actor、amount对应；库存收据必须与product、quantity、冻结单价对应。同样总价但数量和单价互换，也不能被接受。

paid需要一个paid效果；refunded可以来自paid加refunded，或先退款形成的refund_barrier；declined保留declined效果。当前Payment对已经declined再Refund不会改成refunded，因此不能凭空接受declined加refund_barrier的组合。

投影比较商品版本与完整展示payload，包含下架墓碑。相同revision但stock被改成999也会被发现，不能只检查版本号。

### 46.10.3 【精通】工具没有证明库存总量守恒

每个订单收据与绑定匹配，不足以证明产品当前可售库存正确。商品初始库存、授权调整、历史预留与恢复切面共同决定数量；当前对账没有重建完整商品数量账本，也没有验证真实银行结算。

同样，干净结果并未验证Kafka位点与Inbox恢复切面的兼容性。恢复投影库到较早状态但沿用较新位点，会漏掉需要重放的消息；启动消费者之前必须另行处理第43章的保留范围与身份检查。

### 46.10.4 【精通】修复动作按已有协议推进

| 分类 | 可以先做的事 | 不能直接推断 |
| --- | --- | --- |
| pending_requires_resume | 核对绑定、收据和当前依赖，评估恢复原worker | 所有中间订单都应取消 |
| completed_participants_mismatch | 隔离异常范围，查恢复切面与外部事实 | 删除订单就能消除付款责任 |
| payment_binding_mismatch | 保留冲突证据并人工调查 | 换UUID绕开绑定即可重付 |
| orphan_participant_receipt | 查订单是否丢失、迁移映射是否缺失 | 没订单就可以删除收据 |
| projection_not_converged | 查Outbox、位点、Inbox与毒消息 | 修改revision或跳位点即可恢复 |

自动修复需要独立鉴权、幂等命令和审计。本章不新增一个能强行完成所有订单的管理员按钮，原状态机与最小权限继续约束运行行为。

```python
"""Negative histories for the read-only recovery classifier (no Docker required)."""
import copy
import unittest

def completed():
```

## 46.13 Kafka、Outbox与投影恢复

### 46.13.1 【入门】备份里有Inbox，不代表消费位点也一起回退

假设投影备份只处理到某个事件，而Kafka组位点保留后来位置。恢复旧库后若从较新位点继续，中间消息就不会重新送达。相反，位点较旧而Inbox较新时，允许的重复可以由相同事件身份与哈希验证处理，但仍需消息在保留范围内。

因此先核对低水位、已提交位点、目标恢复切面与实际消费身份。第43章遇到不可解释缺口时停止，不会自动选择latest掩盖丢失；恢复工具也不应绕开这个保护。

### 46.13.2 【进阶】区分重放旧事件和生成新事实

outbox-replay使用原event_id重发已有事实，不等于再次执行商品更新。消费者应以相同身份识别重复，并保留版本与墓碑规则。

若消息已经超出保留范围，需要依据权威数据设计新一代完整快照或重新建立读模型；不能随意清空Inbox后沿用不完整事件流。新一代逻辑身份与物理数据库应明确绑定，避免两个世代混在一张表里互相覆盖。

### 46.13.3 【精通】只有恢复切面成立才开放读写

46.7至46.12的离线恢复集合包含两个投影库，但没有备份Kafka日志与组位点，也没有启动消费者去消费这批离线副本。46.15另在保留Kafka的条件下验证新集群运行。对账比较当前商品快照，不验证历史事件完整性。

正式恢复时要说明哪些事实来自数据库备份、哪些来自仍可用Kafka、哪些需要重新导出。若只能证明某个部分，应明确保留停写或只读状态，直到全部在线责任有可执行路径。

## 46.14 依赖、秘密与长期变更

### 46.14.1 【入门】保留能复现的发布身份

保留源码版本或源码指纹、Cargo.lock、镜像身份、迁移账本、配置与验收记录。只写“最新版”无法复现上一次成功恢复；只保留镜像而丢失数据库迁移和秘密来源，也不能启动完整服务。

升级依赖前查官方发行说明、MSRV与行为变化，按影响运行相应检查。第43章消费者对位点默认行为的明确配置，就是避免库升级后把隐含默认值当成协议的一部分。

### 46.14.2 【进阶】秘密轮换也有状态迁移

JWT密钥变化影响旧令牌验证；数据库密码变化影响新建连接与现有连接池；内部服务token变化影响调用双方。一次覆盖文件不会让所有进程和数据库原子更新。

第44章只演练同一实验CA签发新叶证书并重建代理；它不是数据库密码、JWT密钥或内部token的轮换证据。每种秘密应单独设计旧值过渡、撤销时间、回退与验证，避免长期保留无限双凭据。

### 46.14.3 【精通】复盘把缺口变成下一次验收

有效复盘包含影响、触发条件、时间线、保护为何未生效、检测与恢复耗时，以及可检查的后续动作。比如“增加备份”不够具体；“每日将六库备份恢复到独立环境并验证表指纹和关键业务身份，失败告警到负责人”才有明确结果。

复盘中的新自动化仍应受资源、权限和数据生命周期约束。排障方便不是扩大生产管理员权限或长期复制所有用户数据的理由。

## 46.15 在新数据库集群上验证应用恢复

### 46.15.1 【入门】数据副本可用以后还差什么

离线恢复只是第一层证据。现在另建一个PostgreSQL容器和独立数据卷，先通过原空集群bootstrap建立六个受限迁移owner与九个运行账户，再以对应migrate角色恢复对象。

这个新集群与源集群物理数据目录分开，但仍在同一台机器的实验网络里。Kafka、Redis、JWT签名密钥和内部调用token保留。我们验证的是计划停写后的一次数据库恢复切换，不能把它称作跨地域容灾或整套基础设施损毁后的恢复。

### 46.15.2 【进阶】先验证恢复副本，再取得正式库名

restore的内部bootstrap_owners参数只用于这个受控实验：createdb指定对应owner，pg_restore使用相应受限role。数据指纹仍须匹配，不能因为要切换就跳过检查。

bootstrap已经创建六个空库。实验先确认它们没有公共表，再把空库改名保留；恢复验证库取得正式名称。没有删除源集群数据库，也没有覆盖一座已有业务数据的目标库。改名连接使用另一座稳定数据库，避免试图重命名当前连接所在的库。

随后撤销新库的PUBLIC连接权限，授予正确运行角色，并执行原最小权限脚本。对象由迁移角色拥有，应用仍没有DDL或越权改账权限。恢复管理员创建的离线验证库和可供应用运行的恢复环境是不同阶段。

### 46.15.3 【进阶】连接配置也要作为切换事实保存

复制原私有profile到新的0700目录，仅把数据库URL的主机从postgres改成postgres-recovery；原目录与凭据不覆盖。逻辑消费身份、签名密钥与内部token保持原值。

应用容器强制重建，重新加载新的文件挂载，而不是期待已经启动的连接池自动看见文件变化。保持同一Kafka与停写切面，使恢复后的Inbox与原消费进度仍来自这次已对齐的集合；这不替代Kafka也丢失时的恢复设计。

### 46.15.4 【进阶】完整切换实验实现
```python
"""Planned local DB-only cutover of the checker's OWN disposable deployment.

Source remains intact. Same Kafka, Redis, signing keys and service tokens retained;
this does not claim regional DR, broker recovery or a safe rollback after new writes.
"""
import copy
import json
from pathlib import Path
import re
import shutil
import uuid
import recovery46


def exercise_cutover(stage, compose, config, profile, work, args, run, until, api,
                     roles, report, checks, private, source, bundle, metadata,
                     actor, live_token, revoke_token, request, key, oid, pid):
    stopped = roles + (['tls'] if args.tls_dir else [])
    run(compose + ['stop', *stopped])
    spec = copy.deepcopy(config['services']['postgres'])
    for volume in spec['volumes']:
        if volume['target'] == '/var/lib/postgresql/data':
            volume['source'] = 'recovery-data'
    overlay = Path(work.name) / 'recovery-overlay.json'
    overlay.write_text(json.dumps({'services': {'postgres-recovery': spec},
                                   'volumes': {'recovery-data': {}}}))
    alternate = compose + ['-f', str(overlay)]
    # The parent uses its original compose command for cleanup even if this
    # function fails. Register extra resources with the parent before mutations.
    compose.extend(['-f', str(overlay)])
    run(alternate + ['up', '-d', '--wait', '--wait-timeout', '120', 'postgres-recovery'])
    target = run(alternate + ['ps', '-q', 'postgres-recovery']).stdout.strip()
    prefix = 'rustmall_restore_' + uuid.uuid4().hex[:12]
    restored = recovery46.restore(target, bundle, metadata['manifest_sha256'], prefix,
                                  bootstrap_owners=True)
    assert restored['matches']
    for name, verification in restored['databases'].items():
        # Bootstrap creates EMPTY databases with role credentials. Keep them under
        # other names; never DROP or replace a populated business database.
        db = 'rustmall_' + name
        assert recovery46.sql(target, db,
            "SELECT count(*) FROM pg_tables WHERE schemaname='public';") == '0'
        # PostgreSQL cannot rename the database of the active connection.
        connection = 'rustmall_catalog' if name == 'orders' else 'rustmall_orders'
        recovery46.sql(target, connection, f'ALTER DATABASE {db} RENAME TO rustmall_bootstrap_{name};')
        recovery46.sql(target, connection, f'ALTER DATABASE {verification} RENAME TO {db};')
        accounts = {'catalog': ['app_catalog','relay_catalog','inventory_admin'],
                    'orders': ['app_orders','worker_orders']}.get(name, ['app_' + name])
        recovery46.sql(target, db, f'REVOKE ALL ON DATABASE {db} FROM PUBLIC;')
        recovery46.sql(target, db, f'GRANT CONNECT ON DATABASE {db} TO ' + ','.join(accounts) + ';')
    recovery46.execute(target, ['psql','-X','-q','-v','ON_ERROR_STOP=1','-U','postgres','-d','rustmall_orders'],
                       (stage/'deploy/delivery40/permissions.sql').read_bytes())
    original = {name:'rustmall_'+name for name in recovery46.DATABASES}
    assert recovery46.reconcile(recovery46.collect(target, original))['clean']
    candidate = Path(work.name)/'recovery-profile'
    shutil.copytree(profile, candidate)
    candidate.chmod(0o700); (candidate/'secrets').chmod(0o700)
    for path in (candidate/'secrets').iterdir():
        if path.name.endswith('_url'):
            value = path.read_text()
            if '@postgres:5432/' in value:
                path.chmod(0o600)
                path.write_text(value.replace('@postgres:5432/', '@postgres-recovery:5432/'))
                path.chmod(0o444)
        value = path.read_text().strip()
        if len(value)>20:private.append(value)
    env = candidate/'compose.env'
    env.write_text(env.read_text().replace(str(profile/'secrets'), str(candidate/'secrets')))
    env.chmod(0o600)
    # Preserve logical consumer identities and JWT/internal tokens exactly. Only
    # the DB host changes. Force recreation reloads new file-mounted URLs.
    switched = list(alternate)
    switched[switched.index('--env-file')+1] = str(env)
    run(switched + ['up','-d','--no-deps','--force-recreate','--wait','--wait-timeout','180',*stopped])
    assert api('/api/v1/auth/me',token=live_token)[0] == 200
    assert api('/api/v1/auth/me',token=revoke_token)[0] == 401
    assert api('/api/v1/orders','POST',request,live_token,key)[1]['id'] == oid
    status, product = api('/api/v1/products','POST',
        {'name':'恢复环境新商品','price_cents':900,'stock':4}, live_token, uuid.uuid4())
    assert status == 201 and int(product['id']) > pid
    new_pid = int(product['id']); new_key = uuid.uuid4()
    status, order = api('/api/v1/orders','POST',{'product_id':new_pid,'quantity':1},live_token,new_key)
    assert status == 202
    new_oid = str(uuid.UUID(order['id']))
    until(lambda: recovery46.sql(target,'rustmall_orders',
        f"SELECT state FROM orders WHERE id='{new_oid}';") == 'completed', 'new DB restored Saga complete')
    assert recovery46.sql(target,'rustmall_payments',
        f"SELECT count(*) FROM payment_effects WHERE saga_id='{new_oid}' AND kind='paid';") == '1'
    assert recovery46.sql(source,'rustmall_orders',f"SELECT count(*) FROM orders WHERE id='{new_oid}';") == '0'
    assert recovery46.sql(target,'rustmall_catalog',f'SELECT stock FROM products WHERE id={new_pid};') == '3'
    assert api('/api/v1/orders','POST',{'product_id':new_pid,'quantity':1},live_token,new_key)[1]['id'] == new_oid
    def projected(db):
        return recovery46.sql(target,db,f"SELECT count(*) FROM catalog_view WHERE product_id={new_pid} AND (payload->>'stock')::int=3;") == '1'
    until(lambda: projected('rustmall_projection') and projected('rustmall_rebuild'), 'restored projections converge')
    # Use actual TCP login and password-mounted credentials for the new server.
    command='export PGPASSWORD="$(cat /run/secrets/app_users_password)"; exec psql -h 127.0.0.1 -U app_users -d rustmall_catalog -X -v ON_ERROR_STOP=1 -At'
    denied=run(switched+['exec','-T','postgres-recovery','sh','-ec',command],input='SELECT 1;\n',ok=False)
    assert denied.returncode and 'permission denied for database' in denied.stderr
    run(switched+['stop',*stopped])
    final_audit=recovery46.reconcile(recovery46.collect(target,original))
    assert final_audit['clean'],final_audit
    report['new_cluster_cutover']={'restored_tables':restored['verified_tables'],
        'source_retained':True,'new_order_only_in_target':True,'existing_revocation_preserved':True,
        'new_paid_effects':1,'new_stock':3,'final_audit':final_audit,
        'scope':'planned local PostgreSQL-only cutover; same Kafka/Redis/keys retained; no post-write rollback or regional DR proof'}
    checks.append('NEW PostgreSQL cluster restores all six DBs with restricted owners, grants and fresh URL mounts; existing session/revocation and original order identity preserved')
    checks.append('real HTTPS new product/order completes ONLY in restored cluster, paid once and stock3; same-key replay, both projections and cross-DB access denial pass; final quiesced audit clean')
    return switched
```

接着通过真实HTTPS创建新商品和新订单，商品ID大于已有ID；新订单在恢复集群完成，paid效果一次、stock从4变3，相同请求键重放不产生新订单。源订单库查不到这笔新订单，两个恢复投影都推进到stock3，恢复集群上的app_users仍不能连接Catalog库。最后停止客户端，对账同时包含原订单与新订单且干净。

源集群被保留，便于取证和比较；但新订单已经只存在于目标集群。此时直接把URL改回源集群会丢失已受理业务，不是安全回退。

## 46.16 把恢复验收接入交付检查

### 46.16.1 【入门】自动化必须验证当前流程

原CI镜像检查脚本曾固定要求passed等于7，后续累积工程增加真实Redis故障组以后，早期数字已经不适用。本章把CI镜像检查接入recovery-cutover路径，并明确校验新集群业务和最终对账证据。

当前无TLS的CI路径有15组；本章带TLS的路径有19组。它们的差异来自实际启用的检查，不应把一份报告的数字复制到另一份报告里。未来增加检查时要同步评审验证条件，不能为了通过把预期数量任意降低。

### 46.16.2 【进阶】同一受测镜像继续进入发布

### 46.16.3 【精通】本地通过不等于远端已经发布

本章实际运行本机Docker部署与恢复，检查CI脚本语法和对应报告条件。没有触发远端GitHub Actions、推送注册表或执行Argo发布。CI配置是可评审的交付路径，远端成功需要其自己的运行记录。

Rust/Cargo文件与第45章逐项字节相同，所以393项Rust结果作为上一章证据保留，本章没有把它们虚报成再次执行。新增Python测试、SQL运行和镜像实际部署则分别记录本次结果，避免把不同层次的证据合成一个模糊的“全部通过”。

## 46.17 分层练习与参考答案

### 46.17.1 【入门】202为什么不是付款成功率

问题：下单接口一直返回202，能说明用户订单都正常完成吗？

答案：不能。202只代表持久受理；worker可能停在charging。需要另按受理订单的观察截止时间衡量推进与终态。

### 46.17.2 【进阶】六个成功pg_dump为什么仍可能不一致

问题：每个文件都能恢复，为什么跨库事实仍可能错位？

答案：每次导出的单库快照不自动共享业务切面；期间参与者可能已经付款或释放库存。当前实验先停全部客户端，再检查前后数据，不提供通用在线跨库栅栏。

### 46.17.3 【进阶】恢复干净以后能否立即切URL

问题：表和序列匹配、对账干净以后，能否把应用URL改到验证库？

答案：还需恢复角色归属与最小权限、秘密、消息消费切面，并验证真实业务与回退。当前验证库使用管理员离线恢复，不代表应用权限已就绪。

### 46.17.4 【精通】为何退款屏障不能计为退款金额

问题：refunded状态配一个refund_barrier，为何不能当作先付款后退款？

答案：它可以表示退款先到而从未产生paid效果，负责阻挡迟到付款。效果类型与历史一起解释，不能只根据状态名计算资金流水。

### 46.17.5 【精通】区分三种成功

问题：恢复工具退出0，原应用重新ready，是否已经证明灾难恢复成功？

答案：前者证明当前工具覆盖的数据恢复与比较，后者证明原部署恢复运行。还需要新环境的权限、业务、消息切面与切换证据，才能对相应恢复范围作完整声明。
