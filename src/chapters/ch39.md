# 第 39 章 超时、速率限制、重试与熔断恢复

第38章已经让我们看见一笔请求的HTTP/gRPC路径、独立订单尝试和消息传播。现在继续追问：当支付暂时不可用时，系统会不会不断叠加调用？当网关已经等不下去时，下游还允许等待多久？恢复服务以后，原订单能否继续，而不是重新扣一次库存或付款？

本章继续同一工程，增加governance共享包，将逐跳预算、令牌桶、支付依赖熔断和有界扰动接入真实请求与持久worker。原会话撤销、库存事务、支付收据、请求幂等、订单租约、Outbox/Inbox和第38章观测全部保留。

学完后，应能画出真实调用预算，区分并发名额与每秒速率，推演熔断探测被取消后的状态，解释旧响应为什么不能关闭新一代熔断，并用业务收据核对支付恢复、最后一件争抢与强制重启的结果。

## 39.1 先区分不同种类的限制

### 39.1.1 【入门】一个timeout保护不了整个服务

请求大小限制保护接收内存；并发名额限制在途工作；速率限制约束单位时间进入的尝试；连接池限制数据库连接；超时限制本地愿意等待的寿命；熔断暂时减少对故障依赖的新调用。

这些机制可以配合，却不能互相代替。每秒一千次、每次只用一毫秒的请求，可能不触发32个并发名额，却已经产生大量认证和数据库开销。

### 39.1.2 【入门】本章延续哪些真实限制

| 层次 | 当前实验限制 | 解释 |
| --- | --- | --- |
| HTTP业务入口 | 32在途、每实例32次/秒、突发64次 | 两种独立的准入限制 |
| HTTP总等待 | 上限5秒，可被内部相对预算缩短 | 外部edge不采纳调用者自报预算 |
| edge上游客户端 | 上限4.8秒，另受已消耗预算限制 | 修正旧2秒先于正常下游结束的问题 |
| 普通内部HTTP客户端 | 上限2秒，再受当前剩余预算限制 | 不增加应用层自动重试 |
| 密码哈希 | 4个阻塞工作名额 | 名额随真实阻塞工作寿命释放 |
| commerce数据库池 | 10连接、获取500毫秒 | 会话语句1500毫秒、锁等待500毫秒 |
| catalog进程数据库池 | 10连接、获取500毫秒 | 新增默认语句500毫秒、锁等待200毫秒 |
| Inventory RPC | 共享16名额、64KiB消息 | 原事务和回复绑定校验保留 |
| worker步骤 | 单次5秒、租约15秒 | 网络调用结果未知时保存重试责任 |

库存和支付事务中原有SET LOCAL仍可进一步设置自己的限制。单条语句上限也不是整笔多语句事务的总时间证明，不能把这一列简单相加后宣称得到严格跨服务截止时间。

### 39.1.3 【进阶】为什么要修正edge的2秒

一次订单创建可能先认证，再读取商品，最后等待数据库提交。旧edge客户端总共只等2秒，却把每个内部HTTP调用也允许到2秒；这不是一个有序嵌套的预算。

本章将代理上限改为4.8秒，同时从请求当前剩余时间中预留100毫秒。读取请求体花掉的时间也会影响代理可用时间，不能在处理到一半时又重新获得完整5秒。

### 39.1.4 【精通】写操作超时必须保守表达

本地future被取消，不证明远端事务已经回滚。数据库可能提交成功，响应却未到达；阻塞工作也可能仍在运行。

因此超时提示结果可能未知，并要求沿原命令身份恢复。不能因为付款没返回，就新建另一笔付款UUID；不能因为某次HTTP请求结束，就删除订单协调责任。

### 39.2.2 【进阶】在一次执行中消耗同一个单调时钟预算

budget::scope记录本机单调时钟截止点。嵌套scope只能缩短，不能延长已有截止点；remaining把当前剩余时间、调用自身上限和返回预留共同考虑。
```rust
//! Monotonic local budget plus a bounded relative hint for the next hop.
use std::{future::Future, time::Duration};
use tokio::time::Instant;
tokio::task_local! {static DEADLINE:Instant;}
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Expired;
pub async fn scope<T>(duration: Duration, future: impl Future<Output = T>) -> T {
    let end = Instant::now() + duration;
    let end = DEADLINE.try_with(|old| (*old).min(end)).unwrap_or(end);
    DEADLINE.scope(end, future).await
}
pub fn remaining(cap: Duration, reserve: Duration) -> Result<Duration, Expired> {
    match DEADLINE.try_with(|end| end.saturating_duration_since(Instant::now())) {
        Ok(left) => left
            .checked_sub(reserve)
            .filter(|d| !d.is_zero())
            .map(|d| d.min(cap))
            .ok_or(Expired),
        Err(_) => {
            if cap.is_zero() {
                Err(Expired)
            } else {
                Ok(cap)
            }
        }
    }
}
pub fn milliseconds(duration: Duration) -> Result<u64, Expired> {
    let ms = duration.as_millis().min(5000) as u64;
    if ms == 0 { Err(Expired) } else { Ok(ms) }
}
#[cfg(test)]
mod tests {
    use super::*;
    #[tokio::test(start_paused = true)]
    async fn sequential_calls_consume_one_budget_and_nested_scopes_cannot_extend_it() {
        scope(Duration::from_secs(5), async {
            tokio::time::advance(Duration::from_secs(2)).await;
            assert_eq!(
                remaining(Duration::from_secs(4), Duration::from_millis(100)).unwrap(),
                Duration::from_millis(2900)
            );
            scope(Duration::from_secs(30), async {
                tokio::time::advance(Duration::from_secs(3)).await;
                assert_eq!(
                    remaining(Duration::from_secs(2), Duration::ZERO),
                    Err(Expired)
                );
            })
            .await;
        })
        .await;
    }
    #[test]
    fn unscoped_clients_keep_their_cap_and_wire_rounding_never_adds_time() {
        assert_eq!(
            remaining(Duration::from_secs(2), Duration::from_millis(50)).unwrap(),
            Duration::from_secs(2)

    }

```

没有scope的独立客户端仍使用自身上限，这保留了前章独立实验的运行方式。Tokio task-local不会自动传播给任意新spawn的任务；需要跨任务执行时必须显式设计继承和取消关系，不能靠字段名称推断它已经传播。

### 39.2.3 【进阶】HTTP相对预算不是鉴权信息

内部HTTP使用x-rustmall-budget-ms传递剩余毫秒，范围1-5000，重复、负数、非数字和超上限值返回400。它只能缩短当前服务硬上限，不授予访问权限。

edge入口忽略外部自报的这个字段，先建立自己的5秒预算，再计算真正发给下游的值。原头白名单不复制外部预算，业务token仍按原身份规则验证。

### 39.2.4 【精通】逐跳提示不能伪装成严格全球时钟

相对值避免依赖各主机墙上时钟完全同步，但传输、接收与解析也会花时间。下游从接收后开始计时，可能在上游停止等待之后仍短暂工作。

本章用本地timeout、逐跳缩短和返回预留减少预算倒挂，没有声称获得跨机零误差的绝对截止时间。SQL也仍有自己的语句与锁等待限制，可靠恢复继续依赖收据。

### 39.3.3 【进阶】如何判断是本地预算还是依赖过慢

支付客户端在本地预算已经不足时返回LocalBudget，并不发送请求。如果因为上游已经花掉太多时间，支付只获得不足2秒的等待，再发生Deadline，不将它计入依赖熔断故障率。

只有完整2秒调用预算仍耗尽，或发生实际连接/服务不可用，才进入依赖故障统计。否则大量上游排队会把一个正常支付服务错误地熔断。

### 39.3.4 【精通】数据库限制和取消是两层机制

catalog池新增会话语句与锁等待上限，库存和支付仍保留事务内SET LOCAL。调用future的timeout保护应用等待，数据库限制保护服务器资源，两者都需要。

取得连接的等待不等于SQL执行时间；一笔事务的多条SQL也不共享一个简单的单条statement_timeout。第41章进一步分析执行计划、锁等待和事务取消，本章不把参数存在当作已经证明所有资源立即释放。

## 39.4 并发名额与令牌桶

### 39.4.1 【入门】许可何时归还，令牌何时补充

并发信号量在请求结束时归还许可，限制同时在做多少工作。令牌桶在时间推进时补充令牌，限制多少尝试可以进入。请求再快，也要消耗准入令牌；请求再慢，也受32个并发名额约束。

本章新服务的每个HTTP实例每秒补32个令牌，桶最多64个。刚开始允许一次突发，长期持续速率仍受补充速度约束。控制探针与指标抓取不消耗业务令牌。

### 39.4.2 【进阶】用整数保存零头

每个令牌用十亿份整数信用表示，经过的纳秒数乘每秒速率得到补充信用。这样32次/秒的一个令牌周期31.25毫秒可以准确保留，不需要把它截成31或32毫秒。
```rust
//! Process-local token bucket; admission tokens are not concurrency permits.
use std::{
    sync::{Arc, Mutex},
    time::Duration,
};
use tokio::time::Instant;
const UNIT: u128 = 1_000_000_000;
#[derive(Clone)]
pub struct Bucket {
    state: Arc<Mutex<State>>,
    burst: u32,
    per_second: u32,
}
struct State {
    credit: u128,
    at: Instant,
}
impl Bucket {
    pub fn new(burst: u32, per_second: u32) -> Result<Self, &'static str> {
        if burst == 0 || per_second == 0 {
            return Err("rate and burst must be positive");
        }
        Ok(Self {
            state: Arc::new(Mutex::new(State {
                credit: u128::from(burst) * UNIT,
                at: Instant::now(),
            })),
            burst,
            per_second,
        })
    }
    pub fn acquire(&self) -> Result<(), Duration> {
        let mut state = self.state.lock().unwrap_or_else(|p| p.into_inner());
        let now = Instant::now();
        let refill = now
            .saturating_duration_since(state.at)
            .as_nanos()
            .saturating_mul(u128::from(self.per_second));
        state.credit = state
            .credit
            .saturating_add(refill)
            .min(u128::from(self.burst) * UNIT);
        state.at = now;
        if state.credit >= UNIT {
            state.credit -= UNIT;
            Ok(())
        } else {
            let nanos = (UNIT - state.credit).div_ceil(u128::from(self.per_second));
            Err(Duration::from_nanos(nanos as u64))
        }
    }
}

        b.acquire().unwrap();
        b.clone().acquire().unwrap();
        assert_eq!(b.acquire().unwrap_err(), Duration::from_millis(500));
        tokio::time::advance(Duration::from_millis(250)).await;
        assert!(b.acquire().is_err());
        tokio::time::advance(Duration::from_millis(250)).await;
```

## 39.5 支付熔断状态机

### 39.5.1 【入门】Closed表示导通

| 状态 | 本章行为 | 离开条件 |
| --- | --- | --- |
| Closed闭合 | 正常允许调用，统计窗口内完成结果 | 足够样本且失败比例达到阈值 |
| Open断开 | 拒绝新的支付请求 | 冷却到期后第一个调用获得探测许可 |
| HalfOpen半开 | 只允许一个探测，其他调用拒绝 | 探测成功关闭；失败、取消或过期重开 |

Closed不是“禁止访问”，Open也不是“对外开放”。名字描述电路是否接通，初学时要先把这层含义说清。

### 39.5.2 【进阶】明确实验参数和失败分类

本章使用固定30秒统计窗口、至少5个可计入统计的完成样本、失败比例60%、开路冷却5秒、探测最长3秒。这些是可测试的实验策略，不是所有支付系统的生产标准。

Paid、Declined、Refunded和合法的查询无收据，都证明服务能按协议回答。参数错误、认证拒绝、身份冲突或协议损坏不进入Closed失败率。后两类仍可能让订单进入人工对账，不能因为熔断忽略就忽略业务错误。

### 39.5.3 【精通】半开收到忽略结果怎么办

半开只有一次受控探测。若收到401或契约异常，它没有证明当前调用能正常服务；本章重新进入冷却，等待修复，不把它当作成功关闭。

因此Ignore在Closed表示不计入统计，在HalfOpen表示本轮没有获得可用性证明。这个差别必须写进实现和解释，不能只给enum起一个模糊名字。

## 39.6 Rust如何防止熔断竞态

### 39.6.1 【入门】共享状态与许可所有权

Breaker的clone共享Arc&lt;Mutex&lt;Inner&gt;&gt;。acquire返回Permit，完成时显式finish；若future在半开探测期间被取消，Permit的Drop会重新开路。

正常Closed调用被取消时不凭空增加成功或失败样本。它是否已在远端产生业务效果，仍由原支付收据负责回答。

### 39.6.2 【进阶】完整实现与测试
```rust
//! One process-local dependency circuit. All clones share state.
use std::sync::{Arc, Mutex};
use std::time::Duration;
use tokio::time::Instant;
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Outcome {
    Healthy,
    Failure,
    Ignore,
}
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Phase {
    Closed,
    Open,
    HalfOpen,
}
#[derive(Debug, Clone, Copy)]
pub struct Policy {
    pub minimum: u32,
    pub failure_percent: u32,
    pub window: Duration,
    pub cooldown: Duration,
    pub probe_budget: Duration,
}
impl Default for Policy {
    fn default() -> Self {
        Self {
            minimum: 5,
            failure_percent: 60,
            window: Duration::from_secs(30),
            cooldown: Duration::from_secs(5),
            probe_budget: Duration::from_secs(3),
        }
    }
}
struct Inner {
    phase: Phase,
    generation: Arc<()>,
    since: Instant,
    total: u32,
    failed: u32,
}
#[derive(Clone)]
pub struct Breaker {
    inner: Arc<Mutex<Inner>>,
    policy: Policy,
    name: &'static str,
}
#[derive(Debug, Clone, Copy)]
pub struct Rejected {
    pub phase: Phase,
    pub retry_after: Duration,
}
pub struct Permit {
    breaker: Breaker,
    generation: Arc<()>,
    probe: bool,
    finished: bool,
}
impl Breaker {
    pub fn new(name: &'static str, policy: Policy) -> Result<Self, &'static str> {
        if policy.minimum == 0
            || policy.failure_percent == 0
            || policy.failure_percent > 100
            || [policy.window, policy.cooldown, policy.probe_budget]
                .iter()
                .any(Duration::is_zero)
        {
            return Err("invalid circuit policy");
        }
        Ok(Self {
            inner: Arc::new(Mutex::new(Inner {
                phase: Phase::Closed,
                generation: Arc::new(()),
                since: Instant::now(),
                total: 0,
                failed: 0,
            })),
            policy,
            name,
        })
    }
    fn change(&self, state: &mut Inner, phase: Phase, now: Instant) {
        let previous = state.phase;
        state.phase = phase;
        state.generation = Arc::new(());
        state.since = now;
        state.total = 0;
        state.failed = 0;
        tracing::info!(
            dependency = self.name,
            ?previous,
            ?phase,
            "circuit transition"
        );
    }
    pub fn phase(&self) -> Phase {
        self.inner.lock().unwrap_or_else(|p| p.into_inner()).phase
    }
    pub fn acquire(&self) -> Result<Permit, Rejected> {
        let now = Instant::now();
        let mut state = self.inner.lock().unwrap_or_else(|p| p.into_inner());
        let elapsed = now.saturating_duration_since(state.since);
        match state.phase {
            Phase::Closed if elapsed >= self.policy.window => {
                self.change(&mut state, Phase::Closed, now)
            }
            Phase::Open if elapsed >= self.policy.cooldown => {
                self.change(&mut state, Phase::HalfOpen, now)
            }
            Phase::Open => {
                return Err(Rejected {
                    phase: Phase::Open,
                    retry_after: self.policy.cooldown - elapsed,
                });
            }
            Phase::HalfOpen => {
                if elapsed >= self.policy.probe_budget {
                    self.change(&mut state, Phase::Open, now);
                }
                return Err(Rejected {
                    phase: state.phase,
                    retry_after: if state.phase == Phase::Open {
                        self.policy.cooldown
                    } else {
                        self.policy.probe_budget - elapsed
                    },
                });
            }
            _ => {}
        }
        Ok(Permit {
            breaker: self.clone(),
            generation: state.generation.clone(),
            probe: state.phase == Phase::HalfOpen,
            finished: false,
        })
    }
}
impl Permit {
    pub fn finish(mut self, outcome: Outcome) {
        self.settle(outcome);
        self.finished = true;
    }
    fn settle(&self, outcome: Outcome) {
        let now = Instant::now();
        let mut state = self.breaker.inner.lock().unwrap_or_else(|p| p.into_inner());
        if !Arc::ptr_eq(&state.generation, &self.generation) {
            return;
        }
        if !self.probe
            && state.phase == Phase::Closed
            && now.saturating_duration_since(state.since) >= self.breaker.policy.window
        {
            self.breaker.change(&mut state, Phase::Closed, now);
            return;
        }
        if self.probe {
            let healthy = now.saturating_duration_since(state.since)
                < self.breaker.policy.probe_budget
                && outcome == Outcome::Healthy;
            self.breaker.change(
                &mut state,
                if healthy { Phase::Closed } else { Phase::Open },
                now,
            );
        } else if state.phase == Phase::Closed && outcome != Outcome::Ignore {
            state.total = state.total.saturating_add(1);
            state.failed = state
                .failed
                .saturating_add(u32::from(outcome == Outcome::Failure));
            if state.total >= self.breaker.policy.minimum
                && u64::from(state.failed) * 100
                    >= u64::from(state.total) * u64::from(self.breaker.policy.failure_percent)
            {
                self.breaker.change(&mut state, Phase::Open, now);
            }
        }
    }
}
impl Drop for Permit {
    fn drop(&mut self) {
        if !self.finished && self.probe {
            self.settle(Outcome::Ignore);
        }
    }
}
```

### 39.6.3 【精通】为什么旧成功不能关闭新状态

某请求在Closed时开始，其他失败让电路Open；旧请求后来成功，不能据此把已经切换代次的电路关掉。半开探测也可能过期，新的状态不能被它迟到的结果覆盖。

本章用Arc&lt;()&gt;标识代次，Permit保留旧Arc并做ptr_eq比较。只要旧许可还活着，其分配就不会被复用为新代次。这个标记不是业务命令ID，也不替代数据库租约token。

### 39.6.4 【精通】固定窗口何时结束

窗口在30秒边界过期。新acquire会开始新窗口，迟到finish本身也会检测过期，不能因为没有新请求而把旧窗口的失败算成新样本。

它是固定窗口策略，不是精确滑动窗口。生产若改为滚动桶或时间加权统计，应重新验证阈值、迟到结果和并发状态切换，不能只改文档里的术语。

## 39.7 接入真实支付客户端与订单责任

### 39.7.1 【入门】客户端对象必须复用

PaymentRemote在构造时建立Breaker，clone共享它。worker启动时构造一次并长期复用；若每次调用都new一个客户端，统计每次归零，便无法发挥这个进程内策略的作用。

以下完整替换第38章的RemoteError与PaymentRemote部分；本地支付事务、HTTP处理器、State与Action保持不变：
```rust
#[derive(Debug, thiserror::Error, PartialEq, Eq)]
pub enum RemoteError {
    #[error("invalid payment input")]
    InvalidInput,
    #[error("payment identity conflict")]
    IdentityConflict,
    #[error("payment service identity rejected")]
    Unauthenticated,
    #[error("payment deadline; result may be unknown")]
    Deadline,
    #[error("payment dependency unavailable; result may be unknown")]
    Unavailable,
    #[error("invalid payment response")]
    Protocol,
    #[error("payment circuit open; preserve original command identity")]
    CircuitOpen,
    #[error("caller budget exhausted; preserve original command identity")]
    LocalBudget,
}
#[derive(Clone)]
pub struct PaymentRemote {
    client: reqwest::Client,
    base: String,
    key: String,
    breaker: governance::breaker::Breaker,
}
impl PaymentRemote {
    pub fn new(base: &str, key: String) -> anyhow::Result<Self> {
        let url = reqwest::Url::parse(base)?;
        anyhow::ensure!(
            matches!(url.scheme(), "http" | "https")
                && url.host_str().is_some()
                && url.username().is_empty()
                && url.password().is_none()
                && url.path() == "/"
                && url.query().is_none()
                && url.fragment().is_none(),
            "payment endpoint must be an HTTP(S) origin without credentials"
        );
        ServiceKey::parse(&key)?;
        Ok(Self {
            client: client()?,
            base: base.trim_end_matches('/').into(),
            key,
            breaker: governance::breaker::Breaker::new(
                "payments",
                governance::breaker::Policy::default(),
            )
            .map_err(anyhow::Error::msg)?,
        })
    }
    #[tracing::instrument(name="http.client",skip_all,fields(otel.kind="client",peer.service="payments"))]
    async fn request(
        &self,
        c: &Charge,
        action: Option<Action>,
    ) -> Result<Option<Payment>, RemoteError> {
        if !c.valid() {
            return Err(RemoteError::InvalidInput);
        }
        let request = match action {
            Some(Action::Charge) => self
                .client
                .post(format!("{}/internal/payments", self.base))
                .json(c),
            Some(Action::Refund) => self
                .client
                .post(format!("{}/internal/payments/refund", self.base))
                .json(c),
            None => self
                .client
                .get(format!("{}/internal/payments/{}", self.base, c.saga_id)),
        }
        .bearer_auth(&self.key);
        let request =
            outbound(request, Duration::from_secs(2)).map_err(|_| RemoteError::LocalBudget)?;
        let mut response = observability::http(request).send().await.map_err(|e| {
            if e.is_timeout() {
                RemoteError::Deadline
            } else {
                RemoteError::Unavailable
            }
        })?;
        match response.status().as_u16() {
            200 => {}
            404 if action.is_none() => return Ok(None),
            400 | 422 => return Err(RemoteError::InvalidInput),
            409 => return Err(RemoteError::IdentityConflict),
            401 | 403 => return Err(RemoteError::Unauthenticated),
            504 => return Err(RemoteError::Deadline),
            429 | 500 | 502 | 503 => return Err(RemoteError::Unavailable),
            _ => return Err(RemoteError::Protocol),
        }
        let mut bytes = Vec::new();
        while let Some(chunk) = response.chunk().await.map_err(|e| {
            if e.is_timeout() {
                RemoteError::Deadline
            } else {
                RemoteError::Unavailable
            }
        })? {
            if bytes.len().saturating_add(chunk.len()) > 4096 {
                return Err(RemoteError::Protocol);
            }
            bytes.extend_from_slice(&chunk);
        }
        let row: Payment = serde_json::from_slice(&bytes).map_err(|_| RemoteError::Protocol)?;
        if (row.saga_id, row.actor_id, row.amount) != (c.saga_id, c.actor_id, c.amount) {
            return Err(RemoteError::Protocol);
        }
        Ok(Some(row))
    }
    async fn guarded(
        &self,
        c: &Charge,
        action: Option<Action>,
    ) -> Result<Option<Payment>, RemoteError> {
        if !c.valid() {
            return Err(RemoteError::InvalidInput);
        }
        let duration =
            call_duration(Duration::from_secs(2)).map_err(|_| RemoteError::LocalBudget)?;
        let permit=self.breaker.acquire().map_err(|rejection|{
            tracing::warn!(dependency="payments",phase=?rejection.phase,retry_after_ms=rejection.retry_after.as_millis(),"circuit rejected call; no payment request sent");
            RemoteError::CircuitOpen
        })?;
        let result = tokio::time::timeout(duration, self.request(c, action))
            .await
            .unwrap_or(Err(RemoteError::Deadline));
        use governance::breaker::Outcome;
        let outcome = match &result {
            Ok(_) => Outcome::Healthy,
            Err(RemoteError::Unavailable) => Outcome::Failure,
            Err(RemoteError::Deadline) if duration >= Duration::from_secs(2) => Outcome::Failure,
            Err(_) => Outcome::Ignore,
        };
        permit.finish(outcome);
        result
    }
    pub async fn apply(&self, c: &Charge, action: Action) -> Result<Payment, RemoteError> {
        self.guarded(c, Some(action))
            .await?
            .ok_or(RemoteError::Protocol)
    }
    pub async fn query(&self, c: &Charge) -> Result<Option<Payment>, RemoteError> {
        self.guarded(c, None).await
    }
}
```

### 39.7.2 【进阶】CircuitOpen表示这次没有新请求发出

CircuitOpen与服务返回503不同：前者是本地准入拒绝，本次没有新付款HTTP请求；后者已经尝试联系服务。两者都不证明同一订单以前的付款是否发生。

订单worker把CircuitOpen保存为payment-circuit-open并延后原步骤，把LocalBudget保存为caller-budget-exhausted。它不把charging直接改成cancelled，也不更换saga_id。

### 39.7.3 【精通】恢复后仍核对原收据

冷却后一个探测成功，电路恢复导通。这个探测本身可以是带原UUID的Charge；若前次已经付款，参与者返回原收据，不增加第二条paid效果。

熔断器只减少新的依赖尝试，没有执行补偿，没有把未知结果变成未发生，也没有在进程重启后保存全局故障判断。worker重启会重建进程内电路，持久订单与参与者收据则继续保留。

## 39.8 退避、扰动与唯一重试责任

### 39.8.1 【入门】不要每一层都重试三次

网关、订单客户端和参与者若各重试三次，一次用户操作可能被放大成27次下游尝试。更深调用栈会进一步放大。

本章不在edge擅自重试POST。业务恢复由知道原UUID和不可变参数的持久worker承担；Outbox交付恢复由relay承担。客户端可根据查询结果按同一请求身份重放，不能用新键绕过原收据。

### 39.8.2 【进阶】稳定的equal jitter

订单以指数增长、最大32秒的基准延后，Outbox保留原最大300秒基准。本章在基准的一半到全部之间选择稳定扰动，至少1秒，同一身份和attempt得到同样的值。
```rust
//! Stable equal jitter: a replay of the same identity/attempt keeps its delay.
use sha2::{Digest, Sha256};
use uuid::Uuid;
pub fn jitter_seconds(base: u64, id: Uuid, attempt: i32) -> u64 {
    let low = (base / 2).max(1);
    let high = base.max(1);
    let mut hash = Sha256::new();
    hash.update(id.as_bytes());
    hash.update(attempt.to_be_bytes());
    let digest = hash.finalize();
    let mut seed = [0_u8; 8];
    seed.copy_from_slice(&digest[..8]);
    low + u64::from_be_bytes(seed) % (high - low + 1)
}
#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn jitter_is_reproducible_bounded_and_spreads_a_batch() {
        let mut delays = std::collections::HashSet::new();
        for n in 1..100 {
            let id = Uuid::from_u128(n);
            let delay = jitter_seconds(32, id, 8);
            assert!((16..=32).contains(&delay));
            assert_eq!(delay, jitter_seconds(32, id, 8));
            delays.insert(delay);
        }
        assert!(delays.len() > 8);
        assert_eq!(jitter_seconds(0, Uuid::nil(), 0), 1);
    }
}
```

摘要用于打散重试节奏，不是口令散列，也没有引入新的鉴权。确定性有利于复查同一尝试，不能因此把它解释为不可预测的安全随机数。

### 39.8.4 【精通】持续重试需要可见责任

次数达到计数上限不自动取消有未知付款的订单。第38章的订单年龄、manual计数、Outbox年龄和采样时间帮助发现长期未完成责任。

## 39.9 优雅停机与强制终止

### 39.9.1 【入门】停机顺序是协议的一部分

HTTP服务停止接收新请求，再按原20秒预算排空在途工作，随后关闭数据库和遥测。worker收到停止信号后不再进入下一轮领取，当前已经开始的领取或步骤属于在途工作。

不能承诺操作系统送达信号的瞬间，所有已经进入数据库的claim都绝不会提交。正确性需要允许它结束或通过租约恢复，而不是靠这句无法保证的描述。

### 39.9.2 【进阶】SIGKILL没有析构机会

SIGKILL时，进程内Permit Drop和优雅关闭都没有机会运行。但整个进程内Breaker也随之消失，不会留下全局永久半开状态；真正的业务责任仍在数据库。

新worker沿15秒订单租约接管。旧token、旧步骤或过期租约不能推进当前订单，参与者沿原UUID返回收据，避免重复副作用。

### 39.9.3 【精通】容器宽限期要容纳实际排空

未来Kubernetes terminationGracePeriodSeconds需要覆盖摘流、应用排空、数据库和遥测关闭，并预留实际平台延迟。不能看到程序有一个20秒timeout，就把容器宽限也机械地设置20秒。

第40章将更新完整服务交付配置。本章仍是原生应用加真实本地基础设施的验收，没有据此宣称集群摘流或NetworkPolicy已经生效。

### 39.10.2 【进阶】支付不可用时应该保存什么

停止payments进程，创建库存20的实验商品，再通过真实HTTP提交8笔数量1的订单。worker可以预留库存，但不能在没有付款证明时宣布完成，也不能因为熔断就释放并取消。

预期8笔都停在charging，catalog有8条Held，商品可售量12，支付库没有这8个UUID的付款收据；部分订单的last_error为payment-circuit-open。观察应等待全部订单进入这个稳定检查点，而不是抓取尚在reserving的瞬间就下结论。

### 39.10.4 【精通】并发争抢最后一件

创建库存1的独立商品，同时提交两个不同请求键的订单。预期一个完成并付款，另一个因库存稳定拒绝而取消；库存0，不是-1，拒绝者不产生paid效果。

这项实验验证的是权威库存事务与订单恢复的配合，不是读模型中的stock能否让两个客户端在发请求前自行排除竞争。

### 39.10.5 【精通】强杀发生在有未知结果的窗口

暂停payments进程但保留监听连接，提交新订单；在数据库看到charging且lease_token非空时，SIGKILL worker。恢复payments，再启动新worker，等待原租约到期。

预期原UUID最终completed，paid效果恰好1条，商品库存只变化一次。远端可能在旧worker退出前后处理了缓冲请求，所以必须核对收据，不能因为客户端被杀就断言付款从未发生。

### 39.10.6 【精通】撤销缓存丢失不能复活登录

对实验用户执行logout，旧token应401；清空本次隔离Redis数据库后，旧token仍应401，因为持久会话撤销记录保存在PostgreSQL。

这个动作只针对专用测试项目，不是日常修复步骤。实验结束还要检查两份投影与权威商品完整对账，并清理自己创建的进程、容器与卷。

### 39.11.3 【进阶】现象与处理方向

| 现象 | 先确认 | 处理方向 |
| --- | --- | --- |
| 429且有Retry-After | rate准入类别 | 等待补充，写操作保留原身份 |
| 429但业务正在占满 | capacity准入类别 | 检查耗时和依赖，不无限排队 |
| LocalBudget | 上游已花掉的时间 | 查同一trace，不先指责支付故障 |
| CircuitOpen | 是否本地拒绝了新调用 | 查持久步骤和冷却，不直接取消 |
| 半开反复重开 | 探测失败、取消、401或契约异常 | 核对分类与服务配置 |
| 重启后熔断统计归零 | 是否同一个进程实例 | 进程内状态重建，不代表依赖已恢复 |
| 多副本后数据库饱和 | 每实例池与副本上限 | 计算总连接和在途工作 |
| 支付恢复仍有订单等待 | next_attempt与租约 | 等待原计划，不换UUID重建 |
| 没有旧trace但出现paid收据 | 遥测丢失或进程强杀窗口 | 以业务事实对账 |

## 39.12 分层练习与下一章

### 39.12.1 【入门练习】32并发能推出32次/秒吗

参考答案：不能。并发取决于单次工作寿命，速率取决于时间内的准入次数。请求足够快时，同一个并发名额可以每秒服务多次，所以本章分别实现两种限制。

### 39.12.2 【进阶练习】一个401应不应该触发依赖熔断

参考答案：Closed下不计入本章依赖故障率，应修复凭据或授权；HalfOpen收到401也不是探测成功，会重新冷却。订单保留认证依赖不可用的重试责任，不能伪装成用户已经支付失败。

### 39.12.3 【进阶练习】取消半开探测以后谁释放名额

参考答案：异步future被取消时Permit被Drop，若仍是同一代次则重新开路。若新代次已经建立，旧Permit不能更改它。整个进程被SIGKILL则所有内存状态消失，业务租约和收据承担恢复。

### 39.12.4 【精通练习】相对预算可以保证下游绝不晚于上游结束吗

参考答案：不能。传输与接收延迟不会自动从线上数字里消失。它提供受控的逐跳提示，本地单调时钟和等待上限保护各自资源；严格跨机期限还涉及传播模型、时钟和服务端执行语义。写操作仍必须可查收据和幂等恢复。

### 39.12.5 【精通练习】为何不在重试很多次后自动取消

参考答案：次数不证明远端从未提交。应按明确参与者事实推进或补偿，对协议矛盾进入manual；长期未完成责任用年龄、稳定类别和人工对账暴露。自动取消未知付款反而可能同时形成已扣款与已释放库存。
